# game.php 全面技术评估与优化方案

> 评估日期：2026-06-09 | 评估范围：game.php 及其依赖模块 | 版本：v1.0

---

## 一、项目整体代码结构概览

### 1.1 架构分层

项目采用传统 PHP 单体架构，分层如下：

| 层 | 目录 | 职责 |
|---|---|---|
| 入口层 | `*.php`（根目录） | HTTP 请求入口，定义 `CURSCRIPT`，加载 `common.inc.php` |
| 基础设施层 | `include/core/` | 常量、输入过滤、DB连接、配置加载、模板引擎 |
| 数据库层 | `include/db/` | MySQL/MySQLi/PDO 三驱动 |
| 认证层 | `include/auth/` | 用户登录注册 |
| 房间层 | `include/room/` | 房间管理、RuleSet 覆盖 |
| 会话控制层 | `include/gamectl/` | 状态机、系统管理、玩家数据、反挂机 |
| 游戏逻辑层 | `include/game/` | 战斗/物品/社团/事件/探索/任务 等 62 个文件 |
| 跨游戏层 | `include/meta/` | 积分结算、赌局、成就 |
| 指令路由层 | `include/command/` | 2026-06 重构，将 `command.php` 拆分 |

### 1.2 请求生命周期

```
浏览器 → 入口文件 (game.php/command.php/...) 
       → common.inc.php（常量、输入过滤、DB、配置、状态机+DB锁）
       → 按入口分发业务逻辑
       → 模板渲染 或 JSON 输出
```

### 1.3 game.php 的角色定位

`game.php` 是**游戏主界面入口**——玩家每次刷新页面或首次进入游戏时访问。其职责：

1. 玩家认证
2. 加载玩家数据
3. 展开为全局变量
4. 公共初始化
5. 状态判定（死/休息/手持道具/普通）
6. 特殊动作处理（尸体/追击/中立遭遇）
7. 对话/RuleSet剧情检查
8. 资料面板渲染
9. API代理
10. 模板输出

## 三、技术评估

### 3.1 代码质量

**严重问题：**

| 问题 | 位置 | 风险 |
|------|------|------|
| `extract()` 全局污染 | L37, L115, L139 | 197 个变量注入全局作用域，无法追踪来源，IDE 无法静态分析 |
| 认证逻辑重复 | L20-32 vs command.php L10-25 vs api_v2.php L15-33 | 三份几乎相同的认证代码，修改一处易遗漏 |
| 隐式全局依赖 | L108 `$cid=$bid`、L111 `$edata`、L122 `$enemyid` | `$bid` 来源不清，数据流追踪困难 |
| 内联 HTML/JS | L145 (定时器)、L182-188 (对话框) | 前端代码嵌入PHP，难以维护 |
| 直接操作 `$_POST` | L148 `$_POST['command']` | 绕过 `gstrfilter()` 过滤 |

**中等问题：**

| 问题 | 位置 | 风险 |
|------|------|------|
| `include_once` vs `require` 混用 | L77, L126, L137 | 不一致的加载策略，`include_once` 失败时静默 |
| 死代码遗留 | L196 注释掉的 referer 检查 | 增加阅读噪音 |
| 魔法数字 | `$state==1\|\|2\|\|3` (L98)、`$gamestate<40` (L107) | 缺少语义常量 |

### 3.2 性能瓶颈

| 瓶颈 | 位置 | 影响 | 量化 |
|------|------|------|------|
| **RuleSet DB 查询（每次请求）** | L41-46 | 每个 game.php 请求额外一次 DB 查询 | ~5-10ms |
| **`init_profile()` 重型计算** | L197, game.func.php L33-114 | 调用 `get_base_att()`/`get_base_def()` 遍历所有装备属性修正，包含姿态、策略、天气、地点四层修正 | ~20-50ms（战斗系统最大文件 `revattr.func.php`） |
| **`init_bgm()` 每次生成播放器** | L79（command.php），但在 game.php 中被调用 | JSON 编码整个 BGM 列表、shuffle 数组、生成 HTML 音频标签 | ~10-20ms |
| **无缓存策略** | 全局 | 玩家数据、配置数据、聊天数据每次请求都重新查询 | - |
| **`ob_start()` 多层嵌套** | common.inc.php L50, game.php 多处 `ob_clean()` | 多次清理/重写输出缓冲区 | ~1-2ms |
| **聊天数据全量加载** | L62 `getchat(0, ...)` | 无分页，房间聊天量大会拖慢响应 | - |

### 3.3 安全隐患

| 漏洞 | 位置 | 严重度 | 说明 |
|------|------|--------|------|
| **SQL注入** | L123 `pls='$pls'` | **高** | `$pls` 未经 `intval()` 或 `escape_string()` 直接拼入 SQL |
| **SQL注入** | L72 `name='$cuser'` in game.php context | **中** | `$cuser` 在这里没有 escape |
| **无CSRF保护** | 全局 | **高** | 所有 POST 请求无 CSRF Token 验证 |
| **无速率限制** | 全局 | **中** | 可被自动化脚本暴力刷新/操作 |
| **敏感信息泄露** | `$authkey`, `$salt` | **中** | 全局可访问，虽然 `$dbpw` 已 unset |
| **`gstrfilter()` 过度过滤** | global.func.php L56-70 | **低** | 移除单引号和反斜杠破坏合法输入 |

### 3.4 可维护性

| 问题 | 说明 |
|------|------|
| **game.php 与 command.php 高度重复** | 认证、初始化、状态检查、死亡处理几乎相同 (约80行重复) |
| **入口文件职责边界模糊** | game.php 同时承担认证、渲染、API代理、对话系统、RuleSet剧情 五重职责 |
| **全局状态依赖** | 函数如 `init_profile()`、`findcorpse()` 隐式依赖全局变量，无法独立测试 |
| **数据流不可追踪** | `extract()` 后 197 个变量的读写无法通过 IDE 追踪 |
| **注释不一致** | 中英混合、部分注释格式混乱 |

### 3.5 扩展性

| 限制 | 说明 |
|------|------|
| **硬编码动作分支** | L107-144 的 if-else 链，新增动作类型需修改 game.php 本体 |
| **无事件钩子系统** | 对话/RuleSet/BGM 逻辑紧耦合在主流程中 |
| **模板系统老旧** | 自定义模板语法 `{var}` `<!--{if}-->` ，不支持现代前端框架 |
| **双前端并存** | 旧前端 (`game.js`) 和新前端 (`is_new` → `api.php`)、VEX前端 (`vex_api` → `api_v2.php`) 三套在同一个文件分流 |

### 3.6 模块交互

```
game.php
  ├── 读: common.inc.php ($db, $cuser, $gamestate, ...)
  ├── 读: game.func.php (init_playerdata, init_profile, init_battle_rev, init_bgm, player_save)
  ├── 读: player_auth.func.php (auth_game_player)
  ├── 读: init_player.func.php (init_player_log, init_noise_display, init_cooldown, ...)
  ├── 读: encounter.func.php (findcorpse)
  ├── 读: revbattle.func.php (findenemy_rev, findneut)
  ├── 读: api.php (is_new → JSON)
  ├── 读: api_v2.php (vex_api → JSON)
  ├── 读: ruleset/story_config.php (get_ruleset_story)
  ├── 写: players 表 (player_save)
  └── 写: game 表 (gruleset 查询只读)
```

## 四、优化方案与分阶段迭代计划

### 第一阶段：安全加固（1-2周，低风险）

| 优先级 | 任务 | 文件 | 说明 |
|--------|------|------|------|
| P0 | 修复 SQL 注入 | game.php L123 | `pls='$pls'` → `pls='".intval($pls)."'` |
| P0 | 添加 CSRF Token | common.inc.php + 所有入口 | 生成 Token 存入 Session/Cookie，POST 验证 |
| P1 | 添加速率限制 | common.inc.php | 基于 `$cuser` + IP 的请求频率控制 (Redis/文件锁) |
| P2 | `$cuser` SQL 转义 | game.php L72 | 添加 `$db->escape_string($cuser)` |

### 第二阶段：消除重复与提取公共入口骨架（2-3周，中风险）

将 game.php 与 command.php 的公共部分抽取为统一的入口骨架：

```php
// include/core/entrypoint.php (新文件)
function game_entrypoint($entry_type) {
    // 公共认证流程
    $auth_result = auth_game_player();
    // ... 统一认证分支
    
    // 公共初始化
    require GAME_ROOT.'./include/gamectl/init_player.func.php';
    extract($pdata, EXTR_REFS);
    init_playerdata();
    $log = init_player_log();
    
    // 存活状态公共检查
    if ($hp > 0) {
        $log .= init_noise_display();
        $rmcdtime = init_cooldown();
        $log .= init_dizzy_check();
        init_club_check();
    }
    
    return compact('pdata', 'log', 'rmcdtime', ...);
}
```

**game.php 重构后骨架（~60 行）：**

```php
<?php
define('CURSCRIPT', 'game');
require './include/core/common.inc.php';
require GAME_ROOT.'./include/gamectl/game.func.php';
require GAME_ROOT.'./include/gamectl/player_auth.func.php';

// 退出登录快速路径
if (isset($mode) && $mode == 'quit') {
    gsetcookie('user', ''); gsetcookie('pass', '');
    header("Location: index.php"); exit();
}

// 统一入口初始化
$ctx = game_entrypoint('game');
extract($ctx);

// game.php 特有：RuleSet 缓存查询（优化：从 $gruleset 读取，已在 common.inc.php 中查询）
$ruleset_id = $gruleset; // 替代 L40-47 的重复查询

// game.php 特有：聊天数据
$chatdata = getchat(0, isset($teamID) ? $teamID : '');
$emdata = get_emdata();

// game.php 特有：状态判定与动作处理
$render_mode = resolve_game_render_mode($pdata, $action, $gamestate, $bid, $pls);

// 对话/RuleSet 剧情检查
$dialog_result = check_and_prepare_dialogs($pdata, $ruleset_id, $clbpara);

// 渲染
init_profile();
output_game_page($render_mode, $dialog_result);
```

### 第三阶段：架构优化（3-4周，中高风险）

| 任务 | 说明 |
|------|------|
| **对话系统独立** | 将 L148-188 对话/RuleSet 剧情逻辑提取到 `include/game/dialogue/dialogue_trigger.func.php` |
| **动作处理器模式** | L107-144 的 if-else 链改为策略模式：`$handlers = ['corpse' => CorpseHandler::class, 'chase' => ChaseHandler::class, ...]` |
| **player_save 统一** | 将散落的 `player_save($pdata)` 调用统一到入口文件末尾，消除 L82、L155 等处的中间保存 |
| **BGM 渲染解耦** | `init_bgm()` 返回值改为结构化数据，由模板层负责 HTML 生成 |

### 第四阶段：性能优化（2-3周，中风险）

| 优化 | 说明 | 预期提升 |
|------|------|----------|
| **RuleSet 缓存** | `$gruleset` 已在 `load_gameinfo()` 中加载，game.php 不再额外查询 | 减少 1 次 DB 查询 |
| **init_profile 惰性求值** | 仅在新前端 (`is_new`) 或资料面板需要时才调用 `get_base_att()`/`get_base_def()` | 减少 20-50ms |
| **聊天数据分页** | `getchat()` 添加 LIMIT 参数，JS 滚动加载 | 减少响应体积 |
| **配置预加载优化** | `REQUIRED_CONFIGS` 常量按需加载（game.php 不需要 combatcfg） | 减少文件 I/O |
| **BGM 数据缓存** | BGM 播放列表生成结果缓存到 `clbpara`，仅在切换曲集时重新计算 | 减少 10-20ms |

### 第五阶段：长期演进（后续迭代）

| 方向 | 说明 |
|------|------|
| **双前端统一** | 废弃旧前端 (`game.js` + 模板)，全面迁移到 VEX/新前端 JSON API |
| **$pdata 对象化** | 引入 PlayerData 值对象，替代 `extract()` + 全局变量模式 |
| **事件系统** | 引入轻量级事件/钩子系统，对话、RuleSet、BGM 等通过事件解耦 |
| **模板引擎升级** | 评估迁移到原生 PHP 模板或 Plates/Blade 等轻量引擎 |
| **单元测试** | 为核心函数（`init_playerdata`、`init_profile`、`auth_game_player`）编写测试 |

## 六、上线部署建议

## 七、总结

`game.php` 作为游戏主界面入口，承载了认证、状态判定、动作分发、对话系统、RuleSet剧情、BGM、资料渲染等多重职责，代码质量方面存在全局状态污染、认证逻辑重复、SQL注入风险等问题。与 `command.php`（已重构）的高度重复是最突出的可维护性问题。

**核心建议**：优先执行第一阶段的 SQL 注入修复和 CSRF 防护，然后执行第二阶段将 game.php 和 command.php 的公共部分统一为入口骨架函数，这是投入产出比最高的两项优化。
