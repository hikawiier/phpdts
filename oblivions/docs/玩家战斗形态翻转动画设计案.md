# 玩家战斗形态翻转动画设计案

## 一、目标

玩家地图 Actor 使用两套单张立绘：

- 探索形态：`/img/3.png`
- 战斗形态：`/img/3_a.png`

进入战斗时播放一次镜面翻转变身，在立绘转到侧面、水平投影最窄的时刻交换图片；退出战斗时反向切回探索立绘。动画不使用 sprite 帧序列、不创建残影、不使用全屏闪光。

## 二、框架定位

形态切换是 Actor 的可复用表现能力，不是玩家组件的临时 DOM 特效。

调用链：

```text
battleStore currentMode 切换
  -> playerAvatarStore battle-start / battle-end intent
  -> useMapEntities 获取 ActorRuntime pose lease
  -> ActorCommand: transform-appearance
  -> actorAnimations.transformAppearance()
  -> 侧面时刻交换 playerAvatarStore.currentImage
```

`playerAvatarStore.currentImage` 是当前玩家立绘真值。`entitiesStore` 只读取该值，不根据 `battleStore.currentMode` 直接推导图片，避免 Vue 在动画开始前提前换图。

## 三、动画时序

总时长约 0.56 秒：

1. `0-0.22s`：停止 idle，立绘轻微上提和放大，`rotationY: 0 -> 90`。
2. `0.22s`：立绘处于侧面，调用形态切换回调交换图片。
3. `0.22-0.56s`：从 `rotationY: -90 -> 0` 展开新立绘，回落到原位。
4. 动画完成后释放 pose lease，由 ActorRuntime 恢复 idle。

使用 `transformPerspective` 提供翻牌深度，但最终清理 `rotationY`、`scaleX`、`scaleY`、`y` 和 perspective，避免污染后续移动、攻击、受击动画。

## 四、并发与恢复

- 形态动画占用 `pose` 通道，能正确替换 ambient idle。
- battle owner 优先级高于 world/ambient，战斗切换不会被 idle 抢占。
- 重复进入相同形态时不播放动画，只确保图片真值正确。
- 动画在换图前被取消：保持旧形态。
- 动画在换图后被取消：保持新形态；后续 intent 可继续反向切换。
- `prefers-reduced-motion` 下不旋转，立即换图并用极短淡入收口。

## 五、首期边界

本期只实现玩家探索形态与战斗形态互切，不同时重构战斗红光、技能特效或 NPC 形态。该命令保留通用 `swap` 回调，后续可用于 Boss 阶段、持武器姿态和剧情变身。
