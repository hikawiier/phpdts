# Oblivions 道具使用与合成系统 — 设计案

> P0 阶段核心系统设计。涵盖道具使用命令、食物经验系统、合成命令、配方表、
> 工作台 POI 与前端 UI 规范。完成后玩家可体验"捡素材→合成厨具→做饭→升级"
> 的完整沙盒循环。

---

## 一、设计目标

| 目标 | 实现方式 |
|------|---------|
| 让玩家能"使用"背包道具 | 新增 `obl_use_item` 命令 + 道具使用效果分发 |
| 食物成为经验唯一来源 | 食物使用时按衰减曲线发放经验，写入 `oblpara.food_exp` |
| 玩家能合成新道具 | 新增 `obl_craft` 命令 + 配方表 + 工作台 POI |
| 烹饪不独立成系统 | 烹饪 = `category='food'` 的合成配方，复用 craft 命令 |
| 武器损坏机制可用 | 在 use_item / 战斗受击时扣减耐久，itms=0 时道具破坏 |

**核心解耦**：`use_item` 与 `craft` 是两个独立命令。食物通过 `craft` 产出，通过 `use_item` 食用。两个系统通过道具表的数据结构耦合，命令层互不依赖。

## 二、核心概念

### 2.1 道具使用效果（use_effect）

道具的"使用"行为通过效果函数分发，模式与 POI 的 `obl_mechanic_*` 完全对齐：

```
item_table.use_effect = 'restore_hp'
                         ↓
obl_use_effect_restore_hp($item, &$pdata)  ← 框架自动分发
```

新增效果只需添加 `obl_use_effect_{name}()` 函数，框架自动分发。**P0 阶段实现的效果**：

| use_effect | 适用种类 | 行为 |
|-----------|---------|------|
| `restore_hp` | HH（恢复） | 恢复 itme 值的 HP |
| `restore_sp` | HS（食物） | 恢复 itme 值的 SP + 触发经验发放 |
| `cure_poison` | DX（药物） | 解除中毒状态（P0 仅打日志，状态系统待 P1） |

### 2.2 食物经验衰减曲线

| 进食次数 | 经验系数 |
|---------|---------|
| 第 1 次 | 100% |
| 第 2 次 | 50% |
| 第 3 次 | 10% |
| 第 4 次及以后 | 0% |

**存储**：`oblpara.food_exp = { item_id: eat_count }`。每次进食后 count++，按 count 查表得系数。

**经验值**：道具表 `item_table.php` 中 HS 类道具新增 `exp_value` 字段。实际获得经验 = `exp_value × 系数`。

### 2.3 升级机制

- `bra_oblplayers.exp` 字段累加经验
- 达到 `lvl` 对应的 `exp_needed` 时 `lvl++`，应用属性成长
- 单次进食可能连升多级（循环判定）

### 2.4 合成配方（Recipe）

配方是静态配置，定义"用什么素材合成什么产物"：

```php
'recipe_id' => [
    'name'           => '废铁刀',
    'desc'           => '用废铁片磨出的粗糙刀刃',
    'category'       => 'weapon',         // weapon/armor/tool/food/material
    'workbench_lvl'  => 1,                // 所需工作台等级
    'required_tool'  => null,             // 需持有的工具 item_id（如 'frying_pan'）
    'materials'      => [
        ['item_id' => 'scrap_metal', 'count' => 3],
        ['item_id' => 'rusty_gear',  'count' => 1],
    ],
    'result'         => [
        'item_id' => 'scrap_blade',
        'count'   => 1,
    ],
]
```

### 2.5 工作台 POI

工作台是 POI 的一种，通过 `mechanic='craft'` 复用现有 POI 机制：

```php
'workbench_basic' => [
    'name'            => '简易工作台',
    'desc'            => '由废铁拼凑的简易操作台，能制作基础物品。',
    'searchable'      => false,           // 工作台不可搜索
    'mechanic'        => 'craft',
    'mechanic_value'  => 1,               // 工作台等级
    'mechanic_params' => ['weapon', 'tool', 'material'],  // 支持的配方分类
],
```

玩家在工作台所在格点击"合成"按钮即可触发 craft 命令。**P0 阶段工作台等级固定为 1**，等级提升留给 P1 猫背包升级系统。

### 2.6 烹饪 = 食物合成

烹饪不独立成系统。烹饪炉灶作为工作台 POI 的一种，`mechanic_params` 含 `'food'` 分类。烹饪配方与其他配方同表管理，仅 `category='food'` 区分。

**烹饪器具的引入动机**：高级烹饪配方 `required_tool` 字段非空（如 `'frying_pan'` 煎锅、`'sharp_knife'` 锋利菜刀）。玩家需要先合成器具，才能解锁高级料理。这创造了"找素材→做厨具→做饭"的动机链。

## 三、数据结构变更

### 3.1 `item_table.php` 扩展

每个道具模板新增以下可选字段（不填则无对应行为）：

```php
'item_id' => [
    // 现有字段...
    'itm'  => '生锈的水管',
    'itmk' => 'WP',
    'itme' => 8,
    'itms' => 20,
    'itmsk' => '',
    'itmpara' => '',
    'desc' => '...',
    'tier' => 'common',
    'stack' => false,
    
    // ─── 新增字段（P0）───
    'use_effect'  => '',           // 使用效果名（如 'restore_hp'），空=不可使用
    'exp_value'   => 0,            // 食物经验值基础值（仅 HS 类需要）
    'stackable_in_inventory' => false,  // 背包内是否合并堆叠（P0 全部 false，预留）
],
```

**P0 阶段需要补 use_effect / exp_value 字段的道具**：

| item_id | itmk | use_effect | exp_value | 说明 |
|---------|------|-----------|-----------|------|
| health_potion | HH | restore_hp | 0 | 恢复 80 HP |
| stamina_potion | HS | restore_sp | 0 | 恢复 50 SP，无经验（药剂非食物） |
| supply_pack | HH | restore_hp | 0 | 恢复 30 HP，多次使用（itms=3） |
| swamp_herb | HH | restore_hp | 0 | 恢复 20 HP（带毒性，待 P1 状态系统） |
| **roasted_rabbit**（新） | HS | restore_sp | 30 | 烤兔肉，恢复 SP + 经验 |
| **grilled_mushroom**（新） | HS | restore_sp | 15 | 烤蘑菇 |
| **simple_stew**（新） | HS | restore_sp | 50 | 简易炖菜 |

```php
    4 => ['exp_needed' => 750, 'growth' => ['mhp' => 15, 'msp' => 6, 'att' => 3, 'def' => 2]],

    // ... 按需扩展到 20 级左右

```

**经验读取规则**：
- 当前 lvl 在表内：读取该 lvl 的 `exp_needed` 与 `growth`
- 当前 lvl 超出表范围：使用表内最大 lvl 的配置（防越界）
- `exp_needed` 是"升到下一级所需累计经验"（不是单次进食需要）

**升级判定**：`exp += gained; while (exp >= exp_needed_at_lvl) { exp -= exp_needed; lvl++; apply_growth; }`

## 四、后端命令

### 4.1 `obl_use_item` 命令

**请求**：
```
POST command.php
mode=command&command=obl_use_item&slot=3
```

**参数**：
- `slot` (int, 1~itemmaxslots) — 背包槽位号

**状态过滤**：
- 战斗状态（`action='battle'`）下禁止使用 → `obl_command_allowed_by_state` 添加白名单
- 死亡状态（`state=1` 或 `hp<=0`）下禁止使用

**Tick 推进**：**不推进**（在 `obl_command_advances_tick` 白名单中不添加此命令）

**响应**：`{}`（标准 Oblivions 命令响应）

### 4.2 `obl_craft` 命令

**请求**：
```
POST command.php
mode=command&command=obl_craft&iaid=12&recipe_id=craft_roasted_rabbit
```

**参数**：
- `iaid` (int) — 工作台 POI 实例 ID
- `recipe_id` (string) — 配方 ID

**状态过滤**：
- 战斗状态下禁止
- 死亡状态下禁止

**Tick 推进**：**不推进**

**响应**：`{}`

### 4.3 命令注册清单

需要改动的文件：

| 文件 | 改动 |
|------|------|
| `oblivions_router.php` | switch 增加 `obl_use_item` / `obl_craft` 分支 |
| `oblivions_commands.php` | 新增 `cmd_handle_obl_use_item` / `cmd_handle_obl_craft` |
| `player.func.php` 的 `obl_command_allowed_by_state` | 战斗态时这两个命令均被拒（默认即拒，无需改动；但建议显式注释） |
| `tick.func.php` 的 `obl_command_advances_tick` | 不添加这两个命令（默认即不推进，无需改动） |

## 五、后端函数规划

### 5.1 新建 `use_item.func.php`

注册到 `obl_bootstrap.php` 第 1 层（与 explore.func.php 同层）。

```
use_item.func.php
├── obl_use_item($slot, &$pdata)              ← 命令入口
├── obl_execute_use_effect($item, &$pdata)    ← 效果分发框架
├── obl_use_effect_restore_hp($item, &$pdata) ← 恢复 HP
├── obl_use_effect_restore_sp($item, &$pdata) ← 恢复 SP + 触发食物经验
├── obl_use_effect_cure_poison($item, &$pdata)← 解毒（P0 占位）
├── obl_gain_food_exp($item_id, $exp_value, &$pdata)  ← 食物经验衰减
├── obl_apply_level_up(&$pdata)               ← 升级判定与属性成长
└── obl_consume_durability(&$item, $amount=1) ← 耐久扣减
```

### 5.2 新建 `craft.func.php`

注册到 `obl_bootstrap.php` 第 1 层。

```
craft.func.php
├── obl_craft($iaid, $recipe_id, &$pdata)     ← 命令入口
├── obl_get_recipe($recipe_id)                ← 配方读取（带静态缓存）
├── obl_get_recipes_for_workbench($poi_template)  ← 按工作台过滤可用配方
├── obl_count_material_in_inventory(&$pdata, $item_id)  ← 统计素材数量
├── obl_consume_materials(&$pdata, $materials) ← 扣除素材
└── obl_mechanic_craft($template, &$pdata)    ← POI 机制占位（实际合成走 obl_craft 命令）
```

**`obl_mechanic_craft` 设计**：工作台 POI 的 `mechanic='craft'` 主要用于**前端识别**——`tile_actions` API 返回 POI 时携带 mechanic 字段，前端据此显示"合成"按钮。后端搜索工作台 POI 时不需要执行任何机制（`searchable=false`），所以 `obl_mechanic_craft` 函数体留空或返回提示日志。

### 5.3 道具耐久扣减机制

耐久字段 `itms` 当前是字符串（如 `"20"`、`"3"`、`"999"`）。约定：

- 纯数字字符串 → 有限耐久，每次使用/受击扣 1
- `"999"` 或 `"∞"` → 无限耐久，不扣减
- 耐久扣到 0 → 道具破坏（从背包移除，emit 日志）

```php
function obl_consume_durability(&$item, $amount = 1) {
    if (!isset($item['itms'])) return;
    $s = (string)$item['itms'];
    if ($s === '' || $s === '0' || $s === '∞' || $s === '999') return;  // 无限耐久
    
    $cur = (int)$s;
    $cur = max(0, $cur - $amount);
    $item['itms'] = (string)$cur;
    // 调用方根据 $cur === 0 决定是否破坏道具
}
```

**P0 阶段耐久扣减场景**：
- 食物使用后 itms-1，到 0 时消失（已实现于 use_item 流程）
- 武器在战斗中受击不扣耐久（P0 简化，留给 P1）
- 武器损坏的"胃酸腐蚀"剧情由猫背包系统承担（P1）

### 5.4 `obl_use_item` 完整流程

```
1. 参数校验：slot 在 1~itemmaxslots 范围
2. 读取槽位道具，空槽 → emit 'use_item.empty_slot'，return
3. 读取道具模板（item_table），无 use_effect → emit 'use_item.not_usable'，return
4. 调用 obl_execute_use_effect($item, $pdata)
   └─ 分发到 obl_use_effect_{use_effect}() 函数
5. 扣减道具耐久（itms-1）
6. 若耐久归 0：
   - 清空该槽位
   - emit 'use_item.consumed'
7. 否则保留道具（耐久显示更新）
8. obl_save_player($pdata)
```

### 5.5 `obl_use_effect_restore_sp` 完整流程（食物核心）

```
1. 读取 $item['itmid']（item_id）
2. 读取 $item['itme']（恢复量）
3. $pdata['sp'] = min($pdata['sp'] + itme, $pdata['msp'])
4. 读取 $item['exp_value']（食物经验基础值）
5. 若 exp_value > 0：
   调用 obl_gain_food_exp($item_id, $exp_value, $pdata)
     └─ 读取 oblpara['food_exp'][$item_id]，默认 0
     └─ 按次数查系数：0→1.0, 1→0.5, 2→0.1, >=3→0
     └─ 实际获得 = exp_value × 系数
     └─ oblpara['food_exp'][$item_id]++
     └─ $pdata['exp'] += 实际获得
     └─ emit 'exp.gain' / 'exp.gain_diminished' / 'exp.gain_zero'
     └─ 调用 obl_apply_level_up($pdata)（可能连升多级）
6. emit 'use_item.restore_sp'
```

### 5.6 `obl_craft` 完整流程

```
1. 参数校验：iaid 与 recipe_id 非空
2. 读取工作台 POI 实例（bra_oblmappoi）
3. 位置检查：工作台必须在玩家当前格
4. 读取 POI 模板，验证 mechanic='craft'
5. 读取配方模板（recipe_table.php）
6. 配方过滤：
   - 配方 workbench_lvl ≤ 工作台 mechanic_value
   - 配方 category ∈ 工作台 mechanic_params
7. required_tool 检查：玩家背包中是否持有该 item_id
8. 素材检查：遍历 materials，每个 item_id 的库存 ≥ count
   └─ obl_count_material_in_inventory(&$pdata, $item_id) 实现：
      遍历 itempara[1..maxslots]，累加 itmid === item_id 的道具数量
      （注：P0 不支持堆叠合并，每槽一件；后续支持堆叠时此函数仍可用）
9. 背包空位检查：result.count > 0 时需有空槽位
10. 扣除素材：obl_consume_materials(&$pdata, $materials)
    └─ 遍历 materials，按 item_id 扣减槽位（先扣完后扣前，可能跨多槽）
    └─ 槽位道具数量为 0 时清空
11. 添加产物：在空槽位写入 result 道具
12. emit 'craft.success' / 失败时 emit 对应错误日志
13. obl_save_player($pdata)
```

### 6.4 配方列表来源（两种方案）

**A 方案（推荐）**：后端新增 `craft_recipes` API
- 请求：`GET api_v2.php?action=craft_recipes&iaid=xxx`
- 响应：按工作台等级和分类过滤后的配方列表 + 玩家当前持有素材快照
- 优点：素材校验在后端，避免前端配置不同步

**B 方案**：前端静态加载配方表
- 在 `vex-vue/src/data/recipe-table.ts` 镜像后端配方表
- 优点：无网络请求
- 缺点：配方表更新需要前后端同步

P0 选 **A 方案**，理由：配方表会随开发迭代频繁变更，后端单源更稳。

### 6.5 新增 API 端点

**`craft_recipes`** — 获取工作台可用配方

- **请求**：`GET api_v2.php?action=craft_recipes&iaid=123`
- **响应**：
```json
{
  "status": "success",
  "data": {
    "workbench": {
      "name": "简易工作台",
      "level": 1,
      "categories": ["weapon", "tool", "material", "food"]
    },
    "recipes": [
      {
        "recipe_id": "craft_roasted_rabbit",
        "name": "烤兔肉",
        "desc": "用火烤过的兔肉，香气四溢。",
        "category": "food",
        "required_tool": null,
        "materials": [
          {"item_id": "rabbit_meat", "count": 1, "have": 1, "enough": true}
        ],
        "result": {"item_id": "roasted_rabbit", "name": "烤兔肉", "count": 1},
        "craftable": true
      }
    ]
  }
}
```

`materials[].have` 与 `craftable` 字段由后端结合玩家当前背包计算，前端直接渲染。这避免了前端重复实现素材校验逻辑。

## 十一、预留扩展点

### 11.1 P1 猫背包系统的接口预留

猫背包的"胃酸腐蚀"机制将复用 `obl_consume_durability` 函数——道具在猫肚子里每隔一段时间扣减耐久。`food_exp` 数据结构同样适用于猫肚子里的道具（玩家吃过的食物记录不因存放位置改变）。

### 11.2 P1 Buff 系统的接口预留

`use_effect` 框架可扩展 `buff_temp` 效果，写入 `oblpara.buffs` 数组（带 expire_tick）。P0 阶段不实现，但框架已支持。

### 11.3 P1 道具堆叠

`obl_count_material_in_inventory` 已预留堆叠支持。当 `stackable_in_inventory=true` 时，统计逻辑改为按 `itms`（耐久/数量）累加；扣除时按数量优先扣减最满的槽位。

### 11.4 P2 工作台升级

工作台 POI 的 `mechanic_value`（等级）当前固定。P1 猫背包的"便携工作站"升级可以让玩家随身携带等级 2/3 的工作台，只需在 `obl_craft` 入口允许 `iaid=0`（猫肚子里的工作台）+ 玩家 oblpara 中读取便携工作台等级。

## 十二、待确认事项

1. **配方表是否需要"解锁"机制**？当前设计是玩家只要到工作台就能看到所有可合成配方。是否需要"蓝图"或"配方书"道具来限制可见配方？
   - 倾向：P0 不做解锁，所有配方可见。P2 视需要再加。

2. **食物经验是否区分"种类"还是"具体道具"**？当前设计按 item_id 区分（烤兔肉和烤蘑菇独立计算次数）。是否需要按"肉类/蔬菜类"等大类区分？
   - 倾向：按 item_id 区分，简单直接。如果出现"烤兔肉/煮兔肉/炖兔肉"都算同一种导致经验衰减太快，再考虑按"食材来源"分类。

3. **战斗中使用道具**？当前设计战斗中禁止 use_item。设计案中爱丽丝 Boss 战是否有"战中吃药"的需求？
   - 倾向：P0 禁止。如果 P1 需要，再开放战斗态下 use_item 命令（但限制只能用 HH 类）。

4. **多产物配方**？当前 `result` 是单个 item_id + count。是否需要支持"合成产出多个不同道具"（如分解配方）？
   - 倾向：P0 不支持，result 只支持单道具。P2 视分解系统再扩展。
