# Oblivions 道具使用与合成系统 — 设计案

> P0 阶段核心系统设计。涵盖道具使用命令、合成命令、配方表、工作台 POI
> 与前端 UI 规范。完成后玩家可体验"捡素材→合成厨具→做饭"的交互循环。
>
> **食物经验系统与升级机制不在本设计案范围内**，留待后续单独设计。

---

## 一、设计目标

| 目标 | 实现方式 |
|------|---------|
| 让玩家能"使用"背包道具 | 新增 `obl_use_item` 命令 + 道具使用效果分发 |
| 玩家能合成新道具 | 新增 `obl_craft` 命令 + 配方表 + 工作台 POI |
| 烹饪不独立成系统 | 烹饪 = `category='food'` 的合成配方，复用 craft 命令 |
| 道具耐久机制可用 | 使用时扣减 itms，归 0 时道具消失 |
| 遵循道具数据三层分离 | 模板层不放文案，name/desc 归前端 locale（见 [DESIGN.md §2.19](../DESIGN.md#219-道具数据三层分离)） |

**核心解耦**：`use_item` 与 `craft` 是两个独立命令。食物通过 `craft` 产出，通过 `use_item` 食用。两个系统通过道具表的数据结构耦合，命令层互不依赖。

**文案分离**：本设计案新增的所有配置文件（`recipe_table.php` 等）从一开始就不放 name/desc。现有 `item_table.php` / `poi_table.php` 的 itm/desc 字段标记为 deprecated，新代码不依赖。前端通过 `item-locale.ts` / `recipe-locale.ts` / `poi-locale.ts` 查询文案。详见 [道具数据三层分离-设计案](./道具数据三层分离-设计案.md)。

## 二、核心概念

### 2.1 道具使用效果（use_effect）

道具的"使用"行为通过效果函数分发，模式与 POI 的 `obl_mechanic_*` 完全对齐：

```
item_table.use_effect = 'restore_hp'
                         ↓
obl_use_effect_restore_hp($item, &$pdata)  ← 框架自动分发
```

新增效果只需添加 `obl_use_effect_{name}()` 函数，框架自动分发。**P0 阶段实现的效果**：

| use_effect | 适用种类 | 行为 |
|-----------|---------|------|
| `restore_hp` | HH（恢复） | 恢复 itme 值的 HP |
| `restore_sp` | HS（食物） | 恢复 itme 值的 SP |
| `cure_poison` | DX（药物） | 解除中毒状态（P0 仅打日志，状态系统待后续） |

**预留扩展**：后续食物经验系统上线时，只需在 `obl_use_effect_restore_sp` 内部追加经验发放逻辑，不影响外部接口。道具表届时新增 `exp_value` 字段。

### 2.2 合成配方（Recipe）

配方是静态配置，定义"用什么素材合成什么产物"。**不含文案字段**（name/desc 由前端 `recipe-locale.ts` 提供）：

```php
'recipe_id' => [
    'category'       => 'weapon',         // weapon/armor/tool/food/material
    'workbench_lvl'  => 1,                // 所需工作台等级
    'required_tool'  => null,             // 需持有的工具 item_id（如 'frying_pan'）
    'materials'      => [
        ['item_id' => 'scrap_metal', 'count' => 3],
        ['item_id' => 'rusty_gear',  'count' => 1],
    ],
    'result'         => [
        'item_id' => 'scrap_blade',
        'count'   => 1,
    ],
]
```

### 2.3 工作台 POI

工作台是 POI 的一种，通过 `mechanic='craft'` 复用现有 POI 机制。**不含文案字段**（name/desc 由前端 `poi-locale.ts` 提供）：

```php
'workbench_basic' => [
    'searchable'      => false,           // 工作台不可搜索
    'mechanic'        => 'craft',
    'mechanic_value'  => 1,               // 工作台等级
    'mechanic_params' => ['weapon', 'tool', 'material'],  // 支持的配方分类
],
```

玩家在工作台所在格点击"合成"按钮即可触发 craft 命令。**P0 阶段工作台等级固定为 1**，等级提升留给后续猫背包升级系统。

### 2.4 烹饪 = 食物合成

烹饪不独立成系统。烹饪炉灶作为工作台 POI 的一种，`mechanic_params` 含 `'food'` 分类。烹饪配方与其他配方同表管理，仅 `category='food'` 区分。

**烹饪器具的引入动机**：高级烹饪配方 `required_tool` 字段非空（如 `'frying_pan'` 煎锅、`'sharp_knife'` 锋利菜刀）。玩家需要先合成器具，才能解锁高级料理。这创造了"找素材→做厨具→做饭"的动机链。

## 三、数据结构变更

### 3.1 `item_table.php` 扩展

每个道具模板新增以下可选字段（不填则无对应行为）：

```php
'item_id' => [
    // ─── 现有字段 ───
    'itm'  => '生锈的水管',     // deprecated: 文案将移至前端 item-locale.ts
    'itmk' => 'WP',
    'itme' => 8,
    'itms' => 20,
    'itmsk' => '',
    'itmpara' => '',
    'desc' => '...',            // deprecated: 文案将移至前端 item-locale.ts
    'tier' => 'common',
    'stack' => false,        // 现有字段：是否可堆叠（P0 未实现堆叠逻辑，声明性保留）
    'stack_limit' => 10,     // 现有字段：堆叠上限（仅 stack=true 时有意义）
    
    // ─── P0 新增字段 ───
    'use_effect'  => '',     // 使用效果名（如 'restore_hp'），空=不可使用
],
```

**关于 stack 字段**：当前 `obl_pickup_item` 的实现是"找空槽位写入"，未实现堆叠合并。即使 `stack=true`，拾取两件同类道具也会占用两个槽位。P0 阶段维持现状，合成系统的素材统计也按"每槽一件"处理。后续实现堆叠时，扩展 pickup / count_material / consume_materials 三个函数即可。

**P0 阶段需要补 use_effect 字段的道具**：

| item_id | itmk | use_effect | 说明 |
|---------|------|-----------|------|
| health_potion | HH | restore_hp | 恢复 80 HP |
| stamina_potion | HS | restore_sp | 恢复 50 SP |
| supply_pack | HH | restore_hp | 恢复 30 HP，多次使用（itms=3） |
| swamp_herb | HH | restore_hp | 恢复 20 HP（带毒性，待后续状态系统） |
| **roasted_rabbit**（新） | HS | restore_sp | 烤兔肉，恢复 30 SP |
| **grilled_mushroom**（新） | HS | restore_sp | 烤蘑菇，恢复 15 SP |
| **simple_stew**（新） | HS | restore_sp | 简易炖菜，恢复 50 SP |

新文件 `oblivions/gamedata/recipe_table.php`，结构与 `item_table.php` 对齐。**只含游戏逻辑，不含文案**（name/desc 由前端 `recipe-locale.ts` 提供）：

```php
        'required_tool' => null,

            ['item_id' => 'rusty_gear',  'count' => 1],
        ],
        'result'        => ['item_id' => 'scrap_blade', 'count' => 1],

    'craft_frying_pan' => [

    'craft_roasted_rabbit' => [
        'category'      => 'food',
        'workbench_lvl' => 1,                // 简易工作台就能烤（假设工作台带火源）
        'required_tool' => null,             // 无需器具，直接烤
        'materials'     => [
            ['item_id' => 'rabbit_meat', 'count' => 1],
        ],
```

**约定**：

- `result.item_id` 必须在 `item_table.php` 中存在
- `required_tool` 是 item_id（不是配方 ID），玩家背包中持有即可

## 四、后端命令

### 4.1 `obl_use_item` 命令

**请求**：
```
POST command.php
mode=command&command=obl_use_item&slot=3
```

**参数**：
- `slot` (int, 1~itemmaxslots) — 背包槽位号

**状态过滤**：
- 战斗状态（`action='battle'`）下禁止使用 → `obl_command_allowed_by_state` 添加白名单
- 死亡状态（`state=1` 或 `hp<=0`）下禁止使用

**Tick 推进**：**不推进**（在 `obl_command_advances_tick` 白名单中不添加此命令）

**响应**：`{}`（标准 Oblivions 命令响应）

### 4.2 `obl_craft` 命令

**请求**：
```
POST command.php
mode=command&command=obl_craft&iaid=12&recipe_id=craft_roasted_rabbit
```

**参数**：
- `iaid` (int) — 工作台 POI 实例 ID
- `recipe_id` (string) — 配方 ID

**状态过滤**：
- 战斗状态下禁止
- 死亡状态下禁止

**Tick 推进**：**不推进**

**响应**：`{}`

### 4.3 命令注册清单

需要改动的文件：

| 文件 | 改动 |
|------|------|
| `oblivions_router.php` | switch 增加 `obl_use_item` / `obl_craft` 分支 |
| `oblivions_commands.php` | 新增 `cmd_handle_obl_use_item` / `cmd_handle_obl_craft` |
| `player.func.php` 的 `obl_command_allowed_by_state` | 战斗态时这两个命令均被拒（默认即拒，无需改动；但建议显式注释） |
| `tick.func.php` 的 `obl_command_advances_tick` | 不添加这两个命令（默认即不推进，无需改动） |

## 五、后端函数规划

### 5.1 新建 `use_item.func.php`

注册到 `obl_bootstrap.php` 第 1 层（与 explore.func.php 同层）。

```
use_item.func.php
├── obl_use_item($slot, &$pdata)              ← 命令入口
├── obl_execute_use_effect($item, &$pdata)    ← 效果分发框架
├── obl_use_effect_restore_hp($item, &$pdata) ← 恢复 HP
├── obl_use_effect_restore_sp($item, &$pdata) ← 恢复 SP
├── obl_use_effect_cure_poison($item, &$pdata)← 解毒（P0 占位）
└── obl_consume_durability(&$item, $amount=1) ← 耐久扣减
```

### 5.2 新建 `craft.func.php`

注册到 `obl_bootstrap.php` 第 1 层。

```
craft.func.php
├── obl_craft($iaid, $recipe_id, &$pdata)     ← 命令入口
├── obl_get_recipe($recipe_id)                ← 配方读取（带静态缓存）
├── obl_get_recipes_for_workbench($poi_template)  ← 按工作台过滤可用配方
├── obl_count_material_in_inventory(&$pdata, $item_id)  ← 统计素材数量
├── obl_consume_materials(&$pdata, $materials) ← 扣除素材
└── obl_mechanic_craft($template, &$pdata)    ← POI 机制占位（实际合成走 obl_craft 命令）
```

**`obl_mechanic_craft` 设计**：工作台 POI 的 `mechanic='craft'` 主要用于**前端识别**——`tile_actions` API 返回 POI 时携带 mechanic 字段，前端据此显示"合成"按钮。后端搜索工作台 POI 时不需要执行任何机制（`searchable=false`），所以 `obl_mechanic_craft` 函数体留空或返回提示日志。

### 5.3 道具耐久扣减机制

耐久字段 `itms` 当前是字符串（如 `"20"`、`"3"`、`"999"`）。约定：

- 纯数字字符串 → 有限耐久，每次使用扣 1
- `"999"` 或 `"∞"` → 无限耐久，不扣减
- 耐久扣到 0 → 道具破坏（从背包移除，emit 日志）

```php
function obl_consume_durability(&$item, $amount = 1) {
    if (!isset($item['itms'])) return;
    $s = (string)$item['itms'];
    if ($s === '' || $s === '0' || $s === '∞' || $s === '999') return;  // 无限耐久
    
    $cur = (int)$s;
    $cur = max(0, $cur - $amount);
    $item['itms'] = (string)$cur;
    // 调用方根据 $cur === 0 决定是否破坏道具
}
```

**P0 阶段耐久扣减场景**：
- 消耗品使用后 itms-1，到 0 时消失（已实现于 use_item 流程）
- 武器在战斗中受击不扣耐久（P0 简化，留给后续）
- 武器损坏的"胃酸腐蚀"剧情由猫背包系统承担（后续）

### 5.4 `obl_use_item` 完整流程

```
1. 参数校验：slot 在 1~itemmaxslots 范围
2. 读取槽位道具，空槽 → emit 'use_item.empty_slot'，return
3. 读取道具模板（item_table），无 use_effect → emit 'use_item.not_usable'，return
4. 调用 obl_execute_use_effect($item, $pdata)
   └─ 分发到 obl_use_effect_{use_effect}() 函数
5. 扣减道具耐久（itms-1）
6. 若耐久归 0：
   - 清空该槽位
   - emit 'use_item.consumed'
7. 否则保留道具（耐久显示更新）
8. obl_save_player($pdata)
```

### 5.5 `obl_use_effect_restore_sp` 完整流程

```
1. 读取 $item['itme']（恢复量）
2. $pdata['sp'] = min($pdata['sp'] + itme, $pdata['msp'])
3. emit 'use_item.restore_sp'
```

**预留**：后续食物经验系统上线时，在此函数末尾追加 `obl_gain_food_exp(...)` 调用。届时道具表新增 `exp_value` 字段，`oblpara` 新增 `food_exp` 记录。

### 5.6 `obl_craft` 完整流程

```
1. 参数校验：iaid 与 recipe_id 非空
2. 读取工作台 POI 实例（bra_oblmappoi）
3. 位置检查：工作台必须在玩家当前格
4. 读取 POI 模板，验证 mechanic='craft'
5. 读取配方模板（recipe_table.php）
6. 配方过滤：
   - 配方 workbench_lvl ≤ 工作台 mechanic_value
   - 配方 category ∈ 工作台 mechanic_params
7. required_tool 检查：玩家背包中是否持有该 item_id
8. 素材检查：遍历 materials，每个 item_id 的库存 ≥ count
   └─ obl_count_material_in_inventory(&$pdata, $item_id) 实现：
      遍历 itempara[1..maxslots]，累加 itmid === item_id 的道具数量
      （P0 每槽一件，统计结果为匹配槽位数；后续支持堆叠时改为按 itms 累加）
9. 背包空位检查：result.count > 0 时需有空槽位
10. 扣除素材：obl_consume_materials(&$pdata, $materials)
    └─ 遍历 materials，按 item_id 扣减槽位（先扣完后扣前，可能跨多槽）
    └─ 槽位道具数量为 0 时清空
11. 添加产物：在空槽位写入 result 道具
12. emit 'craft.success' / 失败时 emit 对应错误日志
13. obl_save_player($pdata)
```

## 六、前端 UI

### 6.1 道具使用按钮

**改动文件**：`vex-vue/src/components/inventory/InventoryList.vue`

每个道具槽位右侧新增"使用"按钮，仅当道具可使用时显示：

```vue
<button
  v-if="item && isUsable(item)"
  class="use-btn"
  @click="onUse(slot)"
>使用</button>
```

**`isUsable(item)` 判定**：道具的 `itmk` 为 HH/HS/DX 时可使用。或者后端在 `player_inventory` API 中返回 `usable: bool` 字段（推荐）。

**`onUse(slot)` 流程**：
1. `commandQueue.execute({ command: 'obl_use_item', slot: String(slot) })`
2. 成功后 `dataManager.invalidate('player_inventory')` + `loadInventory()`
3. `dataManager.invalidate('player_info')` + `loadPlayerInfo()`（HP/SP 可能变化）
4. 日志通过 `logStore.refreshLog()` 自动刷新

```typescript
  function closeCraftModal() { ... }

  return { modalOpen, workbenchIaid, workbenchMeta, recipes, inventorySnapshot,
```

### 6.3 工作台入口

**改动文件**：`vex-vue/src/components/actions/TileActionBar.vue`

`TileActionBar` 渲染 POI 列表时，根据 POI 的 `mechanic` 字段决定按钮：

```vue
<button v-if="poi.mechanic === 'craft'" @click="onCraft(poi)">
  合成
</button>
<button v-else-if="poi.searchable" @click="onSearch(poi)">
  搜索
```

**`onCraft(poi)` 流程**：
1. 调用 `craftStore.openCraftModal(poi.iaid, { level: poi.mechanic_value, categories: poi.mechanic_params })`
2. `craftStore` 拉取配方列表（GET `/api_v2.php?action=craft_recipes&iaid=...`，或前端从静态配置加载）

### 6.4 配方列表来源（两种方案）

**A 方案（推荐）**：后端新增 `craft_recipes` API
- 请求：`GET api_v2.php?action=craft_recipes&iaid=xxx`
- 响应：按工作台等级和分类过滤后的配方列表 + 玩家当前持有素材快照
- 优点：素材校验在后端，避免前端配置不同步

**B 方案**：前端静态加载配方表
- 在 `vex-vue/src/data/recipe-table.ts` 镜像后端配方表
- 优点：无网络请求
- 缺点：配方表更新需要前后端同步

P0 选 **A 方案**，理由：配方表会随开发迭代频繁变更，后端单源更稳。

### 6.5 新增 API 端点

**`craft_recipes`** — 获取工作台可用配方

- **请求**：`GET api_v2.php?action=craft_recipes&iaid=123`
- **响应**（不含文案，前端通过 `recipe_id`/`item_id`/`poi_id` 查 locale 渲染）：
```json
{
  "status": "success",
  "data": {
    "workbench": {
      "poi_id": "workbench_basic",
      "level": 1,
      "categories": ["weapon", "tool", "material", "food"]
    },
    "recipes": [
      {
        "recipe_id": "craft_roasted_rabbit",
        "category": "food",
        "required_tool": null,
        "materials": [
          {"item_id": "rabbit_meat", "count": 1, "have": 1, "enough": true}
        ],
        "result": {"item_id": "roasted_rabbit", "count": 1},
        "craftable": true
      }
    ]
  }
}
```

`materials[].have` 与 `craftable` 字段由后端结合玩家当前背包计算，前端直接渲染。文案（工作台名称、配方名称/描述、素材名称）由前端通过 `poi_id`/`recipe_id`/`item_id` 查 `poi-locale.ts`/`recipe-locale.ts`/`item-locale.ts` 获取。

## 十一、预留扩展点

### 11.1 食物经验系统（后续单独设计）

`obl_use_effect_restore_sp` 函数末尾预留经验发放挂载点。届时：
- 道具表新增 `exp_value` 字段
- `oblpara` 新增 `food_exp` 记录（`{ item_id: eat_count }`）
- 新建 `obl_gain_food_exp` / `obl_apply_level_up` 函数
- 升级表 `level_table.php` 配置经验曲线与属性成长

### 11.2 猫背包系统的接口预留

猫背包的"胃酸腐蚀"机制将复用 `obl_consume_durability` 函数——道具在猫肚子里每隔一段时间扣减耐久。

### 11.3 道具堆叠

当前 `obl_pickup_item` 未实现堆叠合并（即使 `stack=true` 也每槽一件）。后续实现堆叠时，扩展三个函数：
- `obl_pickup_item` — 同类道具合并到已有槽位
- `obl_count_material_in_inventory` — 按 `itms` 累加而非按槽位计数
- `obl_consume_materials` — 按数量优先扣减最满的槽位

### 11.4 工作台升级

工作台 POI 的 `mechanic_value`（等级）当前固定。后续猫背包的"便携工作站"升级可以让玩家随身携带等级 2/3 的工作台，只需在 `obl_craft` 入口允许 `iaid=0`（猫肚子里的工作台）+ 玩家 oblpara 中读取便携工作台等级。

### 11.5 Buff 系统

`use_effect` 框架可扩展 `buff_temp` 效果，写入 `oblpara.buffs` 数组（带 expire_tick）。P0 阶段不实现，但框架已支持。
