# 固定八阶段战斗动画播放链设计案

## 一、目标

为每次攻击建立统一、严格、可取消的动画播放链。配置者只需要指定八个固定阶段播放哪些动画；未配置阶段自动跳过，不开放任意轨道、毫秒偏移和依赖图。

八个阶段：

1. `attackBefore`：攻击动作前效果。
2. `attackMain`：攻击者主体动作。
3. `attackConcurrent`：与攻击主体动作同时播放的效果。
4. `attackAfter`：攻击主体动作后的传递效果，例如投射物飞行。
5. `hitBefore`：受击动作前效果。
6. `hitMain`：目标受击动作。
7. `hitConcurrent`：与受击动作同时播放的命中特效。
8. `hitAfter`：受击结束后的状态反馈。

## 二、固定执行语义

同一阶段内的多个动画并行播放，阶段之间由执行器统一等待。空阶段立即完成。

攻击链只提供两种命中触发模式：

- `attack-impact`：近战、冲撞。攻击主体到达 `impact` 节点时启动受击链；攻击者回正与受击可以并行。
- `attack-after`：投掷、弹道。先等待攻击主体和 `attackAfter` 的投射物播放完成，再启动受击链。

近战执行顺序：

```text
attackBefore
  -> attackMain + attackConcurrent
       -> impact: hitBefore -> hitMain + hitConcurrent -> hitAfter
  -> 等待攻击与受击全部完成
  -> attackAfter
```

远程执行顺序：

```text
attackBefore
  -> attackMain + attackConcurrent
  -> attackAfter
  -> hitBefore
  -> hitMain + hitConcurrent
  -> hitAfter
```

## 三、配置模型

```ts
interface BattleAnimationChainSpec {
  hitTrigger: 'attack-impact' | 'attack-after';
  attackBefore: readonly BattleAnimationCue[];
  attackMain: BattleAnimationCue | null;
  attackConcurrent: readonly BattleAnimationCue[];
  attackAfter: readonly BattleAnimationCue[];
  hitBefore: readonly BattleAnimationCue[];
  hitMain: BattleAnimationCue | null;
  hitConcurrent: readonly BattleAnimationCue[];
  hitAfter: readonly BattleAnimationCue[];
}
```

首期内置 cue：

- `actor-melee`：攻击者近战主体动作。
- `actor-ranged`：攻击者投掷/远程主体动作。
- `projectile-delivery`：播放 action 中的投射物 delivery。
- `target-hit`：所有真实掉血目标并行播放受击动作。
- `unarmed-hit-popup`：空手攻击的真实掉血目标并行弹出 `on_hit_4.png`，配置在 `hitConcurrent`。
- `explosion-delivery`：播放 action 中的爆炸 delivery。

当前没有确定素材的阶段保持空数组，不创建临时视觉占位。

## 四、框架改造

### BattleDirector

每个 `DirectedActionV2` 只生成一个 `action_choreography` step。`action_delivery` 仍是后端事实事件和 `DirectedActionV2.deliveries` 的组成部分，但不再被拆成独立前端播放步骤。

这消除当前“先逐个播放 delivery，再播放 action animation”的错误顺序，也避免 projectile delivery 自己重复触发一次攻击者动作。

### 动画规格

`action-specs.ts` 从单一近战时长表升级为固定八阶段规格解析器。首期按动作语义选择预设：

- `melee_hit`：`attack-impact`，主体为 `actor-melee`，受击为 `target-hit`。
- `projectile` 或存在 projectile delivery：`attack-after`，主体为 `actor-ranged`，后置为 `projectile-delivery`。
- `area_burst`：远程主体，在 impact 后并行触发多个目标受击。
- 存在 explosion delivery：放入 `hitConcurrent`。

### Executor

新增单一 `playActionChoreography()`。它负责：

- 阶段跳过和阶段内并行。
- 获取 Actor presentation lease。
- 等待攻击主体的 `impact` cue。
- 将所有 AnimationHandle 纳入同一取消域。
- 场景替换、超时或战斗会话终止时统一取消。

ActorRuntime 继续负责单个 Actor 动作，不感知八阶段业务结构。

## 五、边界

- `move`、`escape` 仍由动作 executor 的专用路径执行，不伪装成攻击或受击。
- `death`、`escaped` 继续由 combatant cleared terminal step 执行，优先级高于普通 `hitAfter`。
- `combatant_joined` 是参战状态事实，不播放缩放弹跳；敌人已经由地图实体层呈现，避免加入提示被误认成提前受击。
- `hitAfter` 只表现后端真实存在的状态，不凭攻击类型伪造眩晕、燃烧等状态。
- 本期不新增纸片素材、音效、震屏和 hit-stop，只建立可承载它们的阶段结构。
- 后端只描述 action、delivery、effect 和 status 事实，不下发前端动画毫秒数。

## 六、自检结论

1. 配置复杂度固定为八个槽位，空槽无需配置，符合当前项目规模。
2. `attackConcurrent` 和 `hitConcurrent` 由执行器固定并行，不需要配置依赖关系。
3. 两种 hit trigger 足以覆盖现有近战与投掷流程；没有引入通用时间图。
4. `impact` 是唯一需要保留的同步点，当前 ActorRuntime 已提供对应 cue。
5. Director 收敛为每个 action 一个播放步骤后，投射物、爆炸、攻击动作和受击反应归属清晰。
6. 旧行为可映射到新阶段，不需要后端协议或数据迁移。

## 七、验收

1. 空手攻击：攻击者碰撞到 impact 时，目标开始受击；两者结束后进入下一动作。
2. 投掷攻击：投掷动作结束后播放投射物，投射物到达后同时启动爆炸与目标受击。
3. 无素材阶段不会创建 DOM、不会增加固定延迟。
4. 多目标伤害的目标受击动作并行播放。
5. 同一 action 在 PlaybackPlan 中只有一个 `action_choreography` step。
6. 场景替换和 step timeout 能取消该 action 的全部 Actor 与 overlay 动画。
