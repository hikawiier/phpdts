# 道具使用与装备系统-设计案

> 补完当前道具模板内所有道具的使用效果与装备效果，并实现"道具使用"与"穿上/卸下装备"两个核心功能的完整闭环。
>
> 本案基于 F-1（槽位背包）、F-3（使用效果分发器）、G-1（技能三种生命周期）三个已落地框架的扩展，不破坏既有契约。

---

## 一、问题与目标

### 1.1 现状审计

| 维度 | 现状 | 缺口 |
|------|------|------|
| 道具使用入口 | `item.use` 命令 + `item_use()` + `item_execute_use_effect()` 分发器已实现 | **4 个 use_effect 函数全部未注册**：restore_hp / restore_sp / cure_bs / gain_resistance，调用时仅 emit `use_item.effect_not_registered` |
| 装备槽位 | 数据层 7 槽字段齐全（wep/wep2/arb/arh/arf/ara/art），`obl_format_playerdata` / `obl_save_player` 已编解码 | **没有任何穿上/卸下入口函数与命令**；玩家无法把背包道具装备到槽位 |
| 装备技能注入 | G-1 框架已实现 `skill_inject_equipment` + `skill_equipment_grant_matches`，配置驱动（`equipment_grant`） | 当前仅 `throw` 一个装备技能定义；机制健全，无需改动 |
| 装备属性加成 | `att/def` 字段直接存储在 `oblplayers`，未区分基础值与加成值 | **装备的 `itme` 字段对玩家属性无影响**；装备武器不增 att、装备防具不增 def |
| 前端 UI | `InventoryList.vue` 有"使用/丢弃"按钮；`EquipmentList.vue` 只读展示 7 槽 | **`InventoryList` 无"装备"按钮**；**`EquipmentList` 无"卸下"按钮**；`inventory.ts` 缺 `handleEquip/handleUnequip` |
| 道具模板 | 60+ 道具已定义 `tags`、`use_effect`、`tool_level` | `mystery_box` 应可使用（打开获得随机物品），当前 `use_effect=''` |

### 1.2 设计目标

| 目标 | 实现方式 |
|------|---------|
| 道具使用真实生效 | 实现 4 个 `item_use_effect_*` 函数，让 bread / mineral_water / health_potion / antidote / bandage 等全部生效 |
| 穿上装备 | 新增 `item.equip` 命令 + `item_equip()` 函数，支持自动槽位判定 + 装备交换 |
| 卸下装备 | 新增 `item.unequip` 命令 + `item_unequip()` 函数，背包满时阻止 |
| 装备属性加成 | 新增 `player_get_effective_att/def` 计算函数，战斗系统改读 effective 值 |
| 补完道具效果 | `mystery_box` 新增 `open_gift_box` use_effect；其余工具类道具保持不使用（由 POI 交互消费） |
| 前端闭环 | `InventoryList` 增加"装备"按钮；`EquipmentList` 增加"卸下"按钮；store 增加 handle 方法 |

### 1.3 范围边界

**在本案范围内**：
- 4 个 `item_use_effect_*` 函数实现（restore_hp / restore_sp / cure_bs / gain_resistance）
- 1 个新 use_effect 函数 `open_gift_box`（神秘礼盒）
- `item_equip` / `item_unequip` / `item_swap_weapon` 函数 + 命令 + 命令合约
- 装备属性加成计算函数 `player_get_effective_att/def`（副武器无加成）
- 副武器交换机制（wep/wep2 全字段交换）
- 装备槽位字段重命名：arb→db / arh→dh / ara→da / arf→df / art→ac（DB + PHP + TS 全栈）
- 战斗系统读取 effective 属性的接入点（最小改动）
- 前端 inventory.ts / InventoryList.vue / EquipmentList.vue 闭环 + 槽位中文显示
- `mystery_box` 道具模板补充 `tag_usable` + `use_effect='open_gift_box'`

**不在本案范围内**（归属其他系统）：
- Body Status 系统的具体状态枚举与Tick机制 → 健康系统独立设计案（cure_bs 仅实现"清除全部 Body Status Tag"的简化版本，未来由健康系统注册更精细的解除逻辑）
- 抗性系统的具体抗性类型与跃迁规则 → 被动技能系统独立设计案（gain_resistance 仅 emit 事件供未来订阅）
- 食物经验系统的经验发放规则 → 食物经验系统独立设计案（restore_sp 仅恢复 SP，经验发放由 `use_item.success` 事件订阅）
- 元素口袋、绳索、开锁器等场景道具的使用 → POI 交互系统独立设计案
- 装备耐久损耗机制 → 战斗系统独立设计案
- 装备稀有度/镶嵌孔等扩展属性 → 未规划
- 数据迁移 → Oblivions 模式建表策略为 DROP IF EXISTS + CREATE，无迁移需求

## 二、核心概念

### 2.1 use_effect 注册器模式（既有 F-3 框架）

F-3 框架是纯分发器：`item_execute_use_effect($item, &$pdata)` 根据 `item_table[item_id].use_effect` 调用 `item_use_effect_{name}()` 函数。框架本身不预定义任何效果。

本案在 F-3 框架下注册 5 个效果函数：

| use_effect 名称 | 归属系统 | 行为 | 适用道具 |
|----------------|---------|------|---------|
| `restore_hp` | 物品系统（本案） | 恢复 HP（基于 itme），不超过 mhp | bread / health_potion / supply_pack / soda_crackers / cooked_meat_chunk / cured_meat / concentrated_soup / orange_pill / white_pill / nano_medkit |
| `restore_sp` | 物品系统（本案） | 恢复 SP（基于 itme），不超过 msp | mineral_water / stamina_potion / roasted_rabbit / simple_stew / wild_mushroom / berries / cola / herbal_tea |
| `cure_bs` | 物品系统（本案，简化版） | 清除全部 Body Status Tag（解毒/止痛/绷带）；emit `cure_bs.success` 供未来健康系统订阅 | antidote / bandage / whiskey / painkiller |
| `gain_resistance` | 物品系统（本案，占位） | emit `gain_resistance.triggered` 事件，供未来被动技能系统订阅；当前无副作用 | rabbit_meat_raw / raw_meat_chunk |
| `open_gift_box` | 物品系统（本案） | 随机生成 1 件道具落入背包（itm0 → 自动整理）；消耗 1 个 mystery_box | mystery_box |

**实现细节注释**（对照 F-3 框架代码 `item.use.func.php:110`）：
- F-3 分发器调用形如 `$func_name($item, $pdata)`。PHP 动态调用时，被调函数必须显式声明 `&$pdata` 才能修改玩家数据。本案 5 个函数签名统一为 `item_use_effect_{name}($item, &$pdata)`。
- `$item` 是道具实例（itempara 七字段数组，含 itmid/itmk/itme/itms/itmsk/itmpara/itm），按值传递（F-3 不要求效果函数修改道具实例；itms 扣减由 `item_consume_itms` 统一处理）。
- `itms` 扣减发生在 use_effect 之后（F-3 流程第 4 步），效果函数内部不应自行扣 itms。
- HP/SP 字段位于 `$pdata['hp']` / `$pdata['mhp']` / `$pdata['sp']` / `$pdata['msp']`（参见 `player.func.php` `obl_format_playerdata`）。
- `oblpara.body_status` 字段当前未实现（仅见于归档设计案《第一幕-扫雷与死亡捡尸机制》），`cure_bs` 简化版做防御性检查：存在则清空，不存在则仅 emit 事件。

**设计理由**：
- 4 个原计划函数（restore_hp/restore_sp/cure_bs/gain_resistance）归属系统（食物经验/健康/被动技能）尚未实现，但 use_effect 框架已要求这些函数存在。本案作为"最小可玩实现"先注册这些函数，未来归属系统可通过 `function_exists` 检测接管或替换。
- `cure_bs` 的简化版（清除全部 Body Status Tag）避免依赖未实现的健康系统，同时保证解毒剂/绷带道具有效。
- `gain_resistance` 仅 emit 事件，未来被动技能系统订阅该事件实现抗性跃迁。生肉有"轻微毒性"的设计通过 `tag_raw_food` 表达，不在此处实现。玩家使用生肉后 itms 会被 F-3 扣减，这是"占位但有道具消耗语义"的合理设计——未来抗性系统订阅 `gain_resistance.triggered` 事件后效果自动生效。
- `open_gift_box` 是新增效果，让 mystery_box 有实际价值。

### 2.2 装备槽位映射

7 个装备槽位的语义与 itmk 映射（字段名采用语义化前缀：`wep*` = 武器、`d*` = 防具 defense、`ac*` = 饰品 accessory）：

| 槽位字段 | 前端 label（中文） | 接受的 itmk | 装备效果（itme 影响） |
|---------|------------------|------------|---------------------|
| `wep` | 主武器 | WP / WK / WG / WD / WF / WC | att += itme（战斗主用） |
| `wep2` | 副武器 | WP / WK / WG / WD / WF / WC | **无属性加成**（仅作技能载体 + 可与主武器交换） |
| `db` | 护甲 | AR | def += itme |
| `dh` | 头部防具 | AH | def += itme |
| `da` | 手部防具 | AA | def += itme |
| `df` | 足部防具 | AF | def += itme |
| `ac` | 饰品 | 任意 itmk | 无属性加成（保留槽位） |

**字段顺序约定**：上表行序对齐 `player.func.php` 装备字段顺序（`wep / wep2 / db / dh / da / df / ac`），与 `equip_para_keys`、`obl_save_player.update_fields`、`obl_state_handle_player_info.equipment` 三处保持一致，避免顺序漂移引发字段错位。

**字段名语义**：
- `db` = Defense Body（护甲），原 `arb`
- `dh` = Defense Head（头部防具），原 `arh`
- `da` = Defense Arm（手部防具），原 `ara`（AA 类道具语义从"配件"修订为"手部防具"）
- `df` = Defense Foot（足部防具），原 `arf`
- `ac` = Accessory（饰品），原 `art`（原"其他"槽位语义化命名为"饰品"）

**设计理由**：
- **副武器无属性加成**：副武器作为"备用武器"而非"主副双武器流"设计。副武器槽位用于：(1) 携带不同射程/类型的备用武器供主武器交换；(2) 作为装备技能的载体（如 `throw` 技能注入）。战斗系统仅读取主武器的 att 加成，避免双武器流导致 att 膨胀。
- **字段名语义化**：原 `arb/arh/ara/arf/art` 字段名仅含类型前缀无语义，且 `ara`（原"配件"）与"手部防具"语义不符。重命名为 `db/dh/da/df/ac` 后字段名直接表达槽位语义，降低认知成本。
- **AA 语义修订**：AA itmk 在前端 locale 仍显示为"饰品"（itmk 类别名独立于槽位标签），但装备槽位为 `da`（手部防具）。这是历史 itmk 分类与槽位语义的合理对齐——AA 类道具本质是"手上佩戴物"，既可视为手部防具也可视为饰品，本案统一以槽位语义为准。
- **`ac` 槽位保留**：原 `art` 重命名为 `ac`（饰品），保留为未来扩展（如套装效果、特殊饰品技能等），本案不实现具体属性加成。

### 2.3 装备穿卸流程

**穿上装备** `item_equip($slot, $equip_slot, &$pdata)`：

```
1. 读取背包槽位 $slot 的道具实例
2. 检查 tag_equippable → 不含 emit equip.not_equippable
3. 检查耐久 itms='0' → emit equip.broken
4. 决定目标装备槽位 $equip_slot：
   - 若调用方传入 $equip_slot，校验该槽位接受道具的 itmk
   - 若未传入，根据 itmk 自动映射（WP/WK/WG/WD/WF/WC → wep；AR → db；AH → dh；AA → da；AF → df）
5. 检查目标槽位是否已有装备：
   - 空 → 直接装入
   - 已有装备 → 检查背包是否有空位容纳旧装备：
     - 无空位 → emit equip.bag_full 阻止
     - 有空位 → 旧装备放入背包空位，新装备装入槽位
6. 写入装备字段（{slot}id / {slot} / {slot}k / {slot}e / {slot}s / {slot}sk / {slot}para）
7. 清空背包槽位（unset itempara[$slot]）
8. 立即重建装备技能：先 `skill_strip_temporary($skillpara)` 剥离所有 equipment 类技能，再 `skill_inject_equipment($skillpara, $pdata)` 按新装备字段重新注入（流程见 §2.3 关键决策）
9. emit equip.success（传 item_id、equip_slot）
```

**卸下装备** `item_unequip($equip_slot, &$pdata)`：

```
1. 读取装备槽位 $equip_slot
2. 检查槽位是否为空 → 空 emit unequip.empty_slot
3. 检查背包是否有空位 → 无空位 emit unequip.bag_full 阻止
4. 将装备字段还原为道具实例（itempara 七字段格式）
5. 调用 obl_add_item_to_inventory 放入背包（含堆叠合并）
6. 清空装备字段（{slot}id='' / {slot}='' / {slot}k='' / {slot}e=0 / {slot}s='0' / {slot}sk='' / {slot}para=[]）
7. 立即重建装备技能：先 `skill_strip_temporary($skillpara)` 剥离所有 equipment 类技能，再 `skill_inject_equipment($skillpara, $pdata)` 按卸下后的装备字段重新注入（流程见 §2.3 关键决策）
8. emit unequip.success（传 item_id、equip_slot）
```

**关键决策**：
- **装备交换**：穿上时如目标槽位已有装备，自动卸下放入背包，避免玩家"先卸下再穿上"的两步操作。背包满时阻止交换。
- **立即重建技能**：穿卸后立即调用 `skill_inject_equipment`，避免下次 format 才生效的延迟。`skill_inject_equipment` 是幂等的（已注入的技能不会被重复注入）。
- **不自动剥离旧装备技能**：`skill_inject_equipment` 只注入匹配的技能，不剥离不再匹配的技能。需要在调用前手动剥离，或改为先 `skill_strip_temporary` + 再 `skill_inject_equipment`。本案采用后者：穿卸后先剥离所有 equipment 类技能再重新注入。
- **副武器装备路径**：副武器 `wep2` 槽位的穿上/卸下流程与主武器一致，仅通过 `$equip_slot='wep2'` 显式指定。副武器装备后不提供 att 加成（见 §2.4），但仍会触发装备技能注入（如 throw 技能 slots 配置含 `wep2`）。

### 2.4 装备属性加成

**计算函数**：

```php
function player_get_effective_att($pdata): int {
    $base = (int)($pdata['att'] ?? 0);
    $wep = (int)($pdata['wepe'] ?? 0);
    // 副武器 wep2 不提供 att 加成（仅作技能载体 + 可与主武器交换）
    return $base + $wep;
}

function player_get_effective_def($pdata): int {
    $base = (int)($pdata['def'] ?? 0);
    $db = (int)($pdata['dbe'] ?? 0);
    $dh = (int)($pdata['dhe'] ?? 0);
    $da = (int)($pdata['dae'] ?? 0);
    $df = (int)($pdata['dfe'] ?? 0);
    return $base + $db + $dh + $da + $df;
}
```

**接入点**：
- 战斗系统：所有读取 att/def 的位置改为 `player_get_effective_att($pdata)` / `player_get_effective_def($pdata)`。本案实战 grep `$pdata\['att'\]` / `$pdata\['def'\]` 在 `oblivions/include/game/` 下仅命中 `item.equip.func.php` 自身（计算函数内部）；战斗系统的实际读取位置在 `oblivions/include/game/battle/battle.calc.php` 第 113、140 行，变量名是 `$actor_data['att']` 与 `$target_data['def']`（不是 `$pdata`），需替换这两处。
- API 投影：`obl_state_handle_player_info` 增加 `effective_att` / `effective_def` 字段（保留原 `att` / `def` 作为基础值）
- 不修改 `att/def` 字段的持久化语义（仍是基础值）
- 不修改 NPC/敌人的 att/def 投影：`obl_state_simplify_enemy_data` 仍投影基础值；NPC 无装备，effective 值 = 基础值，无新增投影意义

**设计理由**：
- 不引入 buff 系统：buff 由 H-1（实例化效果生命周期）独立处理，本案不混入
- 不持久化 effective 值：每次计算实时得出，避免装备穿卸后忘记刷新
- **副武器无属性加成**：与 §2.2 槽位映射决策对齐。副武器作为"备用武器 + 技能载体"存在，战斗时仅主武器计入 att。玩家若想用副武器的属性，需通过 `item.swap_weapon` 命令（见 §2.5）将副武器切到主武器槽位。
- **战斗只读主武器**：`obl_calc_damage` / `obl_calc_damage_value` 通过 `player_get_effective_att` 读取属性，函数内部只取 `wepe`，副武器 `wep2e` 完全不影响伤害计算。

### 2.5 副武器交换机制

**核心函数** `item_swap_weapon(&$pdata)`：

```
1. 检查 wep 和 wep2 槽位是否至少有一个非空：
   - 两者均空 → emit swap_weapon.both_empty 阻止
2. 交换 wep 和 wep2 的全部 7 个装备字段：
   - {wep/wep2}id、{wep/wep2}、{wep/wep2}k、{wep/wep2}e、{wep/wep2}s、{wep/wep2}sk、{wep/wep2}para
3. 立即重建装备技能：先 skill_strip_temporary($skillpara) 剥离所有 equipment 类技能，再 skill_inject_equipment($skillpara, $pdata) 按交换后的装备字段重新注入
4. emit swap_weapon.success（传 wep_item_id、wep2_item_id）
```

**设计意图**：
- **战斗中切换武器**：玩家在不同射程/伤害类型的武器间切换（如近战切远程投掷），无需经过"卸下→放下背包→穿上"的三步操作。
- **不推进 tick**：交换是装备管理动作，不消耗时间。
- **技能保持有效**：`throw` 技能的 `equipment_grant.slots` 配置为 `['wep', 'wep2']`（见 `skill_definition_config.php`），交换后技能仍匹配。其他仅配置 `wep` 的技能会因主武器变化而重新评估（剥离 + 重注入流程处理）。
- **属性加成自动切换**：交换后，原副武器若进入 wep 槽位，其 itme 自动计入 effective_att；原主武器进入 wep2 槽位后不再提供 att 加成。无需额外处理。

**边界情况**：
- wep 空 + wep2 非空：交换后 wep2 装备进入 wep，wep2 变空（等同"装备副武器到主武器槽"）
- wep 非空 + wep2 空：交换后 wep 装备进入 wep2，wep 变空（等同"卸下主武器到副武器槽"）
- 两者均空：emit `swap_weapon.both_empty` 阻止，无副作用

**命令合约**：

```php
'item.swap_weapon' => array(
    'legacy' => 'obl_swap_weapon',
    'ui_mode' => 'explore',
    'allowed_actions' => array('', null),
    'advances_tick' => false,
    'itm0_allowed' => false,
    'required_capabilities' => array('free_mutation'),
    'payload_schema' => array(),
    'refresh' => array('player_info', 'player_inventory', 'obl_log'),
),
```

### 4.3 新框架 F-5：装备穿卸与属性加成

**设计意图**：装备系统是物品系统的衍生层。基于 F-1 槽位背包协议实现穿上/卸下流程，基于 G-1 装备技能注入机制联动技能刷新。属性加成采用"基础值 + 装备加成"的纯函数计算模型，不引入 buff 系统（buff 由 H-1 独立处理）。装备穿卸是原子操作，背包满时阻止。副武器作为"备用武器 + 技能载体"存在，不提供属性加成，可通过 `item.swap_weapon` 与主武器交换。

**代码锚点**：`oblivions/include/game/item/item.equip.func.php`（穿上/卸下流程、槽位映射、属性加成计算、副武器交换）

**边界案例**：
- 装备交换：穿上时目标槽位已有装备 → 自动卸下放入背包；背包满阻止
- 装备技能刷新：穿卸/交换后立即 `skill_strip_temporary` + `skill_inject_equipment`，避免延迟
- **副武器无属性加成**：`player_get_effective_att` 只取 `wepe`，副武器 `wep2e` 不计入 att
- **副武器交换**：`item_swap_weapon` 交换 wep/wep2 全部 7 个字段；wep/wep2 均空时阻止
- 装备耐久为 0 时阻止穿上（emit equip.broken）
- `ac` 槽位无属性加成，保留为未来扩展

### 5.1 新增命令合约

```php

    'ui_mode' => 'explore',
    'allowed_actions' => array('', null),
    'advances_tick' => false,
    'itm0_allowed' => true,
    'required_capabilities' => array('free_mutation'),

    'itm0_allowed' => false,

    'refresh' => array('player_info', 'player_inventory', 'obl_log'),
```

**设计决策**：
- `item.equip` 不允许 itm0_pending：穿上装备需要从普通槽位（1~maxslots）取道具，itm0 必须先整理
- `item.unequip` 允许 itm0_pending：卸下装备可能产生 itm0（如果背包满，但本案阻止背包满卸下，所以实际不会产生 itm0；保留 `itm0_allowed=true` 是防御性配置）
- `equip_slot` 可选参数：玩家可显式指定装备到 wep 或 wep2（双武器选择）；不传时根据 itmk 自动决定
- `item.swap_weapon` 不需要 payload：交换逻辑只依赖玩家当前 wep/wep2 状态，无外部参数。`itm0_allowed=false` 防御性配置（交换不涉及背包）。

### 6.1 `inventory.ts` store 新增方法

入参签名、错误处理、刷新策略与现有 `handleUseItem` / `handleDiscard` 完全对齐：
- `try/catch` 包装捕获网络异常
- `debugBus.emit` 触发 trigger/error 调试事件
- payload 条件展开（避免发送 `equip_slot: undefined`）
- 失败 fallback 链：`result.message || result.error || 默认文案`
- 失败时 `isHtml: !!result.messageIsHtml` 透传结构化反馈
- 合约 refresh 配置：`['player_info', 'player_inventory', 'obl_log']`，前端显式 invalidate 前两者

```typescript
async function handleEquip(slot: number, equipSlot?: string): Promise<void> {
  debugBus.emit('action', 'equip:trigger', { slot, equipSlot });
  try {
    const result = await commandQueue.execute({
      command: 'item.equip',
      payload: { slot: Number(slot), ...(equipSlot ? { equip_slot: equipSlot } : {}) },
    });
    if (!result.success) {
      dataManager.broadcast('ui:toast', {
        type: 'error',
        msg: result.message || result.error || '装备失败',
        isHtml: !!result.messageIsHtml,
      });
      return;
    }
    dataManager.invalidate('player_inventory');
    dataManager.invalidate('player_info');
    dataManager.broadcast('game:action-completed');
  } catch (e) {
    debugBus.emit('error', 'equip:error', {
      error: e instanceof Error ? e.message : String(e),
    });
    dataManager.broadcast('ui:toast', {
      type: 'error',
      msg: '装备失败：' + (e instanceof Error ? e.message : String(e)),
    });
  }
}
```

`onSwapWeapon()` 转发到 `inventoryStore.handleSwapWeapon()`。交换按钮位于副武器槽位行，提示玩家"主副武器互换"语义。视觉上建议使用不同样式（如 `term-btn swap`）与"卸下"按钮区分。

## 八、风险与边界

### 8.1 已知风险

1. **战斗系统接入点分散**：`player_get_effective_att/def` 需要在战斗系统多个位置替换原 att/def 读取。漏改位置会导致属性计算不一致。
   - **缓解**：实战 grep 显示战斗系统实际读取位置集中在 `oblivions/include/game/battle/battle.calc.php` 第 113、140 行（`obl_calc_damage` / `obl_calc_damage_value`），变量名为 `$actor_data['att']` 与 `$target_data['def']`。其他 att/def 出现位置（player.func.php 初始化、init.func.php 配置、state_handlers.php 第 289-290 行投影与第 675-676 行 NPC 投影）不属于战斗读取，不替换。

2. **cure_bs 简化版的兼容性**：本案实现的 `cure_bs` 是"清除全部 Body Status Tag"的简化版本，未来健康系统实现后需要替换为更精细的"按 Tag 解除"逻辑。
   - **缓解**：在函数注释中明确标记为"简化版"，并通过 emit `cure_bs.success` 事件让未来健康系统订阅接管。

3. **mystery_box 战利品表配置偏强**：如果配置不当，玩家可能通过刷 mystery_box 获得过量稀有装备。
   - **缓解**：本案配置的 weight 偏向常见物资，稀有装备权重低；未来可通过游戏经济系统调整。

4. **字段重命名遗漏**：5 个槽位字段（arb/arh/ara/arf/art → db/dh/da/df/ac）涉及 PHP 后端 + 前端 TS + DB schema 多处引用，遗漏会导致字段未定义或 null 值。
   - **缓解**：使用 grep 全面扫描旧字段名（`\barb\b` / `\barh\b` / `\bara\b` / `\barf\b` / `\bart\b`），逐处替换；运行 PHP `-l` 语法检查 + `vue-tsc` 类型检查 + 测试房间 fixture 验证。

5. **副武器属性显示与实际不符**：副武器 itme 字段在前端显示原值，但实际不计入 effective_att，玩家可能困惑。
   - **缓解**：UI 可选在副武器槽位提示"无属性加成"；effective_att 投影在 player_info 中显示，玩家可观察到 att 不含副武器 itme。

### 8.2 边界案例

| 边界 | 处理方式 |
|------|---------|
| 穿上装备时背包满 + 目标槽位已有装备 | emit equip.bag_full 阻止，玩家需先丢弃/整理 |
| 卸下装备时背包满 | emit unequip.bag_full 阻止 |
| 装备耐久为 0 | emit equip.broken 阻止穿上 |
| 装备耐久为 `∞`（无限耐久） | 正常穿上，`itms` 字段保留字符串 `∞`；`player_get_effective_att/def` 直接计入 `itme` 加成，无需特殊处理 |
| 同一道具既 tag_usable 又 tag_equippable | 当前无此道具；若未来出现，前端同时显示"使用"和"装备"按钮 |
| itmk 不在映射表中（如 TK 试图装备） | emit equip.invalid_kind 阻止 |
| **副武器无属性加成** | 副武器 itme 不计入 effective_att；前端可显示 itme 原值但需明确"副武器无加成"语义 |
| **副武器交换（wep 空 + wep2 非空）** | 交换后 wep2 装备进入 wep，wep2 变空；effective_att 自动反映新主武器加成 |
| **副武器交换（wep 非空 + wep2 空）** | 交换后 wep 装备进入 wep2，wep 变空；effective_att 变为 base（无主武器加成） |
| **副武器交换（wep + wep2 均空）** | emit swap_weapon.both_empty 阻止，无副作用 |
| **副武器交换（wep + wep2 均非空）** | 7 个字段互换；技能配置 slots 含 wep+wep2 的技能（如 throw）保持有效 |
| `ac` 槽位装备 | 当前无属性加成，仅占用槽位；未来扩展 |
| `obl_save_player` 自动剥离 equipment 类技能 | `obl_save_player` 内部调用 `skill_strip_temporary`，保存时 equipment 技能被剥离；下次 `obl_format_playerdata` 由 `skill_inject_equipment` 重新注入。`item_equip` / `item_swap_weapon` 内的"立即重建"是为本 tick 内立即生效，不依赖保存→加载循环 |
| `$equip_slot` 显式指定但与 itmk 不匹配 | `item_equip_validate_slot` 返回 false，emit equip.invalid_slot 阻止 |
| `open_gift_box` 产物无法放入背包（背包满 + 无法合并） | unset itm0 + emit `open_gift_box.bag_full`，物品实例丢失；mystery_box 仍由 F-3 框架扣减 itms（赌博语义：开盒即消耗，产物落地需背包有空间） |
| `open_gift_box` 多件产物逐件放入 | 逐件 put_itm0 → organize_inventory；前一件 organize 成功后 itm0 清空，下一件可继续 put。中途任意一件失败则 emit bag_full，剩余物品丢失 |
| `cure_bs` 时 `oblpara.body_status` 字段不存在 | 防御性检查：字段不存在视为"无 Body Status 可清"，仍 emit `cure_bs.success` 供未来健康系统订阅；itms 由 F-3 扣减（道具仍被消耗） |
| `restore_hp` / `restore_sp` 时 HP/SP 已满 | 不溢出（min(hp+itme, mhp)），仍 emit success + 扣 itms（玩家有义务看清状态再使用） |

## 九、验收标准

### 9.1 功能验收

1. **道具使用**：
   - bread（use_effect=restore_hp）使用后 HP 增加 120（不超过 mhp），itms-1
   - mineral_water（use_effect=restore_sp）使用后 SP 增加 140（不超过 msp），itms-1
   - antidote（use_effect=cure_bs）使用后清除全部 Body Status Tag，itms-1
   - rabbit_meat_raw（use_effect=gain_resistance）使用后 emit `gain_resistance.triggered` 事件，itms-1
   - mystery_box（use_effect=open_gift_box）使用后获得随机道具，itms-1（归零销毁）

2. **装备穿卸**：
   - rusty_pipe（itmk=WP）从背包装备到 wep 槽位，背包槽位清空，wepid='rusty_pipe'，wepe=8
   - 装备后 `player_get_effective_att` 返回 base+8
   - wep 已有装备时穿上新武器 → 旧武器放入背包空位
   - 背包满时穿上 → emit equip.bag_full 阻止
   - 卸下 wep 装备 → 装备字段清空，背包增加道具实例

3. **装备技能联动**：
   - throwing_spear（tag_weapon_throwing）装备到 wep → `throw` 技能立即注入 skillpara
   - 卸下 throwing_spear → `throw` 技能立即剥离

4. **副武器语义**：
   - 副武器 wep2 装备后 `player_get_effective_att` 不含 wep2e（仅 base + wepe）
   - 副武器装备 throwing_spear → `throw` 技能注入（slots 配置含 wep2）
   - 卸下副武器 → `throw` 技能剥离

5. **副武器交换**：
   - wep + wep2 均非空 → 调用 `item_swap_weapon` 后 7 个字段互换
   - wep 空 + wep2 非空 → 交换后 wep2 进入 wep，wep2 变空
   - wep + wep2 均空 → emit swap_weapon.both_empty 阻止
   - 交换后 `player_get_effective_att` 反映新主武器加成

6. **字段重命名**：
   - DB schema（`oblplayers.sql`）5 个槽位字段前缀为 db/dh/da/df/ac
   - PHP 后端无 arb/arh/ara/arf/art 字段引用（grep 验证）
   - 前端 TS 无 arb/arh/ara/arf/art 字段引用（grep 验证）
   - `player_get_effective_def` 计算 db/dh/da/df 的 itme 之和

7. **前端闭环**：
   - InventoryList 显示"装备"按钮（tag_equippable 道具）
   - EquipmentList 显示"卸下"按钮（非空槽位）+ "交换"按钮（wep/wep2 任一非空）
   - 槽位标签显示中文名（主武器/副武器/护甲/头部防具/手部防具/足部防具/饰品）
   - 点击装备/卸下/交换后 player_info 和 player_inventory 自动刷新
