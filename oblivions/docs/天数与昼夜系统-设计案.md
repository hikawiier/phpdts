# 天数与昼夜系统 - 设计案

> **设计目标**：在 tick（游戏刻）之上引入"天"与"昼夜相位"两层时间语义，为后续 POI 耐久、夜间事件、白天/夜间差异化生态等需求提供框架基准；同步改造地面野生道具刷新机制从 tick 间隔判定改为天数判定；统一全项目 "tick → 刻" 术语。

---

## 一、概念定义

| 概念 | 定义 | 与 tick 关系 |
|------|------|--------------|
| **刻 (tick)** | 世界结算的最小时间单位 | 现有定义不变（DESIGN.md 1.0） |
| **天 (day)** | 由若干刻组成的宏观时间单位 | 1 天 = `day_length_ticks` 刻（默认 120） |
| **昼夜相位 (phase)** | 一天内的时间段标记 | 一天内分 `day`（昼）/`night`（夜）两个相位 |
| **相位刻 (phase_tick)** | 当前相位内已流逝的刻数 | `phase_tick = current_tick % phase_length` |

### 默认配置
- 1 天 = 120 刻
- 昼相位 = 80 刻
- 夜相位 = 40 刻

### 相位切换逻辑
- `tick % 120 < 80` → 昼相位
- `tick % 120 >= 80` → 夜相位

### 天数递增逻辑
- 天数从 1 开始
- 每当 `tick` 跨过 `day_length_ticks` 的整数倍时，天数递增
- 具体判断：`day = floor(tick / day_length_ticks) + 1`

## 二、后端设计

### 2.1 数据结构

#### 数据库表 `bra_oblgame` 新增字段
```sql
ALTER TABLE bra_oblgame
  ADD COLUMN day int unsigned NOT NULL DEFAULT '1' AFTER processed_tick,
  ADD COLUMN phase varchar(16) NOT NULL DEFAULT 'day' AFTER day;
```

- `day`：当前游戏天，从 1 开始递增
- `phase`：当前昼夜相位，取值 `'day'` / `'night'`

> 注：`bra_oblgame.phase` 字段在原表中已存在但当前未使用（`obl_game_default_row` 写入空字符串），本设计将其重新定义为昼夜相位。原 gamestate phase 语义迁移到 `state` 字段（INIT/READY/RUNNING/ENDED）已独立承载。

#### `$gamevars` 兼容镜像
新增：
- `$gamevars['obl_day']` (int)
- `$gamevars['obl_phase']` (string)

通过 `obl_gamevars_sync_to_globals()` / `obl_gamevars_sync_from_globals()` 与 `bra_oblgame` 表双向同步，模式与 `obl_tick` / `obl_pretick` 一致。

### 2.2 配置点

`oblivions/gamedata/obl_config.php` 新增配置块：

```php
// ─── 天与昼夜 / Day & Day-Night Cycle ──────────────
'day_length_ticks'   => 120,  // 1 天 = 120 刻
'day_phase_ticks'    => 80,   // 昼相位刻数（夜 = day_length - day_phase）
// 注：phase = (tick % day_length) < day_phase ? 'day' : 'night'
```

### 2.3 核心模块

新增文件：`oblivions/include/game/day_cycle.func.php`

**职责**：
- 提供 `obl_day_get()` / `obl_day_phase_get()` 读取接口
- 提供 `obl_day_compute($tick)` 纯函数：从 tick 推导 (day, phase)
- 提供 `obl_day_advance_hook()` 钩子：在 tick 推进后检测相位/天数变化并触发事件
- 提供 `obl_day_register_listener($event, $cb)` 监听器注册接口

**事件类型**：
- `day_started`：昼相位开始（夜→昼）
- `night_started`：夜相位开始（昼→夜）
- `day_changed`：天数递增（与新一天的 `day_started` 同时触发，但作为独立事件供不同订阅者使用）

**监听器签名**：
```php
function(array $transition): void
// transition = ['from' => ['day'=>N,'phase'=>'day'], 'to' => ['day'=>N+1,'phase'=>'day'], 'tick' => T]
```

### 2.4 tick 推进时的相位更新

在 `obl_tick_advance()`（`tick.func.php`）末尾调用 `obl_day_advance_hook()`：

```php
function obl_tick_advance() {
    global $gamevars, $ginfochange;
    if (!isset($gamevars['obl_tick'])) $gamevars['obl_tick'] = 0;
    $gamevars['obl_tick']++;
    obl_day_advance_hook();  // 新增：检测相位/天数变化
    $ginfochange = true;
}
```

`obl_day_advance_hook()` 实现：
1. 用 `obl_day_compute($new_tick)` 推导新的 `(day, phase)`
2. 与 `($gamevars['obl_day'], $gamevars['obl_phase'])` 比较
3. 若相位变化：触发 `day_started` 或 `night_started` 事件
4. 若天数变化：触发 `day_changed` 事件
5. 更新 `$gamevars['obl_day']`、`$gamevars['obl_phase']`

### 2.5 事件钩子用途（为后续任务预留）

- **POI 耐久衰减**（任务2/3预备）：订阅 `day_changed` 事件，按天数递减 POI 实例的耐久字段
- **夜间事件**：订阅 `night_started` 事件，触发夜间专属 NPC 行为或环境变化
- **野生道具刷新**：订阅 `day_started` 事件，每天昼开始时刷新一次（替代当前 tick 间隔判定）

### 2.6 与战斗 tick / 世界 tick 的关系

- **不冲突**：昼夜系统建立在 tick 之上，是 tick 的派生层
- **战斗 tick 仍走原战斗域**：战斗命令推进 tick 时同样会触发相位检测，但战斗内相位切换不会影响战斗流程
- **监听器调度**：昼夜事件在 tick 推进后立即同步触发（非异步），与现有 tick 监听器机制一致

### 2.7 bootstrap 加载层序

`day_cycle.func.php` 在 `obl_bootstrap.php` 的第 5.75 层加载（在 `wild_refresh.func.php` 第 5.7 层之后、`tick.func.php` 第 6 层之前），因为：
- 不依赖 tick.func.php（仅被 tick 推进时调用）
- wild_refresh 需要 day cycle 监听器注册（wild_refresh 反过来订阅 day_started）
- tick.func.php 末尾的 `obl_tick_register_listener` 调用方仍走原流程

## 六、DESIGN.md 概念词典登记

在 DESIGN.md 第一节"概念词典"中新增：

### 1.18 天 (day) / 昼夜相位 (phase)

**天**是宏观时间单位，由若干刻组成。1 天 = `day_length_ticks` 刻（默认 120）。天数从 1 开始递增，公式为 `day = floor(tick / day_length_ticks) + 1`。

**昼夜相位**是一天内的时间段标记。1 天分为昼（`day`）与夜（`night`）两个相位，昼占 `day_phase_ticks` 刻（默认 80），夜占剩余刻数（默认 40）。相位判断：`phase = (tick % day_length_ticks) < day_phase_ticks ? 'day' : 'night'`。

**与刻（tick）的关系**：天与相位是 tick 的派生层，不引入新的时间单位。tick 推进时同步计算相位与天数变化，触发相位切换事件。

**与回合（Turn）的关系**：独立概念，互不耦合。回合是战斗域的 tick 别名，天/相位是世界域的 tick 派生。

**事件钩子**：相位切换时触发 `day_started` / `night_started` 事件；天数递增时触发 `day_changed` 事件。供 POI 耐久衰减、夜间事件、野生道具刷新等系统订阅。

```markdown
#### 框架 E-11：天与昼夜相位派生层

**设计意图：** 在刻（tick）之上建立宏观时间语义层。天与昼夜相位都是从 tick 派生的纯函数——天数由 `floor(tick / day_length_ticks) + 1` 推导，相位由 `tick % day_length_ticks` 与昼相位刻数阈值比较推导。tick 推进后立即检测相位/天数变化，同步触发相位切换事件。监听器机制提供三类事件：昼开始、夜开始、天数递增——供 POI 耐久衰减、夜间事件、野生道具刷新等业务系统订阅。事件在 tick 推进调用栈内同步触发，不引入异步队列。

**代码锚点：** `oblivions/include/game/day_cycle.func.php`（天与相位派生、事件钩子、监听器注册）

**边界案例：**

- 刻推进与相位切换是同步原子事件——同一 tick 推进内若同时跨过相位边界和天数边界，两个事件按 `night_started` → `day_changed` 顺序触发（夜→昼切换意味着新一天开始）。
- 配置项 `day_length_ticks` 与 `day_phase_ticks` 必须满足 `day_phase_ticks < day_length_ticks`，否则校验失败回退默认值 80/120。
- 天数从 1 开始而非 0——游戏开局即处于第 1 天昼相位。
- 多 tick 批量推进时按天数循环触发多次 `day_changed` 事件，确保跨多天的离线推进不丢失天数切换副作用。
- 战斗域 tick 推进同样触发相位检测——战斗中也可能发生昼夜切换，但不影响战斗流程。
```
