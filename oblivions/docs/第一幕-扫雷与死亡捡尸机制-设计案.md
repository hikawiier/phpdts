# 第一幕：死亡惩罚与捡尸机制设计案

> 本案为 [第一幕-庇护所与新手区资源案 v0.6](./第一幕-庇护所与新手区资源案.md) 的补充设计案。
> 聚焦死亡惩罚系统、捡尸机制、扫雷信息扫描系统、Body Status Tag 系统的设计。
> 基于 2026-07-05 讨论整理。

---

## 一、 设计哲学

1. **多路径解决方案**：每个核心痛点都提供多条解法路径，匹配不同玩法风格的玩家（战斗型/策略型/保守型）。
2. **复用优先**：优先复用已有机制（discovered 三态、迷雾点亮、地图道具拾取、Tick 系统），避免重复造轮子。
3. **低惩罚 Roguelike**：死亡是"局部战术挫折"，不是"全局进度重置"。所有进度保留，惩罚集中在三个维度。
4. **风险 vs 深度决策循环**：死得越深，捡回越难。玩家每次深入都要权衡"如果死在这里，我能不能捡回来"。

---

## 二、 死亡惩罚系统

### 2.1 死亡保留进度

oblivions 不是传统 Roguelike（永久死亡+重开），而是"在家复活，进度全保留"的生存冒险。玩家死亡后在家里（庇护所铁舱）复活，所有进度保留。

**保留的内容**：

| 类别 | 保留内容 |
|------|---------|
| 玩家属性 | HP/SP/AP（复活后满值）、等级、经验 |
| 物质财富 | 道具、装备（主角自带背包里的） |
| 知识积累 | 鉴定知识、已解锁配方、被动技能 |
| 探索进度 | 已发现的 POI、已走过的路径、已鉴定的素材 |

### 2.2 三个惩罚维度

死亡惩罚集中在三个维度，每个维度都有明确的设计目的：

| 维度 | 重置内容 | 设计目的 |
|------|---------|---------|
| **NPC/敌人状态重置** | HP/位置/AI 状态回到初始 | 拒绝用命耗血战术 |
| **区域迷雾重置** | 潮汐深处未探索区域的临时视野清除 | 拒绝用命探图 |
| **猫被留在原地** | 猫留在死亡点，玩家失去猫背包功能 | 形成"捡尸"玩法钩子 |

前两个维度是"状态重置"（详见第六章），第三个维度是"猫分离"——需要玩家主动捡回猫（详见第三章）。

---

## 三、 捡尸机制：怎么领回猫

猫被留在死亡点后，玩家有三种方案领回猫。三种方案从开始就都可用，让玩家根据自己情况选择。

### 3.1 风险 vs 能力决策矩阵

| 方案 | 风险 | 要求 | 适用场景 |
|------|------|------|---------|
| 武力捡尸 | 高 | 战斗力足够 | 死在可战斗区域 |
| 扫雷引导猫 | 中 | 无人机 + 扫雷技能 | 地图边界可达 |
| 紧急丢弃 | 低 | 接受道具损失 | 卡死时的保底 |

### 3.2 方案 1：武力捡尸

- 玩家直接杀回死亡点，击败路上的敌人
- 到达死亡点后触发"猫归队"逻辑
- **Boss 区域特殊处理**：死在 Boss 战后猫自动跑回（Boss 区域不该反复挑战作为捡尸门槛）

### 3.3 方案 2：扫雷引导猫

- 玩家在地图边界（非死亡点）使用无人机扫描
- 扫雷小游戏：基于已点亮格子的"敌人数"提示，规划安全路径
- 扫描成功后，猫沿着安全路径自己走回来
- 扫雷的具体机制详见第四章

### 3.4 方案 3：紧急丢弃

- 猫丢弃几件仓库道具，自己跑回庇护所
- 随机丢弃，但明确告知玩家以后可以取回
- 道具丢弃的具体逻辑详见第五章

## 四、 扫雷系统的具体机制

### 4.1 核心定位：迷雾系统的玩法化扩展

扫雷不是新增系统，而是已有迷雾系统的 UI 层 + 数据层扩展。三个统一让实现成本大幅降低：

| 扫雷元素 | 对应的已有机制 |
|---------|--------------|
| 扫雷的"空地" | 已点亮的迷雾格子（`bra_oblmapstates.fog=1`） |
| 扫雷的"数字" | 已点亮格子显示的周围敌人数（基于 `discovered=1` 实时统计） |
| 扫雷的"踩雷" | 探索到敌人格子上（`discovered` 字段已有三态） |

扫雷是一个**真正的扫雷小游戏**——激活后替换地图页面，玩家在扫雷 UI 中操作。数据来源是真实地图数据（玩家已点亮的迷雾、已发现的敌人），扫雷结束时根据退出方式决定是否将扫描结果写回地图数据。

### 4.2 已点亮格子的"敌人数"显示

**机制**：
- 当玩家站在已点亮迷雾格子（fog=1）上时，UI 显示该格周围 8 格内 `discovered=1` 的敌人数
- 数字**实时更新**——敌人移动时数字会变，敌人超出视野（discovered→0）后数字减少
- 这与现有 `obl_update_enemy_discovered()` 的"敌人移动后超出视野→discovered=0"逻辑一致

**实现路径**：
- 后端：新增 `obl_get_adjacent_enemy_count($pgroup, $pls)` 函数，统计指定格子周围 8 格的 `discovered=1` 敌人数
- 前端：在已点亮格子上叠加显示数字（类似扫雷的数字提示）

### 4.3 无人机道具（多功能核心道具）

**道具定位**：扫描用无人机，第一个真正多功能的核心道具。

| 用途 | 机制 |
|------|------|
| 扫雷扫描 | 主动使用，扫描未知区域（fog=0）的敌人分布 |
| 诱饵 | 扔出去吸引敌人注意，转移仇恨 |
| 武器 | 直接撞击敌人造成伤害（一次性消耗） |
| 侦察 | 飞到远处查看特定格子的状态 |

**数据结构**：
- 复用 `item_table.php` 的 `itmpara` JSON 字段存放：`{ uses: int, scan_range: int, durability: int }`
- `uses` 字段表示使用次数，每次扫描消耗 1 点
- `scan_range` 表示扫描范围（默认 3x3，可升级）

### 4.4 扫雷小游戏的基本规则

**时间静止**：扫雷不推进游戏刻变化，即扫雷时游戏时间是静止的。玩家可以慢慢思考，不会因为扫雷而被敌人偷袭。

**界面大小**：根据无人机范围动态调整，以玩家所在图格为中心向外延展。例如无人机范围 1 表示以玩家为中心的 3×3 网格（半径 1），范围 3 表示 7×7 网格。obl 地图最大 16×16，与扫雷高难度差不多。

**flood fill 边界**：当点开"0 敌人"格子时触发自动展开（flood fill），展开到无人机范围边缘停止——不会无限扩展到整个地图。

**单次无时限**：随时可退出，没有时间压力。退出方式见 4.7。

**🚩 标记功能**：玩家可以在未点开的格子上放置 🚩 标记，表示"我判断这里有敌人"。🚩 是辅助判断工具，不直接触发任何结果，但会参与"自动展开"的逻辑判定（见 4.5、4.6）。

### 4.5 扫雷的两个操作

| 操作 | 行为 | 结果 |
|------|------|------|
| **点开格子** | 点击未点开的格子（fog=0） | 若格子是敌人→踩雷；否则显示周围敌人数，若数字为 0 触发 flood fill |
| **点击数字自动展开**（chord click） | 点击已点开的数字格子 | 检查周围 8 格的 🚩 数量是否等于数字。匹配则展开未标 🚩 的格子；若 🚩 标错（标在空格上）→踩雷 |

chord click 是传统扫雷的"数字格自动展开"机制：当一个数字格周围已放置的 🚩 数等于该数字时，剩余未点开的格子可以安全展开。如果玩家标错了 🚩（把空格标成了敌人），自动展开就会点到真正的敌人，触发踩雷。

### 4.6 扫雷的两种踩雷条件

| 踩雷条件 | 触发场景 |
|---------|---------|
| **点开敌人格子** | 玩家直接点开一个有敌人的格子（discovered=0 的未发现敌人） |
| **自动展开时🚩标错** | chord click 或结算时，发现 🚩 标在空格上（标错位置） |

踩雷的惩罚见 4.8。

### 4.7 扫雷的三种退出方式

| 退出方式 | 触发 | 情报保留 | uses 消耗 |
|---------|------|---------|----------|
| **踩雷**（被迫） | 点到敌人或 🚩 标错 | ✅ 保留已探索的图格情报 | 已消耗 |
| **结算**（主动） | 玩家主动点击"结算"按钮 | ✅ 保留已探索的图格情报 | 已消耗 |
| **撤回**（主动） | 玩家主动点击"撤回"按钮 | ❌ 不保留（等于没扫过） | 已消耗（不退回） |

**结算的具体逻辑**：对所有已发现的数字进行批量自动展开（批量 chord click）。如果任何数字周围有标错的 🚩，等同于踩雷（按踩雷处理）。结算 = 一次性验证全部判断 + 展开所有可展开的格子。

**撤回的具体逻辑**：放弃本次扫描的所有探索结果，情报不写回地图数据。但 uses 已在激活扫描时消耗，撤回不退回——撤回是"安全退出但付出代价"。

**情报保留的含义**：踩雷/结算时，扫描点亮的格子 fog=0→1（永久点亮），扫描发现的敌人 discovered=0→1（直到敌人移动超出视野后丢失，与现有机制一致）。撤回时这些都不生效，地图数据不变。

**设计说明**：踩雷与结算本质是同一机制（自动展开），只是范围不同——踩雷是单次操作的失败，结算是批量验证的失败。不存在"风险梯度"的区分，两者都是"标错就结束"。

### 4.8 失败惩罚与回收

**失败惩罚**：无人机掉落在踩雷格子上，需要走过去回收。这跟"捡猫尸体"是同构的——都是"东西掉在地图上，去取回"。

**回收的备用方案**：
- 等敌人移动走后回收（敌人 AI 移动后格子可能空出来）
- 武力清除敌人后回收
- 放弃回收（无人机丢失，需要制作新的）

**关于"敌人移动超出视野会丢失"**：扫雷点亮的敌人位置是"临时信息快照"，不是永久揭示。敌人移动超出玩家视野后 discovered→0，玩家会丢失追踪——这意味着雷达有持续使用的价值。

### 4.9 复用到雷达道具

扫雷机制不仅用于捡尸场景，还可以复用到雷达道具的主动扫描、危险区域探索。这意味着扫雷是一个**通用的信息扫描系统**，实现成本可被多个场景摊销：

| 场景 | 扫雷的作用 |
|------|-----------|
| 捡尸引导猫 | 扫描回去路上的敌人，规划安全路径 |
| 雷达道具主动使用 | 扫描周围区域的敌人位置 |
| 危险区域探索 | 扫描未知格子的威胁分布 |

## 五、 道具丢弃机制

### 5.1 随机丢弃规则

- 猫丢弃几件仓库道具，自己跑回庇护所
- **随机丢弃**：不让玩家选择，增加不可控感
- **固定数量**：建议 3 件（简单且可预测，玩家知道"最多丢 3 件"）

### 5.2 明确告知设计

- UI 提示"猫把东西藏好了，以后可以取回"，消除丢失焦虑
- 猫会说"老子把东西藏好了，丢不了"——符合猫的地头蛇设定（它知道哪里藏东西安全）
- "藏好了"这个叙事解释暗示：**道具在地图格上是安全的，不会被敌人捡走或消失**

### 5.3 与主动丢弃的统一

死亡丢弃 = 主动丢弃 = 地图数据库增加道具。这是个统一的机制：

- 道具 `INSERT INTO bra_oblmapitem`，`discovered=0`（需探索发现）
- 玩家走过去探索就能拾取，复用 `obl_pickup_item` 逻辑
- 死几次都是同一个基本逻辑——地图数据库增加道具

这意味着**死亡丢弃的实现成本几乎为零**——只是个数据写入操作，把道具从猫背包转移到地图格上。

## 六、 状态重置系统

### 6.1 NPC/敌人状态重置

**死亡时触发**：
- 所有敌人的 HP/位置/AI 状态回到初始值
- 已击败的普通敌人复活（保持挑战）
- **Boss/独特 NPC 保留死亡状态**（防止重复打）
- 实现路径：新增 `obl_reset_enemies_on_death($pgroup)` 函数

### 6.2 潮汐深处迷雾重置

**死亡时触发**：
- 潮汐深处区域的"临时视野"清除（fog=0）
- **已发现的 POI 保留发现状态**（避免重复内容）
- **已走过的路径保留可见**（避免纯粹重复劳动）
- 只重置"未探索区域的探索状态"
- 实现路径：新增 `obl_reset_tide_fog($pgroup, $tide_zone)` 函数

### 6.3 多次死亡的叠加处理

- 猫/掉落物移动到最新死亡点，旧的丢弃
- 这样惩罚不叠加，但捡尸挑战不消失
- 道具丢弃机制统一：死几次都是同一个基本逻辑（地图数据库增加道具）

## 七、 Body Status Tag 系统

### 7.1 存储位置

复用 `bra_oblplayers.oblpara` JSON 大字段，新增 `body_status` 数组：
```json
{
  "body_status": ["foot_hurt", "stomach_sick", "arm_numb"],
  "death_location": {"pgroup": 1, "pls": 42},
  "cat_inventory": {...}
}
```

### 7.2 核心 Tag 定义

| Tag | 触发条件 | 机制惩罚 | 解除方式 |
|-----|---------|---------|---------|
| `[足部刺痛]` | 无足部防具时移动 | 移动时损失 HP，降低体力回复 | 装备足部防具 |
| `[胃部不适]` | 饮用工业废水/生食有毒素材 | 精力/AP 恢复速度减半 | 服用净化药剂/等待时间 |
| `[手臂麻木]` | 生食带电兔肉/受到重击 | 武器攻击速度/命中率下降 | 等待时间/使用绷带 |

### 7.3 触发与解除机制

**触发**：
- 移动后钩子检查 `[足部刺痛]`（Tick 系统的 post phase）
- 使用道具时检查 `[胃部不适]`/`[手臂麻木]`（`obl_use_item` 命令内）
- 战斗中受击时检查 `[手臂麻木]`（战斗系统扩展）

**解除**：
- 装备对应防具立即解除
- 时间流逝自然解除（Tick 系统递减持续时间）
- 使用对应道具解除（绷带、净化药剂）

### 7.4 吃瘪看板娘视觉呈现

**1-bit 剪纸状态立绘联动**：
- 在左侧抽屉或主界面角落，显示 1-bit 剪纸风格的苹果小人
- 小人根据当前持有的 Body Status Tag 切换吃瘪表情与滑稽姿势

| 状态 | 立绘表现 |
|------|---------|
| 健康 | 面无表情背着物理圣剑（正常站姿） |
| 足部刺痛 | 单脚着地，另一只脚提起，哭丧的"叉叉眼" |
| 胃部不适 | 捂着肚子蹲在地上，头顶肠胃蠕动黑线 |
| 电火花律动 | 发梢静电状竖起，指尖噼啪静电字符 |

**实现**：前端新组件，根据 `oblpara.body_status` 数组切换立绘资源。立绘资源量：健康 + 3 个负面状态 = 至少 4 套（可扩展）。

## 八、 死亡触发与复活逻辑

### 8.1 死亡触发（扩展现有 `battle_state_clear('death')`）

1. 玩家 state=1（已有逻辑）
2. 记录死亡位置（`pgroup, pls`）到 `oblpara.death_location`
3. 触发猫分离逻辑（猫记录保持原位）
4. 触发状态重置逻辑（见第六章）
5. 触发道具丢弃逻辑（如果选择紧急丢弃方案）

### 8.2 复活逻辑（新增 `obl_respawn` 函数）

1. 玩家位置回到庇护所铁舱（存档点）
2. HP/SP/AP 恢复满值
3. 清除所有 Body Status Tag
4. state=0（复活）
5. 保留死亡位置记录，供捡尸使用

### 8.3 猫分离机制

**数据层处理**：
- 猫是 `bra_oblplayers` 表里 type>0 的 NPC
- 死亡时，猫的记录保持在死亡点（不跟随玩家回庇护所）
- 玩家记录回到庇护所，猫记录留在原地——数据层自然实现"分离"

**猫分离期间的玩法影响**：
- 玩家失去猫背包功能（仓储扩展、保鲜功能、便携工作站）
- 主角自带背包（`itempara` 7 槽）必须能独立支撑基本玩法，不能假设玩家永远有猫

**待确认的设计点**：
- 猫背包的内容存储位置（猫自己的 `oblpara`？还是玩家的 `itempara` 分区？）
- 这影响"猫分离期间玩家失去仓储"的实现方式
- 建议方案：猫背包内容存在猫的 `oblpara.cat_inventory`，分离时玩家无法访问该字段

## 十一、 待确认的设计点

1. **猫背包的内容存储位置**：猫自己的 `oblpara.cat_inventory`？还是玩家的 `itempara` 分区？影响"猫分离期间玩家失去仓储"的实现方式。

2. **随机丢弃的道具数量**：固定 3 件？还是按猫背包容量的比例（如 30%）？建议固定数量，简单且可预测。

3. **丢弃道具的 discovered 初始值**：`discovered=0`（需探索发现）还是 `discovered=1`（立即可见）？建议 `discovered=0`，玩家需要重新探索死亡区域才能捡回道具，增加"捡尸"的玩法挑战。

4. **潮汐深处区域的定义**：是"深渊区域"的另一种叫法？还是子区域的一种类型？需要在区域配置里明确标注 `is_tide_deep: true`。

5. **无人机扫描的范围配置**：默认 3x3？可升级？扫描是否消耗资源（使用次数）？建议默认 3x3，通过 `itmpara.scan_range` 配置，每次扫描消耗 1 点 `uses`。

6. **Boss 区域的判定方式**：如何在死亡时判断玩家是否死在 Boss 区域？建议在区域配置里标注 `is_boss_zone: true`。

7. **捡尸的时限**：猫会一直等吗？还是一段时间后猫自己跑回家？建议"一直等"，但可设计"猫的饥饿度"——时间太久猫会饿，捡回来后状态更差。

8. **`obl_scan` 命令的白名单**：扫雷不推进游戏刻（时间静止），因此**不加入** Tick 推进命令白名单。但扫描激活时消耗 1 点 uses，撤回也不退回。

## 十三、 核心设计观点

### 13.1 三个统一降低实现成本

讨论中揭示的多个"新框架"实际是已有机制的复用和扩展：

1. **扫雷 = 迷雾系统的玩法化扩展**（discovered 三态 + fog 字段 + UI 显示）
2. **死亡丢弃 = 地图道具机制的复用**（`bra_oblmapitem` + `obl_pickup_item`）
3. **捡尸 = 通用"地图取回"机制**（猫/无人机/道具都是"地图上有东西去取回"）

这让真实新增框架数量从表面的 12 个降到 8 个左右。

### 13.2 风险 vs 深度的决策循环

死亡机制的核心张力不是"活下去"，而是**"深入多远才值得冒险"**。死得越深，捡回越难（迷雾重置 + 敌人满血 + 猫不在身边）。这形成了暗黑之魂式的"魂"系统哲学，但用"猫"做载体更有情感重量。

### 13.3 多路径解决方案的哲学

每个核心痛点都提供多条解法路径：
- **捡尸**：武力 / 扫雷引导 / 紧急丢弃
- **足部刺痛**：合成厚底鞋 / 体质强化
- **雾气障目**：制作荧光瓶 / 食疗夜视
- **重金属腹泻**：水净化 / 食疗抗性

这符合泰拉瑞亚式的"多路径成长"——玩家有选择权，所有行为都能带来正向反馈。
