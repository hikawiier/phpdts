# 队列清理职责重构-设计案

> 修复 NPC 逃跑导致玩家卡在战斗状态的 BUG，重构 bid 语义与队列清理职责分工。

---

## 一、问题背景

NPC AI 重构引入 escape/idle 兜底后，NPC 作为 actor 逃跑时，玩家会卡在战斗状态。

### 根因

`battle_manage_queue` 的两个解散分支只清理 `$actor_data`（动作发起者），不清理队列中其他存活的 combatant。NPC 逃跑时：

1. `battle_main_end` 清理 NPC：`battle_state_clear` → `battle_queue_exit` 删队列行 + **清空 `NPC.bid=0`** + save
2. `battle_manage_queue`：`$qid = (int)$actor_data['bid']` → **$qid=0** → 查不到队列 → `empty($queue_rows)` → disbanded
3. 解散分支只清理 `$actor_data`（NPC，已清理过，二次调用保护 return），**玩家 bid 仍指向已不存在的队列**

### 深层原因：bid 语义混用 + 职责越权

`bid` 当前承担两种语义：
- **语义 A**："关联的队列 ID"（`battle_manage_queue` / `battle_cache_create` / `obl_command` 用它取 qid）
- **语义 B**："是否在战斗中"（`battle_queue_setup` / `enemy_ai` / `battle_main_end` 用它判断）

`battle_state_clear`（个人清理函数）越权清空了 bid 并删除队列行，导致：
- 队列管理系统（`battle_manage_queue`）拿不到 qid（语义 A 被破坏）
- 队列行被删，无法通过队列行找到其他存活者

---

## 二、设计原则

1. **bid 语义固定为 A**：bid = 关联的队列 ID，退出后仍保留，仅在队列解散时由队列管理系统统一清空
2. **action 表示"是否在战斗中"**：`'battle'` = 在战斗中，`''` = 不在。原用 bid 判断"是否在战斗中"的地方改用 action；但 bid>0 仍等价于"在队列中"（解散时才清空），不可与"在战斗中"混淆
3. **队列表新增 `active` 字段**：1=可参战，0=已退出。不删行只标记，队列状态稳定
4. **职责分离**：
   - 个人清理（`battle_state_clear`）：只清 action + 标记 active=0 + 恢复 AP + save，不清 bid
   - 队列解散清理（`battle_manage_queue`）：统一清空所有人 bid + action，删队列 + 销毁状态机

```php
function obl_fetch_queue_current_initiator($qid) {
```

### 3.2 battle_state_clear 改造

```php
function battle_state_clear(&$actor_data, &$obl_battle_log, &$battle_cache, $reason = 'unknown')
{
    // 二次调用保护：只检查 action（bid 保留不代表在战斗中）
    if (empty($actor_data['action'])) {
        return;
    }

    if ($reason === 'death') {

    $actor_data['action'] = '';

    if (!empty($actor_data['bid'])) {
        battle_queue_exit($actor_data, $obl_battle_log, $battle_cache);
    }
    $actor_data['ap'] = $actor_data['max_ap'];
    obl_save_player($actor_data);
}
```

#### 3.4.2 新增 battle_disband_cleanup 函数

解散时统一清理所有队列参与者（包括已退出 active=0 的）的 bid + action：

```php
/**
 * 队列解散时统一清理所有参与者
 *
 * 遍历队列所有行（包括 active=0 已退出的），清空 bid + action + 恢复 AP + save。
 * actor_data 是引用传入，直接修改；其他人 fetch 后修改。
 *
 * @param int    $qid
 * @param array  &$actor_data   当前 actor（引用，直接修改）
 * @param array  &$obl_battle_log
 */
function battle_disband_cleanup($qid, &$actor_data, &$obl_battle_log): void {
    $queue_rows = obl_fetch_queue_all_by_qid($qid);
    foreach ($queue_rows as $r) {
        $pid = (int)$r['pid'];
        if ($pid === (int)$actor_data['pid']) {
            $actor_data['bid'] = 0;
            $actor_data['action'] = '';
            $actor_data['ap'] = $actor_data['max_ap'];
            obl_save_player($actor_data);
            continue;
        }
        $c_data = obl_fetch_playerdata_by_pid($pid);
        if (!$c_data) continue;
        $c_data['bid'] = 0;
        $c_data['action'] = '';
        $c_data['ap'] = $c_data['max_ap'];
        obl_save_player($c_data);

        if ($obl_battle_log) {
            $obl_battle_log->setPhase('disband_cleanup');
            $obl_battle_log->emit([
                'cleared_pid'  => $pid,
                'cleared_name' => $c_data['name'],
            ], true);  // debug
        }
    }
}
```

#### 3.4.3 empty($queue_rows) 兜底分支

改造后 $qid 不会为 0（bid 保留），此分支仅在队列被意外删除时触发。需清理所有 bid 指向此 qid 的人（队列行已不存在，改扫玩家表）：

```php
$queue_rows = obl_fetch_queue_all_by_qid($qid);
if (empty($queue_rows)) {
    // 极端兜底：队列不存在但 actor 还有 bid
    if ($obl_battle_log) {
        $obl_battle_log->setPhase('battle_end');
        $obl_battle_log->emit([
            'winner_pid' => (int)$actor_data['pid'],
            'reason'     => 'queue_empty',
        ]);
    }
    // 清理所有 bid 指向此 qid 的人（队列行已不存在，改扫玩家表）
    $stale_pids = obl_fetch_pids_by_bid($qid);
    foreach ($stale_pids as $pid) {
        if ((int)$pid === (int)$actor_data['pid']) {
            $actor_data['bid'] = 0;
            $actor_data['action'] = '';
            $actor_data['ap'] = $actor_data['max_ap'];
            obl_save_player($actor_data);
        } else {
            $c_data = obl_fetch_playerdata_by_pid($pid);
            if (!$c_data) continue;
            $c_data['bid'] = 0;
            $c_data['action'] = '';
            $c_data['ap'] = $c_data['max_ap'];
            obl_save_player($c_data);
        }
    }
    if ($qid > 0) {
        obl_battle_state_transition($qid, 'battle_end');
        obl_battle_state_destroy($qid);
    }
    $result['disbanded'] = true;
```

### 3.8 ambush 模式兼容性

- **突袭者暴毙/逃跑（step 6a）**：调用 `battle_state_clear`。此时队列未建，bid=0，`battle_queue_exit` 中 `$qid <= 0` 不执行。无影响。
- **突袭者杀光敌人（step 6b）**：bid=0。`battle_queue_setup` 用 `!empty($bid)` 判断（§3.5 保留原判断），bid=0 不误判为"已在队列中"，正常检查存活者数量。存活者 <2 返回 false → `ambush_killed_all` 分支。
- **突袭后建队列（step 6c）**：`battle_queue_setup` 返回 pids（bid=0 不误判），`battle_queue_create_and_init` 设 bid。后续正常流程。

### 3.9 玩家逃跑场景验证

1. 玩家行动 → escape_calc → `combatants[player]=0`, `tag_mutations[player][escaped]=true`
2. `battle_main_end` → `combatants[player]=0` → `battle_state_clear(player)`：
   - action=''
   - `battle_queue_exit`：标记 active=0（不删行、不清 bid）
   - AP 恢复
   - save
3. `battle_manage_queue`：
   - `$qid = $actor_data['bid']` = qid（**保留**）
   - 查队列行：active=1 的人只剩 NPC（如果 NPC 还活着）
   - `$has_player = false`（玩家 active=0）
   - 解散分支（!$has_player）→ `battle_disband_cleanup`：
     - 遍历所有行，清空 NPC 的 bid + action + AP + save
     - 清空玩家的 bid + action（已空）+ AP + save
   - 删队列 + 销毁状态机
   - disbanded=true

**玩家 bid 被正确清空，不再卡在战斗状态。**

## 五、验证清单

1. **NPC 逃跑 → 玩家不卡战斗**：NPC 用 escape 后，`battle_manage_queue` 解散，玩家 bid=0、action=''
2. **玩家逃跑 → NPC 正常清理**：玩家用 escape 后，NPC bid=0、action=''
3. **玩家杀人 → 正常解散**：NPC 被杀后，玩家 bid=0、action=''、AP 恢复
4. **NPC 杀玩家 → 正常解散**：玩家被杀后，NPC bid=0、action=''
5. **多 NPC 战斗**：2v2 场景，一方减员后不解散，继续战斗直到 active=1 <= 1
6. **多 NPC 战斗 rebuild**：active=0 的人不参与重投先攻，不被 `obl_fetch_queue_current_initiator` 选中，不出现在 `$undone` 中
7. **多 NPC 战斗 combatants 载入**：`battle_cache_create` 通过 `obl_fetch_queue_pids_by_qid`（已加 active=1）载入，active=0 的人不被标记为存活 combatant
8. **ambush 突袭**：
   - 突袭者暴毙/逃跑/杀光敌人时，bid=0（队列未建），正常退出
   - 突袭后建队列（step 6c）正常触发，`battle_queue_setup` 用 `!empty($bid)` 判断不误判
9. **二次调用保护**：`battle_state_clear` 对 action='' 的人直接 return，不重复处理
10. **obl_command 状态查询**：用 bid 取 qid 查状态机，战斗中返回正确状态，解散后返回 IDLE
11. **enemy_ai 跳过战斗中敌人**：用 action='battle' 判断，不误判已退出战斗的 NPC
12. **turn end hook 触发条件**：Phase 0（ambush，bid=0）不触发，Phase 1（bid>0 且 action='battle'）触发
13. **极端兜底**：队列被意外删除时，`empty($queue_rows)` 分支扫玩家表清理所有 bid 指向该 qid 的人
