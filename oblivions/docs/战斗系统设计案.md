# Oblivions 战斗系统设计案

> 基于 [原始方案/战斗设定.txt](原始方案/战斗设定.txt) 的策略回合制战斗系统。
>
> **核心设计**：战棋式回合制战斗，前后端分离——后端瞬间结算，前端逐步播放动画。
>
> **设计原则**：后端只传数据（动作索引 + 效果值），前端完全控制视觉呈现（文案、动画、HP 条）。

---

## 一、设计目标

### 1.1 核心目标

1. **战棋式战斗**：地图格为单位位置载体，技能需瞄准目标，图格位置至关重要
2. **前后端分离**：后端瞬间结算一个先攻轮生命周期，返回结构化动作日志；前端逐条播放动画
3. **策略导向**：预装填 + AP + 策略槽，非简单"选技能→释放"
4. **状态持久化**：战斗状态存数据库 `action` 字段，断线重连可恢复
5. **1vN 架构**：后端先攻队列按 1vN 设计，前端按当前先攻者渲染（1v1 和 1vN 无区别）

### 1.2 非目标

- **技能系统**：独立大系统，本设计案只预留接口，不实现技能定义
- **AOE 范围技能**：MVP 只做 single/self，aoe 形状定义留给技能系统
- **模拟功能**：预装填阶段的"思考"模拟，留待后续
- **混乱状态**：AP 透支惩罚机制，留待后续
- **BOSS 机制**：突破 AP 限制的强力技能，留待后续

## 二、核心概念

### 2.1 游戏刻（Tick）

游戏世界的行为驱动单元，由玩家行为而非时间驱动：

- **非战斗场合**：玩家行动（移动/探索）时更新一次游戏刻；思考、切换姿态、查看笔记不更新
- **战斗场合**：任意角色（玩家或 NPC）的一个先攻轮结束时，更新一次游戏刻
- **游戏刻更新时**：时间流逝、全局结算敌人 AI 行为、buff/dot 等时效内容结算一轮

### 2.2 先攻轮（Initiative Round）

战斗的核心循环单元，包含 s1-s5 五个阶段（详见 [原始方案](原始方案/战斗设定.txt)）：

- **s1**：先攻者第一个技能必定先手释放
- **s2**：防守者从策略槽建立防守执行队列（逃跑最优先）
- **s3**：防守者与先攻者再次先攻对抗，失败累乘 1.5 倍补正，成功则插队打出 1 个动作
- **s4**：先攻者继续下一个技能
- **s5**：先攻轮结束，游戏刻更新，选择下一顺位先攻者

### 2.3 预装填（Preload）

玩家作为先攻者时的操作阶段：

- 拖拽技能/道具到"放置区"，按顺序排列
- 显示当前 AP 与预估消耗
- 完成后一次性按顺序打出所有动作
- 预装填阶段不更新游戏刻
- **预装填数据是前端临时状态，刷新页面后丢失，需重新配置**

### 2.4 AP（Action Points）

动作的资源约束：

- **唯一自然恢复手段**：先攻者在预装填阶段恢复（= 最大 AP）
- 自然恢复不超过最大 AP
- AP 为负数时，只能放入 AP 消耗为 0 的动作
- 防守者 s3 阶段可透支 AP（详见原始方案的混乱惩罚，MVP 不实现）

### 2.5 策略槽（Strategy Slots）

防守者的预设反应配置：

- 非战斗时可配置，1-4 个槽
- 每个槽放 1 个技能或 1 件道具
- 战斗中不可修改
- 空槽默认填"逃跑"
- 道具消耗后对应槽变空

### 2.6 先攻队列（Initiative Queue）

1vN / 多方混战时的行动顺序：

- 所有参战者进行先攻率随机数对抗，排定队列
- 每个参战者扮演一次先攻者后，重新生成随机数决定新队列
- 新加入者固定排序到队列末尾
- **玩家补偿**：未成为第一顺位时，获得第一顺位 25% 的先攻补偿，但最高只能成为第二顺位（仅玩家生效）

## 三、战斗状态机

### 3.1 三个 action 状态

玩家 `$pdata['action']` 字段标识战斗状态：

| 状态 | 含义 | 界面表现 |
|------|------|---------|
| `null` | 无战斗 | 正常探索/移动/拾取界面 |
| `prebattle` | 玩家主动发起，未真正开打 | 预装填界面 + `[执行]` + `[取消并退出战斗]` |
| `battle` | 真正进入战斗（突袭或缠斗） | 预装填界面（玩家先攻）/ 动画播放（NPC 先攻），无取消按钮 |

### 3.2 状态转换

```
null ──玩家点击已发现敌人──→ prebattle
null ──敌人突袭玩家────────→ battle
prebattle ──玩家执行预装填──→ battle（第一轮先攻后进入缠斗）
prebattle ──玩家取消────────→ null（清空 action）
battle ──玩家逃跑成功──────→ null
battle ──敌人全灭──────────→ null
```

### 3.3 进入战斗的条件

**A. 玩家主动攻击（→ prebattle）**：
- 玩家点击界面上已发现的敌人
- 后端变更 `action = 'prebattle'`
- 玩家可取消退出

**B. 敌人突袭（→ battle）**：
- 敌人未被发现（discovered=0）
- 游戏刻更新时（由玩家探索/移动触发），全局结算敌人 AI
- 敌人 AI 移动到玩家所在格（pls + pgroup 重叠）
- 后端变更 `action = 'battle'`，敌人先攻
- 前端播放敌人先攻轮动画

**C. 缠斗状态（→ battle）**：
- 玩家从 prebattle 执行预装填后，经历一轮先攻轮
- 敌人未死，双方保持缠斗
- `action = 'battle'`

### 3.4 退出战斗的条件

**A. prebattle 状态取消**：
- 预装填界面 `[取消并退出战斗]` 按钮
- 后端清空 `action`，返回 `null`

**B. battle 状态（不可主动退出）**：
- 界面无 `[取消并退出战斗]` 按钮
- 玩家向后端传递指令也不能退出战斗

**C. 逃跑成功**：
- 玩家预装填"逃跑"技能并执行成功
- 后端结算清空 `action`

**D. 敌人全灭**：
- 敌人死亡且先攻队列清空（无其他敌人）
- 后端结算清空 `action`

## 四、数据结构

### 4.1 敌人数据（$wdata）

敌人和玩家数据都保存在数据库 `players` 表，通过 `$type` 区分：
- `$type = 0`：玩家
- `$type != 0`：敌人（NPC）

敌人数据结构与玩家同构（`$pdata`），包含：
- 基础属性：hp, max_hp, sp, max_sp, range（射程）等
- 位置：pgroup, pls
- 发现状态：discovered（0=未发现, 1=已发现）
- 技能：`$pdata['clbpara']['skill_id']` 数组
- 策略槽：固定配置（NPC 不可改）
- AI 类型：行为树标识

### 4.2 动作日志结构（BattleLogEntry）

每条 `battle_log` 条目的结构：

```typescript
{
    id: 'battle.action',           // 统一 ID
    turn: number,                  // 第几个先攻轮
    actor: string,                 // 动作执行者标识（'player' | 'enemy_{pid}'）
    action_id: string,             // 动作索引 ID（技能 ID，如 'basic_attack'）
    action_name: string,           // 动作名称（如"基础攻击"）
    target: string,                // 动作目标标识（'player' | 'enemy_{pid}'）
    effect_value: number | number[],  // 效果值（int 或数组）
    extra: object | null,          // 额外效果（结构化，如 { type: 'status', status: 'bleed', duration: 3 }）
    position: object | null,       // 位移信息（如果有）
}
```

**position 结构**（位移动作时填充）：
```typescript
{
    actor_from: { pgroup: number, pls: number },
    actor_to: { pgroup: number, pls: number }
}
```

**effect_value 语义**（由 `action_id` 决定，前端渲染）：
- `basic_attack`：伤害值（int）
- `escape`：1=成功，0=失败
- `heal`：治疗值（int）
- `move`：无（位移信息在 position 字段）

### 4.3 持久化日志（obl_log 摘要）

战斗细节走 `command.php` 响应的 `battle_log` 字段（临时，不持久化）。
`obl_log` 只存战斗摘要：

| 日志 ID | action | params | 说明 |
|---------|--------|--------|------|
| `battle.start` | `battle` | `{ enemy_id, enemy_name }` | 战斗开始 |
| `battle.end` | `battle` | `{ result, enemy_id, enemy_name }` | 战斗结束（result: victory/defeat/escape） |

## 五、后端设计

### 5.1 命令（command.php）

| 命令 | 触发场景 | 参数 | 说明 |
|------|---------|------|------|
| `obl_battle_start` | 玩家点击已发现敌人 | `{ enemy_pid }` | 后端设 `action='prebattle'`，返回 battle_state |
| `obl_battle_cancel` | prebattle 状态取消 | 无 | 后端清空 `action`，返回 null |
| `obl_battle_execute` | 玩家执行预装填 | `{ actions: [{ action_id, target }] }` | 后端结算，返回 battle_log + gamedata |

**`obl_battle_execute` 响应格式**：
```json
{
    "success": true,
    "gamedata": { ... },
    "battle_log": [ BattleLogEntry, BattleLogEntry, ... ],
    "battle_state": "battle" | null,
    "timer": null
}
```

- `battle_log`：本批次所有动作日志（玩家先攻轮 + 所有 NPC 先攻轮，直到下次玩家先攻或战斗结束）
- `battle_state`：战斗结束后为 `null`，未结束为 `"battle"`

### 5.2 API（api_v2.php）

| action | 返回数据 | 消费模块 |
|--------|---------|---------|
| `enemies` | 当前区域 discovered=1 的敌人列表（含突袭者） | battle.js |

**`enemies` API 响应**：
```json
{
    "status": "success",
    "data": {
        "enemies": [
            { "pid": 101, "name": "史莱姆", "type": 1, "pgroup": 1, "pls": 5, "hp": 50, "max_hp": 50, "range": 1, ... },
            ...
        ]
    }
}
```

**实现方式**：改造 `handle_player_info($pdata)` 接受参数，循环获取 players 表中 `$type != 0` 的所有敌人数据。

    obl_tick_update();

}

### 5.4 战斗流程（后端视角）

```
玩家提交 obl_battle_execute
    ↓
后端结算玩家先攻轮：
    s1-s5（预装填动作 + 防守者反应 + 游戏刻更新）
    ↓
检查先攻队列：
    ├── 还有 NPC 未行动 → 结算 NPC 先攻轮 → 游戏刻更新 → 循环
    └── 轮到玩家或战斗结束 → 停止
    ↓
返回 battle_log（所有动作日志）+ battle_state
```

**关键点**：后端一次性结算到"下次玩家先攻"或"战斗结束"，前端收到完整日志批次。

## 六、前端设计

### 6.1 模块拆分

```
vex/js/
├── battle.js          # 战斗主模块：状态机、流程控制、API 调用
├── battle-player.js   # 战斗动画播放器：模态框、逐条播放、暂停/跳过
├── battle-preload.js  # 预装填界面：AP槽、放置区、技能拖拽、瞄准模式
└── battle-render.js   # 战斗日志渲染：解析 battle_log，生成模态框内容
```

### 6.2 界面布局（战斗模式）

战斗模式下主界面布局调整：

**左侧（地图区）**：
- 始终保留，显示地图
- 高亮敌人位置（图标或文字 `[敌人A]` + 地名）
- 瞄准模式下高亮射程内可选目标
- 玩家位置始终显示

**右侧（从上到下）**：
- **CHRONICLE 区** → 替换为**技能/道具栏**（可拖拽源）
- **ACTIONS 区** → 替换为**AP 槽 + 放置区**（拖拽目标）

**AP 槽 + 放置区**内容：
- 当前 AP / 最大 AP（数字 + 可视化条）
- 放置区：已装填的动作列表（按顺序）
- 每个装填项显示：动作名 + 目标 + AP 消耗
- `[执行]` 按钮（提交预装填）
- `[取消并退出战斗]` 按钮（仅 prebattle 状态）

**技能/道具栏**内容：
- 技能列表（图标 + 名称 + AP 消耗 + 射程）
- 道具列表（复用背包数据）
- 可拖拽到放置区

### 6.3 敌人信息展示

**悬浮显示**（光标移到敌人图标/文字上）：
- 简单信息窗：头像、名字、模糊血量描述

**模糊血量描述阈值**：
| HP 百分比 | 描述 |
|-----------|------|
| 100%-75% | 非常健康 |
| 75%-50% | 比较健康 |
| 50%-25% | 身体不错 |
| 25%-1% | 伤痕累累 |
| 0% | 已死亡 |

**点击显示**（非瞄准模式下点击敌人）：
- 模态框显示具体信息
- 测试阶段：显示所有信息
- 技能系统实装后：决定隐藏哪些信息

### 6.4 瞄准模式交互

**生命周期**：
1. 玩家拖技能进入预装填区
2. 如果技能需要瞄准（`type: 'single'`），进入瞄准模式
3. 地图上高亮显示技能射程内的可选目标（格/单位）
4. 玩家点击目标
5. 技能+目标组合临时保存在前端
6. 退出瞄准模式

**射程高亮**：类似当前"可达性格"的高亮，高亮玩家周围 N 格内的敌人。

### 6.5 动画播放

**两阶段呈现**：

**阶段一（模态框文字播报）**：
- 左上：敌人头像
- 右下：玩家头像
- 中间：文字播报区
- 头像旁：HP 条（播放前记录初始 HP，逐条应用 effect_value 更新）
- 位移用头像抖动模拟

**阶段二（地图动画，可选）**：
- 模态框关闭后回到地图
- 如果技术可行，播放单位位置变化动画
- MVP 阶段可先不做，直接刷新地图到最终状态

**播放控制**：
- 每条日志停留 1.2 秒（可配置）
- 玩家点击模态框：暂停/继续
- 玩家点击"跳过"：直接播放到最后，关闭模态框
- 跳过后仍需更新地图状态

### 6.6 播放流程

```
玩家提交预装填（obl_battle_execute）
    ↓
后端结算，返回 { battle_log, gamedata, battle_state }
    ↓
前端：
    1. 拉取 player_info + enemies，记录初始 HP
    2. 进入"播放模式"：
       for each log in battle_log:
           显示模态框（左上敌人头像 + 右下玩家头像 + 中间文字 + HP条）
           根据 log.effect_value 更新 HP 条
           停留 1.2s（可暂停/跳过）
           关闭模态框
           如果 log 是 battle.escape_success 或 battle.end：
               中止播放
    3. 播放完毕，刷新 game_map + player_info + enemies
    4. 检查 battle_state：
       - "battle" → 进入预装填界面（下一轮玩家先攻）
       - null → 退出战斗模式，恢复主界面
```

### 6.7 战斗模式进入/退出

**进入战斗模式**：
- 检测 `player_info` 的 `action` 字段变化
- `action = 'prebattle'` → 进入预装填界面（显示取消按钮）
- `action = 'battle'` → 进入战斗模式（无取消按钮）
- 敌人突袭：探索/移动响应带 `battle_event` 标记 → 前端进入战斗模式

**退出战斗模式**：
- `battle_state = null` → 恢复主界面
- 刷新所有面板（地图、背包、状态栏等）

## 七、动作日志渲染

### 7.1 渲染规则

后端只传数据（`action_id` + `effect_value`），前端根据 `action_id` 查模板渲染文字。

**渲染示例**：

| action_id | effect_value | 前端渲染 |
|-----------|--------------|---------|
| `basic_attack` | 15 | "A 攻击了 B → B 受到了 15 点伤害" |
| `basic_attack` | 0 | "A 攻击了 B → 但是没有命中" |
| `escape` | 1 | "A 尝试逃离 B → A 成功逃离！" |
| `escape` | 0 | "A 尝试逃离 B → A 没能逃离！" |
| `heal` | 20 | "A 使用了治疗 → 恢复了 20 点 HP" |
| `move` | - | "A 从格5移动到格3" |

### 7.2 额外效果渲染

`extra` 字段为结构化数据，前端渲染文字：

```javascript
// 后端传
extra: { type: 'status', status: 'bleed', duration: 3 }

// 前端渲染
"附加流血效果，持续 3 回合"
```

## 八、MVP 范围

### 8.1 包含

- **1v1 战斗**（后端先攻队列按 1vN 设计，前端按当前先攻者渲染）
- **玩家先攻轮**：预装填 + AP + 执行
- **NPC 先攻轮**：后端自动结算
- **策略槽**：非战斗时可配置，战斗中不可改
- **基础技能接口**：预留，MVP 硬编码 2-3 个技能（基础攻击、逃跑、位移）
- **战斗日志结构**：统一 `battle.action` ID
- **前端动画播放**：模态框逐条展示，可暂停/跳过
- **战斗中位移**：更新地图格位置
- **敌人 AI**：基础行为树（移动/攻击/发呆）
- **敌人突袭**：未发现敌人移动到玩家所在格
- **敌人信息展示**：悬浮模糊血量 + 点击详细模态框

### 8.2 不包含

- 技能系统（预留接口）
- AOE 范围技能（MVP 只做 single/self）
- 模拟功能（预装填阶段的"思考"）
- 混乱状态（AP 透支惩罚）
- BOSS 机制（突破 AP 限制的强力技能）
- 1vN 前端特殊渲染（后端支持，前端按 1v1 渲染）
- 地图动画（阶段二，MVP 直接刷新地图）
