# Oblivions 战斗系统设计案

> 基于 [原始方案/战斗设定.txt](原始方案/战斗设定.txt) 的策略回合制战斗系统。
>
> **核心设计**：战棋式回合制战斗，前后端分离——后端瞬间结算，前端逐步播放动画。
>
> **设计原则**：后端只传数据（动作索引 + 效果值），前端完全控制视觉呈现（文案、动画、HP 条）。

---

## 一、设计目标

### 1.1 核心目标

1. **战棋式战斗**：地图格为单位位置载体，技能需瞄准目标，图格位置至关重要
2. **前后端分离**：后端瞬间结算一个先攻轮生命周期，返回结构化动作日志；前端逐条播放动画
3. **策略导向**：预装填 + AP + 策略槽，非简单"选技能→释放"
4. **状态持久化**：战斗状态存数据库 `action` 字段，断线重连可恢复
5. **1vN 架构**：后端先攻队列按 1vN 设计，前端按当前先攻者渲染（1v1 和 1vN 无区别）

### 1.2 非目标

- **技能系统**：独立大系统，本设计案只预留接口，不实现技能定义
- **AOE 范围技能**：MVP 只做 single/self，aoe 形状定义留给技能系统
- **模拟功能**：预装填阶段的"思考"模拟，留待后续
- **混乱状态**：AP 透支惩罚机制，留待后续
- **BOSS 机制**：突破 AP 限制的强力技能，留待后续

## 二、核心概念

### 2.1 游戏刻（Tick）

游戏世界的行为驱动单元，由玩家行为而非时间驱动：

- **非战斗场合**：玩家行动（移动/探索）时更新一次游戏刻；思考、切换姿态、查看笔记不更新
- **战斗场合**：任意角色（玩家或 NPC）的一个先攻轮结束时，更新一次游戏刻
- **游戏刻更新时**：时间流逝、全局结算敌人 AI 行为、buff/dot 等时效内容结算一轮

### 2.2 先攻轮（Initiative Round）

战斗的核心循环单元，包含 s1-s5 五个阶段（详见 [原始方案](原始方案/战斗设定.txt)）：

- **s1**：先攻者第一个技能必定先手释放
- **s2**：防守者从策略槽建立防守执行队列（逃跑最优先）
- **s3**：防守者与先攻者再次先攻对抗，失败累乘 1.5 倍补正，成功则插队打出 1 个动作
- **s4**：先攻者继续下一个技能
- **s5**：先攻轮结束，游戏刻更新，选择下一顺位先攻者

> **阶段一简化**：s2/s3 暂不实现（无策略槽），先攻轮简化为 s1（先攻者行动）→ s5（切换先攻者）。

### 2.3 预装填（Preload）

玩家作为先攻者时的操作阶段：

- 拖拽技能/道具到"放置区"，按顺序排列
- 显示当前 AP 与预估消耗
- 完成后一次性按顺序打出所有动作
- 预装填阶段不更新游戏刻
- **预装填数据是前端临时状态，刷新页面后丢失，需重新配置**

> **阶段一无预装填**：玩家直接选择单个动作（攻击/逃跑）执行，不涉及拖拽装填。

### 2.4 AP（Action Points）

动作的资源约束：

- **唯一自然恢复手段**：先攻者在预装填阶段恢复（= 最大 AP）
- 自然恢复不超过最大 AP
- AP 为负数时，只能放入 AP 消耗为 0 的动作
- 防守者 s3 阶段可透支 AP（详见原始方案的混乱惩罚，MVP 不实现）

> **阶段一无 AP**：玩家每回合执行 1 个动作，无资源约束。`ap`/`max_ap` 字段已存在于 `bra_oblplayers` 表，阶段二启用。

### 2.5 策略槽（Strategy Slots）

防守者的预设反应配置：

- 非战斗时可配置，1-4 个槽
- 每个槽放 1 个技能或 1 件道具
- 战斗中不可修改
- 空槽默认填"逃跑"
- 道具消耗后对应槽变空

> **阶段一无策略槽**：防守方不预设反应，先攻轮只有先攻者行动。`tacpara` 字段已存在于 `bra_oblplayers` 表，阶段二启用。

### 2.6 先攻队列（Initiative Queue）

1vN / 多方混战时的行动顺序：

- 所有参战者进行先攻率随机数对抗，排定队列
- 每个参战者扮演一次先攻者后，重新生成随机数决定新队列
- 新加入者固定排序到队列末尾
- **玩家补偿**：未成为第一顺位时，获得第一顺位 25% 的先攻补偿，但最高只能成为第二顺位（仅玩家生效）

> **阶段一简化**：1v1 固定交替（玩家先攻 → 敌人先攻 → 玩家先攻 → ...），无随机先攻对抗。阶段二引入完整先攻队列。

### 2.7 射程（Range）

单位在战斗中可攻击的距离（地图格跳数），是一个**计算属性**而非存储属性：

```
最终射程 = 基础射程(1) + 武器射程补正 + 技能射程补正
```

- **基础射程**：所有单位默认 1（近战）
- **武器射程补正**：由武器类别（itmk）决定，详见 2.8 节武器类别射程表
- **技能射程补正**：某些技能自带射程修正（如远程技能），留待技能系统实现

**接口预留**：`obl_get_range($pdata)` 函数统一计算射程，战斗逻辑中所有射程判断都调此函数。
- 阶段一：固定返回 1
- 阶段二：根据装备武器类别计算
- 阶段三：叠加技能射程补正

**射程与战斗的关系**：
- 射程决定瞄准模式下可选目标的范围（玩家周围 N 格内的敌人）
- 射程 < 距离时无法选中目标
- 阶段一 1v1 固定交替，双方相邻，射程暂不影响战斗逻辑

### 2.8 武器攻击模式（Weapon Attack Modes）

武器不只是属性加成，它还定义了"你能做什么动作"——武器提供 1~N 个**攻击模式**（本质是技能 ID），这些技能可放入 AP 区（预装填区）。

**没有武器时**：默认攻击技能为 `unarmed_strike`（空手攻击），射程 1，伤害基于裸体 `att`。

**武器提供的三层补正**：

| 补正类型 | 来源 | 说明 |
|---------|------|------|
| 攻击力补正 | 武器效果值（itme） | 直接加到 `att` 上参与伤害计算 |
| 射程补正 | 武器类别（itmk） | 加到基础射程上，决定攻击距离 |
| 攻击模式 | 武器配置（itmpara） | 提供可放入 AP 区的技能 ID 列表 |

**武器类别射程补正表**：

| itmk | 类别 | 射程补正 | 典型攻击模式 | 说明 |
|------|------|---------|-------------|------|
| WP | 钝器 | 0 | `weapon_blunt` | 近战重击，高伤害 |
| WK | 刃器 | 0 | `weapon_blade` | 近战连斩，多段低伤 |
| WG | 枪械 | +3 | `weapon_gun` | 远程射击，稳定伤害 |
| WD | 投掷 | +2 | `weapon_throw` | 远程投掷，消耗弹药 |
| WF | 灵符 | +1 | `weapon_charm` | 中程符术，魔法伤害 |
| （无武器） | — | 0 | `unarmed_strike` | 空手攻击，基础伤害 |

> **注**：射程补正表为设计初值，后续根据平衡性调整。攻击模式的具体效果（伤害系数/命中/AP 消耗）留待技能系统定义，本设计案只预留接口。

**武器攻击模式的数据结构**：

武器的 `itmpara`（JSON）存储该武器提供的攻击模式列表：
```json
{
    "attack_modes": ["weapon_blade"]
}
```

- 单件武器可提供多个攻击模式（如魔法剑同时提供 `weapon_blade` + `weapon_charm`）
- 未配置 `attack_modes` 的武器，按武器类别回退到默认攻击模式
- 武器效果值（itme）作为攻击力补正，所有攻击模式共享

**接口预留**：
- `obl_get_range($pdata)`：计算射程（2.7 节）
- `obl_get_weapon_attack_modes($pdata)`：获取装备武器提供的攻击模式列表
- `obl_calc_damage($att, $def, $weapon_bonus = 0)`：伤害计算，预留武器补正参数

## 三、战斗状态机

### 3.1 三个 action 状态

玩家 `$pdata['action']` 字段标识战斗状态（字段已存在于 `bra_oblplayers` 表）：

| 状态 | 含义 | 界面表现 |
|------|------|---------|
| `null`/空 | 无战斗 | 正常探索/移动/拾取界面 |
| `prebattle` | 玩家主动发起，未真正开打 | 预装填界面 + `[执行]` + `[取消并退出战斗]` |
| `battle` | 真正进入战斗（突袭或缠斗） | 预装填界面（玩家先攻）/ 动画播放（NPC 先攻），无取消按钮 |

### 3.2 状态转换

```
null ──玩家点击已发现敌人──→ prebattle
null ──敌人突袭玩家────────→ battle
prebattle ──玩家执行预装填──→ battle（第一轮先攻后进入缠斗）
prebattle ──玩家取消────────→ null（清空 action）
battle ──玩家逃跑成功──────→ null
battle ──敌人全灭──────────→ null
```

### 3.3 进入战斗的条件

**A. 玩家主动攻击（→ prebattle）**：
- 玩家点击界面上已发现的敌人
- 后端变更 `action = 'prebattle'`，`bid = 敌人pid`
- 玩家可取消退出

**B. 敌人突袭（→ battle）**：
- 敌人未被发现（discovered=0）
- 游戏刻更新时（由玩家探索/移动触发），全局结算敌人 AI
- 敌人 AI 移动到玩家所在格（pls + pgroup 重叠）
- 后端变更 `action = 'battle'`，`bid = 敌人pid`，敌人先攻
- 前端播放敌人先攻轮动画

**C. 缠斗状态（→ battle）**：
- 玩家从 prebattle 执行预装填后，经历一轮先攻轮
- 敌人未死，双方保持缠斗
- `action = 'battle'`

### 3.4 退出战斗的条件

**A. prebattle 状态取消**：
- 预装填界面 `[取消并退出战斗]` 按钮
- 后端清空 `action` + `bid`，返回 `null`

**B. battle 状态（不可主动退出）**：
- 界面无 `[取消并退出战斗]` 按钮
- 玩家向后端传递指令也不能退出战斗

**C. 逃跑成功**：
- 玩家预装填"逃跑"技能并执行成功
- 后端结算清空 `action` + `bid`

**D. 敌人全灭**：
- 敌人死亡且先攻队列清空（无其他敌人）
- 后端结算清空 `action` + `bid`

## 四、数据结构

### 4.1 敌人数据

敌人和玩家数据统一保存在 `bra_oblplayers` 表，通过 `type` 字段区分：
- `type = 0`：玩家
- `type > 0`：敌人（NPC），值为敌人类型 ID（关联 `enemies_config.php`）

敌人数据结构与玩家同构（`$pdata`），战斗相关字段：
- 基础属性：`hp`/`mhp`/`sp`/`msp`/`att`/`def`
- 位置：`pgroup`/`pls`
- 战斗状态：`action`（null/prebattle/battle）、`bid`（战斗目标 pid）
- 发现状态：`discovered`（0=未发现, 1=已发现）
- 技能：`skillpara`（JSON，技能数据）
- 策略槽：`tacpara`（JSON，策略配置）
- 杂项：`oblpara`（JSON，含 `ai_type`/`vision_range`/`action_chance` 等）
- AP：`ap`/`max_ap`（独立字段，阶段二启用）
- 装备：`wep`（武器槽，6 字段：name/k/e/s/sk/para），武器的 `itme` 提供攻击力补正，`itmk` 提供射程补正，`itmpara` 提供攻击模式

### 4.2 动作日志结构（BattleLogEntry）

每条 `battle_log` 条目的结构：

```typescript
{
    id: 'battle.action',           // 统一 ID
    turn: number,                  // 第几个先攻轮
    actor: string,                 // 动作执行者标识（'player' | 'enemy_{pid}'）
    action_id: string,             // 动作索引 ID（技能 ID，如 'unarmed_strike'）
    action_name: string,           // 动作名称（如"空手攻击"）
    target: string,                // 动作目标标识（'player' | 'enemy_{pid}'）
    effect_value: number | number[],  // 效果值（int 或数组）
    extra: object | null,          // 额外效果（结构化，如 { type: 'status', status: 'bleed', duration: 3 }）
    position: object | null,       // 位移信息（如果有）
}
```

**position 结构**（位移动作时填充）：
```typescript
{
    actor_from: { pgroup: number, pls: number },
    actor_to: { pgroup: number, pls: number }
}
```

**effect_value 语义**（由 `action_id` 决定，前端渲染）：
- `unarmed_strike` / `weapon_*`：伤害值（int）
- `escape`：1=成功，0=失败
- `heal`：治疗值（int）
- `move`：无（位移信息在 position 字段）

### 4.3 持久化日志（obl_log 摘要）

战斗细节走 `command.php` 响应的 `battle_log` 字段（临时，不持久化）。
`obl_log` 只存战斗摘要：

| 日志 ID | logcategory | params | 说明 |
|---------|-------------|--------|------|
| `battle.start` | `battle` | `{ enemy_id, enemy_name }` | 战斗开始 |
| `battle.end` | `battle` | `{ result, enemy_id, enemy_name }` | 战斗结束（result: victory/defeat/escape） |
| `battle.skirmish` | `battle` | `{ enemy_name, enemy_pid, initiator }` | 碰撞交火（过渡实现，完整战斗后移除） |

## 五、后端设计

### 5.1 命令（command.php）

| 命令 | 触发场景 | 参数 | 说明 |
|------|---------|------|------|
| `obl_battle_start` | 玩家点击已发现敌人 | `{ enemy_pid }` | 后端设 `action='prebattle'`，`bid=enemy_pid`，返回 battle_state |
| `obl_battle_cancel` | prebattle 状态取消 | 无 | 后端清空 `action`+`bid`，返回 null |
| `obl_battle_execute` | 玩家执行动作 | `{ action_id, target }`（阶段一）/ `{ actions: [...] }`（阶段二） | 后端结算，返回 battle_log + gamedata |

**`obl_battle_execute` 响应格式**：
```json
{
    "success": true,
    "gamedata": { ... },
    "battle_log": [ BattleLogEntry, BattleLogEntry, ... ],
    "battle_state": "battle" | null,
    "timer": null
}
```

- `battle_log`：本批次所有动作日志（玩家先攻轮 + 所有 NPC 先攻轮，直到下次玩家先攻或战斗结束）
- `battle_state`：战斗结束后为 `null`，未结束为 `"battle"`

### 5.2 API（api_v2.php）

`enemies` API 已实现（详见 [oblivions/CODEBASE.md](../CODEBASE.md) 5.5 节），返回当前区域已发现的敌人列表。战斗状态下确保返回战斗对象（即使 `discovered=0`）。

### 5.4 战斗流程（后端视角）

```
玩家提交 obl_battle_execute
    ↓
后端结算玩家先攻轮：
    s1（先攻者行动）→ s5（游戏刻更新）
    ↓
检查先攻队列：
    ├── 还有 NPC 未行动 → 结算 NPC 先攻轮 → 游戏刻更新 → 循环
    └── 轮到玩家或战斗结束 → 停止
    ↓
返回 battle_log（所有动作日志）+ battle_state
```

**关键点**：后端一次性结算到"下次玩家先攻"或"战斗结束"，前端收到完整日志批次。

### 5.5 碰撞战斗过渡实现的替换

当前 `obl_resolve_collision_battle()`（[enemy_ai.func.php](../include/game/enemy_ai.func.php)）是过渡实现：设 `action='battle'` → emit 日志 → 立即清空。阶段一需替换为：

```php
function obl_resolve_collision_battle(&$a, &$b) {
    // $a 永远是发起方/移动方
    $a_is_player = ($a['type'] == 0);
    
    if ($a_is_player) {
        // 玩家撞上敌人 → 不应发生（玩家移动不会主动撞敌人，由敌人 AI 触发）
        // 防御性处理：进入 prebattle
        obl_battle_enter_prebattle($b['pid']);
    } else {
        // 敌人撞上玩家 → 突袭
        obl_battle_ambush($b, $a);  // $b=玩家, $a=敌人
    }
}
```

## 六、前端设计

### 6.1 模块拆分

```
vex/js/
├── battle.js          # 战斗主模块：状态机、流程控制、API 调用
├── battle-player.js   # 战斗动画播放器：模态框、逐条播放、暂停/跳过
├── battle-preload.js  # 预装填界面：AP槽、放置区、技能拖拽、瞄准模式
└── battle-render.js   # 战斗日志渲染：解析 battle_log，生成模态框内容
```

> **阶段一**：只需 `battle.js` + `battle-render.js`（最简战斗界面，无预装填/动画播放器）。

### 6.2 界面布局（战斗模式）

战斗模式下主界面布局调整：

**左侧（地图区）**：
- 始终保留，显示地图
- 高亮敌人位置（图标或文字 `[敌人A]` + 地名）
- 瞄准模式下高亮射程内可选目标（射程由 `obl_get_range()` 决定）
- 玩家位置始终显示

**右侧（从上到下）**：
- **CHRONICLE 区** → 替换为**技能/道具栏**（可拖拽源）
- **ACTIONS 区** → 替换为**AP 槽 + 放置区**（拖拽目标）

**AP 槽 + 放置区**内容：
- 当前 AP / 最大 AP（数字 + 可视化条）
- 放置区：已装填的动作列表（按顺序）
- 每个装填项显示：动作名 + 目标 + AP 消耗
- `[执行]` 按钮（提交预装填）
- `[取消并退出战斗]` 按钮（仅 prebattle 状态）

**技能/道具栏**内容：
- 技能列表（图标 + 名称 + AP 消耗 + 射程）
  - 武器攻击模式由 `obl_get_weapon_attack_modes()` 提供
  - 无武器时显示"空手攻击"
- 道具列表（复用背包数据）
- 可拖拽到放置区

> **阶段一简化**：右侧只显示动作按钮列表（`[空手攻击]` `[逃跑]`），无拖拽/AP 槽。

### 6.3 敌人信息展示

**悬浮显示**（光标移到敌人图标/文字上）：
- 简单信息窗：头像、名字、模糊血量描述

**模糊血量描述阈值**：
| HP 百分比 | 描述 |
|-----------|------|
| 100%-75% | 非常健康 |
| 75%-50% | 比较健康 |
| 50%-25% | 身体不错 |
| 25%-1% | 伤痕累累 |
| 0% | 已死亡 |

**点击显示**（非瞄准模式下点击敌人）：
- 模态框显示具体信息
- 测试阶段：显示所有信息
- 技能系统实装后：决定隐藏哪些信息

### 6.4 瞄准模式交互

**生命周期**：
1. 玩家拖技能进入预装填区
2. 如果技能需要瞄准（`type: 'single'`），进入瞄准模式
3. 地图上高亮显示技能射程内的可选目标（格/单位）
4. 玩家点击目标
5. 技能+目标组合临时保存在前端
6. 退出瞄准模式

**射程高亮**：类似当前"可达性格"的高亮，高亮玩家周围 `obl_get_range()` 格内的敌人。

> **阶段一无瞄准**：1v1 只有一个目标，点击敌人直接进入 prebattle，无需瞄准。

### 6.5 动画播放

**两阶段呈现**：

**阶段一（模态框文字播报）**：
- 左上：敌人头像
- 右下：玩家头像
- 中间：文字播报区
- 头像旁：HP 条（播放前记录初始 HP，逐条应用 effect_value 更新）
- 位移用头像抖动模拟

**阶段二（地图动画，可选）**：
- 模态框关闭后回到地图
- 如果技术可行，播放单位位置变化动画
- MVP 阶段可先不做，直接刷新地图到最终状态

**播放控制**：
- 每条日志停留 1.2 秒（可配置）
- 玩家点击模态框：暂停/继续
- 玩家点击"跳过"：直接播放到最后，关闭模态框
- 跳过后仍需更新地图状态

> **阶段一简化**：无动画播放器，battle_log 直接渲染为文字列表显示在战斗界面，玩家点击动作按钮后刷新列表。

### 6.6 播放流程

```
玩家提交动作（obl_battle_execute）
    ↓
后端结算，返回 { battle_log, gamedata, battle_state }
    ↓
前端：
    1. 拉取 player_info + enemies，记录初始 HP
    2. 进入"播放模式"：
       for each log in battle_log:
           显示模态框（左上敌人头像 + 右下玩家头像 + 中间文字 + HP条）
           根据 log.effect_value 更新 HP 条
           停留 1.2s（可暂停/跳过）
           关闭模态框
           如果 log 是 battle.escape_success 或 battle.end：
               中止播放
    3. 播放完毕，刷新 game_map + player_info + enemies
    4. 检查 battle_state：
       - "battle" → 进入预装填界面（下一轮玩家先攻）
       - null → 退出战斗模式，恢复主界面
```

### 6.7 战斗模式进入/退出

**进入战斗模式**：
- 检测 `player_info` 的 `action` 字段变化
- `action = 'prebattle'` → 进入预装填界面（显示取消按钮）
- `action = 'battle'` → 进入战斗模式（无取消按钮）
- 敌人突袭：探索/移动响应带 `battle_event` 标记 → 前端进入战斗模式

**退出战斗模式**：
- `battle_state = null` → 恢复主界面
- 刷新所有面板（地图、背包、状态栏等）

## 七、实施计划（三阶段）

### 7.1 阶段一：最小战斗闭环

**目标**：跑通 1v1 战斗的完整流程，验证状态机 + 后端结算 + 前端渲染的链路。

**后端**：
- 替换 `obl_resolve_collision_battle()` 过渡实现 → 调用 `obl_battle_ambush()`
- 实现 `obl_battle_enter_prebattle($enemy_pid)`：校验 + 设 `action='prebattle'` + `bid`
- 实现 `obl_battle_cancel()`：清空 `action` + `bid`
- 实现 `obl_battle_execute($action_id, $target)`：结算 1 个先攻轮
- 实现 `obl_execute_action($actor, $action)`：硬编码 2 个技能
  - `unarmed_strike`：伤害 = `obl_calc_damage(att, def, 0)`（保底 1），扣 HP
  - `escape`：50% 概率成功，成功则清空 `action` + `bid`
- 实现战斗结束判定：一方 HP ≤ 0 → 清空 `action` + `bid` + emit `battle.end`
- 实现接口预留函数（阶段一返回固定值）：
  - `obl_get_range($pdata)` → 返回 1
  - `obl_get_weapon_attack_modes($pdata)` → 返回 `['unarmed_strike']`
  - `obl_calc_damage($att, $def, $weapon_bonus = 0)` → `max(1, $att - $def)`（阶段一 `$weapon_bonus` 传 0）
- 新增命令：`obl_battle_start` / `obl_battle_cancel` / `obl_battle_execute`
- 先攻轮简化：s1（先攻者行动）→ s5（切换先攻者），无 s2/s3
- 先攻队列简化：1v1 固定交替（玩家↔敌人）

**前端**：
- `battle.js`：战斗状态机（检测 `action` 字段变化，进入/退出战斗模式）
- `battle-render.js`：渲染 `battle_log` 为文字列表
- 最简战斗界面：右侧显示 `[空手攻击]` `[逃跑]` 按钮 + 战斗日志区
- 无预装填、无 AP、无策略槽、无动画播放器、无瞄准模式

**硬编码技能清单**：

| action_id | 名称 | 效果 | 阶段一 |

| `weapon_blunt` | 钝器攻击 | 武器攻击模式，伤害含 itme 补正 | ❌ 阶段二 |

| `weapon_throw` | 投掷 | 武器攻击模式，消耗弹药 | ❌ 阶段二 |
