# Oblivions 战斗系统设计案

> 基于 [原始方案/战斗设定.txt](原始方案/战斗设定.txt) 的策略回合制战斗系统。
>
> **核心设计**：战棋式回合制战斗，前后端分离——后端瞬间结算，前端逐步播放动画。
>
> **设计原则**：后端只传数据（动作索引 + 效果值），前端完全控制视觉呈现（文案、动画、HP 条）。
>
> **关联文档**：
> - [游戏刻机制设计案.md](游戏刻机制设计案.md)：游戏刻推进、事件处理、前端自动刷新机制
> - [战斗系统重构设计案.md](战斗系统重构设计案.md)：先攻轮单方性、先攻率、先攻队列、遭遇战
> - [战斗演出系统设计案.md](战斗演出系统设计案.md)：三阶段播放、played 标记、并发锁、回合指示器

## 一、设计目标

### 1.1 核心目标

1. **战棋式战斗**：地图格为单位位置载体，技能需瞄准目标，图格位置至关重要
2. **前后端分离**：后端瞬间结算一个先攻轮生命周期，返回结构化动作日志；前端逐条播放动画
3. **策略导向**：预装填 + AP + 策略槽，非简单"选技能→释放"
4. **状态持久化**：战斗状态存数据库 `action` 字段，断线重连可恢复
5. **1v1v1v1 架构**：每个敌人独立战斗单元，先攻队列可多参战者，每次攻击 1对1

### 1.2 非目标

- **技能系统**：独立大系统，本设计案只预留接口，不实现技能定义
- **AOE 范围技能**：MVP 只做 single/self，aoe 形状定义留给技能系统
- **模拟功能**：预装填阶段的"思考"模拟，留待后续
- **混乱状态**：AP 透支惩罚机制，留待后续
- **BOSS 机制**：突破 AP 限制的强力技能，留待后续

### 1.3 设计原则

- **不写过渡代码**：要么做完整版，要么用现有版。不要写"未来一定会重写的东西"
- **1v1v1v1 而非 1vN**：每个敌人独立战斗单元，每次攻击 1对1，群体伤害是分别判定多个 1对1 事件
- **NPC 行为由游戏刻更新统一驱动**：战斗流程不越权处理 NPC 行为，详见 [游戏刻机制设计案](游戏刻机制设计案.md)

## 二、核心概念

### 2.1 游戏刻（Tick）

游戏世界的行为驱动单元，详见 [游戏刻机制设计案](游戏刻机制设计案.md)。

**核心要点**：
- 1 游戏刻 = 1 单位时间 = 1 次请求
- 玩家行动 / NPC 先攻轮推进游戏刻
- 非战斗 NPC 行为不推进游戏刻（并行，同时发生）
- 一次 `obl_resolve_tick_events()` 最多推进 1 游戏刻

**时间消耗模型**：
- 玩家行动（移动/探索）：`obl_command.php` [F] 段推进游戏刻
- 玩家先攻轮：`obl_command.php` [F] 段推进游戏刻
- NPC 先攻轮：`obl_resolve_tick_events()` 末尾推进游戏刻
- 非战斗 NPC AI 行为：不推进游戏刻（并行）

### 2.2 先攻轮（Initiative Round）

战斗的核心循环单元，详见 [战斗系统重构设计案](战斗系统重构设计案.md)。

**核心要点**：
- 先攻轮单方性：只有先攻者行动，防守者不行动（s2/s3 推迟到批次 2.5）
- 先攻率机制：先攻者进行先攻率随机数对抗，排定队列
- 先攻队列：每个参战者扮演一次先攻者后，重新生成随机数决定新队列
- 新加入者固定排序到队列末尾

**先攻轮简化**（当前阶段）：
- s1（先攻者行动）→ s5（切换先攻者），无 s2/s3
- s2/s3 推迟到批次 2.5

### 2.3 预装填（Preload）

玩家作为先攻者时的操作阶段：

**两种预装填状态**：
- **首次预装填**（临时状态）：玩家主动点击敌人后，前端切换为预装填界面。不保存到后端，可以随时取消，刷新页面后不保留记忆。
- **战斗中预装填**（持久化页面）：玩家在战斗状态中，执行到先攻轮之前的预装填阶段。刷新后需要保持战斗页面（和现在战斗页面逻辑一样）。

**预装填界面内容**：
- 拖拽技能/道具到"放置区"，按顺序排列
- 显示当前 AP 与预估消耗
- 完成后一次性按顺序打出所有动作
- 预装填阶段不更新游戏刻

**预装填数据**：
- 不需要持久化"玩家装填了哪些技能"
- 装填的具体内容是前端临时状态，提交后即清空
- 后端可引入 prebattle 逻辑阶段处理装填技能接收和 NPC 行为树读取

### 2.4 AP（Action Points）

动作的资源约束：

- **AP 是数据库持久化字段**：初次战斗直接读取玩家数据里的 AP 和 maxAP
- **AP 恢复公式**：`AP = min(AP + maxAP, maxAP)`
  - 注意是加法（AP += maxAP），不是赋值（AP = maxAP）
  - 因为 AP 可能为负数（透支）
  - AP 恢复后封顶 maxAP，但负数时不封底
- **AP 恢复时机**：prebattle 阶段触发 AP 恢复事件
- AP 为负数时，只能放入 AP 消耗为 0 的动作
- 防守者 s3 阶段可透支 AP（详见原始方案的混乱惩罚，MVP 不实现）

**AP 恢复示例**：
- AP = -5, maxAP = 10 → min(-5+10, 10) = 5
- AP = 3, maxAP = 10 → min(3+10, 10) = 10
- AP = -15, maxAP = 10 → min(-15+10, 10) = -5（仍为负，只能放 AP 消耗为 0 的动作）

### 2.5 策略槽（Strategy Slots）

防守者的预设反应配置：

- 非战斗时可配置，1-4 个槽
- 每个槽放 1 个技能或 1 件道具
- 战斗中不可修改
- 空槽默认填"逃跑"
- 道具消耗后对应槽变空

> **推迟到批次 2.5**：s2/s3 防守者策略槽反应推迟到批次 2.5 实现。

### 2.6 先攻队列（Initiative Queue）

1v1v1v1 架构的行动顺序，详见 [战斗系统重构设计案](战斗系统重构设计案.md)：

- 所有参战者进行先攻率随机数对抗，排定队列
- 每个参战者扮演一次先攻者后，重新生成随机数决定新队列
- 新加入者固定排序到队列末尾
- **玩家补偿**：未成为第一顺位时，获得第一顺位 25% 的先攻补偿，但最高只能成为第二顺位（仅玩家生效）

### 2.7 射程（Range）

单位在战斗中可攻击的距离（地图格跳数），是一个**计算属性**而非存储属性：

```
最终射程 = 基础射程(1) + 武器射程补正 + 技能射程补正
```

- **基础射程**：所有单位默认 1（近战）
- **武器射程补正**：由武器类别（itmk）决定，详见 2.8 节武器类别射程表
- **技能射程补正**：某些技能自带射程修正（如远程技能），留待技能系统实现

**接口预留**：`obl_get_range($pdata)` 函数统一计算射程，战斗逻辑中所有射程判断都调此函数。

**射程与战斗的关系**：
- 射程决定瞄准模式下可选目标的范围（玩家周围 N 格内的敌人）
- 射程 < 距离时无法选中目标

### 2.8 武器攻击模式（Weapon Attack Modes）

武器不只是属性加成，它还定义了"你能做什么动作"——武器提供 1~N 个**攻击模式**（本质是技能 ID），这些技能可放入 AP 区（预装填区）。

**没有武器时**：默认攻击技能为 `unarmed_strike`（空手攻击），射程 1，伤害基于裸体 `att`。

**武器提供的三层补正**：

| 补正类型 | 来源 | 说明 |
|---------|------|------|
| 攻击力补正 | 武器效果值（itme） | 直接加到 `att` 上参与伤害计算 |
| 射程补正 | 武器类别（itmk） | 加到基础射程上，决定攻击距离 |
| 攻击模式 | 武器配置（itmpara） | 提供可放入 AP 区的技能 ID 列表 |

**武器类别射程补正表**：

| itmk | 类别 | 射程补正 | 典型攻击模式 | 说明 |
|------|------|---------|-------------|------|
| WP | 钝器 | 0 | `weapon_blunt` | 近战重击，高伤害 |
| WK | 刃器 | 0 | `weapon_blade` | 近战连斩，多段低伤 |
| WG | 枪械 | +3 | `weapon_gun` | 远程射击，稳定伤害 |
| WD | 投掷 | +2 | `weapon_throw` | 远程投掷，消耗弹药 |
| WF | 灵符 | +1 | `weapon_charm` | 中程符术，魔法伤害 |
| （无武器） | — | 0 | `unarmed_strike` | 空手攻击，基础伤害 |

> **注**：射程补正表为设计初值，后续根据平衡性调整。攻击模式的具体效果（伤害系数/命中/AP 消耗）留待技能系统定义，本设计案只预留接口。

**武器攻击模式的数据结构**：

武器的 `itmpara`（JSON）存储该武器提供的攻击模式列表：
```json
{
    "attack_modes": ["weapon_blade"]
}
```

- 单件武器可提供多个攻击模式（如魔法剑同时提供 `weapon_blade` + `weapon_charm`）
- 未配置 `attack_modes` 的武器，按武器类别回退到默认攻击模式
- 武器效果值（itme）作为攻击力补正，所有攻击模式共享

**接口预留**：
- `obl_get_range($pdata)`：计算射程（2.7 节）
- `obl_get_weapon_attack_modes($pdata)`：获取装备武器提供的攻击模式列表
- `obl_calc_damage($att, $def, $weapon_bonus = 0)`：伤害计算，预留武器补正参数

### 2.9 动作瞄准模式

动作的瞄准分三种模式：

- **单选模式**：选择一个目标（阶段二实现）
- **多选模式**：选择多个目标（todo，留待技能系统）
- **多格模式**：一个固定的图格形状，玩家在地图上选择一个图格为中心点，瞄准被技能形状包含在内的目标（todo，复杂）

阶段二只实现单选模式，这与 1v1v1v1 设计一致：每次攻击 1 个目标。多选/多格模式作为 todo，留给技能系统。

## 三、战斗状态机

### 3.1 两个 action 状态

玩家 `$pdata['action']` 字段标识战斗状态（字段已存在于 `bra_oblplayers` 表）：

| 状态 | 含义 | 界面表现 |
|------|------|---------|
| `null`/空 | 无战斗 | 正常探索/移动/拾取界面 |
| `battle` | 真正进入战斗（突袭或缠斗） | 预装填界面（玩家先攻）/ 动画播放（NPC 先攻），无取消按钮 |

> **注**：原设计案的 `prebattle` 状态已取消。玩家主动点击敌人后，前端切换为预装填界面（临时状态），玩家配置完动作后提交 `obl_battle_start` 命令直接进入 `battle` 状态。

### 3.2 状态转换

```
null ──玩家点击已发现敌人──→ 前端临时预装填界面（action 仍为 null）
null ──玩家提交 obl_battle_start──→ battle（先攻判定 + 玩家/NPC 先攻轮）
null ──敌人突袭玩家────────→ battle（敌人先攻）
battle ──玩家逃跑成功──────→ null
battle ──敌人全灭──────────→ null
```

### 3.3 进入战斗的条件

**A. 玩家主动攻击（→ battle）**：
- 玩家点击界面上已发现的敌人
- 前端切换为预装填界面（临时状态，action 仍为 null）
- 玩家配置动作序列后提交 `obl_battle_start` 命令
- 后端 `obl_battle_initiate()`：校验目标 → 设 `action='battle'` → 先攻判定 → 玩家/NPC 先攻轮

**B. 敌人突袭（→ battle）**：
- 敌人未被发现（discovered=0）
- 游戏刻更新时（由玩家探索/移动触发），全局结算敌人 AI
- 敌人 AI 移动到玩家所在格（pls + pgroup 重叠）
- 后端 `obl_battle_encounter()`：设 `action='battle'` → 先攻判定 → NPC 先攻轮
- 前端播放 NPC 先攻轮动画

### 3.4 退出战斗的条件

**A. battle 状态（不可主动退出）**：
- 界面无 `[取消并退出战斗]` 按钮
- 玩家向后端传递指令也不能退出战斗

**B. 逃跑成功**：
- 玩家预装填"逃跑"技能并执行成功
- 后端结算清空 `action` + `bid`

**C. 敌人全灭**：
- 敌人死亡且先攻队列清空（无其他敌人）
- 后端结算清空 `action` + `bid`

## 四、数据结构

### 4.1 敌人数据

敌人和玩家数据统一保存在 `bra_oblplayers` 表，通过 `type` 字段区分：
- `type = 0`：玩家
- `type > 0`：敌人（NPC），值为敌人类型 ID（关联 `enemies_config.php`）

敌人数据结构与玩家同构（`$pdata`），战斗相关字段：
- 基础属性：`hp`/`mhp`/`sp`/`msp`/`att`/`def`
- 位置：`pgroup`/`pls`
- 战斗状态：`action`（null/battle）、`bid`（战斗目标 pid）
- 发现状态：`discovered`（0=未发现, 1=已发现）
- 技能：`skillpara`（JSON，技能数据）
- 策略槽：`tacpara`（JSON，策略配置）
- 杂项：`oblpara`（JSON，含 `ai_type`/`vision_range`/`action_chance`/`battle` 等）
- AP：`ap`/`max_ap`（独立字段，阶段二启用）
- 装备：`wep`（武器槽，6 字段：name/k/e/s/sk/para），武器的 `itme` 提供攻击力补正，`itmk` 提供射程补正，`itmpara` 提供攻击模式

### 4.2 动作日志结构（BattleLogEntry）

每条 `battle_log` 条目的结构（详见 [战斗演出系统设计案](战斗演出系统设计案.md)）：

```typescript
{
    id: 'battle.action',           // 统一 ID
    turn: number,                  // 第几个先攻轮（0=战斗开始）
    actor: string,                 // 动作执行者标识（'player' | 'enemy_{pid}'）
    action_id: string,             // 动作索引 ID（技能 ID，如 'unarmed_strike'）
    action_name: string,           // 动作名称（如"空手攻击"）
    target: string,                // 动作目标标识（'player' | 'enemy_{pid}'）
    effect_value: number | number[],  // 效果值（int 或数组）
    extra: object | null,          // 额外效果（结构化，如 { type: 'status', status: 'bleed', duration: 3 }）
    position: object | null,       // 位移信息（如果有）
}
```

**effect_value 语义**（由 `action_id` 决定，前端渲染）：
- `unarmed_strike` / `weapon_*`：伤害值（int）
- `escape`：1=成功，0=失败
- `heal`：治疗值（int，前端显示为绿色 +N）
- `move`：无（位移信息在 position 字段）

### 4.3 played 标记机制

战斗日志的播放机制，详见 [战斗演出系统设计案](战斗演出系统设计案.md)：

- 后端持久化所有 battlelog，`played=0`（未播放），`log_id`（自增），`enemy_pid`
- 前端 fetch `played=0` 的日志 → 三阶段播放 → 调用 `mark_battle_log_played.php` 标记 `played=1`
- 前端播放完后自动发 `api_v2` 请求，触发游戏刻更新（详见 [游戏刻机制设计案](游戏刻机制设计案.md)）

## 五、后端设计

### 5.1 命令（command.php）

| 命令 | 触发场景 | 参数 | 说明 |
|------|---------|------|------|
| `obl_battle_start` | 玩家提交首次预装填 | `{ enemy_pid, actions: [...] }` | 后端 `obl_battle_initiate()` → 先攻判定 → 玩家/NPC 先攻轮 |
| `obl_battle_action` | 玩家提交战斗中预装填 | `{ actions: [...] }` | 后端 `obl_battle_resolve_round()` → 玩家先攻轮 |

> **注**：原设计案的 `obl_battle_cancel` 命令已移除（prebattle 状态取消）。原设计案的 `obl_battle_execute` 命令改名为 `obl_battle_action`。

**命令响应格式**：
```json
{
    "success": true,
    "gamedata": { ... },
    "battle_state": "battle" | null,
    "timer": null
}
```

- `battle_state`：战斗结束后为 `null`，未结束为 `"battle"`
- battlelog 不在命令响应中返回，前端通过 played 标记机制拉取

### 5.2 API（api_v2.php）

`enemies` API 已实现，返回当前区域已发现的敌人列表。战斗状态下确保返回战斗对象（即使 `discovered=0`）。

`battle_log` API 已实现，返回 `played=0` 的战斗日志。

`player_info` API 已实现，包含 `oblpara.battle`（先攻队列、当前先攻者等）。

### 6.2 界面布局（战斗模式）

战斗模式下主界面布局调整：

**左侧（地图区）**：
- 始终保留，显示地图
- 高亮敌人位置（图标或文字 `[敌人A]` + 地名）
- 瞄准模式下高亮射程内可选目标（射程由 `obl_get_range()` 决定）
- 玩家位置始终显示

**右侧（从上到下）**：
- **CHRONICLE 区** → 替换为**技能/道具栏**（可拖拽源）
- **ACTIONS 区** → 替换为**AP 槽 + 放置区**（拖拽目标）

**AP 槽 + 放置区**内容：
- 当前 AP / 最大 AP（数字 + 可视化条）
- 放置区：已装填的动作列表（按顺序）
- 每个装填项显示：动作名 + 目标 + AP 消耗
- `[执行]` 按钮（提交预装填）

**技能/道具栏**内容：
- 技能列表（图标 + 名称 + AP 消耗 + 射程）
  - 武器攻击模式由 `obl_get_weapon_attack_modes()` 提供
  - 无武器时显示"空手攻击"
- 道具列表（复用背包数据）
- 可拖拽到放置区

### 6.3 敌人信息展示

**悬浮显示**（光标移到敌人图标/文字上）：
- 简单信息窗：头像、名字、模糊血量描述

**模糊血量描述阈值**：
| HP 百分比 | 描述 |
|-----------|------|
| 100%-75% | 非常健康 |
| 75%-50% | 比较健康 |
| 50%-25% | 身体不错 |
| 25%-1% | 伤痕累累 |
| 0% | 已死亡 |

**点击显示**（非瞄准模式下点击敌人）：
- 模态框显示具体信息
- 测试阶段：显示所有信息
- 技能系统实装后：决定隐藏哪些信息

### 6.4 瞄准模式交互

**生命周期**：
1. 玩家拖技能进入预装填区
2. 如果技能需要瞄准（`type: 'single'`），进入瞄准模式
3. 地图上高亮显示技能射程内的可选目标（格/单位）
4. 玩家悬停目标 → 显示弹道线（从玩家到目标的轨迹预览）
5. 玩家点击目标 → 弹道线确认，技能+目标组合保存到放置区
6. 退出瞄准模式

**弹道线视觉**：
- 简单的 SVG 线条或 CSS 轨迹
- 颜色根据武器类别区分（枪械=黄色直线，投掷=橙色抛物线，灵符=紫色虚线）
- 射程范围用半透明高亮格表示，已选目标用实线轨迹

**射程高亮**：类似当前"可达性格"的高亮，高亮玩家周围 `obl_get_range()` 格内的敌人。

### 6.5 动画播放

**三阶段播放**（已实现，详见 [战斗演出系统设计案](战斗演出系统设计案.md)）：

1. **碰撞动画**：攻击方冲刺 + 受击方抖动（450ms）
2. **模态框**：详细日志播放（逐条，可暂停/跳过）
3. **滞留伤害数字**：模态框关闭后，伤害数字在地图上淡入显示

**治疗动作的演出**：
- 碰撞动画：自己抖一下（攻击方=受击方=自己，复用现有动画）
- 滞留数字：绿色 +N（而不是红色 -N）

**远程武器的演出**：
- 直接用现有碰撞动画（冲刺+抖动），不管近战远程
- 不做"远程武器简化版碰撞动画"（不写过渡代码原则）
- 未来如果要做完整弹道演出，直接替换现有动画

### 6.6 预装填多动作的播放

**分开播放**：预装填多个动作时，每个动作独立播放三阶段。

```
动作1（攻击A）→ 碰撞动画 → 模态框 → 滞留伤害数字
  ↓ 间隔
动作2（治疗自己）→ 碰撞动画（自己抖）→ 模态框 → 滞留数字（绿色 +N）
  ↓ 间隔
动作3（攻击B）→ 碰撞动画 → 模态框 → 滞留伤害数字
```

**合并播放**（todo）：
- 如果多个动作攻击同一目标，可以考虑合并播放
- 需要对 battlelog 结构进行设计（标记同一目标的连续动作）
- 作为未来优化

### 6.7 前端自动刷新

战斗中 NPC 先攻轮推进游戏刻后，前端自动发 `api_v2` 请求触发下次游戏刻更新，详见 [游戏刻机制设计案](游戏刻机制设计案.md)。

**自动刷新循环**：
```javascript
async function autoRefreshLoop() {
    while (true) {
        const logs = await fetchBattleLog();  // fetch played=0
        if (logs.length === 0) break;  // 没有新日志，停止
        
        await playBattleLogGroup(logs);  // 三阶段播放
        await markBattleLogPlayed(logs);  // 标记 played=1
        
        const playerInfo = await fetchPlayerInfo();  // 刷新页面
        if (playerInfo.action !== 'battle') break;  // 战斗结束，停止
        if (isPlayerTurn(playerInfo)) break;  // 玩家先攻轮，停止
    }
}
```

### 6.8 战斗模式进入/退出

**进入战斗模式**：
- 检测 `player_info` 的 `action` 字段变化
- `action = 'battle'` → 进入战斗模式（无取消按钮）
- 敌人突袭：探索/移动响应带 `battle_event` 标记 → 前端进入战斗模式

**退出战斗模式**：
- `battle_state = null` → 恢复主界面
- 刷新所有面板（地图、背包、状态栏等）
