# 前端统一调试参数设计案

## 1. 目标

Vex-Vue 的前端调试能力统一使用一个 URL 参数 `debug`。业务模块不得再自行新增 `actor_debug`、`actor_labels`、`poll_error` 等平级参数，也不得各自解析 `window.location.search`。

## 2. 规范

`debug` 的值是以英文逗号分隔的能力标识：

```txt
?debug=ai
?debug=actor
?debug=actor,labels
?debug=error-poll
?debug=ai,actor,labels,error-poll
?debug=all
```

能力语义：

| 标识 | 语义 |
|---|---|
| `ai` | 显示 AI/debug 日志和诊断 Toast |
| `actor` | 开启 ActorRuntime、PlaybackStep 等详细动作轨迹 |
| `labels` | 在角色头顶显示当前动作名或动作 id |
| `error-poll` | 开启后端错误日志的独立轮询，并显示诊断 Toast |
| `all` | 开启以上全部能力 |

标识可以任意组合，未知标识忽略。`labels` 与 `actor` 相互独立，避免为了查看头顶标签被迫产生完整轨迹记录。

## 3. 代码边界

1. `src/utils/debug-flags.ts` 是唯一的 URL 调试参数解析入口。
2. 业务模块只通过 `isDebugEnabled()` 或集中导出的 flags 判断能力。
3. 开发环境默认开启 Actor 轨迹是构建环境策略，不改变 URL 参数语义。
4. 旧参数不再兼容，避免长期形成两套地址结构。

## 4. Actor 头顶标签

`labels` 标签必须读取 ActorRuntime 的真实命令生命周期，不读取 Director 计划，也不使用定时器推测：

1. `PresentationLease.play()` 成功创建动画 handle 后登记命令。
2. handle 完成、取消或被替换时移除命令。
3. 同一 Actor 有多个并行动画时显示最后启动且仍未结束的命令；该命令结束后回退到仍在运行的上一命令。
4. 标签显示 `owner / command`，例如 `battle / attack:ranged`、`world / move:long`，DOM 的 `title` 保留 session id。
5. 标签仅在 `?debug=labels`、包含 `labels` 的组合或 `?debug=all` 时创建，不参与正式 UI 布局。
