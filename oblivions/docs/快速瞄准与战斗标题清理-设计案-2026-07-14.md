[StatusBar.vue:181-186](file:///d:/wamp64/www/phpdts/vex-vue/src/components/layout/StatusBar.vue#L181-L186) 的战斗按钮有三态，存在两处问题：

## 二、快速瞄准（方向 A）

### 2.1 痛点与目标

**痛点**：连续对同一敌人放多个技能（如攻击A → 投掷A → 处决A），每次都要进入瞄准模式、在地图上找到并点击同一敌人。重复操作量大。

**目标**：提供一条"用上次目标快速入队"的并行快捷路径，不改变默认瞄准流程。

### 2.2 交互设计

**核心规则**：技能库中，需要瞄准敌人的技能（`aimType === 'pid'`），当队列中已存在 pid 类型目标时，项右侧显示 `→[目标名]` 快捷标签。

- **点击快捷标签**：校验射程 + 目标有效性 → 直接入队（跳过瞄准模式）
- **点击技能本身**：正常进入瞄准模式（默认行为不变）
- `@click.stop` 阻止冒泡到技能项的 click

```
┌──────────────────────────────────────────┐
│ [空手攻击]  AP:1 R:1   →兔子  攻击       │ ← 队列已有 pid 目标"兔子"时
└──────────────────────────────────────────┘
         ↑点击技能本体    ↑点击快速瞄准
```

**不显示快捷标签的条件**：
- 队列中无 pid 类型目标（`lastPidTarget` 为 null）
- 技能非 `aimType === 'pid'`（tile/self/none 类不显示）
- 该技能是终结技且队列已有终结技（耗尽态——快速添加必然失败，不提供快捷入口）
- 目标不在该技能射程内（含目标已死亡/状态变化）

### 2.3 数据派生

```ts
/** 队列中最后一个 pid 类型目标（快速瞄准数据源） */
const lastPidTarget = computed<{ pid: number; name: string; pls: number | string | null } | null>(() => {
  for (let i = queue.value.length - 1; i >= 0; i--) {
    const item = queue.value[i];
    if (item.target.type === 'pid') {
      const pid = parseInt(String(item.target.id));
      const target = getCombatTarget(pid);
      const name = target?.name || `目标${pid}`;
      const pls = (target as { pls?: number | string | null } | null)?.pls ?? null;
      return { pid, name, pls };
    }
  }
  return null;
});
```

**取"最后一个"而非"最频繁"的理由**：用户规划时序时，最近的决策最能代表当前意图。如果用户先打 A 再打 B，"快速瞄准"应指向 B 而非 A。

**`pls` 字段的作用**：`lastPidTarget` 同时携带目标的 `pls`（位置），用于生成消除同名歧义的显示标签 `名字(位置)`。位置是玩家在地图上识别敌人的主要方式，是 PID 之外最强的人类可读识别码。

**快速瞄准位置推算缓存**：快速瞄准是追加到队列末尾，前缀队列就是完整 `queue.value`。所有技能共享同一推算位置，用 computed 缓存避免每项重复计算：

```ts
/** 快速瞄准推算的玩家位置（前缀 = 完整 queue，因为快速瞄准追加到末尾） */
const quickAimPlannedLoc = computed(() => getPlannedActorPls());
```

**显示标签派生**：始终带位置以消除同名敌人歧义，位置缺失时（极端兜底）退化为纯名字：

```ts
/** 快速瞄准显示标签：名字(位置)——位置消除同名敌人歧义；位置缺失时退化为纯名字 */
const quickAimLabel = computed(() => {
  if (!lastPidTarget.value) return '';
  const { name, pls } = lastPidTarget.value;
  return pls !== null && pls !== undefined && pls !== '' ? `${name}(${pls})` : name;
});
```

### 2.4 射程与有效性校验

```ts
/** 判断技能是否可快速瞄准（显示快捷标签的条件） */
function canQuickAim(skill: Skill): boolean {
  if (skill.aimType !== 'pid') return false;
  if (!skill.available) return false;  // 不可用技能（含 on_cd）不显示快捷标签
  if (!lastPidTarget.value) return false;
  // CD 重复：有 CD 的技能已在队列中时不显示快捷标签
  if (Number(skill.cd) > 0 && queue.value.some(item => item.act_id === skill.act_id)) return false;
  // 终结技耗尽态：不显示快捷标签（快速添加必然失败）
  if (isFinisherSkill(skill) && hasFinisherInQueue.value) return false;
  // 射程校验（用推算位置）
  return isEnemyInSkillRange(skill, lastPidTarget.value.pid, quickAimPlannedLoc.value);
}
```

**`canQuickAim` 提前过滤原则**：所有在 `onQuickAimClick` 中会导致 toast 提示失败的校验（CD 重复、终结技耗尽、不可用），都应在 `canQuickAim` 中提前过滤——快捷标签的职责是"快速添加"，不能添加就不应出现。`onQuickAimClick` 中的校验保留作为二次防御（防止 `canQuickAim` 到点击期间的竞态），但正常流程中不应被触发。

**快速瞄准执行**（点击快捷标签时）：

```ts
function onQuickAimClick(actId: string): void {
  const skill = skills.value.find(s => s.act_id === actId);
  if (!skill || !skill.available) return;
  if (!lastPidTarget.value) return;

  const pid = lastPidTarget.value.pid;

  // CD 校验
  if (Number(skill.cd) > 0 && queue.value.some(item => item.act_id === actId)) {
    useToastStore().showToast('该技能有冷却，无法重复装填', 'warning', 3000);
    return;
  }

  // 终结技唯一性校验
  if (isFinisherAct(actId) && hasFinisherInQueue.value) {
    useToastStore().showToast('一场战斗只能有一个终结技', 'warning', 3000);
    return;
  }

  // 目标有效性校验（目标可能已死亡/状态变化）
  const candidate = findSelectableCombatTarget(
    battleStore.combatTargets,
    battleStore.currentQid,
    pid,
    targetPid => characterStore.getCharacter(targetPid),
  );
  if (!candidate) {
    useToastStore().showToast('目标状态已变化，请手动瞄准', 'warning', 3000);
    return;
  }

  // 射程校验（二次校验，防止 canQuickAim 到点击期间状态变化）
  if (!isEnemyInSkillRange(skill, pid, quickAimPlannedLoc.value)) {
    useToastStore().showToast('目标距离过远，请手动瞄准', 'warning', 3000);
    return;
  }

  // 直接入队，跳过瞄准模式
  addToQueue(actId, { type: 'pid', id: pid });
}
```

**校验顺序设计**：CD → 终结技 → 目标有效性 → 射程。先校验"技能自身约束"（与目标无关），再校验"目标约束"。这样 CD 冲突或终结技冲突时，即使用户手动瞄准也无法添加，先报这些错误更符合用户心智模型。

**与 `onSkillClick` 校验的对称性**：`onQuickAimClick` 的 CD 和终结技校验与 [onSkillClick](file:///d:/wamp64/www/phpdts/vex-vue/src/components/battle/PreloadArea.vue#L494-L539) 完全一致，确保两条入队路径的约束对称。`addToQueue` 内部不再重复校验（保持现有逻辑）。

### 2.5 UI 与样式

**模板**（技能库项内，分类小标签之前）：

```html
<span
  v-if="skill.aimType === 'pid' && canQuickAim(skill)"
  class="quick-aim-tag"
  role="button"
  tabindex="0"
  :title="`用上次目标「${quickAimLabel}」快速装填`"
  @click.stop="onQuickAimClick(skill.act_id)"
  @keydown.enter.prevent="onQuickAimClick(skill.act_id)"
>→{{ quickAimLabel }}</span>
```

**显示格式**：`→兔子(7)`——名字+括号位置。位置始终显示，理由：

1. **消除同名歧义**：地图上同种敌人可能有多只（如多只"兔子"），仅显示名字用户无法判断点击会打哪只。位置是 PID 之外唯一的人类可读识别码。
2. **与装填轨道项 target chip 视觉语言一致**：[getTargetDisplayText](file:///d:/wamp64/www/phpdts/vex-vue/src/components/battle/PreloadArea.vue#L467-L480) 生成的 target chip 文本包含位置信息（`位于位置7的 兔子`），快速瞄准标签始终带位置达成语义对齐。
3. **无依赖、无边界**：智能切换（同名才显示位置）需依赖 `battleStore.combatTargets.candidates` 统计同名数量，但 candidates 在 pre-battle 模式下可能未加载。始终显示位置无此依赖。
4. **冗余可接受**：单敌人时 `@7` 只多 2-3 字符，是不刺眼的有意义冗余（用户可核对"是不是这只"），不同于"槽位序号"那种纯冗余。

### 2.6 边界案例

1. **射程依赖队列前缀**：快速瞄准追加到末尾，前缀 = 完整 queue。用 `quickAimPlannedLoc` computed（`getPlannedActorPls()` 无参，默认用完整 queue）推算位置。如果队列前面的 move 改变了玩家位置，射程推算自动跟随。✓

2. **目标死亡/状态变化**：`findSelectableCombatTarget` 校验目标是否仍在可选列表中。in-battle 模式下目标可能在前一回合死亡，校验失败 → toast 提示 + 回退到手动瞄准。✓

3. **多 pid 目标**：队列中有多个不同 pid 目标时，取最后一个 pid 项的目标。如「攻击A → 攻击B」后，快捷标签指向 B。用户若想对 A 快速瞄准，需手动瞄准一次 A，之后快捷标签切换到 A。✓

4. **tile vs pid**：`canQuickAim` 首先检查 `skill.aimType !== 'pid'`，tile 类技能（move）不显示快捷标签。tile 目标是位置而非敌人，"快速重复"语义不适用。✓

5. **终结技耗尽态**：`canQuickAim` 检查 `isFinisherSkill(skill) && hasFinisherInQueue.value`，耗尽态下不显示快捷标签。与技能按钮的耗尽态视觉（`is-finisher-exhausted`）一致——按钮本身保留可点击性以触发 toast 解释，但快捷入口不保留（快捷入口的职责是"快速添加"，不能添加就不应出现）。✓

6. **pendingItem 激活时**：技能库整体 `pointer-events: none`（§5.1 v4 补充），快捷标签在技能库内，自动被禁用。✓

7. **pre-battle 模式首次添加**：队列为空时 `lastPidTarget` 为 null，不显示快捷标签。第二次添加 pid 类技能时才出现。✓

8. **队列只有 tile 目标（move）时**：`lastPidTarget` 为 null（只有 pid 类型才匹配），不显示快捷标签。✓

9. **canQuickAim 到点击期间的状态变化**：`canQuickAim` 是实时 computed（响应式），标签在条件不满足时立即消失。但用户可能已在标签上悬停——`onQuickAimClick` 内部二次校验（目标有效性 + 射程），防止极端竞态。✓

10. **重新瞄准时 lastPidTarget 的变化**：重新瞄准时项被临时移出队列进入 pendingItem。如果被移出的是最后一个 pid 项，`lastPidTarget` 会立即回退到前一个 pid 项（或 null）。这是正确行为——pending 项不算"已入队"。✓

11. **同名敌人歧义**：地图上存在多只同名敌人（如多只"兔子"）时，仅显示 `→兔子` 用户无法判断点击会打哪只。`quickAimLabel` 始终带位置生成 `→兔子(7)`——位置是玩家在地图上识别敌人的主要方式，是 PID 之外最强的人类可读识别码。位置始终显示而非"同名才显示"，避免依赖 `battleStore.combatTargets.candidates`（pre-battle 模式下可能未加载）作为同名数量统计的数据源。位置缺失时（极端兜底，target.pls 为空）退化为纯名字 `→兔子`。✓

### 2.7 概念分级

- **模块级**：快速瞄准是 PreloadArea 的交互增量，不改变装填轨道的时序语义或 AP 预算模型。它复用现有的 `addToQueue` 入队路径、`findSelectableCombatTarget` 目标校验、`isEnemyInSkillRange` 射程校验、`getPlannedActorPls` 位置推算——所有基础设施已存在，只是新增一条"跳过瞄准模式"的并行路径。
