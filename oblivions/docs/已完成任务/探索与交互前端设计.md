## 二、道具归属模型

### 2.1 核心规则

道具通过 `bra_oblmapitem.iaid` 字段关联建筑物：

- **iaid > 0**：道具属于该建筑物，显示在建筑物的[检查]弹窗中
- **iaid = 0**：非建筑物来源的道具（如敌人掉落/野生道具），显示在「就在脚边...[检查]」中

**道具始终归属于建筑物，直到被拾取。** 不会因为玩家移动或其他操作而改变归属。

### 2.2 前端无需维护临时状态

后端 API 每次返回当前格数据时，已按 iaid 分好组。前端只需按分组渲染，无需追踪"搜索刚完成"等临时状态。

## 三、底部动作条（Tile Action Bar）

### 3.1 设计理念

底部动作条是当前格的**统一互动入口**，所有可交互实体集中展示，不分散到地图格或侧边面板。
移动端优先：拇指可达区域操作，无需精确点击地图格上的小图标。

### 3.2 动作条结构

动作条展示两类内容：**建筑物**（逐条）和**脚边道具入口**（一条），以及**原地探索按钮**。

```
┌─────────────────────────────────────┐
│           地 图 主 视 图             │
│                                     │
│    建筑物以图标显示在地图格上          │
│                                     │
├─────────────────────────────────────┤  ← 底部动作条（Tile Action Bar）
│ 📦 补给储藏箱           [搜索]       │  ← 未搜索 → [搜索]
│ 📦 危险宝箱(已搜索)     [检查]       │  ← 已搜索有掉落 → [检查]
│ 🏛️ 地标                              │  ← 不可搜索 → 无按钮
│ 🗡️ 就在脚边...          [检查]       │  ← iaid=0 的道具（有才显示）
│ 🔍 [原地探索]                        │  ← 点击当前格或此按钮触发探索
└─────────────────────────────────────┘
```

**排列规则**：
1. 可交互建筑物排前（未搜索 > 已搜索有掉落 > 可重复搜索）
2. 不可搜索建筑物排后（灰显，无按钮）
3. 「就在脚边...[检查]」始终在最末（仅有 iaid=0 道具时显示）
4. 「原地探索」按钮固定在动作条底部

### 3.3 建筑物状态与按钮

| 建筑物状态 | 动作条显示 | 按钮行为 |
|-----------|-----------|----------|
| 未搜索 | 图标 + 名称 + [搜索] | 发送搜索指令 → 后端结算 → 日志显示结果 → 状态变为"已搜索" |
| 已搜索 + 有掉落物未拾取(iaid下有道具) | 图标 + 名称(已搜索) + [检查] | 打开底部弹窗，展示该建筑物的掉落物列表 |
| 已搜索 + 掉落物已全部拾取（一次性） | 图标 + 名称（灰显） | 无按钮，显示"已搜索" |
| 已搜索 + 可重复搜索 + 有掉落物 | 图标 + 名称(已搜索) + [检查] / [再搜索] | [检查]查看掉落物，[再搜索]再次结算 |
| 已搜索 + 可重复搜索 + 无掉落物 | 图标 + 名称(已搜索) + [再搜索] | 再次发送搜索指令 → 后端按 repeat_loot 结算 |
| 可重复搜索 + 冷却中 | 图标 + 名称 + [再搜索(冷却中)] | 按钮灰显，显示剩余冷却回合数 |
| 可重复搜索 + 已达上限 | 图标 + 名称（灰显） | 无按钮，显示"已搜索(上限)" |
| 不可搜索 | 图标 + 名称（灰显） | 无按钮，仅展示 |
| 机制触发型（图腾等） | 图标 + 名称 + [搜索/触碰] | 搜索时触发机制效果（回血/学技能），无道具掉落 |

**POI 可见性说明**：POI 无近视机制。迷雾清除后该格上所有 POI 自动可见，不存在"未知的建筑物（？）"状态。

**核心逻辑**：搜索和检查是两步操作。[搜索]是后端结算（生成道具），[检查]是查看结算结果（拾取道具）。

### 3.4 脚边道具入口

| 条件 | 显示 | 按钮行为 |
|------|------|----------|
| 当前格有 iaid=0 的已发现道具(discovered=1) | 🗡️ 就在脚边... + [检查] | 打开底部弹窗，展示所有脚边道具 |
| 当前格有 iaid=0 的近视道具(discovered=2) | 🗡️ 就在脚边... + "道具名（？）" | 可拾取，但拾取时揭示真实身份 |

### 3.5 近视道具的交互（拟态怪机制）

近视道具（discovered=2）采用**拟态怪**设计——靠近不会揭示真相，必须拾取才能发现真实身份：

| 近视类型 | 弹窗显示 | 拾取结果 |
|---------|---------|---------|
| 真实道具（fake_item_id 空） | "废铁片（？）" | 获得废铁片（就是它本身） |
| 同级不同道具（fake_item_id 非空） | "生命药剂（？）" | 获得真实道具（可能是废铁片等同级道具） |
| 更高级不同道具（fake_item_id 非空） | "废铁片（？）" | 获得真实道具（可能是更高级道具） |
| 伪装怪物（is_trap=1） | "生命药剂（？）" | 触发战斗，不获得道具 |

- 近视道具在弹窗中**可以点击[拾取]**，拾取时后端揭示真实身份
- 拾取后日志显示真实结果："你拾取了废铁片" 或 "那是一个陷阱！战斗开始！"
- **靠近不会揭示**：discovered=2 是近视道具的固定状态，不会因为走近而升级为 discovered=1
- 近视道具**只有拾取时才揭示**，这是拟态怪的核心体验

### 3.6 空状态

当前格无任何可交互实体时，底部动作条显示提示：

```
┌─────────────────────────────────────┐
│  这里空无一物...                     │
│  🔍 [原地探索]                       │
└─────────────────────────────────────┘
```

## 五、地图迷雾渲染

### 5.1 问题

当前 `game_map` API 返回 `links.tiles` 是静态地图数据（来自 `tiles/region_{pgroup}.php`），不含 fog 状态。前端无法区分已探索/未探索格子。

### 5.2 方案：game_map API 扩展 fog 数据

在 `handle_game_map()` 的 Oblivions 分支中，查询 `bra_oblmapstates` 表，将 fog 状态附加到 `links` 中返回。

**API 响应变更**（新增 `fog` 字段）：

```json
{
  "links": {
    "regions": { "1": {...}, "2": {...} },
    "tiles": { "1": { "1": {...}, "2": {...} } },
    "grids": { "1": { "cols": 10, "rows": 10 } },
    "fog": { "1": { "1": 1, "2": 1, "5": 1 } }   // 新增：{pgroup: {pls: fog}}
  }
}
```

`fog` 结构：仅包含 fog=1 的格子（稀疏表示），未列出的格子默认 fog=0。

**后端修改**（`api_v2.php` `handle_game_map()`）：

```php
// 在 $data['links'] 赋值之后追加：
$fog_result = $db->query("SELECT pls, fog FROM {$tablepre}oblmapstates
                           WHERE pgroup='$cur_pgroup' AND fog=1");
$fog_data = array();
while ($row = $db->fetch_array($fog_result)) {
    $fog_data[(int)$row['pls']] = 1;
}
$data['links']['fog'] = array($cur_pgroup => $fog_data);
```

### 5.3 前端迷雾渲染

map.js 的 `renderMapGrid()` 中，根据 `mapData.links.fog` 判定格子状态：

```javascript
// 在 renderMapGrid() 中，渲染每个格子时：
const fogData = mapData.links.fog;
const regionFog = fogData && fogData[mapData.curRegion] ? fogData[mapData.curRegion] : {};
const isFogged = !regionFog[tileInfo.pls];  // 不在 fog 列表中 = 迷雾

if (isFogged) {
    cell.className += ' fogged';
    cell.innerHTML = '<span class="cell-fog">?</span>';
    // 迷雾格不可点击
} else {
    // 正常渲染（现有逻辑）
}
```

**迷雾格行为**：
- 不可点击移动（只能移动到已点亮的邻居格）
- 显示深色遮罩 + "?" 符号
- 不显示格子名称
- 不显示 POI/道具图标

**迷雾格的邻居可达性**：`isReachable()` 函数需修改——迷雾格不可作为移动目标，即使它在 neighbors 列表中：

```javascript
function isReachable(areaId) {
    // ... 现有逻辑 ...
    if (curTile.neighbors.indexOf(areaId) !== -1) {
        // 新增：目标格如果是迷雾，不可达
        const fogData = mapData.links.fog;
        const regionFog = fogData && fogData[mapData.curRegion] ? fogData[mapData.curRegion] : {};
        if (!regionFog[areaId]) return false;  // fog=0 → 迷雾中 → 不可达
        return true;
    }
    // ...
}
```

### 5.4 迷雾视觉

| 迷雾状态 | 地图格显示 | CSS 类 |
|---------|-----------|--------|
| 未探索 (fog=0) | 深色遮罩 + "?" | `.fogged` |
| 已探索 (fog=1) | 正常显示 | 无额外类 |

## 六、地图格视觉标识

### 6.1 建筑物图标

建筑物在地图格上以小图标标识，帮助玩家在地图层面快速识别。数据来源：`tile_actions` API 的 `pois` 数组。

| 建筑物状态 | 地图格显示 | CSS 类 |
|-----------|-----------|--------|
| 未搜索 | 彩色图标（按类型区分） | `.poi-icon` |
| 已搜索 + 有掉落物 | 彩色图标 + 闪光提示 | `.poi-icon.poi-has-items` |
| 已搜索 + 掉落物已拾取 | 灰色图标 + 勾 | `.poi-icon.poi-cleared` |
| 已搜索（可重复） | 彩色图标 + 循环标记 | `.poi-icon.poi-repeatable` |
| 可重复 + 冷却中 | 彩色图标 + 沙漏标记 | `.poi-icon.poi-cooldown` |
| 不可搜索 | 浅色图标 | `.poi-icon.poi-landmark` |
| 迷雾中 | 不显示 | — |

### 6.2 道具标识

地图格上的道具以小点标识。数据来源：`tile_actions` API 的 `ground_items` 数组。

| 道具状态 | 地图格显示 | CSS 类 |
|---------|-----------|--------|
| 已发现（iaid=0） | 小亮点 | `.item-dot` |
| 近视（discovered=2） | 模糊小点 | `.item-dot.item-nearsighted` |
| 属于建筑物 | 不单独显示 | — |
| 未发现 | 不显示 | — |

### 6.3 实现方式

在 `renderMapGrid()` 中，格子渲染完成后，叠加 POI/道具标识。需要将 `tile_actions` 数据与地图格子关联：

```javascript
// 在 renderMapGrid() 中，非迷雾格的渲染逻辑末尾追加：
if (tilePois && tilePois.length > 0) {
    // 渲染建筑物图标
    for (const poi of tilePois) {
        let poiClass = 'poi-icon';
        if (!poi.searchable) poiClass += ' poi-landmark';
        else if (poi.searched && poi.items && poi.items.length > 0) poiClass += ' poi-has-items';
        else if (poi.searched && poi.repeatable) poiClass += ' poi-repeatable';
        else if (poi.searched) poiClass += ' poi-cleared';
        html += '<span class="' + poiClass + '">📦</span>';
    }
}
if (tileGroundItems && tileGroundItems.length > 0) {
    const hasNearsighted = tileGroundItems.some(it => it.discovered === 2);
    const dotClass = hasNearsighted ? 'item-dot item-nearsighted' : 'item-dot';
    html += '<span class="' + dotClass + '">●</span>';
}
```

**数据来源问题**：`tile_actions` API 只返回当前格数据。要渲染整张地图的 POI/道具标识，需要额外数据。两种方案：

- **方案A（推荐）**：`game_map` API 额外返回当前区域所有已点亮格的 POI 摘要（仅 iaid/poi_id/searched，不含 items），前端据此渲染图标。点击图标时再调 `tile_actions` 获取详情。
- **方案B**：地图格上不显示 POI/道具图标，仅在底部动作条展示。简化实现，牺牲地图层面的信息密度。

**v1 采用方案B**：地图格上不渲染 POI/道具图标，所有交互集中在底部动作条。后续迭代再实现方案A。

## 八、可重复搜索的冷却/次数显示

### 8.1 renderPoiRow 补充

原设计缺少 `repeat_cooldown_remaining` 和 `repeat_limit` 的处理。补充完整逻辑：

```javascript
function renderPoiRow(poi) {
    const { iaid, name, searchable, repeatable, searched, items, mechanic,
            search_count, repeat_limit, repeat_cooldown, repeat_cooldown_remaining } = poi;
    let row = '<div class="tile-row tile-poi">';
    row += '<span class="tile-icon">📦</span>';
    row += '<span class="tile-name">' + escapeHtml(name);

    // 状态标注
    if (searched && !repeatable && (!items || items.length === 0)) {
        row += ' <span class="grey">(已搜索)</span>';
    } else if (searched && repeatable) {
        row += ' <span class="grey">(已搜索)</span>';
    }

    // 可重复搜索次数显示
    if (repeatable && repeat_limit > 0) {
        row += ' <span class="repeat-count">' + search_count + '/' + repeat_limit + '</span>';
    }

    row += '</span>';

    // 按钮逻辑
    if (!searchable) {
        // 不可搜索 → 无按钮
    } else if (!searched) {
        // 未搜索 → [搜索] 或 [触碰]
        const btnText = mechanic ? '[触碰]' : '[搜索]';
        row += '<button class="cmdbutton" onclick="window._tileActionSearch(' + iaid + ')">' + btnText + '</button>';
    } else if (items && items.length > 0) {
        // 已搜索 + 有掉落物 → [检查]
        row += '<button class="cmdbutton" onclick="window._tileActionCheckPoi(' + iaid + ')">[检查]</button>';
    } else if (repeatable) {
        // 可重复搜索
        if (repeat_limit > 0 && search_count >= repeat_limit) {
            // 已达上限
            row += '<span class="grey">(已达上限)</span>';
        } else if (repeat_cooldown_remaining && repeat_cooldown_remaining > 0) {
            // 冷却中
            row += '<button class="cmdbutton" disabled>[冷却' + repeat_cooldown_remaining + '回合]</button>';
        } else {
            // 可再搜索
            const btnText = mechanic ? '[再触碰]' : '[再搜索]';
            row += '<button class="cmdbutton" onclick="window._tileActionSearch(' + iaid + ')">' + btnText + '</button>';
        }
    } else {
        // 已搜索 + 一次性 + 无掉落 → 灰显
        row += '<span class="grey">(已搜索)</span>';
    }

    row += '</div>';
    return row;
}
```
