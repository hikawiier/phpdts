# Oblivions 错误日志迁移与前端增强执行方案

> 依据 `错误日志与异常处理搜索报告.md` 与 `vex-vue 错误日志检测与展示设计方案.md` 生成。
> 错误日志系统（`OblivionsErrorLogger`）已实装，本方案补齐后端 emit 端 + 前端展示端。

---

## 背景约束

- `OblivionsErrorLogger::emit($id, $params, $request)` 签名**无 logcategory**（与 `OblivionsLogger::emit($id, $logcategory, $params)` 不同）。
- `$obl_error_log` 在 `common.inc.php:311` 初始化，command 路径（`obl_command.php`）与 api 路径（`api_v2.php`）均可访问。
- **command 路径无 `register_shutdown_function`**：仅 `api_v2.php:26` 注册了 shutdown 持久化。command 路径靠 `obl_command.php:89` 直接调用 `obl_error_log_persist()`。因此 `obl_command.php:32` 的 `exit` 前若 emit，**不会被持久化**（exit 跳过 line 89）。
- 结论：`command.concurrent_rejected`（低优先级）不可行（除非额外注册 shutdown），本方案**跳过**该项。

## 阶段一：后端 emit 迁移 + 前端渲染器

### 1.1 tick.player_fetch.error（高）

- **文件**：`oblivions/include/game/tick.func.php`
- **函数**：`obl_resolve_tick_events`（line 329）
- **现状**：`if (!$player) return;` 静默返回，tick 卡死前端无感知
- **改动**：
  - 函数声明 `global $cuser, $obl_error_log;`
  - `!$player` 分支 emit `'tick.player_fetch.error'`，params: `user/delta`，request: `'api'`
- **request 来源**：`'api'`（与同文件 `tick.dispatch.error` 一致，tick 事件由 `common.inc.php` 在 command/api 共享路径触发）

### 1.2 command.rejected（高，设计文档第 197 行明确要求）

- **文件**：`oblivions/include/core/obl_command.php`
- **行号**：50-54、66-70（两处）
- **现状**：`$obl_log->emit('command.rejected', 'system', [...])`
- **改动**：迁移到 `$obl_error_log->emit('command.rejected', [...], 'command')`
  - 移除 logcategory 参数
  - request: `'command'`（明确在命令路径）
  - `$obl_error_log` 在文件作用域已可访问（line 88 已直接使用），无需 `global` 声明
  - 加 `isset` 守卫与 line 88 风格一致
- **理由**：设计文档已为前端预留 `'command.rejected'` 渲染器；Toast 比游戏日志更即时

### 1.3 search.data_error（中）

- **文件**：`oblivions/include/game/explore.func.php`
- **函数**：`obl_search_poi`（line 304）
- **行号**：329
- **现状**：`$obl_log->emit('search.data_error', 'search');`（无 params，混在 obl_log 会被 200 条上限挤掉）
- **改动**：迁移到 `$obl_error_log->emit('search.data_error', [...], 'command')`
  - 函数 `global` 声明追加 `$obl_error_log`
  - params: `poi_id/iaid`（便于定位配置缺失项）
- **对比**：同函数 `search.not_found`/`search.not_adjacent` 等是业务校验，**不迁移**

### 1.4 enemy_ai.config_missing（中）

- **文件**：`oblivions/include/game/enemy_ai.func.php`
- **函数**：`obl_create_enemy_record`（line 116）
- **行号**：124-125
- **现状**：`if (!$config) return false;` 静默返回
- **改动**：return 前 emit `'enemy_ai.config_missing'`，params: `enemy_type/pgroup/pls`，request: `'api'`
  - 函数 `global` 声明追加 `$obl_error_log`
  - 仍 `return false`（调用方 `obl_init_enemies` 依赖返回值）
- **request 来源**：`'api'`（NPC 生成在游戏初始化阶段，通常经 api 路径触发）

### 1.5 前端 ERROR_RENDERERS 补充（error-log.ts）

- **文件**：`vex-vue/src/stores/error-log.ts`
- **现状**：仅 `tick.dispatch.error` 一个渲染器
- **新增**：
  - `tick.player_fetch.error`：系统异常 + 玩家名 + 待处理游戏刻
  - `command.rejected`：操作被拒绝 + reason 友好映射（`command_not_allowed_in_current_state`→当前状态不允许此操作；`npc_action_pending`→NPC 事件未结算完毕，请稍候）
  - `search.data_error`：数据异常 + POI ID
  - `enemy_ai.config_missing`：配置异常 + 敌人类型

## 阶段二：前端错误展示增强

> 独立于 obl_error_log 系统，补齐关键 store 的静默 catch 分支，让用户感知前端拉取/处理异常。

### 2.1 error-log.ts 拉取失败 Toast（line 101-103）

- **现状**：`catch (e) { console.error(...) }` 静默
- **改动**：catch 内 `useToastStore().showToast('错误日志拉取失败', 'error', 4000, false, 'error-log-fetch')`
- **mergeId**：`'error-log-fetch'` 避免刷屏

### 2.2 battle.ts 三处异常 Toast（line 371/427/536）

- **现状**：三处 `catch (e) { console.error(...) }` 静默，玩家可能卡在战斗模式
- **改动**：每处 catch 补充 Toast（`'战斗数据异常，请刷新'`，mergeId `'battle-error'`）
- **注意**：`refreshBattle`/`fetchAndPlayBattleLog`/`refreshContextFromApi` 均在 store 内部，可直接调 `useToastStore()`

### 2.3 log.ts 拉取失败 Toast（line 147-148）

- **现状**：`catch (e) { console.error(...) }` 静默
- **改动**：Toast `'游戏日志拉取失败'`，mergeId `'log-fetch'`

### 2.4 PreloadArea.vue 技能列表拉取失败 Toast（line 78-79）

- **现状**：`catch (e) { console.error(...); skills.value = [] }` 静默清空，玩家进入战斗无法操作
- **改动**：Toast `'技能列表加载失败，请重进战斗'`，mergeId `'skill-fetch'`
- **注意**：组件内用 `useToastStore()`（Pinia store 可在组件 setup 外调用，但此处 fetchSkillList 是普通函数，需确保 Pinia 已初始化——在组件 setup 中调用时已初始化）

### 2.5 main.ts 注册全局错误处理器

- **现状**：`main.ts` 仅 createApp + mount，无任何错误处理
- **改动**：
  - `app.config.errorHandler`：捕获 Vue 组件渲染/生命周期错误 → console.error + Toast
  - `window.addEventListener('error', ...)`：捕获运行时错误
  - `window.addEventListener('unhandledrejection', ...)`：捕获未处理的 Promise rejection
- **Toast mergeId**：`'global-error'` 避免刷屏
- **注意**：全局错误处理器内不能直接 `useToastStore()`（Pinia 可能未就绪），需用 `app.config.globalProperties.$pinia` 或在 mount 后注册

### 2.6 tileAction.ts / inventory.ts catch 分支错误详情（低）

- **现状**：catch 分支 `debugBus.emit('error', ...)` + 通用 Toast（如"探索失败"），`e.message` 仅写入 debugBus 不可见
- **改动**：在通用 Toast 消息后追加 `e.message`（如 `'探索失败：' + (e instanceof Error ? e.message : String(e))`）
- **范围**：tileAction.ts 的 explore/search/pickup/switchRegion catch；inventory.ts 的 discard catch
- **注意**：`loadTileAction`/`loadInventory`（纯拉取）当前无 Toast，保持静默（拉取失败由 dataManager 重试机制兜底，不需要每次失败都 Toast）

## 不做项

- `command.concurrent_rejected`（低）：command 路径无 shutdown 持久化，exit 前 emit 会丢失，需额外注册 shutdown function，收益低
- 业务校验日志（`explore.no_sp`/`move.blocked`/`pickup.bag_full` 等）：保留 obl_log，不迁移
- 战斗日志 `$obl_battle_log`：独立系统，不迁移
