# 战斗状态机重构设计案

> **核心目标**：将战斗系统从"隐式状态推断"重构为"显式状态机驱动"，让战斗流程内部能感知时间（tick）的推进，前后端通过单一数据源协调行为。
>
> **性质**：破坏性重构。允许移除/替换现有的 `pending_npc` 组合判断逻辑，以状态机作为新的单一数据源。
>
> **多战场支持**：状态按 `qid`（先攻队列编号 = 战场编号）分离，支持同时存在多个独立战场。

---

## 一、问题背景与根因分析

### 1.1 当前架构的根本问题

战斗系统的状态是**推断**出来的，不是**声明**出来的：

```
当前推断逻辑（分散在前后端多处）：

后端：
  - obl_command.php [F] 段推进 tick → 隐式表示"玩家行动完成"
  - tick.func.php 的 battle_npc phase → 隐式表示"NPC 行动中"
  - battle_queue 的顺位 → 隐式表示"该谁行动了"
  - pending_npc 标志 → 隐式表示"NPC 还没处理完"

前端：
  - pending_npc=true → 推断"NPC 行动中，继续轮询"
  - battle_queue 顺位是玩家 + pending_npc=false → 推断"轮到我了"
  - battle_queue 为空 → 推断"战斗结束"
```

**没有任何一个字段直接告诉你"战斗现在处于什么阶段"**。

### 1.2 战斗与 tick 的耦合关系是隐式的

- tick 推进是战斗流程的驱动力，但战斗系统内部感知不到"时间推进了"
- `battle_main()` 不知道自己是被玩家命令触发的还是被 tick 事件触发的
- 状态转换分散在 5 个文件中，没有集中管理

### 1.3 前端两套轮询冗余

- `command-queue.ts` 的 `_pendingNpcTimer`（1s 间隔，10s 超时）
- `battle.ts` 的 `npcTurnRefreshTimer`（1s 间隔，无超时）
- 两者都轮询 `player_info`，都触发后端 `common.inc.php`，职责重叠

### 1.4 文档与实现不一致

- `escape_skip_tick` 标志读取但从未设置
- `obl_battle_end`/`obl_battle_check_end` 文档描述的函数不存在
- tick 字段标记为"调试用"但 `obl_tick_pending_npc` 实际是核心机制
- `bra_oblplayers.bid` 注释写"战斗目标 pid"但实际存储 qid

### 1.5 全局状态无法支持多战场

- `$gamevars['obl_tick_pending_npc']` 是全局单一标志
- 但 `bra_oblqueue` 表通过 `qid` 支持多个战场同时存在
- `obl_tick_phase_battle_npc` 通过 `SELECT DISTINCT qid` 遍历所有活跃战场
- 全局 `pending_npc` 无法区分哪个战场在等待 NPC 行动

## 二、设计目标

| 目标 | 描述 |
|------|------|
| **显式状态** | 战斗流程的当前阶段由 `bra_oblbattle_state.state` 字段标识，按 qid 分离 |
| **集中转换** | 所有状态转换集中在状态机模块，其他模块只触发事件 |
| **感知时间** | 状态机监听 tick 推进事件，战斗系统内部能感知"时间流逝了" |
| **单一数据源** | 前端直接读取 `obl_battle_state`，不再组合多个信号推断 |
| **统一轮询** | 前端由状态机统一驱动轮询逻辑，消除两套轮询冗余 |
| **多战场支持** | 每个战场（qid）独立维护状态，互不干扰 |
| **全局统筹** | 支持查询所有活跃战场状态，替代全局 `pending_npc` |
| **清理债务** | 修复 `escape_skip_tick`、文档不一致等历史问题 |

## 三、状态机设计

### 3.1 状态枚举

```
IDLE            无活跃战斗
PLAYER_ACTING   玩家行动中（命令处理中，tick 即将推进）
NPC_ACTING      NPC 行动中（tick 事件处理中，前端应轮询）
WAITING_PLAYER  等待玩家操作（前端停止轮询，启用操作）
ENDED           战斗结束（待清理）
```

### 3.2 状态转换图

```
  IDLE ──(battle_start)──→ PLAYER_ACTING
                                │
                                ├──(tick_advanced)──→ NPC_ACTING
                                │                        │
                                │                        ├──(npc_done, 顺位=玩家)──→ WAITING_PLAYER
                                │                        ├──(npc_done, 顺位=NPC)──→ NPC_ACTING（循环）
                                │                        └──(battle_end)──→ ENDED
                                │
                                └──(battle_end)──→ ENDED
                                                            │
  WAITING_PLAYER ──(player_command)──→ PLAYER_ACTING       │
                                │                           │
                                └──(battle_end)──→ ENDED ──┘
                                                            │
  ENDED ──(cleanup)──→ IDLE ←──────────────────────────────┘
```

### 3.3 状态转换表

| 当前状态 | 事件 | 目标状态 | 触发条件 |
|---------|------|---------|---------|
| IDLE | battle_start | PLAYER_ACTING | 玩家发起战斗（obl_battle_start 命令） |
| PLAYER_ACTING | tick_advanced | NPC_ACTING | 玩家命令完成，tick 推进 |
| PLAYER_ACTING | battle_end | ENDED | 战斗在玩家行动中结束（如玩家击杀最后敌人） |
| NPC_ACTING | npc_done_player_turn | WAITING_PLAYER | NPC 行动完成，顺位回到玩家 |
| NPC_ACTING | npc_done_npc_turn | NPC_ACTING | NPC 行动完成，顺位仍是 NPC（继续循环） |
| NPC_ACTING | battle_end | ENDED | 战斗在 NPC 行动中结束（如 NPC 击杀玩家） |
| WAITING_PLAYER | player_command | PLAYER_ACTING | 玩家提交新命令 |
| WAITING_PLAYER | battle_end | ENDED | 战斗在等待玩家时结束（如玩家逃跑） |
| ENDED | cleanup | IDLE | 战斗结束清理完成 |

### 3.4 存储方案：新建 bra_oblbattle_state 表

**设计原则**：状态按 qid 分离，支持多战场；独立表职责清晰，无数据冗余。

**建表 SQL**：

```sql
CREATE TABLE bra_oblbattle_state (
  qid int(11) NOT NULL,                      -- 先攻队列编号（主键）= 战场编号
  state varchar(20) NOT NULL DEFAULT 'IDLE', -- 战斗状态
  turn int(11) NOT NULL DEFAULT 0,           -- 当前回合数（未来扩展）
  updated_at int(11) NOT NULL DEFAULT 0,     -- 最后更新时间戳（超时检测）
  PRIMARY KEY (qid)
) ENGINE=MyISAM DEFAULT CHARSET=utf8mb4;
```

**字段说明**：

| 字段 | 类型 | 用途 |
|------|------|------|
| `qid` | int(11) | 先攻队列编号（主键），等于战场编号，与 `bra_oblqueue.qid` 对应 |
| `state` | varchar(20) | 战斗状态（IDLE/PLAYER_ACTING/NPC_ACTING/WAITING_PLAYER/ENDED） |
| `turn` | int(11) | 当前回合数（预留扩展，可用于回合数显示或技能 CD） |
| `updated_at` | int(11) | 最后更新时间戳，用于超时检测和卡死恢复 |

**与 bra_oblqueue 表的关系**：

| 表 | 职责 | 粒度 |
|----|------|------|
| `bra_oblqueue` | 先攻队列顺位、行动状态（done） | 每个参战者一行（pid 主键） |
| `bra_oblbattle_state` | 战斗流程状态 | 每个战场一行（qid 主键） |

两表通过 `qid` 关联，职责分离，无冗余。

### 3.5 生命周期管理

```
创建：battle_queue_create() 创建先攻队列后
  → INSERT INTO bra_oblbattle_state (qid, state, updated_at) VALUES (X, 'PLAYER_ACTING', now)

更新：状态机 transition 时
  → UPDATE bra_oblbattle_state SET state='NPC_ACTING', updated_at=now WHERE qid=X

销毁：battle_queue_update() 检测到队列解散（count <= 1）时
  → DELETE FROM bra_oblqueue WHERE qid=X        （现有逻辑）
  → DELETE FROM bra_oblbattle_state WHERE qid=X  （新增）

重建：battle_queue_create(preserve_qid) 时
  → 状态记录保留，重置为 WAITING_PLAYER（新回合开始，等待玩家行动）
```

## 四、后端实现方案

### 4.1 新建状态机模块

**文件**：`oblivions/include/game/battle_state_machine.func.php`

```php
<?php
/**
 * 战斗状态机模块
 *
 * 职责：
 * - 管理战斗流程的状态转换（按 qid 分离，支持多战场）
 * - 监听 tick 推进事件，触发状态转换
 * - 提供单一数据源 obl_battle_state 供前后端查询
 * - 提供全局统筹查询（替代 pending_npc）
 *
 * 存储方案：bra_oblbattle_state 表（qid 主键）
 *
 * 设计原则：
 * - 状态转换集中管理，其他模块只触发事件
 * - 非法转换记录错误日志，不抛异常（避免阻塞流程）
 * - 状态按 qid 分离，多战场互不干扰
 */

// 状态枚举
define('OBL_BS_IDLE',           'IDLE');
define('OBL_BS_PLAYER_ACTING',  'PLAYER_ACTING');
define('OBL_BS_NPC_ACTING',     'NPC_ACTING');
define('OBL_BS_WAITING_PLAYER', 'WAITING_PLAYER');
define('OBL_BS_ENDED',          'ENDED');

/**
 * 获取指定战场的战斗状态
 *
 * @param int $qid 先攻队列编号（战场编号）
 * @return string 战斗状态，qid 不存在时返回 IDLE
 */
function obl_battle_state_get($qid) {
    global $db, $tablepre;
    if ($qid <= 0) return OBL_BS_IDLE;
    $result = $db->query("SELECT state FROM {$tablepre}oblbattle_state WHERE qid = " . (int)$qid);
    $row = $db->fetch_array($result);
    return $row ? $row['state'] : OBL_BS_IDLE;
}

/**
 * 设置指定战场的战斗状态（内部函数，外部应使用 transition）
 */
function obl_battle_state_set($qid, $state) {
    global $db, $tablepre, $now;
    $db->query("UPDATE {$tablepre}oblbattle_state SET state = '" . addslashes($state) . "', updated_at = " . (int)$now . " WHERE qid = " . (int)$qid);
}

/**
 * 创建战场状态记录
 * 在 battle_queue_create 创建先攻队列后调用
 *
 * @param int $qid 先攻队列编号
 * @param string $initial_state 初始状态（默认 PLAYER_ACTING）
 */
function obl_battle_state_create($qid, $initial_state = OBL_BS_PLAYER_ACTING) {
    global $db, $tablepre, $now;
    $db->query("INSERT INTO {$tablepre}oblbattle_state (qid, state, turn, updated_at) VALUES ("
        . (int)$qid . ", '" . addslashes($initial_state) . "', 0, " . (int)$now . ")");
}

/**
 * 销毁战场状态记录
 * 在 battle_queue_update 检测到队列解散时调用
 *
 * @param int $qid 先攻队列编号
 */
function obl_battle_state_destroy($qid) {
    global $db, $tablepre;
    $db->query("DELETE FROM {$tablepre}oblbattle_state WHERE qid = " . (int)$qid);
}

/**
 * 状态转换（核心函数）
 *
 * @param int $qid 先攻队列编号（战场编号）
 * @param string $event 触发事件
 * @return string 转换后的状态（如果非法转换则保持原状态）
 */
function obl_battle_state_transition($qid, $event) {
    global $obl_error_log;

    if ($qid <= 0) return OBL_BS_IDLE;

    $current = obl_battle_state_get($qid);

    // 状态转换表
    static $transitions = [
        OBL_BS_IDLE => [
            'battle_start' => OBL_BS_PLAYER_ACTING,
        ],
        OBL_BS_PLAYER_ACTING => [
            'tick_advanced'    => OBL_BS_NPC_ACTING,
            'battle_end'       => OBL_BS_ENDED,
        ],
        OBL_BS_NPC_ACTING => [
            'npc_done_player_turn' => OBL_BS_WAITING_PLAYER,
            'npc_done_npc_turn'    => OBL_BS_NPC_ACTING,
            'battle_end'           => OBL_BS_ENDED,
        ],
        OBL_BS_WAITING_PLAYER => [
            'player_command' => OBL_BS_PLAYER_ACTING,
            'battle_end'     => OBL_BS_ENDED,
        ],
        OBL_BS_ENDED => [
            'cleanup' => OBL_BS_IDLE,
        ],
    ];

    $new_state = $transitions[$current][$event] ?? null;

    if ($new_state === null) {
        // 非法转换：记录错误日志，保持原状态
        if (isset($obl_error_log) && $obl_error_log) {
            $obl_error_log->emit('battle_state.illegal_transition', [
                'qid'     => $qid,
                'current' => $current,
                'event'   => $event,
            ], 'battle');
        }
        return $current;
    }

    // 特殊处理：NPC_ACTING → NPC_ACTING（循环，不实际改变状态）
    if ($current === $new_state) {
        return $current;
    }

    obl_battle_state_set($qid, $new_state);

    if (isset($obl_error_log) && $obl_error_log) {
        $obl_error_log->emit('battle_state.transition', [
            'qid'   => $qid,
            'from'  => $current,
            'to'    => $new_state,
            'event' => $event,
        ], 'battle');
    }

    return $new_state;
}

/**
 * 强制重置指定战场的状态（用于异常恢复）
 *
 * @param int $qid 先攻队列编号
 */
function obl_battle_state_reset($qid) {
    global $obl_error_log;
    obl_battle_state_set($qid, OBL_BS_IDLE);
    if (isset($obl_error_log) && $obl_error_log) {
        $obl_error_log->emit('battle_state.reset', [
            'qid'    => $qid,
            'reason' => 'manual_or_timeout',
        ], 'battle');
    }
}

// ── 全局统筹查询（替代 pending_npc） ──

/**
 * 获取所有活跃战场状态
 *
 * @return array [qid => state, ...]
 */
function obl_battle_state_get_all_active() {
    global $db, $tablepre;
    $result = $db->query("SELECT qid, state FROM {$tablepre}oblbattle_state WHERE state != 'IDLE'");
    $states = [];
    while ($row = $db->fetch_array($result)) {
        $states[(int)$row['qid']] = $row['state'];
    }
    return $states;
}

/**
 * 检测是否有任何战场在 NPC_ACTING 状态
 * 替代 obl_tick_is_pending_npc() 的全局判断
 *
 * @return bool
 */
function obl_battle_state_has_npc_acting() {
    global $db, $tablepre;
    $result = $db->query("SELECT 1 FROM {$tablepre}oblbattle_state WHERE state = 'NPC_ACTING' LIMIT 1");
    return (bool)$db->fetch_array($result);
}

/**
 * 找出卡死的战场（NPC_ACTING 状态超时）
 *
 * @param int $timeout_seconds 超时秒数（默认 30 秒）
 * @return array [qid, ...] 卡死的战场编号列表
 */
function obl_battle_state_find_stale($timeout_seconds = 30) {
    global $db, $tablepre, $now;
    $cutoff = $now - $timeout_seconds;
    $result = $db->query("SELECT qid FROM {$tablepre}oblbattle_state WHERE state = 'NPC_ACTING' AND updated_at < " . $cutoff);
    $stale = [];
    while ($row = $db->fetch_array($result)) {
        $stale[] = (int)$row['qid'];
    }
    return $stale;
}
```

```php
function battle_finish_check(&$actor_data, &$obl_battle_log, &$battle_cache)
{
    if (empty($actor_data['bid']))
    {
        // 战斗结束
        $qid = isset($battle_cache['last_qid']) ? (int)$battle_cache['last_qid'] : 0;

        // 触发 battle_end 事件（如果状态记录还存在）
        if ($qid > 0) {
            obl_battle_state_transition($qid, 'battle_end');
            // 战斗清理完成后，销毁状态记录
            obl_battle_state_destroy($qid);
        }

        battle_state_clear($actor_data, $obl_battle_log, $battle_cache);
        return;
    }
    battle_new_turn($actor_data, $obl_battle_log, $battle_cache);
    return;
}
```

### 4.4 异常恢复机制

**风险**：状态机可能卡死（如状态卡在 NPC_ACTING，但后端实际已处理完）

**恢复方案：基于 updated_at 的超时检测**

在 `common.inc.php` 的 tick 事件处理中，检测卡死的战场：

```php
// common.inc.php tick 事件处理段
if (function_exists('oblivions_is_active') && oblivions_is_active()
    && isset($gamevars['obl_tick']) && isset($gamevars['obl_pretick'])
    && $gamevars['obl_pretick'] < $gamevars['obl_tick'])
{
    $delta = (int)$gamevars['obl_tick'] - (int)$gamevars['obl_pretick'];
    obl_tick_synchronize();
    obl_resolve_tick_events($delta);

    // 新增：状态机超时检测
    // 找出 NPC_ACTING 状态超过 30 秒的战场
    $stale_qids = obl_battle_state_find_stale(30);
    foreach ($stale_qids as $qid) {
        // 降级到 WAITING_PLAYER（假设 NPC 行动已完成但状态未更新）
        obl_battle_state_set($qid, OBL_BS_WAITING_PLAYER);
    }

    // 如果 tick 已同步但仍有 NPC_ACTING 状态，说明卡死了
    if ($gamevars['obl_pretick'] >= $gamevars['obl_tick']) {
        $npc_acting_qids = obl_battle_state_find_stale(0); // 立即超时
        foreach ($npc_acting_qids as $qid) {
            obl_battle_state_reset($qid);
        }
        if (obl_tick_is_pending_npc()) {
            obl_tick_clear_pending_npc();
        }
    }

    $ginfochange = true;
}
```

## 五、多战场场景处理

### 5.1 多战场状态转换示例

```
时刻 T1：
  战场 A (qid=1)：玩家 vs NPC1
    玩家行动完成 → tick_advanced → NPC_ACTING
  战场 B (qid=2)：NPC2 vs NPC3
    NPC2 行动完成 → npc_done_npc_turn → NPC_ACTING（轮到 NPC3）

时刻 T2（tick 推进，obl_tick_phase_battle_npc 遍历所有 qid）：
  遍历 qid=1：当前顺位是 NPC1 → 执行 NPC1 先攻轮 → break
    NPC1 行动完成 → npc_done_player_turn → WAITING_PLAYER
  qid=2 未处理（break 退出）

时刻 T3（下次 tick 推进）：
  遍历 qid=1：当前顺位是玩家 → continue
  遍历 qid=2：当前顺位是 NPC3 → 执行 NPC3 先攻轮 → break
    NPC3 行动完成 → npc_done_npc_turn → NPC_ACTING（轮到 NPC2）

时刻 T4（下次 tick 推进）：
  遍历 qid=1：当前顺位是玩家 → continue
  遍历 qid=2：当前顺位是 NPC2 → 执行 NPC2 先攻轮 → break
    ...
```

### 5.2 全局 pending_npc 判断

```
obl_battle_state_has_npc_acting() 实现：
  SELECT 1 FROM bra_oblbattle_state WHERE state = 'NPC_ACTING' LIMIT 1

只要任何战场在 NPC_ACTING 状态，就返回 true
→ 前端继续轮询
→ 后端拒绝推进 tick 的命令
```

### 5.3 前端感知

前端只关心**当前玩家所在战场**的状态：

```php

- 玩家在战场 A（bid=1）→ 返回战场 A 的状态
- 玩家不在战斗中（bid=0）→ 返回 IDLE
- 前端根据 `obl_battle_state` 决定轮询行为

  if (npcTurnRefreshTimer !== null) return;

// battle_finish_check → battle_state_clear 会处理状态销毁
```

### 7.2 玩家突袭（先攻轮跳过 NPC）

**场景**：玩家突袭成功，NPC 没有先攻轮

**处理**：状态机正常流转
- `battle_start` → PLAYER_ACTING
- `tick_advanced` → NPC_ACTING
- `obl_tick_phase_battle_npc` 检查顺位，如果是玩家 → `npc_done_player_turn` → WAITING_PLAYER

### 7.3 多 NPC 先攻轮

**场景**：多个 NPC 连续行动

**处理**：状态机循环
- NPC_ACTING → `npc_done_npc_turn` → NPC_ACTING（循环）
- 直到顺位回到玩家 → `npc_done_player_turn` → WAITING_PLAYER

### 7.4 战斗中玩家死亡

**场景**：NPC 击杀玩家

**处理**：
- `battle_finish_check` 检测到玩家死亡（bid 为空）
- 触发 `battle_end` → 销毁状态记录

### 7.5 状态机卡死恢复

**场景**：状态卡在 NPC_ACTING，但后端实际已处理完

**处理**：后端基于 `updated_at` 超时检测（见 4.4 节）

### 7.6 多战场并存

**场景**：多个战场同时存在，各自独立流转

**处理**：
- 每个战场（qid）独立维护状态记录
- `obl_tick_phase_battle_npc` 遍历所有 qid，每个 qid 独立判断状态转换
- 全局 `pending_npc` 判断改为 `obl_battle_state_has_npc_acting()` 查询

### 7.7 旧数据兼容

**场景**：现有存档没有 `bra_oblbattle_state` 表

**处理**：
- 新建表后，现有活跃战场没有状态记录
- `obl_battle_state_get()` 返回 IDLE（默认值）
- 下次战斗开始时自动创建状态记录
- 不影响现有存档加载

### 7.8 队列重建（新回合）

**场景**：所有参战者 done=1，触发先攻队列重建

**处理**：
- `battle_queue_update` 检测到需要重建
- 调用 `battle_queue_create(preserve_qid)` 重建队列
- 状态记录保留，重置为 WAITING_PLAYER（新回合等待玩家行动）

## 十二、总结

本次重构的核心是**将战斗流程从"隐式推断"转为"显式声明"**，并**按 qid 分离状态以支持多战场**：

1. **独立状态表** `bra_oblbattle_state` 按 qid 存储每个战场的状态，无冗余、可扩展
2. **显式状态字段** `obl_battle_state` 替代多个隐式信号的组合
3. **集中转换表** 替代分散在 5 个文件中的状态判断
4. **事件驱动转换** 让战斗系统内部能感知 tick 推进（时间流逝）
5. **单一数据源** 让前后端协调更可靠
6. **统一轮询** 消除前端两套轮询的冗余
7. **多战场支持** 每个战场独立维护状态，互不干扰
8. **全局统筹** `obl_battle_state_has_npc_acting()` 替代全局 `pending_npc`

这是一个**破坏性重构**，但通过阶段化实施和 `pending_npc` 并行运行策略，可以控制风险。重构完成后，战斗系统的可维护性、可扩展性和多战场支持能力将显著提升。
