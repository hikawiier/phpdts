# Oblivions 结构化日志系统设计案

> 替代 Oblivions 模式下的传统 `$log` HTML 字符串机制，建立前后端分层的新日志传递体系。
>
> **设计原则**：后端只输出事件结构（发生了什么 + 参数），前端完全控制视觉呈现（文案、样式、随机化）。

---

## 一、设计目标

### 1.1 核心目标

1. **结构化**：后端输出数组而非 HTML 字符串，每条日志包含 ID 索引、动作标记、参数
2. **前端控制文案**：前端维护模板配置文件，按 ID 索引渲染文案；后端不参与视觉呈现
3. **动作标记粗粒度**：6 类（move/explore/search/pickup/discard/system），与细粒度 ID 正交
4. **完全替代**：Oblivions 模式下不再使用 `$log`，新建独立机制
5. **隔离性**：改动只影响 Oblivions 模式和 Vex 前端，不侵入传统模式

### 1.2 非目标

- 不改造传统模式的 `$log` 机制
- 不实现 i18n（但为本未来需求留路）
- 不实现日志去重（前端可自行处理）

---

## 二、数据结构

### 2.1 单条日志条目（LogEntry）

```typescript
{
  id: string,            // 细粒度 ID，前端查模板（如 'move.success'）
  action: string,        // 粗粒度动作标记（move/explore/search/pickup/discard/system）
  params: Object,        // 模板参数（键值对，值均为原始类型）
  html: string | null,   // fallback HTML，正常为 null
  ts: number             // Unix 时间戳（秒），用于排序
}
```

**字段说明**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 细粒度 ID，命名规则 `{action}.{subevent}`，如 `move.success`、`pickup.trap` |
| `action` | string | 是 | 6 类之一：`move`/`explore`/`search`/`pickup`/`discard`/`system` |
| `params` | object | 是 | 模板参数，值限 string/number/boolean。可为空对象 `{}` |
| `html` | string\|null | 否 | 逃生通道，正常为 `null`。仅用于前端模板无法覆盖的极端情况 |
| `ts` | number | 是 | `time()` 返回的 Unix 秒级时间戳 |

### 2.2 API 响应格式

`api_v2.php?action=obl_log` 返回：

```json
{
  "status": "success",
  "data": {
    "entries": [LogEntry, LogEntry, ...],
    "total": 42
  }
}
```

- `entries`：日志条目数组，按时间正序（旧→新）
- `total`：当前存储的条目总数（受 200 条上限裁剪）

### 3.1 move 动作（17 处）

| ID | 触发场景 | params |
|----|---------|--------|
| `move.same_pos` | 已经在当前位置 | `{}` |
| `move.invalid_target` | 目标格无效 | `{}` |
| `move.blocked` | 目标格不可通行 | `{tile_name}` |
| `move.unreachable` | 跨格移动不可达 | `{tile_name}` |

> **区域切换拆分说明**：区域切换（无论前进还是回退）统一拆分为三条独立日志：

> **注意**：`move.tile_desc` 是关键设计——后端只传地块属性参数，前端自己组合描述文案（含随机化）。详见第五节"terrain_desc 迁移"。

## 四、后端设计

### 4.1 新建 `oblivions/include/game/log.func.php`

提供日志收集器，替代 `global $log` 拼接：

```php
<?php
if (!defined('IN_GAME')) exit('Access Denied');

// ================================================================
// Oblivions 结构化日志收集器
// 替代传统 $log HTML 字符串机制
// ================================================================

/**
 * 日志收集器（单次请求内累积，请求结束前持久化）
 * 在 command.php 入口初始化为全局 $obl_log
 */
class OblivionsLogger {

    /** @var array 本请求累积的日志条目 */
    private $entries = [];

    /**
     * 追加一条日志
     *
     * @param string $id     细粒度 ID（如 'move.success'）
     * @param string $action 粗粒度动作（move/explore/search/pickup/discard/system）
     * @param array  $params 模板参数
     * @param string $html   fallback HTML，默认 null
     */
    public function emit($id, $action, $params = [], $html = null) {
        $this->entries[] = [
            'id'     => $id,
            'action' => $action,
            'params' => $params,
            'html'   => $html,
            'ts'     => time(),
        ];
    }

    /**
     * 获取本请求累积的日志条目
     * @return array
     */
    public function getEntries() {
        return $this->entries;
    }

    /**
     * 本请求是否有日志
     * @return bool
     */
    public function hasEntries() {
        return !empty($this->entries);
    }
}

/**
 * 持久化日志到文件（追加模式，带条目上限裁剪）
 *
 * 文件路径：vex/cache/obl_log_{groomid}_{pid}.json
 * 格式：JSON 数组，按时间正序
 *
 * @param OblivionsLogger $logger
 * @param int $groomid 房间 ID
 * @param int $pid      玩家 ID
 * @param int $max_entries 最大条目数（默认 200，可配置）
 */
function obl_log_persist($logger, $groomid, $pid, $max_entries = 200) {
    $new_entries = $logger->getEntries();
    if (empty($new_entries)) return;

    $log_file = GAME_ROOT . "./vex/cache/obl_log_{$groomid}_{$pid}.json";

    // 读取已有日志
    $existing = [];
    if (file_exists($log_file)) {
        $raw = file_get_contents($log_file);
        $existing = json_decode($raw, true);
        if (!is_array($existing)) $existing = [];
    }

    // 追加新条目
    $all = array_merge($existing, $new_entries);

    // 裁剪到上限（保留最新的 N 条）
    if (count($all) > $max_entries) {
        $all = array_slice($all, -$max_entries);
    }

    // 写入文件
    file_put_contents($log_file, json_encode($all, JSON_UNESCAPED_UNICODE), LOCK_EX);
}

/**
 * 从文件读取日志
 *
 * @param int $groomid 房间 ID
 * @param int $pid      玩家 ID
 * @return array 日志条目数组（按时间正序）
 */
function obl_log_load($groomid, $pid) {
    $log_file = GAME_ROOT . "./vex/cache/obl_log_{$groomid}_{$pid}.json";
    if (!file_exists($log_file)) return [];

    $raw = file_get_contents($log_file);
    $entries = json_decode($raw, true);
    return is_array($entries) ? $entries : [];
}
```

### 4.4 `obl_*` 函数改造模式

**改造前**（以 [move.func.php:226](../../oblivions/include/game/move.func.php#L226) 为例）：

```php
$log .= "从{$from_name}移动到了<span class=\"yellow\">{$to_name}</span>。<br>";
if (!empty($target_tile['desc'])) {
    $log .= $target_tile['desc'] . '<br>';
}
```

**改造后**：

```php
global $obl_log;
$obl_log->emit('move.success', 'move', [
    'from_name' => $from_name,
    'to_name'   => $to_name,
]);
// 地块描述作为独立条目，前端自行组合
$obl_log->emit('move.tile_desc', 'move', [
    'name'     => $target_tile['name'],
    'desc'     => $target_tile['desc'],
    'floor'    => $target_tile['floor'],
    'tide'     => $target_tile['tide'],
    'passable' => !empty($target_tile['passable']),
]);
```

**关键变化**：
- `global $log` → `global $obl_log`
- `$log .= '...'` → `$obl_log->emit($id, $action, $params)`
- 样式标记（`<span class="yellow">`）由前端模板控制，后端不输出
- 地块描述从"拼进移动日志"改为"独立条目"，前端自行渲染

### 4.5 `obl_get_tile_display_name()` 的处理

当前函数在 [move.func.php](../../oblivions/include/game/move.func.php) 有 5 处调用，用于生成地块显示名（含无名格随机描述）。

**处理方案**：
- **有名格**：后端仍传 `name` 参数（直接用 `$tile['name']`），前端模板直接显示
- **无名格**：后端传 `floor/tide/passable` 参数，前端词库自行组合随机描述

因此 `obl_get_tile_display_name()` **不再需要**——后端只传原始属性，前端负责生成显示名。

**迁移步骤**：
1. 删除 `obl_get_tile_display_name()` 函数
2. 改造 5 处调用点，改为传原始属性给 `$obl_log->emit()`
3. 词库迁移到前端（详见第五节）

### 5.2 新建 `vex/data/terrain-desc.js`

```javascript
// ══════════════════════════════════════════════════
// Oblivions 地形描述词库（从后端 terrain_desc.php 迁移）
// 无名地块根据 floor/tide/passable 属性随机生成描述
// ══════════════════════════════════════════════════

export const TERRAIN_DESC = {
    floor: {
        standard: {
            name: ['荒地', '空地', '平地', '碎石地'],
            adj:  ['荒芜的', '空旷的', '干裂的', '布满灰尘的'],
        },
        metal: {
            name: ['废铁地', '金属地', '铁皮地', '锈蚀地'],
            adj:  ['金属覆盖的', '锈迹斑斑的', '铁皮铺就的', '残骸堆积的'],
        },
        water: {
            name: ['湿地', '水洼地', '泥潭', '浅滩'],
            adj:  ['泥泞的', '潮湿的', '积水覆盖的', '黏腻的'],
        },
        vegetation: {
            name: ['灌木丛', '草丛', '荆棘地', '枯枝地'],
            adj:  ['杂草丛生的', '藤蔓缠绕的', '枯枝遍地的', '荆棘密布的'],
        },
    },

    tide: {
        shallow: [''],
        deep:    ['深', '幽深的', '没过膝盖的'],
        abyss:   ['深渊般的', '深不见底的', '令人窒息的'],
    },

    impassable_suffix: ['，无法通行', '，挡住了去路', '，无法通过'],

    templates: {
        default: [
            '一片{tide_adj}{floor_adj}{floor_name}',
            '{tide_adj}{floor_adj}{floor_name}',
            '一处{tide_adj}{floor_adj}{floor_name}',
        ],
        no_tide: [
            '一片{floor_adj}{floor_name}',
            '{floor_adj}{floor_name}',
            '一处{floor_adj}{floor_name}',
        ],
    },
};

/**
 * 生成无名地块的随机描述
 * @param {string} floor - 地面类型
 * @param {string} tide  - 潮汐类型
 * @param {boolean} passable - 是否可通行
 * @returns {string} 描述文本
 */
export function generateTerrainDesc(floor, tide, passable) {
    const floorCfg = TERRAIN_DESC.floor[floor] || TERRAIN_DESC.floor.standard;
    const floorName = pickRandom(floorCfg.name);
    const floorAdj  = pickRandom(floorCfg.adj);

    const tidePool = TERRAIN_DESC.tide[tide] || [''];
    const tideAdj  = pickRandom(tidePool);

    let text;
    if (tideAdj) {
        const tpl = pickRandom(TERRAIN_DESC.templates.default);
        text = tpl
            .replace('{tide_adj}', tideAdj)
            .replace('{floor_adj}', floorAdj)
            .replace('{floor_name}', floorName);
    } else {
        const tpl = pickRandom(TERRAIN_DESC.templates.no_tide);
        text = tpl
            .replace('{floor_adj}', floorAdj)
            .replace('{floor_name}', floorName);
    }

    if (!passable) {
        text += pickRandom(TERRAIN_DESC.impassable_suffix);
    }

    return text;
}

function pickRandom(arr) {
    return arr[Math.floor(Math.random() * arr.length)];
}
```

/**
 * 渲染单条日志为 HTML
 * @param {Object} entry 日志条目
 * @returns {string} HTML 字符串
 */
export function renderLogEntry(entry) {
    // fallback HTML 优先
    if (entry.html) return entry.html;

    const template = LOG_TEMPLATES[entry.id];
    if (!template) {
        // 未知 ID：显示原始信息
        return `<span class="grey">[未知日志: ${escapeHtml(entry.id)}]</span>`;
    }

    // 自定义渲染函数优先
    if (template.render) {
        return template.render(entry.params || {});
    }

    // 文本模板渲染
    let text = template.text || '';
    const params = entry.params || {};

    // 替换占位符
    for (const key in params) {
        text = text.replace(new RegExp('\\{' + key + '\\}', 'g'), escapeHtml(String(params[key])));
    }

    // 应用高亮
    if (template.highlight && template.highlightClass) {
        for (const key of template.highlight) {
            if (params[key] !== undefined) {
                const escaped = escapeHtml(String(params[key]));
                text = text.replace(escaped, `<span class="${template.highlightClass}">${escaped}</span>`);
            }
        }
    }

    return text;
}

// ══════════════════════════════════════════════════
// 游戏日志 / Chronicle log (Oblivions 结构化日志)

import { DebugBus } from './data.js';
import { gameApi } from './utils.js';
import { dataManager } from './data-manager.js';
import { renderLogEntry } from '../data/log-templates.js';

// 动作标记 → 前端显示标签
const ACTION_TAGS = {
    move:    'MOV',
    explore: 'EXP',
    search:  'SRC',
    pickup:  'PKG',
    discard: 'DSC',
    system:  'SYS',
};

/**
 * 刷新日志：从 obl_log API 拉取结构化日志并渲染
 */
export async function refreshLog() {
    const el = document.getElementById('logContent');
    if (!el) return;

    const result = await gameApi('obl_log');
    if (result.status !== 'success') return;

    const entries = result.data.entries || [];
    if (entries.length === 0) {
        el.innerHTML = '<span class="grey">[SYS] 暂无日志</span>';
        return;
    }

    // 渲染所有条目
    const htmlParts = entries.map(entry => {
        const tag = ACTION_TAGS[entry.action] || 'SYS';
        const content = renderLogEntry(entry);
        if (!content) return ''; // 空内容（如 move.tile_desc 无 desc 时）
        return `<span class="log-tag">[${tag}]</span>${content}`;
    }).filter(p => p); // 过滤空字符串

    el.innerHTML = htmlParts.join('<br>');
    el.scrollTop = el.scrollHeight;

    DebugBus.emit('log', 'refreshLog:done', { count: entries.length });
}

// ─── 事件驱动刷新 ───
dataManager.listen('game:action-completed', function() { refreshLog(); });
dataManager.listen('map:loaded', function() { refreshLog(); });

## 十一、待确认问题

### Q1：`move.tile_desc` 的触发时机

当前设计：移动成功后，**无论目标格是否有 desc**，都 emit 一条 `move.tile_desc`。前端模板判断：
- 有名格 + 有 desc → 显示 desc
- 有名格 + 无 desc → 返回空字符串（被 log.js 过滤）
- 无名格 → 调用 `generateTerrainDesc` 生成

这样设计是否合理？还是应该后端判断"有 desc 才 emit"？

**我的倾向**：后端统一 emit，前端过滤空内容。理由是后端逻辑更简单，且前端过滤成本极低。

### Q2：区域切换日志的拆分

当前 `move.region_forward` 把"离开 X 进入 Y"+"区域描述"+"入口格描述"合并成一条日志的 params。是否应该拆成多条日志？

**我的倾向**：不拆。区域切换是一个原子事件，合并成一条更符合语义。前端用 `render` 函数组合显示。

### Q3：`obl_log` 文件的清理时机

`vex/cache/obl_log_{groomid}_{pid}.json` 文件何时清理？

- **选项 A**：游戏重置时清理（`rs_game()` 时删除所有 obl_log 文件）
- **选项 B**：不主动清理，依赖 200 条上限自然轮转

**我的倾向**：选项 A，避免跨游戏残留。但需要找到 `rs_game()` 的清理钩子位置。
