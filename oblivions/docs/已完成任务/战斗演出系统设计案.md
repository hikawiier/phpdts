# 战斗演出系统设计案

> 本文档定义战斗系统的前端演出框架，包含战斗地图、三阶段播放（碰撞动画 → 模态框 → 滞留伤害数字）、played 标记机制、三层并发锁四大核心模块。
>
> **当前状态**：已落地实现。本文档与代码同步，作为系统设计的事实来源。
> **关联文档**：[oblivions/CODEBASE.md](../CODEBASE.md) §13 | [vex/CODEBASE.md](../../vex/CODEBASE.md) §14

---

## 一、设计目标

### 核心问题（已解决）

1. **战斗结束日志丢失** → played 标记机制确保日志持久化，前端按需拉取
2. **缺乏演出反馈** → 三阶段播放提供视觉冲击（碰撞动画 + 模态框 + 滞留伤害数字）
3. **状态机冗余** → 简化为 normal/battle 两态，取消 prebattle/ended 中间态
4. **战斗与探索界限模糊** → 战斗模式下地图禁止游戏指令，仅保留视图操作
5. **并发竞态** → 三层并发锁（前端 isProcessingBattle + commandQueue._locked + 后端 flock）
6. **回合归属不清** → 回合指示器（turn-active 呼吸光效）+ "你的回合" toast

### 设计原则

1. **职责分离**：地图显示、动作交互、演出播放三层独立
2. **零依赖端点**：mark_battle_log_played.php 不依赖 auth/DB，仅文件读写
3. **discard 模式**：战斗处理期间新指令直接丢弃，避免队列堆积
4. **可扩展性**：模态框支持加速显示、碰撞动画支持特效扩展

## 二、整体架构

### 界面布局

```
┌─────────────────────────────────────────┐
│  Header（保留不变）                        │
├─────────────────────┬───────────────────┤
│                     │  探索模式：         │
│  地图区             │  日志 + 动作        │
│  （同一组件）        │  ───────────────  │
│  探索/战斗模式切换    │  战斗模式：         │
│                     │  AP + 装填槽 +     │
│                     │  动作按钮           │
│                     │  （无日志区）       │
├─────────────────────┴───────────────────┤
│  [模态框叠加层] 演出时弹出，播放完关闭      │
│  [战斗边框光效] 战斗状态下全界面红色流动边框  │
│  [滞留伤害数字] 模态框关闭后在地图上淡入显示  │
└─────────────────────────────────────────┘
```

### 三层职责分离

| 层 | 职责 | 交互性 |
|----|------|--------|
| 地图层 | 显示双方位置、射程范围、瞄准图格（未来） | 视图操作可用（缩放/拖拽），游戏指令禁止 |
| 动作层 | AP 管理、预装填槽、动作按钮、回合指示器 | 战斗中可操作，模态框播放时禁止 |
| 演出层 | 三阶段播放（碰撞动画 → 模态框 → 滞留伤害数字） | 纯展示，无交互按钮 |

### 状态机简化

```
normal（探索）←→ battle（战斗）
```

- **prebattle 取消**：玩家点击敌人 → 纯前端确认界面（"是否攻击？"）→ 确认后直接提交 `obl_battle_start`，后端直接进入 `action='battle'`
- **ended 取消**：模态框播放完自动关闭，关闭后刷新状态决定去留

## 三、战斗地图页面设计

### 地图模式切换

地图组件不分离，通过模式切换改变显示内容：

| 模式 | 显示内容 | 交互 |
|------|---------|------|
| 探索模式 | 移动路径、资源点、敌人位置 | 点击移动、探索、搜索 |
| 战斗模式 | 敌人高亮、双方位置、射程范围（未来）、瞄准图格（未来） | 仅视图操作（缩放/拖拽/双指），禁止游戏指令 |

### 战斗模式视觉特征

1. **全界面边框光效**：红色流动光效包裹整个界面，持续提示战斗状态
2. **敌人高亮**：地图上当前战斗敌人图标高亮/脉冲
3. **色调变化**：战斗模式下地图色调偏暖/高对比（可选）

### 地图交互保留

战斗模式下保留以下视图操作（不触发游戏指令）：
- 自动缩放
- Ctrl+滚轮缩放
- 鼠标拖拽
- 双指缩放

禁止以下交互（后端已过滤，前端地图分离后自然消失）：
- 点击移动
- 点击探索
- 点击搜索

### 未来扩展（不在本设计案范围）

- 瞄准图格：点击地图格选择攻击目标
- 战术移动：战斗中有限度移动
- 射程线：显示武器射程范围
- 掩体/障碍物：地形影响战斗

## 四、三阶段播放设计

### 设计理念

将战斗演出拆分为三个阶段，分别承担不同反馈职责：

| 阶段 | 反馈类型 | 时长 | 内容 |
|------|---------|------|------|
| 1. 碰撞动画 | 即时物理反馈 | ~450ms | 攻击方冲刺 + 受击方抖动（**无伤害数字**） |
| 2. 模态框 | 详细信息展示 | 自动关闭 | battlelog 逐条显示、HP 变化、回合分隔 |
| 3. 滞留伤害数字 | 地图视觉残留 | ~1.5s | 模态框关闭后，伤害数字在地图上淡入显示并停留 |

### 阶段 1：碰撞动画（地图上）

攻击动作时，地图上播放即时物理动画：

| 动画 | 说明 | 时长 |
|------|------|------|
| 攻击方冲刺 | 攻击方图标向受击方方向位移后回位 | ~150ms |
| 受击方抖动 | 受击方图标左右抖动 | ~150ms |
| 等待 | 等待动画完成 | ~150ms |

**关键设计**：碰撞动画阶段**不显示伤害数字**，避免与模态框信息重复，伤害数字延迟到阶段 3 显示。

### 阶段 2：模态框（中央叠加层）

半透明遮罩 + 中央信息面板，纯展示无交互按钮。

```
┌───────────────────────────────────┐
│  [半透明遮罩，拦截点击]              │
│  ┌─────────────────────────────┐  │
│  │  敌人头像    HP: ████░░ 80   │  │
│  │                              │  │
│  │  你使用了空手攻击！           │  │
│  │  造成 15 点伤害              │  │
│  │  敌人 HP: 80 → 65            │  │
│  │                              │  │
│  │           玩家头像 HP: ████  │  │
│  └─────────────────────────────┘  │
└───────────────────────────────────┘
```

**信息面板布局**：
- **左侧**：敌人头像/图标 + 名称 + HP 条
- **右下**：玩家头像/图标 + 名称 + HP 条
- **中间**：文本区，逐条播放 battlelog

**播放逻辑**：
1. **逐条显示**：battlelog 按 `log_id` 排序后逐条出现，每条间隔 ~500ms
2. **打字机效果**：每条文本逐字显示（可选，未来）
3. **播放完停留**：所有条目显示完后停留 1-2 秒
4. **自动关闭**：停留结束后模态框淡出关闭
5. **加速显示**（未来）：长按加速播放，快速浏览 battlelog

**排序规则**：
- 按 `log_id`（emit 顺序）排序，**不按 `turn` 排序**（turn 非唯一，同一回合多条日志 turn 相同）
- `turn=0` 显示为 `── 战斗开始 ──` 分隔线，不显示"回合 0"
- `turn>=1` 显示为 `── 回合 N ──` 分隔线

### 阶段 3：滞留伤害数字（地图上）

模态框关闭后，伤害数字在地图受击方位置淡入显示并停留：

| 动画 | 说明 | 时长 |
|------|------|------|
| 淡入 | 伤害数字从透明渐显 | ~300ms |
| 停留 | 数字固定显示在受击方位置 | ~1s |
| 淡出 | 数字渐隐消失 | ~200ms |

**技术实现**：
- **position: fixed** + viewport 坐标（避免地图缩放/拖拽影响位置）
- 通过 `getBoundingClientRect()` 获取受击方图格的视口坐标
- CSS 动画 `damage-linger` 控制淡入/停留/淡出

### 时序总览

```
玩家提交攻击 → 后端持久化 battlelog（played=0）
→ 前端 fetch played=0 日志
→ 阶段 1：碰撞动画（~450ms，冲刺 + 抖动，无伤害数字）
→ 阶段 2：模态框弹出播放详细 battlelog（自动关闭）
→ 阶段 3：模态框关闭后，滞留伤害数字在地图淡入（~1.5s）
→ 前端调用 mark_battle_log_played.php 标记 played=1
→ 刷新状态
```

### 未来扩展

- 弹道线（远程武器）
- 特效粒子（技能/爆炸）
- 屏幕震动（重击）
- 音效反馈

## 五、played 标记机制

### 设计动机

**旧方案问题**：battlelog 随命令响应返回，存在以下问题：
1. tick 结算产生的 battlelog（遭遇战、NPC AI）无法通过命令响应传递
2. 网络中断或页面刷新导致日志丢失
3. 前端无法区分"已播放"和"未播放"日志

**新方案**：后端持久化所有 battlelog（`played=0`），前端按需拉取并标记。

### 数据结构

BattleLogEntry 字段定义：

| 字段 | 类型 | 说明 |
|------|------|------|
| `log_id` | int | 自增 ID，**排序依据**（emit 顺序） |
| `id` | string | 事件类型（如 `battle.action`、`battle.start`、`battle.end`） |
| `turn` | int | 回合数（0=战斗开始，>=1=正常回合） |
| `actor` | string | `player` / `enemy` / `system` |
| `enemy_pid` | int | 关联敌人 PID（用于前端定位受击方） |
| `action_id` | string | 动作 ID（如 `unarmed_strike`） |
| `action_name` | string | 动作名称（如"空手攻击"） |
| `target` | string | 目标标识（如 `enemy_5`） |
| `effect_value` | int | 效果数值（伤害量） |
| `extra` | object | 扩展数据（`damage`、`enemy_hp_after` 等） |
| `ts` | int | 时间戳 |
| `played` | int | 0=未播放，1=已播放 |

### 数据流

```
┌─────────────────────────────────────────────────────────────┐
│ 后端                                                         │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐  │
│  │ 命令处理      │───▶│ BattleLog    │───▶│ 持久化文件    │  │
│  │ (battle.func) │    │ Collector    │    │ (played=0)   │  │
│  └──────────────┘    └──────────────┘    └──────────────┘  │
│                                                │            │
│  ┌──────────────┐    ┌──────────────┐         │            │
│  │ tick 结算     │───▶│ BattleLog    │─────────┤            │
│  │ (NPC AI)      │    │ Collector    │         │            │
│  └──────────────┘    └──────────────┘         │            │
│                                                ▼            │
│  ┌──────────────────────────────────────────────────────┐  │
│  │ api_v2.php handle_battle_log()                        │  │
│  │ → 返回 played=0 的日志                                │  │
│  └──────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 前端                                                         │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐  │
│  │ fetch        │───▶│ 三阶段播放    │───▶│ mark played  │  │
│  │ played=0     │    │ (碰撞+模态+   │    │ (mark_battle │  │
│  │ 日志         │    │  滞留数字)    │    │  _log_played)│  │
│  └──────────────┘    └──────────────┘    └──────────────┘  │
```

### API 接口

#### 1. 拉取未播放日志

**端点**：`GET api_v2.php?action=battle_log`
**响应**：
```json
{
    "success": true,
    "data": {
        "logs": [
            {
                "log_id": 42,
                "id": "battle.action",
                "turn": 1,
                "actor": "player",
                "enemy_pid": 5,
                "action_id": "unarmed_strike",
                "action_name": "空手攻击",
                "target": "enemy_5",
                "effect_value": 15,
                "extra": {"damage": 15, "enemy_hp_after": 65},
                "ts": 1718800000,
                "played": 0
            }
        ]
    }
}
```

#### 2. 标记日志已播放

**端点**：`POST vex/mark_battle_log_played.php`
**零依赖设计**：不依赖 auth/DB，仅文件读写
**请求**：
```json
{
    "log_id": 42
}
```
**响应**：
```json
{
    "success": true,
    "log_id": 42
}
```

**安全措施**：
- `(int)` 强制转换 `log_id`，防止路径遍历攻击
- `LOCK_EX` 文件锁，防止并发写入冲突
- 进程结束自动释放锁（无需 `LOCK_UN`）

### 完整数据流场景

#### 玩家主动攻击流程（首次进入战斗）

```
1. 玩家点击地图敌人 → 前端确认界面 → 确认后提交 obl_battle_start（带 enemy_pid）
2. 后端处理（obl_battle_initiate）：
   - 校验目标（obl_battle_validate_target）
   - obl_battle_enter_battle → 双方 action='battle'
   - emit battle.start 到 $obl_battle_log（played=0）
   - obl_battle_roll_initiative($pdata, $enemy, 101) → 玩家强制先攻
   - obl_battle_auto_npc（玩家100%先攻，NPC 不会立即行动）
   - 持久化 battlelog 到文件
   - 响应 JSON（空响应，不含 battlelog 字段）
3. 前端收到响应：
   a. 切换到 battle 模式（地图战斗模式 + 边框光效）
   b. fetch battle_log（played=0）→ 获取 battle.start + initiative.roll
   c. 三阶段播放（碰撞动画 → 模态框 → 滞留伤害数字）
   d. 调用 mark_battle_log_played.php 标记 played=1
   e. 刷新状态（fetch player_info）
4. 等待玩家选择动作
```

#### 玩家攻击动作流程（战斗中）

```
1. 玩家点击动作按钮 → 提交 obl_battle_action（带 action_id）
2. 后端处理（obl_battle_resolve_round）：
   - 校验 action='battle'
   - 获取当前顺位（应该是玩家）
   - 执行玩家先攻轮（obl_battle_execute）
   - NPC 自动执行直到玩家顺位或战斗结束
   - emit battlelog 到 $obl_battle_log（played=0）
   - 持久化到文件
   - 响应 JSON（空响应）
3. 前端收到响应：
   a. fetch battle_log（played=0）
   b. 阶段 1：碰撞动画（~450ms）
   c. 阶段 2：模态框播放 battlelog
   d. 阶段 3：模态框关闭后，滞留伤害数字淡入
   e. 调用 mark_battle_log_played.php 标记 played=1
   f. 刷新状态（fetch player_info）
4. 刷新后判断：
   - action='battle' 且玩家顺位 → 显示回合指示器 + "你的回合" toast
   - action='battle' 且 NPC 顺位 → 等待（NPC 在后端自动执行，下次刷新时获取结果）
   - action='' → 切换到 normal
```

#### 遭遇战流程

```
1. 玩家移动 → move 命令 → tick 推进
2. 后端 tick 结算：
   - NPC AI 移动到玩家格
   - obl_battle_encounter 触发
   - emit battlelog（battle.start + initiative.roll + NPC 先攻动作，played=0）
   - 持久化到文件
3. 前端收到 move 响应 → 刷新状态
4. 发现 action='battle' → 切换到 battle 模式
5. fetch battle_log（played=0）→ 三阶段播放遭遇战日志
6. 标记 played=1 → 等待玩家操作
```

#### 连续战斗流程

```
1. 玩家击败敌人A → 后端持久化 A 的结算 battlelog（played=0）
2. 前端 fetch → 三阶段播放 A 的结算
3. 模态框A关闭 → 标记 played=1 → 刷新状态
4. 发现 action='battle'（敌人B遭遇）→ fetch B 的 battlelog
5. 模态框A淡出 → 短暂过渡 → 模态框B淡入（B 的遭遇战）
6. 模态框B关闭 → 标记 played=1 → 等待玩家操作
```

## 六、三层并发锁机制

### 设计动机

战斗演出涉及多步骤异步操作（fetch → 动画 → 模态框 → 标记），期间用户可能误操作触发新指令，导致：
1. battlelog 顺序错乱
2. 动画/模态框叠加显示
3. 后端文件读写竞态

### 三层锁架构

```
┌─────────────────────────────────────────────────────────────┐
│ 层 1：前端 isProcessingBattle（全生命周期锁）                  │
│  - 范围：confirmStartBattle → onBattleAction 整个流程         │
│  - 模式：discard（新指令直接丢弃，不排队）                     │
│  - 实现：try/finally 确保异常时释放                           │
├─────────────────────────────────────────────────────────────┤
│ 层 2：commandQueue._locked（HTTP 请求锁）                     │
│  - 范围：单个 HTTP 请求期间                                    │
│  - 模式：discard（请求期间新指令丢弃）                         │
│  - 实现：command-queue.js 中的 _locked 标志                   │
├─────────────────────────────────────────────────────────────┤
│ 层 3：后端 flock(LOCK_EX|LOCK_NB)（文件锁）                   │
│  - 范围：命令处理期间                                          │
│  - 模式：拒绝（获取锁失败返回错误）                            │
│  - 实现：obl_command.php [A2] 步骤                            │
└─────────────────────────────────────────────────────────────┘
```

### 层 1：isProcessingBattle（前端全生命周期锁）

**作用范围**：从玩家点击"确认攻击"或"动作按钮"开始，到三阶段播放完成 + mark played 成功结束。

**实现**：
```javascript
async function confirmStartBattle(enemyPid) {
    if (isProcessingBattle) return;  // discard 模式
    isProcessingBattle = true;
    try {
        // 1. 提交命令
        // 2. fetch battlelog
        // 3. 三阶段播放
        // 4. mark played
    } finally {
        isProcessingBattle = false;  // 确保异常时释放
    }
}
```

**discard 模式选择理由**：
- 战斗指令有时效性，排队执行旧指令可能造成状态混乱
- 用户重复点击应被忽略，而非累积
- 简化实现，避免队列管理复杂度

### 层 2：commandQueue._locked（HTTP 请求锁）

**作用范围**：单个 HTTP 请求发送到响应返回期间。

**实现**：`vex/js/command-queue.js` 中的 `_locked` 标志，请求期间为 true，响应后置 false。

**与层 1 的关系**：层 1 覆盖整个生命周期（含动画播放），层 2 仅覆盖 HTTP 请求期间。层 1 释放前层 2 已多次获取/释放。

### 层 3：flock(LOCK_EX|LOCK_NB)（后端文件锁）

**作用范围**：命令处理期间（从 `obl_command.php` [A2] 步骤获取锁，到进程结束自动释放）。

**实现**：
```php
// obl_command.php [A2] 步骤
$lockFile = fopen($lockFilePath, 'w');
if (!flock($lockFile, LOCK_EX | LOCK_NB)) {
    // 获取锁失败，返回错误
    echo json_encode(['success' => false, 'error' => 'command_in_progress']);
    exit;
}
// 命令处理...
// 进程结束自动释放锁，无需 LOCK_UN
```

**flock vs DB 锁选型理由**：
- **自动释放**：进程结束（包括 PHP 超时）自动释放，避免死锁
- **性能**：文件锁比 DB 锁轻量
- **单机足够**：PHPDTS 单机部署，无需分布式锁
- **简单**：无需额外表结构或事务管理

### 锁失败处理

| 层 | 失败场景 | 处理方式 |
|----|---------|---------|
| 层 1 | 战斗处理期间用户点击 | 静默丢弃（无提示） |
| 层 2 | HTTP 请求期间新指令 | 静默丢弃 |
| 层 3 | 后端命令处理期间新请求 | 返回 `command_in_progress` 错误 |

## 八、前端状态机

### 状态定义

```
normal（探索模式）
  └─ 玩家点击敌人 → 纯前端确认界面 → 提交 obl_battle_start
     → 后端 action='battle' → 切换到 battle

battle（战斗模式）
  ├─ 玩家提交 obl_battle_action → 三阶段播放 → 仍在 battle → 继续
  ├─ 战斗结束（action=''）→ 模态框播放结算 → 关闭 → 切换到 normal
  └─ 连续战斗（新敌人遭遇）→ 模态框A播放 → 模态框B播放 → 继续 battle
```

### 状态切换

| 切换 | 触发 | 动作 |
|------|------|------|
| normal → battle | 后端 action='battle' | 地图切战斗模式 + 右侧切 battleMode + 边框光效 |
| battle → normal | 后端 action='' | 地图切探索模式 + 右侧切 normalMode + 移除边框光效 |

### prebattle 取消（前后端协同）

**纯前端确认，后端直接进入 battle**：

前端：
1. 玩家点击地图敌人 → 前端显示确认界面（"是否攻击 [敌人名]？"）
2. 玩家确认 → 提交 `obl_battle_start` 命令（带 `enemy_pid`）
3. 前端收到响应 → 切换到 battle 模式

后端（`obl_battle_start` 命令职责变更）：
1. 校验目标（`obl_battle_validate_target()`）
2. 状态检测（`obl_battle_enter_battle()`）→ 双方 `action='battle'`
3. emit `battle.start` 日志（played=0）
4. 先攻判定（`obl_battle_roll_initiative($pdata, $enemy, 101)`）→ 玩家强制先攻
5. NPC 自动执行（`obl_battle_auto_npc()`，玩家100%先攻时 NPC 不会立即行动）
6. 持久化 battlelog 到文件

**关键变化**：原 `obl_battle_action` 命令承担的"prebattle → battle 转换 + 先攻判定"职责，前移到 `obl_battle_start` 命令。`obl_battle_action` 只负责执行先攻轮。

### ended 取消

模态框播放完自动关闭，不需要 ended 中间态：
1. 模态框播放 battlelog（含 `battle.end`）
2. 播放完关闭
3. 刷新状态 → action='' → 切换到 normal

### 关键实现细节

#### 后端

**`obl_battle_initiate($enemy_pid, &$pdata)`**：
- 校验目标（`obl_battle_validate_target`）
- `obl_battle_enter_battle` → 双方 action='battle'
- emit `battle.start`（含 enemy_pid）
- `obl_battle_roll_initiative($pdata, $enemy, 101)` → 玩家强制先攻
- `obl_battle_auto_npc`（玩家100%先攻，NPC 不会立即行动）

**`obl_battle_resolve_round()`**：
- 移除 `action === 'prebattle'` 分支，只处理 `action === 'battle'`
- 执行玩家先攻轮 → NPC 自动执行直到玩家顺位或战斗结束
- 所有 emit() 调用均传 `enemy_pid` 参数

**`obl_battle_end()`**：
- turn-before-clear 修复：先 emit `battle.end` 日志，再清理 battle 状态
- 确保结算日志能正确关联 enemy_pid

**`obl_command.php` 命令流**：
- [A2] flock(LOCK_EX|LOCK_NB) 获取文件锁，失败返回 `command_in_progress`
- [E2] 持久化 battlelog 到文件（played=0）
- [H] 返回空 JSON 响应（不含 battlelog 字段）

**`mark_battle_log_played.php` 零依赖设计**：
- 不引入 `common.inc.php`，不依赖 auth/DB
- `(int) $_POST['log_id']` 强制转换，防止路径遍历
- `LOCK_EX` 文件锁，进程结束自动释放

#### 前端

**`battle.js` 状态机**：
- `isProcessingBattle` 全生命周期锁（try/finally 释放）
- `confirmStartBattle(enemyPid)` / `onBattleAction(actionId)` 入口
- `fetchAndPlayBattleLog()` → `playBattleLogGroup()` → `markBattleLogPlayed()` 流水线
- "你的回合" toast 触发条件：玩家顺位 + 非首次进入

**`battle-modal.js` 排序**：
- 按 `log_id` 排序（emit 顺序），不按 `turn` 排序
- `turn=0` → `── 战斗开始 ──` 分隔线
- `turn>=1` → `── 回合 N ──` 分隔线

**`battle-animation.js` 三阶段**：
- `playCollisionAnimation()`：450ms 等待，攻击方冲刺 + 受击方抖动，**无伤害数字**
- `playDamageNumbersAfterModal()`：模态框关闭后调用，position:fixed + viewport 坐标
- `.map-cell.current` 选择器（非 `.cell.current`）

**`battle-render.js` 回合指示器**：
- `renderBattleActions()` 中根据顺位添加 `.turn-active` 类
- `renderBattleLogEntryHtml()` 处理所有 action_id 类型

**`command-queue.js` HTTP 锁**：
- `_locked` 标志，请求期间 true，响应后 false
- 仅覆盖 HTTP 请求期间，不覆盖动画播放
