# 缓存路径迁移设计案：vex/cache → oblivions/cache

## 背景

`vex/` 前端已废弃，但后端 PHP 运行时缓存文件仍输出到 `vex/cache/`。昨日因此触发严重 bug：`vex/cache/` 目录缺失导致 `fopen()` 失败，`obl_command.php` 的 flock 锁无法获取，所有命令返回 `COMMAND_IN_PROGRESS`，前端操作完全无反应。

此外，`vex/` 目录下现仅剩 `mark_battle_log_played.php` 一个孤立的入口文件，整个 `vex/` 目录应当被清理。

## 目标

1. 将后端运行时缓存文件从 `vex/cache/` 迁移到 `oblivions/cache/`，按用途分子目录
2. 将 `vex/mark_battle_log_played.php` 迁移到 `oblivions/mark_battle_log_played.php`
3. 删除整个 `vex/` 目录
4. 同步前端 URL 与 vite proxy 配置
5. 增加目录创建保护，避免重蹈昨日 bug 覆辙

## 缓存目录结构

```
oblivions/cache/
├── .htaccess              # Apache 访问保护（Deny from all）
├── locks/                 # obl_lock_{groomid}_{pid}.php — 命令并发锁
├── logs/                  # obl_log_{groomid}_{pid}.json + obl_error_{groomid}_{pid}.json
├── battles/               # obl_battle_log_{groomid}_{pid}.json — 战斗日志
└── debug/                 # ai_dump_{groomid}.jsonl — AI 调试 dump
```

## 风险与边界

### 风险

1. **目录缺失**：昨日 bug 的根因。已在每个 `*_persist` 函数和 `obl_command.php` 锁文件路径处加 `is_dir + mkdir` 保护。
2. **前端 URL 不同步**：`mark_battle_log_played.php` 迁移后，前端必须同步更新 URL 和 vite proxy，否则 404。
3. **旧缓存文件残留**：`vex/cache/` 下的旧文件不会影响新逻辑（路径已变），但应清理避免混淆。

### 不做项

- **不迁移旧缓存文件**：游戏重置时 `rs_game()` 钩子会清理，让旧文件自然过期。迁移期间旧文件仍在 `vex/cache/` 但不会被读写。
- **不做向后兼容**：不保留 `vex/cache/` 路径作为 fallback。一次性切换，避免双路径混乱。
- **不修改 `mark_battle_log_played.php` 的零依赖设计**：它仍然不依赖任何游戏框架，只做文件读写。目录创建由 `obl_battle_log_persist` 负责。

## 验证

1. **目录创建**：确认 `oblivions/cache/{locks,logs,battles,debug}/` 四个子目录存在
2. **命令执行**：执行探索命令，确认 `oblivions/cache/locks/obl_lock_*.php` 生成
3. **日志写入**：执行命令后，确认 `oblivions/cache/logs/obl_log_*.json` 生成
4. **战斗日志**：触发战斗，确认 `oblivions/cache/battles/obl_battle_log_*.json` 生成
5. **mark 接口**：前端播放战斗日志后，确认 `mark_battle_log_played.php` 调用成功（网络请求 200）
6. **vex 目录清理**：确认 `vex/` 目录已删除
7. **vue-tsc + vite build**：前端编译通过
