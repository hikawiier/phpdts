# Oblivions 前端交互设计

> 版本：3.0 | 2026-06-14
> 本文档聚焦 vex 前端的交互设计，后端数据模型见《建筑物与道具系统设计.md》
> 基于 v2.0 调整：POI 无近视机制（迷雾控制可见性）；道具近视=拟态怪（拾取才揭示）；新增原地探索命令；可重复搜索冷却/次数


### 1.2 新增模块

| 模块 | 文件 | DOM 位置 | 职责 |
|------|------|----------|------|
| Tile Action Bar | `vex/js/tile-action.js` | `col-left` 地图面板下方 | 当前格互动入口：建筑物搜索/检查 + 脚边道具拾取 + 原地探索 |

### 1.3 模块间通信

```
map.js ──(移动完成)──→ DebugBus.emit('player:moved')
                          │
tile-action.js ←──(监听)──┘ → 刷新动作条内容

map.js ──(原地探索)──→ DebugBus.emit('player:explored')
                          │
tile-action.js ←──(监听)──┘ → 刷新动作条内容
```

- map.js 不依赖 tile-action.js，仅通过 DebugBus 发事件
- tile-action.js 监听 `player:moved` 和 `player:explored` 事件后请求 API 刷新数据

## 二、道具归属模型

### 2.1 核心规则

道具通过 `bra_oblmapitem.iaid` 字段关联建筑物：

- **iaid > 0**：道具属于该建筑物，显示在建筑物的[检查]弹窗中
- **iaid = 0**：非建筑物来源的道具（如敌人掉落/野生道具），显示在「就在脚边...[检查]」中

**道具始终归属于建筑物，直到被拾取。** 不会因为玩家移动或其他操作而改变归属。

### 2.2 前端无需维护临时状态

后端 API 每次返回当前格数据时，已按 iaid 分好组。前端只需按分组渲染，无需追踪"搜索刚完成"等临时状态。

## 三、底部动作条（Tile Action Bar）

### 3.1 设计理念

底部动作条是当前格的**统一互动入口**，所有可交互实体集中展示，不分散到地图格或侧边面板。
移动端优先：拇指可达区域操作，无需精确点击地图格上的小图标。

### 3.2 动作条结构

动作条展示两类内容：**建筑物**（逐条）和**脚边道具入口**（一条），以及**原地探索按钮**。

```
┌─────────────────────────────────────┐
│           地 图 主 视 图             │
│                                     │
│    建筑物以图标显示在地图格上          │
│                                     │
├─────────────────────────────────────┤  ← 底部动作条（Tile Action Bar）
│ 📦 补给储藏箱           [搜索]       │  ← 未搜索 → [搜索]
│ 📦 危险宝箱(已搜索)     [检查]       │  ← 已搜索有掉落 → [检查]
│ 🏛️ 地标                              │  ← 不可搜索 → 无按钮
│ 🗡️ 就在脚边...          [检查]       │  ← iaid=0 的道具（有才显示）
│ 🔍 [原地探索]                        │  ← 点击当前格或此按钮触发探索
└─────────────────────────────────────┘
```

**排列规则**：
1. 可交互建筑物排前（未搜索 > 已搜索有掉落 > 可重复搜索）
2. 不可搜索建筑物排后（灰显，无按钮）
3. 「就在脚边...[检查]」始终在最末（仅有 iaid=0 道具时显示）
4. 「原地探索」按钮固定在动作条底部

### 3.3 建筑物状态与按钮

| 建筑物状态 | 动作条显示 | 按钮行为 |
|-----------|-----------|----------|
| 未搜索 | 图标 + 名称 + [搜索] | 发送搜索指令 → 后端结算 → 日志显示结果 → 状态变为"已搜索" |
| 已搜索 + 有掉落物未拾取(iaid下有道具) | 图标 + 名称(已搜索) + [检查] | 打开底部弹窗，展示该建筑物的掉落物列表 |
| 已搜索 + 掉落物已全部拾取（一次性） | 图标 + 名称（灰显） | 无按钮，显示"已搜索" |
| 已搜索 + 可重复搜索 + 有掉落物 | 图标 + 名称(已搜索) + [检查] / [再搜索] | [检查]查看掉落物，[再搜索]再次结算 |
| 已搜索 + 可重复搜索 + 无掉落物 | 图标 + 名称(已搜索) + [再搜索] | 再次发送搜索指令 → 后端按 repeat_loot 结算 |
| 可重复搜索 + 冷却中 | 图标 + 名称 + [再搜索(冷却中)] | 按钮灰显，显示剩余冷却回合数 |
| 可重复搜索 + 已达上限 | 图标 + 名称（灰显） | 无按钮，显示"已搜索(上限)" |
| 不可搜索 | 图标 + 名称（灰显） | 无按钮，仅展示 |
| 机制触发型（图腾等） | 图标 + 名称 + [搜索/触碰] | 搜索时触发机制效果（回血/学技能），无道具掉落 |

**POI 可见性说明**：POI 无近视机制。迷雾清除后该格上所有 POI 自动可见，不存在"未知的建筑物（？）"状态。

**核心逻辑**：搜索和检查是两步操作。[搜索]是后端结算（生成道具），[检查]是查看结算结果（拾取道具）。

### 3.4 脚边道具入口

| 条件 | 显示 | 按钮行为 |
|------|------|----------|
| 当前格有 iaid=0 的已发现道具(discovered=1) | 🗡️ 就在脚边... + [检查] | 打开底部弹窗，展示所有脚边道具 |
| 当前格有 iaid=0 的近视道具(discovered=2) | 🗡️ 就在脚边... + "道具名（？）" | 可拾取，但拾取时揭示真实身份 |

### 3.5 近视道具的交互（拟态怪机制）

近视道具（discovered=2）采用**拟态怪**设计——靠近不会揭示真相，必须拾取才能发现真实身份：

| 近视类型 | 弹窗显示 | 拾取结果 |
|---------|---------|---------|
| 真实道具（fake_item_id 空） | "废铁片（？）" | 获得废铁片（就是它本身） |
| 同级不同道具（fake_item_id 非空） | "生命药剂（？）" | 获得真实道具（可能是废铁片等同级道具） |
| 更高级不同道具（fake_item_id 非空） | "废铁片（？）" | 获得真实道具（可能是更高级道具） |
| 伪装怪物（is_trap=1） | "生命药剂（？）" | 触发战斗，不获得道具 |

- 近视道具在弹窗中**可以点击[拾取]**，拾取时后端揭示真实身份
- 拾取后日志显示真实结果："你拾取了废铁片" 或 "那是一个陷阱！战斗开始！"
- **靠近不会揭示**：discovered=2 是近视道具的固定状态，不会因为走近而升级为 discovered=1
- 近视道具**只有拾取时才揭示**，这是拟态怪的核心体验

### 3.6 空状态

当前格无任何可交互实体时，底部动作条显示提示：

```
┌─────────────────────────────────────┐
│  这里空无一物...                     │
│  🔍 [原地探索]                       │
└─────────────────────────────────────┘
```

## 四、底部弹窗（Bottom Sheet）

底部弹窗由[检查]按钮触发，有两种场景，共用同一弹窗组件。

### 4.1 建筑物检查弹窗

点击建筑物(已搜索)的[检查]后触发：

```
┌─────────────────────────────────────┐
│           地 图 主 视 图             │
│           （半透明遮罩）              │
├─────────────────────────────────────┤
│  危险宝箱                            │  ← 建筑物名称
│  散发着不祥气息的金属箱...            │  ← 描述
│ ─────────────────────────────────── │
│  🗡️ 废铁片 ×3            [拾取]     │  ← 该建筑物的掉落物
│  🧪 生命药剂 ×1          [拾取]     │
│ ─────────────────────────────────── │
│                    [全部拾取]         │  ← 批量操作
└─────────────────────────────────────┘
```

### 4.2 脚边检查弹窗

点击「就在脚边...[检查]」后触发：

```
┌─────────────────────────────────────┐
│           地 图 主 视 图             │
│           （半透明遮罩）              │
├─────────────────────────────────────┤
│  脚边的物品                          │  ← 标题
│ ─────────────────────────────────── │
│  🗡️ 废铁片 ×2            [拾取]     │  ← iaid=0 的道具
│  🧪 生命药剂 ×1          [拾取]     │
│ ─────────────────────────────────── │
│                    [全部拾取]         │  ← 批量操作
└─────────────────────────────────────┘
```

### 4.3 交互规则

- 弹窗内道具逐个拾取或全部拾取
- 拾取后道具从弹窗列表消失，同时从 bra_oblmapitem 删除
- 全部拾取后弹窗自动关闭
- 点击遮罩区域可关闭弹窗（道具留在原地）
- 建筑物掉落物全部拾取后，动作条中该建筑物变为灰显"已搜索"状态
- 脚边道具全部拾取后，动作条中「就在脚边...」条目消失

### 4.4 机制触发

图腾类建筑物（mechanic 非空）搜索时，弹窗显示机制效果而非道具列表：

```
┌─────────────────────────────────────┐
│  生命图腾                            │
│  刻满符文的石柱，触碰后感到...        │
│ ─────────────────────────────────── │
│  ✦ 最大生命值 +10                    │  ← 机制效果
│ ─────────────────────────────────── │
│                    [确认]             │
└─────────────────────────────────────┘
```

**可重复机制触发型POI**（如生命图腾，repeat_limit=3）：搜索后显示效果，按钮变为[再触碰]，并显示剩余次数"2/3"。达到上限后灰显。

**一次性机制触发型POI**（如技能图腾，repeatable=false）：搜索后显示效果，按钮消失，建筑物灰显。

## 五、交互流程

### 5.1 完整生命周期

```
游戏初始化
  └── 后端: 生成野生道具(iaid=0) + 建筑物 → bra_oblmapitem / bra_oblmappoi
  └── 后端: 玩家出生点自动点亮迷雾 → bra_oblmapstates.fog=1
  └── 前端: 加载地图 + 动作条

玩家移动到某格
  └── map.js: obl_move() → 移动完成
  └── map.js: obl_explore() → 自动触发探索（点亮迷雾，发现道具/建筑物）
  └── map.js: DebugBus.emit('player:moved')
  └── tile-action.js: 监听事件 → 请求 tile_actions API
  └── tile-action.js: 渲染底部动作条
      ├── 建筑物交互项（逐条，按状态显示[搜索]/[检查]/[再搜索]）
      ├── 「就在脚边...[检查]」（仅有 iaid=0 道具时）
      └── 「原地探索」按钮

玩家原地探索（点击当前格 / 点击[原地探索]按钮）
  └── map.js: obl_explore() → 触发探索（同移动时的探索逻辑）
  └── map.js: DebugBus.emit('player:explored')
  └── tile-action.js: 监听事件 → 请求 tile_actions API → 刷新动作条

玩家点击建筑物的 [搜索]
  └── tile-action.js: POST command.php (action=obl_search, iaid=xxx)
  └── 后端: obl_search_poi() → 按掉落表生成道具 → bra_oblmapitem (iaid=该建筑物iaid, discovered=1)
  └── 后端: 若为机制触发型POI → 执行机制效果（回血/学技能），无道具掉落
  └── 后端: 若为可重复搜索 → 检查冷却/次数限制
  └── 后端: 写日志"你搜索了补给储藏箱……"
  └── 后端: 返回搜索结果
  └── tile-action.js: 动作条中建筑物状态更新 → 显示 [检查]

玩家点击建筑物的 [检查]
  └── tile-action.js: 打开底部弹窗，展示该建筑物(iaid)下的所有道具

玩家点击「就在脚边...[检查]」
  └── tile-action.js: 打开脚边检查弹窗，展示所有 iaid=0 的道具

玩家点击 [拾取]（弹窗内）
  └── tile-action.js: POST command.php (action=obl_pickup, iid=xxx)
  └── 后端: obl_pickup_item() → 揭示真实身份（近视道具）→ 写入 players 背包 → 删除 bra_oblmapitem 记录
  └── 后端: 若 is_trap=1 → 触发战斗，不获得道具
  └── 后端: 返回拾取结果（真实道具名 / 陷阱触发）
  └── tile-action.js: 弹窗中道具项更新/消失
  └── tile-action.js: 若建筑物道具全部拾取，该建筑物变为灰显
  └── tile-action.js: 若脚边道具全部拾取，「就在脚边...」条目消失

玩家离开再回到此格
  └── 动作条重新加载
  └── 未拾取的道具仍在原建筑物/脚边（bra_oblmapitem 不变）
```

### 5.2 搜索距离规则

- **默认**：只能搜索当前格的建筑物
- **技能扩展**：未来可通过技能解锁远程搜索（如视野范围内），届时动作条展示范围外的可搜索建筑物，并标注距离

## 六、地图格上的视觉标识

### 6.1 建筑物图标

建筑物在地图格上以小图标标识，帮助玩家在地图层面快速识别：

| 建筑物状态 | 地图格显示 |
|-----------|-----------|
| 未搜索 | 彩色图标（按类型区分） |
| 已搜索 + 有掉落物 | 彩色图标 + 闪光提示 |
| 已搜索 + 掉落物已拾取 | 灰色图标 + 勾 |
| 已搜索（可重复） | 彩色图标 + 循环标记 |
| 可重复 + 冷却中 | 彩色图标 + 沙漏标记 |
| 不可搜索 | 浅色图标 |
| 迷雾中 | 不显示（迷雾未清除时不可见） |

### 6.2 道具标识

地图格上的道具以小点或迷你图标标识：

| 道具状态 | 地图格显示 |
|---------|-----------|
| 已发现（属于建筑物） | 不单独显示（通过建筑物图标闪光提示） |
| 已发现（iaid=0） | 小亮点/图标 |
| 近视（discovered=2） | 模糊小点 |
| 未发现（迷雾中） | 不显示 |

### 6.3 迷雾视觉

| 迷雾状态 | 地图格显示 |
|---------|-----------|
| 未探索 | 深色遮罩 |
| 已探索 | 正常显示 |

## 七、API 需求

### 7.1 新增 API Action

| Action | 方法 | 参数 | 返回 | 说明 |
|--------|------|------|------|------|
| `tile_actions` | GET | `pgroup`, `pls` | 当前格的建筑物列表 + 道具分组 | 动作条数据源 |
| `obl_explore` | POST | `pgroup`, `pls` | 探索结果（迷雾更新 + 发现的道具/建筑物） | 原地探索 |
| `obl_search` | POST | `iaid` | 掉落道具列表 + 机制效果 | 搜索建筑物 |
| `obl_pickup` | POST | `iid` | 拾取结果（含真实身份揭示） | 拾取地图道具 |

- `pois[].items`：该建筑物(iaid)下的道具列表
- `ground_items`：iaid=0 的脚边道具列表
- POI 无 `discovered` 字段，其可见性由地图格迷雾状态决定
- 道具 `discovered`：0=未发现, 1=已发现, 2=近视（拟态怪）
- 当道具 `discovered=2` 时，额外返回 `display_name`（显示名+（？））、`fake_item_id`、`is_trap`
- 当道具 `discovered=1` 时，不返回 `fake_item_id` 和 `is_trap`（前端不需要知道）
- `repeat_limit`：最大搜索次数，0=无限
- `repeat_cooldown`：冷却回合数，0=无冷却
- `repeat_cooldown_remaining`：剩余冷却回合数（仅冷却中时返回）
- `mechanic`：机制标识（非空时为机制触发型POI，搜索时触发效果而非掉落道具）
