# 设计案2：新建前端导演系统

> 本文档定义前端 `BattleDirector` 模块的设计方案：把后端 raw entries 编排为演出脚本。
>
> **所属总纲**：[战斗演出三层架构设计案.md](战斗演出三层架构设计案.md)
> **依赖**：[设计案1-重构后端battle_log.md](设计案1-重构后端battle_log.md)（需要后端提供细分 phase + 完整字段）
> **下游**：[设计案3-重构前端播放系统.md](设计案3-重构前端播放系统.md)

---

## 一、设计目标

### 1.1 核心问题

当前前端 battlelog 播放逻辑中，表现逻辑（分组、显示模式、动画类型、HP 快照选取）散落在 `battle.ts` 和 `BattleModal.vue` 的各处 `if` 判断中。每新增一种动作/动画，就要在前端多处添加判断。

### 1.2 改动目标

1. **新增 `BattleDirector` 模块**：集中所有表现逻辑判断
2. **同步纯函数**：输入 raw entries → 输出 `PlayScript[]`，无副作用
3. **与现有代码隔离**：新文件，不影响现有播放逻辑（设计案3 才接入）
4. **可测试性**：纯函数，易于单元测试

---

## 二、模块定位

### 2.1 文件位置

```
vex-vue/src/stores/battle-director.ts
```

### 2.2 模块性质

- **同步纯函数**：不涉及任何异步操作（不查 API、不等待动画）
- **无副作用**：不修改输入 entries，不修改任何 store 状态
- **一次性处理**：拉取到一批 entries 后，一次性编排完所有场景

### 2.3 调用时机

在 `fetchAndPlayBattleLog` 中，拉取到 entries 之后、播放之前调用：

```
fetchAndPlayBattleLog()
  → 拉取 entries（played=0）     ← 后端返回 raw data
  → BattleDirector.direct(entries)  ← 导演：同步纯函数，编排为 PlayScript[]
  → BattlePlayer.play(scripts)      ← 演员：逐场景执行（设计案3）
  → markBattleLogPlayed()
```

## 三、输入/输出定义

### 3.1 输入：Raw BattleLog Entry

来自后端的 raw entries，字段按 [设计案1](设计案1-重构后端battle_log.md) 改造后的结构：

```typescript
interface BattleLogEntry {
  log_id: number;
  played: number;
  ts: number;
  turn: number | null;

  // 事件标识
  phase: string;              // 细分后的 phase
  action_id: string | null;   // 具体动作（可为 null）

  // 行动者信息
  actor_pid: number | null;
  actor_type: number | null;
  actor_name: string | null;
  actor_hp: number | null;
  actor_max_hp: number | null;
  actor_ap: number | null;
  actor_max_ap: number | null;

  // 目标信息
  target_pid: number | null;
  target_type: number | null;
  target_name: string | null;
  target_hp: number | null;
  target_max_hp: number | null;

  // 效果
  effect_value: number | null;

  // 事件元数据
  qid: number | null;
  rolls: array | null;
  ambush_pid: number | null;
  combatants: array | null;
  is_rebuild: boolean | null;
  reason: string | null;
  winner_pid: number | null;
}
```

### 3.2 输出：PlayScript

```typescript
/** 动画类型 */
type AnimationType = 'none' | 'collision' | 'skill_effect';

/** 显示模式 */
type DisplayMode = 'flow' | 'combat';

/** 导演编排后的条目 */
interface DirectedEntry extends BattleLogEntry {
  /** 动画类型（导演决定） */
  animation: AnimationType;
  /** HP 快照（从 damage_pre/damage_post 配对选取） */
  hpSnapshot: {
    actorHpBefore: number;
    actorHpAfter: number;
    actorMaxHp: number;
    targetHpBefore: number;
    targetHpAfter: number;
    targetMaxHp: number;
  } | null;
  /** 配对的 damage_post entry（如果是 damage_pre） */
  pairedPost: BattleLogEntry | null;
  /** 配对的 damage_pre entry（如果是 damage_post） */
  pairedPre: BattleLogEntry | null;
}

/** 演出脚本（一个场景） */
interface PlayScript {
  /** 分组标识 */
  groupId: string;
  /** 显示模式 */
  displayMode: DisplayMode;
  /** NPC PID（combat 模式下用于碰撞动画定位） */
  npcPid: number;
  /** 编排后的条目 */
  entries: DirectedEntry[];
}
```

## 四、核心函数设计

### 4.1 主函数 direct()

```typescript
/**
 * 战斗导演：把后端 raw entries 编排为演出脚本
 *
 * 集中所有表现逻辑判断，消除散落在 store/modal 的 if。
 *
 * @param entries 后端 raw battlelog entries（按 log_id 升序）
 * @returns 演出脚本数组
 */
export function direct(entries: BattleLogEntry[]): PlayScript[] {
  if (entries.length === 0) return [];

  // 1. 配对 damage_pre / damage_post
  const paired = pairDamagePrePost(entries);

  // 2. 分组：按交战对（actor_pid/target_pid 无序对）分组
  const groups = groupByEncounterPair(paired);

  // 3. 每组编排演出
  return groups.map(group => ({
    groupId: group.id,
    npcPid: group.npcPid,
    displayMode: decideDisplayMode(group),
    entries: group.entries.map(e => ({
      ...e,
      animation: decideAnimation(e),
      hpSnapshot: pickHpSnapshot(e),
      pairedPost: e.pairedPost ?? null,
      pairedPre: e.pairedPre ?? null,
    })),
  }));
}
```

### 4.2 配对函数 pairDamagePrePost()

```typescript
/**
 * 配对 damage_pre 和 damage_post
 *
 * 按顺序配对：damage_pre 后面紧跟的 damage_post 视为同一次伤害。
 * 当前 battle_once_excute 中两次 emit 之间无其他 emit，顺序配对安全。
 *
 * @param entries raw entries
 * @returns 配对后的 entries（damage_pre 携带 pairedPost，damage_post 携带 pairedPre）
 */
function pairDamagePrePost(entries: BattleLogEntry[]): DirectedEntry[] {
  const result: DirectedEntry[] = [];
  let pendingPre: BattleLogEntry | null = null;

  for (const e of entries) {
    if (e.phase === 'damage_pre') {
      // 如果有未配对的 damage_pre，先入队（异常情况：damage_pre 后无 damage_post）
      if (pendingPre) {
        result.push({ ...pendingPre, animation: 'none', hpSnapshot: null, pairedPost: null, pairedPre: null });
      }
      pendingPre = e;
    } else if (e.phase === 'damage_post') {
      if (pendingPre) {
        // 配对成功
        result.push({
          ...pendingPre,
          animation: 'none',  // 待 decideAnimation 填充
          hpSnapshot: null,   // 待 pickHpSnapshot 填充
          pairedPost: e,
          pairedPre: null,
        });
        result.push({
          ...e,
          animation: 'none',
          hpSnapshot: null,
          pairedPost: null,
          pairedPre: pendingPre,
        });
        pendingPre = null;
      } else {
        // 异常情况：damage_post 无对应的 damage_pre
        result.push({ ...e, animation: 'none', hpSnapshot: null, pairedPost: null, pairedPre: null });
      }
    } else {
      // 非 damage 条目，直接入队
      if (pendingPre) {
        result.push({ ...pendingPre, animation: 'none', hpSnapshot: null, pairedPost: null, pairedPre: null });
        pendingPre = null;
      }
      result.push({ ...e, animation: 'none', hpSnapshot: null, pairedPost: null, pairedPre: null });
    }
  }

  // 处理尾部未配对的 damage_pre
  if (pendingPre) {
    result.push({ ...pendingPre, animation: 'none', hpSnapshot: null, pairedPost: null, pairedPre: null });
  }

  return result;
}
```

### 4.3 分组函数 groupByEncounterPair()

```typescript
interface EntryGroup {
  id: string;
  npcPid: number;
  entries: DirectedEntry[];
}

/**
 * 按交战对分组
 *
 * 规则：
 * - 有目标条目（actor_pid>0 && target_pid>0）→ 按 {min(a,t), max(a,t)} 无序对分组
 * - 无目标条目（initiative_roll / queue_create / ap_recover / turn_start / battle_end）
 *   → 每条单独成组（flow 组）
 *
 * @param entries 配对后的 entries
 * @returns 分组结果
 */
function groupByEncounterPair(entries: DirectedEntry[]): EntryGroup[] {
  const map = new Map<string, EntryGroup>();

  for (const e of entries) {
    const a = Number(e.actor_pid) || 0;
    const t = Number(e.target_pid) || 0;

    let key: string;
    let npcPid: number;

    if (a > 0 && t > 0) {
      // 有目标：按无序对分组
      key = `pair_${Math.min(a, t)}_${Math.max(a, t)}`;
      npcPid = extractNpcPid(e);
    } else {
      // 无目标：单独成组
      key = `solo_${e.phase}_${e.log_id}`;
      npcPid = 0;
    }

    if (!map.has(key)) {
      map.set(key, { id: key, npcPid, entries: [] });
    }
    map.get(key)!.entries.push(e);
  }

  return Array.from(map.values());
}

/**
 * 从 entry 中提取 NPC PID
 * actor_type > 0 → actor_pid
 * target_type > 0 → target_pid
 */
function extractNpcPid(e: BattleLogEntry): number {
  if (Number(e.actor_type) > 0) return Number(e.actor_pid) || 0;
  if (Number(e.target_type) > 0) return Number(e.target_pid) || 0;
  return 0;
}
```

### 4.4 显示模式判断 decideDisplayMode()

```typescript
/**
 * 决定显示模式
 *
 * 规则：
 * - 组内任一条目有目标（actor_pid>0 && target_pid>0）→ combat（有 HP 条）
 * - 否则 → flow（无 HP 条）
 *
 * @param group 分组
 * @returns 显示模式
 */
function decideDisplayMode(group: EntryGroup): DisplayMode {
  const hasTarget = group.entries.some(
    e => Number(e.actor_pid) > 0 && Number(e.target_pid) > 0,
  );
  return hasTarget ? 'combat' : 'flow';
}
```

### 4.5 动画类型判断 decideAnimation()

```typescript
/**
 * 决定动画类型
 *
 * 规则：
 * - damage_pre 阶段 + action_id 为攻击类 → collision
 * - 其他 → none
 *
 * 未来扩展：
 * - skill_xxx → skill_effect
 *
 * @param e 配对后的 entry
 * @returns 动画类型
 */
function decideAnimation(e: DirectedEntry): AnimationType {
  // 只有 damage_pre 播放碰撞动画（damage_post 不播）
  if (e.phase !== 'damage_pre') return 'none';

  // 攻击类动作播碰撞动画
  const attackActions = ['unarmed_strike', 'escape'];
  if (e.action_id && attackActions.includes(e.action_id)) {
    return 'collision';
  }

  // 未来扩展：技能特效
  // if (e.action_id?.startsWith('skill_')) return 'skill_effect';

  return 'none';
}
```

### 4.6 HP 快照选取 pickHpSnapshot()

```typescript
/**
 * 选取 HP 快照
 *
 * 规则：
 * - damage_pre：从自身读 actor_hp/target_hp（before），从 pairedPost 读 after
 * - damage_post：从 pairedPre 读 before，从自身读 after
 * - 其他：null
 *
 * @param e 配对后的 entry
 * @returns HP 快照（或 null）
 */
function pickHpSnapshot(e: DirectedEntry): DirectedEntry['hpSnapshot'] {
  if (e.phase === 'damage_pre' && e.pairedPost) {
    return {
      actorHpBefore: Number(e.actor_hp) || 0,
      actorHpAfter: Number(e.pairedPost.actor_hp) || 0,
      actorMaxHp: Number(e.actor_max_hp) || 0,
      targetHpBefore: Number(e.target_hp) || 0,
      targetHpAfter: Number(e.pairedPost.target_hp) || 0,
      targetMaxHp: Number(e.target_max_hp) || 0,
    };
  }

  if (e.phase === 'damage_post' && e.pairedPre) {
    return {
      actorHpBefore: Number(e.pairedPre.actor_hp) || 0,
      actorHpAfter: Number(e.actor_hp) || 0,
      actorMaxHp: Number(e.pairedPre.actor_max_hp) || 0,
      targetHpBefore: Number(e.pairedPre.target_hp) || 0,
      targetHpAfter: Number(e.target_hp) || 0,
      targetMaxHp: Number(e.pairedPre.target_max_hp) || 0,
    };
  }

  return null;
}
```

## 七、边界情况

### 7.1 damage_pre 无配对

异常情况：`damage_pre` 后无 `damage_post`（如 battle_once_excute 中途异常退出）。

处理：`pairDamagePrePost` 将未配对的 `damage_pre` 直接入队，`hpSnapshot` 为 `null`，前端演员降级显示（不播 HP 条动画）。

### 7.2 damage_post 无配对

异常情况：`damage_post` 无对应的 `damage_pre`。

处理：同上，`hpSnapshot` 为 `null`，降级显示。

### 7.3 多 NPC 战斗

多个交战对各自成组，分别播放。`groupByEncounterPair` 用 `pair_{min}_{max}` 作为 key，不同交战对不会混淆。

### 7.4 玩家自己作为目标

`ap_recover` 的 `target_pid` 为 `null`（设计案1 改造后），`decideDisplayMode` 判定为 flow，不会误显示 HP 条。

### 7.5 空 entries

`direct([])` 返回 `[]`，不报错。
