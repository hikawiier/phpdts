# Oblivions 道具数据三层分离 — 设计案

> 将道具/POI 的"游戏逻辑初始值"、"运行时实例状态"、"展示文案"三层职责分离。
> 与 [DESIGN.md §2.2](../DESIGN.md)（后端只输出事件结构）理念对齐，将文案职责彻底归前端。

---

## 一、问题背景

当前 `item_table.php` / `poi_table.php` 把两类数据混在一起：

| 数据类型 | 当前位置 | 性质 |
|---------|---------|------|
| 游戏逻辑初始值 | `itmk/itme/itms/itmsk/itmpara/use_effect` | 后端权威，前端不需要 |
| 文案资源 | `itm(名称)/desc(描述)` | 前端展示用，后端不关心 |

这与日志系统的设计理念**不一致**——日志已经走了"后端发 `log_id + params`，前端用 `log-templates.ts` 渲染"的模式（DESIGN.md §2.2）。道具/POI 的文案应该对齐这个模式。

---

## 二、逐字段变化分析

七字段（itmid/itm/itmk/itme/itms/itmsk/itmpara）中，哪些会在游戏进程中偏离模板初始值？

| 字段 | 模板初始值 | 实例变化场景 | 结论 |
|------|-----------|-------------|------|
| `itmid` | item_id（如 `'rusty_pipe'`） | 不变（实例不会变成另一个模板） | 实例层保留作索引 |
| `itm` | 模板名称 | **改名机制**（玩家自定义名称/称号） | 实例层保留 |
| `itmk` | 种类代码（WP/WK/...） | **武器进化/升星**（子类型变化） | 实例层保留 |
| `itme` | 效果值（攻击力/恢复量） | **强化/改造/附魔** | 实例层保留 |
| `itms` | 耐久 | **使用消耗/胃酸腐蚀/战斗磨损** | 实例层保留 |
| `itmsk` | 特殊属性（`'p'`毒/`'f'`火） | **涂毒/附魔/改造** | 实例层保留 |
| `itmpara` | 自由字段（通常空） | **任何实例状态**（充能/附魔参数/自定义数据） | 实例层保留 |

**核心洞察**：七字段本质上**全部都是"道具实例的运行时状态"**，任何一个都可能在游戏过程中偏离模板初始值。因此持久化层必须完整保留七字段，不能砍掉任何一个。

真正可以剥离的是**模板层的文案字段**（itm/desc）——它们是展示资源，不是游戏逻辑。

---

## 三、三层分离架构

问题不在于"砍字段"，而在于**区分三层职责**：

```
┌─ 前端文案层（locale）──────────────────────────────┐
│  vex-vue/src/data/item-locale.ts                    │
│    item_id → { name, desc }                         │
│  vex-vue/src/data/recipe-locale.ts                  │
│    recipe_id → { name, desc }                       │
│  vex-vue/src/data/poi-locale.ts                     │
│    poi_id → { name, desc }                          │
│  纯文案，前端权威，后端不持有                         │
└─────────────────────────────────────────────────────┘

┌─ 后端模板层（gamedata/*.php）──────────────────────┐
│  item_table.php                                     │
│    item_id → { itmk, itme, itms, itmsk, itmpara,    │
│                use_effect, tier, stack, ... }        │
│  游戏逻辑初始值。拾取时作为"出厂设置"复制到实例       │
│  移除 itm 和 desc 字段（文案归前端 locale）          │
└─────────────────────────────────────────────────────┘

┌─ 后端实例层（itempara / bra_oblmapitem）───────────┐
│  itempara[slot] = { itmid, itm, itmk, itme, itms,   │
│                     itmsk, itmpara }                 │
│  运行时状态。任何字段都可能偏离模板初始值             │
│  itm 字段语义改为"自定义名称"，空=用 locale 渲染     │
└─────────────────────────────────────────────────────┘
```

### 3.1 前端文案层

- 纯文案，前端权威，后端不持有
- 支持本地化（未来多语言只需替换 locale 文件）
- 前端可独立迭代文案，无需后端发版

### 3.2 后端模板层

- 游戏逻辑初始值，后端权威
- 拾取时作为"出厂设置"复制到实例
- **移除 itm 和 desc 字段**（文案归前端 locale）

### 3.3 后端实例层

- 运行时状态，任何字段都可能偏离模板初始值
- 完整保留七字段
- **itm 字段语义调整**：从"模板名称"改为"自定义名称"，空值=用 locale 渲染

---

## 四、itm 字段的特殊处理

这是唯一需要语义调整的字段：

| 场景 | 实例层 itm | 前端渲染 |
|------|-----------|---------|
| 普通道具 | 留空 `""` | 查 locale 显示模板名称 |
| 改名道具 | `"我的爱棍"` | 直接显示 itm |
| 涂毒道具 | 留空 `""` | 查 locale + itmsk 后缀（如"生锈的水管(毒)"） |

**拾取时 itm 留空**（不再从模板复制名称）。前端渲染时判断 itm 是否为空：
- 空 → 用 `itmid` 查 locale 得到模板名称
- 非空 → 用 itm 作为自定义名称

这样改名机制 P0 不实现也不影响，未来启用时只需让改名道具写入 itm 字段。

---

## 五、迁移方案

### 5.1 短期（P0 立即采用）

- **新增系统（use_item/craft）的 API 响应不带 itm/desc**
- **新文件（`recipe_table.php`）从一开始就不放文案**
- 前端建立 `item-locale.ts` / `recipe-locale.ts` / `poi-locale.ts`
- 后端 `item_table.php` 保留 itm/desc 作为 deprecated 源头数据，新代码不依赖
- `obl_pickup_item` 调整：拾取时 itm 留空

### 5.2 长期（后续重构）

- `item_table.php` 移除 itm/desc 字段
- 现有持久化数据兼容：`itempara` / `bra_oblmapitem` 里的 itm 字段保留不动（有值继续用，新拾取的留空）
- 装备字段已新增独立模板 ID 列（`wepid`/`wep2id`/`arbid`/`arhid`/`araid`/`arfid`/`artid`），原 `wep`/`arb` 等名称字段改为自定义名语义

## 六、影响范围

### 新增文件

| 文件 | 说明 |
|------|------|
| `vex-vue/src/data/item-locale.ts` | item_id → { name, desc } |
| `vex-vue/src/data/recipe-locale.ts` | recipe_id → { name, desc } |
| `vex-vue/src/data/poi-locale.ts` | poi_id → { name, desc } |

### 修改文件

| 文件 | 改动 |
|------|------|
| `oblivions/gamedata/item_table.php` | 移除 itm/desc（长期），或标记 deprecated（短期） |
| `oblivions/gamedata/poi_table.php` | 移除 name/desc（长期），或标记 deprecated（短期） |
| `oblivions/gamedata/recipe_table.php`（新建） | 从一开始就不放文案 |
| `oblivions/include/game/explore.func.php` | `obl_pickup_item` 拾取时 itm 留空 |
| `vex-vue/src/api/endpoints.ts` | 新 API 响应不含 itm/desc |
| `vex-vue/src/components/` | 渲染时通过 locale 查询名称 |

---

## 七、与日志系统的对齐

| 系统 | 后端输出 | 前端渲染 |
|------|---------|---------|
| 结构化日志 | `log_id + params` | `log-templates.ts` |
| 战斗日志 | `action_id + params` | `battle-templates.ts` |
| 道具/POI（目标） | `item_id`/`poi_id` + 游戏逻辑 | `item-locale.ts` / `poi-locale.ts` |

三层文案职责统一归前端，后端只输出"发生了什么 + 数据参数"。
