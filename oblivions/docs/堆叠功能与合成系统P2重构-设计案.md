# 堆叠功能与合成系统 P2 重构 - 设计案

> 本案实现背包道具堆叠机制，引入 itm0 缓存槽作为新增道具的中转站，并同步完成合成系统的 P2 重构（提取 placed_items 辅助函数）。
> 核心架构：新增操作（拾取/合成产物）→ itm0 缓存 → 自动整理（转移 itm0 + 合并背包）。

---

## 一、背景与目标

### 1.1 当前问题

| 问题 | 现状 | 影响 |
|------|------|------|
| 堆叠未实现 | `item_table.php` 声明了 `stack=true`，但代码层 `obl_set_item` 不合并堆叠 | 5个布料占5个槽位，背包浪费严重 |
| 合成不支持部分投入 | `slots` 参数只携带槽位号，不携带数量 | 堆叠后无法从一堆中投入部分素材 |
| placed_items 构建重复 | 3处代码重复构建 placed_items（item_craft / item_match_recipes_by_slots / item_consume_materials） | 维护负担，P2 重构目标 |
| consume='all' 消耗整槽 | `unset($pdata['itempara'][$slot])` | 堆叠后会浪费多余素材 |

### 1.2 目标

1. 实现堆叠：通过 itm0 缓存 + 整理功能，实现同类道具自动合并
2. 合成系统支持部分投入：`slots` 参数携带数量，如 `"1:3,2:1"`
3. P2 重构：提取 `_item_build_placed_items` 辅助函数，统一3处重复逻辑
4. 职责分离：新增操作（找空槽放入）与整理操作（合并同类）拆分为独立模块

### 1.3 核心架构

```
新增操作（拾取/合成产物）
    ↓
itm0 缓存槽（itempara[0]，持久化）
    ↓
自动整理（转移 itm0 → 背包 + 合并背包同类堆叠）
    ↓
背包（itempara[1..itemmaxslots]）
```

**关键约束**：itm0 不为空时，后端拒绝所有非整理命令（全局门控）。

## 二、itms 语义规则

### 2.1 双重语义（不拆分字段）

| 道具类型 | itme | itms | 示例 |
|---------|------|------|------|
| 可堆叠道具（stack=true） | 单个效果值 | **堆叠数量** | cloth: itme=1, itms=3 → 3块布料 |
| 不可堆叠道具（stack=false） | 攻击力/效果值 | **耐久度** | rusty_pipe: itme=8, itms=20 → 耐久20 |

**不拆分理由**：两个语义互斥（可堆叠道具无耐久概念，不可堆叠道具无堆叠概念），操作逻辑统一（`itms-1` + 归零移除），拆分代价远大于收益。

### 2.2 无限标识

`itms='∞'`（或 `'999'`）统一表示"无限"：
- 可堆叠道具：无限多个（如特殊事件赋予的无限素材）
- 不可堆叠道具：无限耐久（如永久武器）

`item_consume_durability` 中 `if ($s === '∞' || $s === '999') return;` 对两种情况都正确。

### 2.3 itms 的两种语义模型

itms 的含义由 `stack` 字段决定，两种模型互斥：

| 模型 | stack | itms 含义 | 使用消耗（itms-1） | 合成 consume='all' | 合成 consume='durability' |
|------|-------|----------|-------------------|-------------------|------------------------|
| **数量模型** | true | 堆叠数量 | 消耗1个单位 | 扣 itms-N（N=该槽位投入数） | 扣1个数量（itms-1） |
| **耐久模型** | false | 耐久度/使用次数 | 扣1点耐久 | unset 整槽 | 扣1点耐久（itms-1） |

**consume='durability' 的统一语义**：消耗1单位（数量模型=扣1个数量，耐久模型=扣1点耐久）。
- 与 consume='all' 的区别：consume='all' 消耗整个槽位（数量模型扣 itms-N，耐久模型 unset 整槽）；consume='durability' 只消耗1单位，剩余保留。
- 与使用消耗（itms-1）的语义一致：无论数量模型还是耐久模型，都是"消耗1单位"。

**判断标准**（设计阶段，由使用语义反推）：
1. 使用时消耗"道具本身"（吃掉、喝掉、用掉）→ **数量模型** → `stack=true`
   - 典型：面包（吃1块）、药剂（喝1瓶）、布料（合成消耗1块）
2. 使用时消耗"道具耐久"而非道具本身（磨刀损耗、武器攻击损耗）→ **耐久模型** → `stack=false`
   - 典型：磨刀石（磨1次刀损耗）、武器（攻击损耗）、防具（防御损耗）

**phpdts 原设计原则的实质**：堆叠前提是"堆内每个单位完全相同"。
- 数量模型 + itme 恒定 → 可堆叠（每块面包 itme 相同，合并无歧义）
- 耐久模型 → 即使 itme 相同也**不可堆叠**（耐久是个体属性，两块耐久10和耐久5的磨刀石合并成 itms=15 后无法区分个体）

**itmpara 的堆叠约束**：可堆叠道具（stack=true）的 itmpara 必须是**模板参数**（来自 item_table 的静态参数），不可存储个体运行时状态（如剩余冷却时间、强化等级、累计使用次数）。理由：堆叠合并要求堆内每个单位完全相同，若 itmpara 携带个体状态，合并后无法区分个体，状态会被错误聚合或丢失。

设计阶段需判断：若道具需要存储个体运行时状态 → 必须设为 `stack=false`（耐久模型，不可堆叠）。堆叠合并时通过 `_item_para_key()` 比较 itmpara 是否相等（详见 §6.1），不同 itmpara 的同类道具不合并（各自占据独立槽位）。

**关键洞察**：`use_effect` 的存在**不**决定模型——面包有 use_effect 但是数量模型，磨刀石有 use_effect 但是耐久模型。决定模型的是"使用时消耗的是什么"。

**从需求反推**：合成时需要走量（3块布、2个面包）→ 数量模型 → `stack=true`；合成时只需1个（1把刀、1个磨刀石）→ 耐久模型 → `stack=false`。合成需求是使用语义的衍生，两者一致。

## 四、itm0 缓存槽与全局门控

### 4.1 itm0 的定义

- **位置**：`itempara[0]`（特殊槽，已预留，`obl_find_empty_slot` 不查槽0）
- **持久化**：itm0 随玩家数据持久化（phpdts 传统做法），断线重连后 itm0 内容保留
- **容量规则**：与普通槽位相同——可堆叠道具最多放 `stack_limit` 个，不可堆叠道具放1个

### 4.2 全局门控

**核心约束**：itm0 不为空时，后端拒绝所有非整理/丢弃命令。

```php
// oblivions_cmd_dispatch 中，switch 之前插入门控
function oblivions_cmd_dispatch($command, &$pdata, $post) {
    include_once GAME_ROOT . './oblivions/include/command/oblivions_commands.php';
    global $obl_log;

    // 全局门控：itm0 不为空时，只放行整理和丢弃命令
    $itm0_pending = isset($pdata['itempara'][0]) && !empty($pdata['itempara'][0]['itmid']);
    if ($itm0_pending && !in_array($command, ['obl_organize', 'obl_discard'])) {
        $obl_log->emit('system.itm0_pending', 'system');
        return 'command';
    }

    switch ($command) {
        // ... 现有命令 ...
        case 'obl_organize':
            cmd_handle_obl_organize($pdata);
            return 'command';
    }
}
```

**门控放行的命令**：
- `obl_organize`：整理背包（转移 itm0 + 合并背包）
- `obl_discard`：丢弃道具（含丢弃 itm0，slot=0 时丢弃 itm0 内容）

**门控拒绝的命令**：移动、探索、搜索、拾取、合成、战斗、使用道具等所有其他命令。

**门控拒绝 `obl_use_item` 的理由**：保持 itm0 处理的最高优先级。itm0 中的道具处于"待整理"状态，玩家必须先将其处理（整理入背包或丢弃）才能继续其他游戏行为。若允许使用背包内道具，玩家可能消耗掉本可用于容纳 itm0 道具的空间（如使用药剂后腾出的空槽应优先用于整理 itm0），导致状态机复杂化。强制先处理 itm0 简化了状态管理。

**门控解锁时机**：门控是动态检查 `!empty($pdata['itempara'][0]['itmid'])`，不依赖任何状态标记。一旦 itm0 被清空（通过整理成功或丢弃 itm0），下一条命令立即解锁，无需额外操作。

**状态保证**：正常游戏时 itm0 始终为空。只有3种情况 itm0 会有道具：
1. 新增操作刚执行完，自动整理失败（背包满）
2. 断线重连（上次操作中途断线）
3. 合成部分成功（多产物配方中途背包满，剩余产物保留在 itm0）

**前端感知原则**：前端通过 log/error_log 系统统一感知命令执行结果（成功/失败/堵塞）。`system.itm0_pending` 事件即堵塞信号，前端收到后引导玩家整理背包或丢弃 itm0 道具。无需额外的 API 字段或轮询机制。

**预留说明（暂不实现）：拆分命令（split_itm）**

旧模式 phpdts 在 itm0 门控白名单中包含 `split_itm` 命令（允许玩家在 itm0 锁定状态下拆分堆叠）。本案不实现拆分命令，理由：
1. **整理功能已覆盖主要场景**：自动整理会合并同类堆叠，玩家无需手动拆分来"腾出空槽"。
2. **合成支持部分投入**：`slots="1:3"` 允许从一堆中投入部分素材，覆盖了"拆分用于合成"的需求。
3. **简化玩家心智**：减少命令数量，降低 UI 复杂度。

若未来发现拆分需求（如"想给队友分一半道具"），可独立设计 `obl_split` 命令。门控白名单需同步扩展（`obl_split` 加入 itm0 门控放行列表）。

### 4.3 新增流程

**拾取流程**（单产物 + 操作可回滚）：

```
1. 产物 → itm0（obl_put_item_to_itm0，检查 itm0 为空后放入）
2. 操作执行（删除地图实例）
   - 失败（并发拾取被抢）：回滚 itm0（unset itempara[0]），终止
3. 自动整理（obl_organize_inventory）
   - 成功：itm0 清空，玩家无感知
   - 失败：itm0 保留，玩家被锁定，前端通过 organize.fail 事件感知（见 §4.2）
4. 拾取成功 emit（pickup.success，与整理结果解耦）
5. 整理失败 emit（organize.fail，带 item_id）
```

**顺序理由**：先入 itm0 再执行操作，操作失败时只需 `unset(itempara[0])` 即可回滚（O(1)）。若先操作再入 itm0，操作成功但 itm0 写入失败会丢失道具。

**事件解耦**：拾取成功（`pickup.success`）与整理失败（`organize.fail`）是独立事件。拾取成功表示道具已从地图删除并存入 itm0 或背包；整理失败表示道具卡在 itm0 需要玩家手动处理。前端可同时收到两个事件，分别处理。

**合成流程**（见 §8.6 详细实现）：

```
1. 扣减素材（item_consume_materials）
2. 逐个产物循环：
   a. 产物 → itm0（obl_put_item_to_itm0）
   b. 自动整理（obl_organize_inventory）
      - 成功：itm0 清空，继续下一个产物
      - 失败：emit organize.fail（带 item_id），break 退出循环，玩家被锁定
3. 合成成功 emit（craft.success，仅传 recipe_id，前端从配置查产物）
```

**合成不适用"先入 itm0 再操作"流程的理由**：合成可能有多个产物，若第一个产物入 itm0 后还没整理，第二个产物入 itm0 会覆盖第一个。所以合成必须"先扣素材 → 逐个产物入 itm0 + 整理"。素材扣减在 §8.4 步骤6 已通过空间预检查保证成功，扣减本身不会失败。

**自动整理的意义**：拾取是高频操作，玩家不应每次都手动整理。自动整理成功时与原拾取体验一致；失败时与"背包满无法拾取"体验一致，只是多了一个"取出 itm0 或丢弃背包道具"的选择。

**预留说明（暂不实现）：卸装备走 itm0**

未来实现装备系统时，卸下装备应走 itm0 流程（卸装备 → 填入 itm0 → 自动整理），与拾取/合成产物统一架构。旧模式 phpdts 的 `itemoff()` 即采用此模式（卸装备→itm0→itemget()）。

实现装备系统时需扩展：
- `obl_unequip` 命令：卸装备 → 设置 itempara[0] → 自动整理
- 失败处理：背包满时装备保留在装备槽，不卸下（避免装备丢失）
- 门控逻辑：与现有 itm0 门控一致

## 五、整理功能模块

### 5.1 整理操作的定义

整理 = **合并背包内同类堆叠** + **转移 itm0 → 背包**（含合并到已有堆叠）

```
整理算法：
  1. 合并背包内同类堆叠（腾出空槽）
  2. 转移 itm0 → 背包（先合并到已有堆叠，再找空槽）
```

**无步骤3**：`obl_add_item_to_inventory` 在转移时已做"先合并到已有堆叠"，转移后不会存在"itm0 道具 + 背包同类未合并"状态；步骤2 创建的新堆叠必为 stack_limit 满堆叠（除最后一个可能不满），无需再次合并。

**整理的幂等性**：多次执行结果相同，不重复消耗资源。失败后再次整理，如果背包状态没变，结果仍为失败。

### 5.2 整理的触发时机

| 时机 | 场景 | 说明 |
|------|------|------|
| **自动触发** | 新增操作（拾取/合成）后自动调用 | 玩家无感知，失败时 itm0 保留 |
| **手动触发** | 玩家点击"整理"按钮（`obl_organize` 命令） | 用于 itm0 被锁定时主动整理 |

### 5.3 整理失败的处理

自动整理失败时（背包满 + 合并后仍无空间）：
- itm0 保留道具，玩家被门控锁定
- 前端弹出"背包已满，请整理背包或丢弃道具"的提示
- 玩家可选择：
  1. 手动整理（`obl_organize`）：再次尝试合并 + 转移
  2. 丢弃背包内道具（`obl_discard`，slot ≥ 1）：腾出空间后**需再次执行整理**才能转移 itm0（丢弃不自动整理，保持命令职责分离）
  3. 丢弃 itm0 道具（`obl_discard`，slot = 0）：放弃拾取，itm0 清空

## 六、堆叠核心函数

### 6.1 新增 `item_get_stack` + `item_get_stack_limit`

```php
// item.tag.func.php
function item_get_stack($item_id) {
    static $cache = null;
    if ($cache === null) {
        $table = item_load_table();
        $cache = [];
        foreach ($table as $id => $tpl) {
            $cache[$id] = !empty($tpl['stack']);
        }
    }
    return isset($cache[$item_id]) ? $cache[$item_id] : false;
}

/**
 * 读取道具的 stack_limit（带静态缓存）
 *
 * 与 item_get_stack 共享缓存加载时机，避免 obl_find_mergeable_slot 等高频函数
 * 每次调用 item_load_table（即使 item_load_table 内部有缓存，仍省一次哈希查找）。
 *
 * @param string $item_id
 * @return int  stack_limit，不可堆叠或不存在时返回 1
 */
function item_get_stack_limit($item_id) {
    static $cache = null;
    if ($cache === null) {
        $table = item_load_table();
        $cache = [];
        foreach ($table as $id => $tpl) {
            $cache[$id] = isset($tpl['stack_limit']) ? (int)$tpl['stack_limit'] : 1;
        }
    }
    return isset($cache[$item_id]) ? $cache[$item_id] : 1;
}

/**
 * 将 itmpara 标准化为字符串键，用于堆叠合并时的相等性比较
 *
 * 设计理由：堆叠合并要求堆内每个单位完全相同。itmpara 携带个体状态时，
 * 不同 itmpara 的道具不可合并（避免状态丢失或错误聚合）。
 *
 * 数量模型道具的 itmpara 应为模板参数（来自 item_table），同 item_id 必相等。
 * 耐久模型道具不可堆叠，不调用此函数。
 *
 * @param mixed $itmpara  道具实例的 itmpara 字段（数组或 null）
 * @return string  标准化键（空 itmpara 返回空字符串）
 */
function _item_para_key($itmpara) {
    if (!is_array($itmpara) || empty($itmpara)) return '';
    ksort($itmpara);  // 按 key 排序，避免字段顺序不同导致键不同
    $parts = [];
    foreach ($itmpara as $k => $v) {
        $parts[] = $k . '=' . (is_array($v) ? json_encode($v) : (string)$v);
    }
    return implode('&', $parts);
}
```

### 6.2 新增 `obl_find_mergeable_slot`

```php
// player.func.php
/**
 * 查找可合并堆叠的槽位（仅查 1~itemmaxslots，不含 itm0）
 *
 * 合并条件：item_id 相同 + itmpara 相等（避免合并个体状态不同的道具，§2.3 约束）
 *
 * @param array &$pdata
 * @param string $item_id  道具 ID
 * @param mixed $itmpara   待合并道具的 itmpara（用于相等性检查）
 * @return int|false  可合并的槽位号，无则 false
 */
function obl_find_mergeable_slot(&$pdata, $item_id, $itmpara = null) {
    if (!item_get_stack($item_id)) {
        return false;  // 不可堆叠的道具
    }
    $stack_limit = item_get_stack_limit($item_id);
    $para_key = _item_para_key($itmpara);

    $maxslots = isset($pdata['itemmaxslots']) ? (int)$pdata['itemmaxslots'] : 6;
    for ($i = 1; $i <= $maxslots; $i++) {
        $item = isset($pdata['itempara'][$i]) ? $pdata['itempara'][$i] : null;
        if (!$item || !is_array($item) || empty($item['itmid'])) continue;
        if ($item['itmid'] !== $item_id) continue;

        // itmpara 相等性检查：避免合并个体状态不同的道具（§2.3 约束）
        $slot_para_key = _item_para_key(isset($item['itmpara']) ? $item['itmpara'] : null);
        if ($slot_para_key !== $para_key) continue;

        $s = (string)$item['itms'];
        if ($s === '∞' || $s === '999') return $i;  // 无限堆叠直接返回
        $cur = (int)$s;
        if ($cur < $stack_limit) return $i;  // 还有空间
    }
    return false;
}
```

### 6.3 新增 `obl_add_item_to_inventory`

添加道具到背包（含合并 + 预检查 + 原子性）。用于整理时转移 itm0。

```php
// player.func.php
/**
 * 添加道具到背包（自动合并，原子性）
 *
 * 行为：
 * - 不可堆叠道具 / 无限标识：直接找空槽位放入
 * - 可堆叠道具：先合并到已有堆叠，超限部分找空槽位创建新堆叠
 * - 预检查空间不足时返回 false，不修改任何数据（原子性）
 *
 * 注意：此函数不操作 itm0，只操作背包槽位 1~itemmaxslots。
 *       用于 obl_organize_inventory 转移 itm0 内容。
 *
 * @param array &$pdata
 * @param array $item  道具实例（itempara 格式）
 * @return int|false  实际放入的首个槽位号，空间不足返回 false
 */
function obl_add_item_to_inventory(&$pdata, $item) {
    $item_id = isset($item['itmid']) ? $item['itmid'] : '';
    $add_itms = isset($item['itms']) ? (string)$item['itms'] : '1';
    $item_itmpara = isset($item['itmpara']) ? $item['itmpara'] : null;
    $para_key = _item_para_key($item_itmpara);

    // 不可堆叠道具或无限标识：直接找空槽位
    $is_stack = ($item_id !== '') && item_get_stack($item_id);
    if ($add_itms === '∞' || $add_itms === '999' || !$is_stack) {
        $slot = obl_find_empty_slot($pdata);
        if ($slot === false) return false;
        $pdata['itempara'][$slot] = $item;
        return $slot;
    }

    $add_count = max(1, (int)$add_itms);
    $stack_limit = item_get_stack_limit($item_id);

    // 预检查：可用空间是否足够（原子性保证）
    // 注意：空槽判断与 obl_find_empty_slot 一致——只查 null，不查 itmid
    //       避免"软空槽位"（数组存在但 itmid 为空）误判：预检查通过但实际放入失败
    //       itmpara 相等性检查：只统计同 itmpara 的堆叠空间（§2.3 约束）
    $available_space = 0;
    $maxslots = isset($pdata['itemmaxslots']) ? (int)$pdata['itemmaxslots'] : 6;
    for ($i = 1; $i <= $maxslots; $i++) {
        $slot_item = isset($pdata['itempara'][$i]) ? $pdata['itempara'][$i] : null;
        if ($slot_item === null) {
            $available_space += $stack_limit;
        } elseif (is_array($slot_item) && isset($slot_item['itmid']) && $slot_item['itmid'] === $item_id) {
            // itmpara 相等性检查：不同 itmpara 的堆叠不可合并，不计入可用空间
            $slot_para_key = _item_para_key(isset($slot_item['itmpara']) ? $slot_item['itmpara'] : null);
            if ($slot_para_key !== $para_key) continue;

            $s = (string)$slot_item['itms'];
            if ($s === '∞' || $s === '999') {
                $available_space = PHP_INT_MAX;
                break;
            }
            $available_space += max(0, $stack_limit - (int)$s);
        }
    }
    if ($available_space < $add_count) {
        return false;  // 空间不足，不修改任何数据
    }

    // 执行添加：先合并到已有堆叠（itmpara 相等的堆叠）
    $remaining = $add_count;
    $first_slot = false;

    while ($remaining > 0) {
        $slot = obl_find_mergeable_slot($pdata, $item_id, $item_itmpara);
        if ($slot === false) break;
        if ($first_slot === false) $first_slot = $slot;

        $cur = (string)$pdata['itempara'][$slot]['itms'];
        if ($cur === '∞' || $cur === '999') {
            return $slot;  // 无限堆叠，无需增加
        }
        $cur = (int)$cur;
        $merge = min($remaining, $stack_limit - $cur);
        $pdata['itempara'][$slot]['itms'] = (string)($cur + $merge);
        $remaining -= $merge;
    }

    // 剩余的找空槽位创建新堆叠
    while ($remaining > 0) {
        $slot = obl_find_empty_slot($pdata);
        if ($slot === false) break;  // 理论上不会走到这里（预检查已通过）
        if ($first_slot === false) $first_slot = $slot;

        $put = min($remaining, $stack_limit);
        $new_item = $item;
        $new_item['itms'] = (string)$put;
        $pdata['itempara'][$slot] = $new_item;
        $remaining -= $put;
    }

    return $first_slot;
}
```

### 6.4 新增 `obl_merge_stacks_in_inventory`

合并背包内同类堆叠（仅合并，不转移 itm0）。

```php
// player.func.php
/**
 * 合并背包内同类堆叠
 *
 * 遍历背包槽位，找同类可堆叠道具合并到 stack_limit。
 * 无限堆叠吸收所有同类。仅合并，不转移 itm0，不排序。
 *
 * @param array &$pdata
 */
function obl_merge_stacks_in_inventory(&$pdata) {
    $maxslots = isset($pdata['itemmaxslots']) ? (int)$pdata['itemmaxslots'] : 6;

    // 按 item_id + itmpara 分组（避免合并个体状态不同的道具，§2.3 约束）
    $groups = [];  // group_key => ['item_id' => ..., 'slots' => [...]]
    for ($i = 1; $i <= $maxslots; $i++) {
        $item = isset($pdata['itempara'][$i]) ? $pdata['itempara'][$i] : null;
        if (!$item || !is_array($item) || empty($item['itmid'])) continue;
        if (!item_get_stack($item['itmid'])) continue;  // 不可堆叠跳过
        $item_id = $item['itmid'];
        $para_key = _item_para_key(isset($item['itmpara']) ? $item['itmpara'] : null);
        $group_key = $item_id . '|' . $para_key;
        if (!isset($groups[$group_key])) {
            $groups[$group_key] = ['item_id' => $item_id, 'slots' => []];
        }
        $groups[$group_key]['slots'][] = $i;
    }

    foreach ($groups as $group) {
        $item_id = $group['item_id'];
        $slots = $group['slots'];
        if (count($slots) < 2) continue;  // 只有1堆，无需合并

        $stack_limit = item_get_stack_limit($item_id);

        // 检查是否有无限堆叠
        $infinite_slot = null;
        foreach ($slots as $slot) {
            $s = (string)$pdata['itempara'][$slot]['itms'];
            if ($s === '∞' || $s === '999') {
                $infinite_slot = $slot;
                break;
            }
        }

        if ($infinite_slot !== null) {
            // 无限堆叠吸收所有同类
            foreach ($slots as $slot) {
                if ($slot !== $infinite_slot) {
                    unset($pdata['itempara'][$slot]);
                }
            }
            continue;
        }

        // 有限堆叠合并：每轮取一个未满槽位作目标，吸收其他槽位
        // 嵌套循环：目标满后换下一个未处理槽位作新目标，剩余源槽位留待下轮处理
        $remaining_slots = $slots;
        while (count($remaining_slots) > 1) {
            $target_slot = array_shift($remaining_slots);
            $target_count = (int)$pdata['itempara'][$target_slot]['itms'];

            // 目标已满，跳过（换下一个）
            if ($target_count >= $stack_limit) continue;

            $next_remaining = [];
            foreach ($remaining_slots as $src_slot) {
                // 目标已满，源留待下轮处理
                if ($target_count >= $stack_limit) {
                    $next_remaining[] = $src_slot;
                    continue;
                }
                $src_count = (int)$pdata['itempara'][$src_slot]['itms'];
                $merge = min($src_count, $stack_limit - $target_count);
                if ($merge > 0) {
                    $target_count += $merge;
                    $pdata['itempara'][$target_slot]['itms'] = (string)$target_count;
                    $src_count -= $merge;
                }
                if ($src_count > 0) {
                    $pdata['itempara'][$src_slot]['itms'] = (string)$src_count;
                    $next_remaining[] = $src_slot;  // 源还有剩余，留待下轮
                } else {
                    unset($pdata['itempara'][$src_slot]);
                }
            }
            $remaining_slots = $next_remaining;
        }
    }
}
```

**预留说明（暂不实现）：无限道具堆叠策略**

当前无限堆叠（itms='∞'）采用"吸收同类"策略——遇到同类有限堆叠时，吸收所有同类并 unset 被吸收的槽位。旧模式 phpdts 采用相反策略——"无限不可堆叠"（`if($its1==$nosta || $its2==$nosta) { 不能合并 }`，无限道具与任何道具都不合并，包括同类无限）。

本案选择"吸收同类"的理由：现代游戏惯例中，无限道具通常是事件奖励或特殊状态，吸收同类符合玩家直觉（"我有无限布料后，普通布料自动归并"）。

具体策略可能根据未来游戏设计调整（如考虑无限道具与有限道具的来源区分、UI 显示区分）。届时需修改：
- `obl_find_mergeable_slot`：无限标识的处理分支
- `obl_add_item_to_inventory` 预检查：无限标识的可用空间计算
- `obl_merge_stacks_in_inventory`：`$infinite_slot` 处理逻辑

```php
// item.basic.func.php
```

**`obl_organize_inventory`**：整理背包（合并 + 转移 itm0）。

```php
// player.func.php
/**
 * 整理背包：合并同类堆叠 + 转移 itm0 → 背包
 *
 * 算法：
 * 1. 合并背包内同类堆叠（腾出空槽）
 * 2. 转移 itm0 → 背包（原子性，含合并到已有堆叠）
 *
 * 无步骤3：obl_add_item_to_inventory 转移时已合并，新堆叠必为满堆叠，无需再合并。
 *
 * @param array &$pdata
 * @return bool  true=整理成功（itm0 已清空），false=背包满（itm0 保留）
 */
function obl_organize_inventory(&$pdata) {
    global $obl_log;

    // 1. 合并背包内同类堆叠（腾出空槽）
    obl_merge_stacks_in_inventory($pdata);

    // 2. 转移 itm0 → 背包
    if (!isset($pdata['itempara'][0]) || empty($pdata['itempara'][0]['itmid'])) {
        return true;  // itm0 为空，整理成功
    }

    $item = $pdata['itempara'][0];
    $slot = obl_add_item_to_inventory($pdata, $item);

    if ($slot === false) {
        // 背包满，itm0 保留
        return false;
    }

    // 转移成功，清空 itm0
    unset($pdata['itempara'][0]);

    return true;
}
```

### 7.1 `obl_pickup_item` 改写

当前拾取逻辑：先 `obl_find_empty_slot` + `obl_set_item` 放入背包，再原子删除地图实例，失败时回滚。

改为：地图实例 → itm0 → 原子删除 → 自动整理。

```php
function obl_pickup_item($iid, &$pdata) {
    global $db, $tablepre, $obl_log;

    $iid = (int)$iid;
    $cur_pgroup = (int)$pdata['pgroup'];
    $cur_pls = (int)$pdata['pls'];

    // 1. 读取道具实例
    $result = $db->query("SELECT * FROM {$tablepre}oblmapitem WHERE iid='$iid'");
    if (!$db->num_rows($result)) {

        return;
    }
    $item = $db->fetch_array($result);

    // 2. 位置检查
    if ((int)$item['pgroup'] != $cur_pgroup || (int)$item['pls'] != $cur_pls) {
        $obl_log->emit('pickup.not_adjacent', 'pickup');
        return;
    }

    // 3. 发现状态检查
    if (empty($item['discovered'])) {
        $obl_log->emit('pickup.unknown', 'pickup');
        return;
    }

    // 4. 近视道具揭示（陷阱处理等，与原逻辑一致）
    // ...（省略陷阱处理代码，保持原样）...
    // 注意：$real_itm 在此步骤中定义（从 $item['itm'] 读取，为空时回退到 item_table 的模板 itm），
    //       后续 emit 使用 $real_itm 作为日志显示名称。
    //       详见现有 obl_pickup_item 的步骤4（explore.func.php）。

    // 5. 构建道具实例
    $new_item = [
        'itm'     => '',
        'itmk'    => $item['itmk'],
        'itme'    => (int)$item['itme'],
        'itms'    => $item['itms'],  // 地图实例的 itms（可能是任意值）
        'itmsk'   => $item['itmsk'],
        'itmpara' => $item['itmpara'],
        'itmid'   => $item['item_id'],
    ];

    // 6. 放入 itm0（obl_put_item_to_itm0，不直接放背包）
    if (!obl_put_item_to_itm0($pdata, $new_item)) {
        // itm0 已被占用（理论不应发生，router 门控已拦截）
        $obl_log->emit('system.itm0_occupied', 'system');
        return;
    }

    // 7. 原子删除地图实例
    $db->query("DELETE FROM {$tablepre}oblmapitem WHERE iid='$iid' AND discovered>0");

        // 并发拾取失败，回滚 itm0
        unset($pdata['itempara'][0]);
        $obl_log->emit('system.pickup_concurrent_loss', 'system');
        return;
    }

    // 8. 自动整理（obl_organize_inventory，转移 itm0 → 背包）
    $organized = obl_organize_inventory($pdata);

    // 9. 拾取成功（道具已从地图删除，已存入 itm0 或背包）
    //    近视道具已在步骤4 emit reveal，不重复 emit success
    if (!$was_nearsighted) {
        $obl_log->emit('pickup.success', 'pickup', [
            'item_name' => $real_itm,
        ]);
    }

    // 10. 整理失败提示（与步骤9解耦：拾取成功是独立事件，整理失败是独立事件）
    if (!$organized) {
        $obl_log->emit('organize.fail', 'system', [
            'item_id' => $item['item_id'],
        ]);
    }
}
```

**回滚简化**：并发拾取失败时只需 `unset($pdata['itempara'][0])`，O(1) 操作，不再需要 `$modified` 数组。

**itmpara 字段格式说明**：地图实例表 `oblmapitem.itmpara` 与玩家数据 `itempara[*].itmpara` 的格式应保持一致（数组或 JSON 字符串）。现有 `obl_pickup_item` 直接赋值 `$item['itmpara']`，要求读取时已解码为数组。若数据库层存储为 JSON 字符串，应在数据库读取层统一解码（本案范围外，属现有代码约定）。`_item_para_key()` 接受数组或 null，不处理字符串——若传入字符串会返回空键导致错误合并。实施时需确认 `oblmapitem.itmpara` 读取后已是数组格式。

## 八、合成系统适配

### 8.1 slots 参数格式

**格式**：`"槽位:数量,槽位:数量"`，不含冒号时默认数量=1（向后兼容）。

```
"1:3,2:1"  → 槽位1投入3个，槽位2投入1个
"1,2,3"    → 槽位1/2/3各投入1个（旧格式兼容）
"1:3"      → 槽位1投入3个
```

**解析函数**（新增）：

```php
/**
 * 解析 slots 参数为 [slot => count] 映射
 *
 * @param mixed $slots  逗号分隔字符串或数组
 * @return array  [slot => count, ...]
 */
function item_parse_slots($slots) {
    if (!is_array($slots)) {
        $slots = ($slots === '' || $slots === null) ? [] : explode(',', (string)$slots);
    }
    $result = [];
    foreach ($slots as $entry) {
        $entry = trim((string)$entry);
        if ($entry === '') continue;
        if (strpos($entry, ':') !== false) {
            list($slot, $count) = explode(':', $entry, 2);
            $slot = (int)$slot;
            $count = max(1, (int)$count);
        } else {
            $slot = (int)$entry;
            $count = 1;
        }
        if ($slot < 1) continue;  // 特殊槽（含 itm0）不可投入
        $result[$slot] = ($result[$slot] ?? 0) + $count;  // 同槽多次引用合并
    }
    return $result;
}
```

### 8.2 placed_items 展开模型

**核心设计**：把堆叠素材展开为"虚拟 placed_item"，每个虚拟 placed_item 代表1个素材。`item_resolve_material_mapping` 核心匹配逻辑**不需要改动**。

```
槽位1有3个布料 → 展开为3个虚拟 placed_item，都指向槽位1
槽位2有1个布料 → 展开为1个虚拟 placed_item，指向槽位2
```

展开逻辑在 `_item_build_placed_items` 中实现（见 §九）。

### 8.3 consume='all' 与 consume='durability' 消耗逻辑适配

**consume='all'**（消耗整个槽位）：
- 数量模型（stack=true）：按槽位汇总消耗数量，扣减 itms，归零才 unset
- 耐久模型（stack=false）：直接 unset 整槽（§2.3 明确规定）

**consume='durability'**（消耗1单位，§2.3 统一语义）：
- 数量模型（stack=true）：扣1个数量（itms-1），归零 unset
- 耐久模型（stack=false）：扣1点耐久（item_consume_durability）

```php
// item_consume_materials 中消耗处理改为：
$slot_consume_all = [];     // [slot => consume_count] consume='all' 汇总
$slot_consume_dur = [];     // [slot => 1] consume='durability' 汇总（每个 placed_item 扣1）
foreach ($mapping as $m) {
    $idx = $m['placed_index'];
    if ($idx >= $bag_count) continue;  // 工作台素材跳过
    $slot = $slot_map[$idx];
    if ($m['consume'] === 'all') {
        $slot_consume_all[$slot] = ($slot_consume_all[$slot] ?? 0) + 1;
    } elseif ($m['consume'] === 'durability') {
        $slot_consume_dur[$slot] = ($slot_consume_dur[$slot] ?? 0) + 1;
    }
    // consume='none' 不操作
}

// 批量扣减 consume='all' 的槽位（区分模型）
foreach ($slot_consume_all as $slot => $cnt) {
    $item = &$pdata['itempara'][$slot];
    $item_id = $item['itmid'];

    // 耐久模型（stack=false）：consume='all' 直接 unset 整槽
    if (!item_get_stack($item_id)) {
        unset($pdata['itempara'][$slot]);
        continue;
    }

    // 数量模型（stack=true）：扣 itms-N，归零才 unset
    $s = (string)$item['itms'];
    if ($s === '∞' || $s === '999') continue;  // 无限不扣
    $cur = max(0, (int)$s - $cnt);
    if ($cur <= 0) {
        unset($pdata['itempara'][$slot]);
    } else {
        $item['itms'] = (string)$cur;
    }
}

// 批量扣减 consume='durability' 的槽位（区分模型，扣1单位）
foreach ($slot_consume_dur as $slot => $cnt) {
    $item = &$pdata['itempara'][$slot];
    $item_id = $item['itmid'];

    // 数量模型（stack=true）：扣1个数量×cnt，归零 unset
    if (item_get_stack($item_id)) {
        $s = (string)$item['itms'];
        if ($s === '∞' || $s === '999') continue;  // 无限不扣
        $cur = max(0, (int)$s - $cnt);
        if ($cur <= 0) {
            unset($pdata['itempara'][$slot]);
        } else {
            $item['itms'] = (string)$cur;
        }
        continue;
    }

    // 耐久模型（stack=false）：扣 cnt 点耐久，归零 unset
    item_consume_durability($item, $cnt);
    if (isset($item['itms']) && (string)$item['itms'] === '0') {
        unset($pdata['itempara'][$slot]);
    }
}
```

**设计要点**：consume='durability' 在数量模型下与 consume='all'（count=1）等价，但语义不同——consume='all' 表示"消耗全部投入"，consume='durability' 表示"消耗1单位"。例如 craft_blade_wrapped 配方用1个 blade_shard（可堆叠刀片碎片，consume='durability'）时扣1个数量，用1个 scrap_blade（不可堆叠废铁刀，consume='durability'）时扣1点耐久。

### 8.4 item_craft 步骤6 空间检查适配

**当前**：`freed_slots` = consume='all' 的 placed_item 数量

### 8.5 合成产出原则

**核心约束**：一次合成**最多产出1个不可堆叠道具**。这包括两种情况：
1. 单个产物 `count > 1` 且 `stack=false` → 禁止（数据校验拒绝加载）
2. `results` 中有多个 `stack=false` 产物（每个 count=1）→ 禁止（数据校验拒绝加载）

**理由**：不可堆叠道具无法合并，每个都需独立槽位。多产物合成场景下，逐个产物入 itm0 + 整理的流程对不可堆叠产物无优势（不能合并），且增加 itm0 锁定风险（第二个不可堆叠产物入 itm0 时，第一个可能已占满空槽）。未来若有"一次合成多把武器"的具体需求，再调整架构（如引入批量产物入背包的快路径）。

| 产物类型 | count 允许值 | itm0 操作 | 说明 |
|---------|------------|----------|------|
| 可堆叠产物（stack=true） | 1 ≤ N ≤ stack_limit | itm0.itms=N，1次整理 | 一次产出 N 个；上限由 §12.1 数据校验强制（超过 itm0 装不下） |
| 不可堆叠产物（stack=false） | **只能 1** | itm0.itms=模板itms，1次整理 | 数据校验强制 |

**多产物配方**（results 多元素）规则：
- results 中可包含多个可堆叠产物（如 [cloth×3, scrap_metal×2]）
- results 中**最多1个**不可堆叠产物（如 [weapon] 或 [weapon, cloth×3]）
- results 中**禁止**多个不可堆叠产物（如 [weapon, armor] → 拒绝加载）
- 逐个产物处理，每个产物走一次"产物 → itm0 → 自动整理"循环

**数据校验规则**（§十二详述）：
- 配方 `results` 中 `stack=false` 的产物 `count > 1` → 拒绝加载并报错
- 配方 `results` 中 `stack=false` 的产物总数 > 1 → 拒绝加载并报错
- 可堆叠产物的 `count <= stack_limit` → 否则 itm0 装不下

### 8.6 item_craft 步骤9 产物入背包适配

**当前**：逐个 `obl_find_empty_slot` + `obl_set_item`，用模板 itms

**改为**：逐个产物 → itm0（`obl_put_item_to_itm0`）→ 自动整理（`obl_organize_inventory`）

```php
    $new_item = [
        'itm'     => '',
        'itmk'    => $template['itmk'],
        'itme'    => (int)$template['itme'],

        break;
    }

    $organized = obl_organize_inventory($pdata);

        // 注意：素材已扣减，之前的产物已入背包，当前产物卡在 itm0
```

```php
/**
 * 构建 placed_items + slot_map（P2 重构 + 堆叠适配）
 *
 * 把背包素材按投入数量展开为虚拟 placed_item，追加工作台素材。
 * 供 item_match_recipes_by_slots / item_consume_materials / item_craft 共用。
 *
 * @param array &$pdata
 * @param array $slot_counts  [slot => count] 映射（由 item_parse_slots 生成）
 * @param array $workbench_materials  工作台素材 ID 列表
 * @return array  [
 *   'placed_items' => [...],   // 虚拟 placed_item 列表
 *   'slot_map'     => [...],   // placed_index → 槽位号（仅背包素材）
 *   'bag_count'    => int,     // 背包素材数量（区分工作台素材的起点）
 * ]
 */
function _item_build_placed_items(&$pdata, $slot_counts, $workbench_materials = []) {
    $placed_items = [];
    $slot_map = [];
    $bag_count = 0;

    // 1. 背包素材：按 count 展开为虚拟 placed_item（校验不超实际数量）
    foreach ($slot_counts as $slot => $count) {
        $slot = (int)$slot;
        $item = isset($pdata['itempara'][$slot]) ? $pdata['itempara'][$slot] : null;
        if (!$item || !is_array($item) || empty($item['itmid'])) continue;

        // 校验投入数量不超过实际堆叠数量（无限标识不限）
        $s = (string)$item['itms'];
        if ($s === '∞' || $s === '999') {
            $actual_count = $count;
        } else {
            $actual_count = min($count, max(0, (int)$s));
        }

        $item_id = $item['itmid'];
        for ($i = 0; $i < $actual_count; $i++) {
            $placed_items[] = [
                'item_id'    => $item_id,
                'itmk'       => item_get_itmk($item_id),
                'tags'       => item_get_tags($item_id),
                'tool_level' => item_get_tool_level($item_id),
                'source'     => 'bag',
            ];
            $slot_map[] = $slot;
            $bag_count++;
        }
    }

    // 2. 工作台素材（不展开，每个工作台素材是1个 placed_item）
    $available_wb = item_get_available_workbench_materials($pdata);
    foreach ($workbench_materials as $wb_id) {
        foreach ($available_wb as $wb) {
            if ($wb['id'] === $wb_id) {
                $placed_items[] = [
                    'item_id'    => $wb['item_id'],
                    'itmk'       => item_get_itmk($wb['item_id']),
                    'tags'       => item_get_tags($wb['item_id']),
                    'tool_level' => $wb['tool_level'],
                    'source'     => 'workbench',
                ];
                break;
            }
        }
    }

    return [
        'placed_items' => $placed_items,
        'slot_map'     => $slot_map,
        'bag_count'    => $bag_count,
    ];
}
```

```php
function item_craft($slots, &$pdata, $workbench_materials = []) {
    global $obl_log;

    $slot_counts = item_parse_slots($slots);
    if (empty($slot_counts) && empty($workbench_materials)) {
        $obl_log->emit('craft.fail_no_match', 'system');
        return;
    }

    $built = _item_build_placed_items($pdata, $slot_counts, $workbench_materials);
    $placed_items = $built['placed_items'];
    $slot_map = $built['slot_map'];
    $bag_count = $built['bag_count'];

    // 步骤 3：匹配
    $matched = [];
    foreach (item_get_all_recipes() as $recipe_id => $recipe) {
        if (item_materials_match($recipe['materials'], $placed_items)) {
            $matched[] = $recipe_id;
        }
    }

    // 步骤 4：分支
    $match_count = count($matched);
    if ($match_count === 0) { $obl_log->emit('craft.fail_no_match', 'system'); return; }
    if ($match_count >= 2) { $obl_log->emit('craft.fail_ambiguous', 'system', ['match_count' => $match_count]); return; }

    // 步骤 5：取配方
    $recipe_id = $matched[0];
    $recipe = item_get_recipe($recipe_id);

    // 步骤 6：空间检查（按 §8.4 适配，区分模型，含 consume='all' 和 consume='durability'）
    $mapping = item_resolve_material_mapping($recipe['materials'], $placed_items);
    if ($mapping === null) { $obl_log->emit('craft.fail_no_match', 'system'); return; }

    $slot_consume_all = [];
    $slot_consume_dur = [];
    foreach ($mapping as $m) {
        if ($m['placed_index'] >= $bag_count) continue;
        $slot = $slot_map[$m['placed_index']];
        if ($m['consume'] === 'all') {
            $slot_consume_all[$slot] = ($slot_consume_all[$slot] ?? 0) + 1;
        } elseif ($m['consume'] === 'durability') {
            $slot_consume_dur[$slot] = ($slot_consume_dur[$slot] ?? 0) + 1;
        }
    }

    $freed_slots = 0;
    // consume='all' 空出的槽位
    foreach ($slot_consume_all as $slot => $cnt) {
        $item = isset($pdata['itempara'][$slot]) ? $pdata['itempara'][$slot] : null;
        if (!$item) continue;
        if (!item_get_stack($item['itmid'])) {
            $freed_slots++;
            continue;
        }
        $s = (string)$item['itms'];
        if ($s === '∞' || $s === '999') continue;
        if ((int)$s - $cnt <= 0) $freed_slots++;
    }
    // consume='durability' 空出的槽位（§2.3 统一语义，按模型区分）
    foreach ($slot_consume_dur as $slot => $cnt) {
        $item = isset($pdata['itempara'][$slot]) ? $pdata['itempara'][$slot] : null;
        if (!$item) continue;
        if (item_get_stack($item['itmid'])) {
            $s = (string)$item['itms'];
            if ($s === '∞' || $s === '999') continue;
            if ((int)$s - $cnt <= 0) $freed_slots++;
            continue;
        }
        $s = (string)$item['itms'];
        if ($s === '∞' || $s === '999') continue;
        if ((int)$s - $cnt <= 0) $freed_slots++;
    }

    $results_count = 0;
    foreach ($recipe['results'] as $r) {
        $results_count += (int)($r['count'] ?? 1);
    }

    $empty_count = 0;
    $maxslots = isset($pdata['itemmaxslots']) ? (int)$pdata['itemmaxslots'] : 6;
    for ($i = 1; $i <= $maxslots; $i++) {
        // 与 obl_find_empty_slot 一致：只查 null，不查 itmid
        if (!isset($pdata['itempara'][$i]) || $pdata['itempara'][$i] === null) {
            $empty_count++;
        }
    }

    if ($empty_count + $freed_slots < $results_count) {
        $obl_log->emit('craft.fail_bag_full', 'system');
        return;
    }

    // 步骤 7：介入点 1（P0 跳过）

    // 步骤 8：扣减素材
    item_consume_materials($pdata, $recipe['materials'], $slots, $workbench_materials);

    // 步骤 9：添加产物（按 §8.6，产物 → itm0 → 自动整理，事件解耦）
    $table = item_load_table();
    foreach ($recipe['results'] as $r) {
        $item_id = $r['item_id'];
        $count = (int)($r['count'] ?? 1);
        $template = isset($table[$item_id]) ? $table[$item_id] : null;
        if (!$template) continue;

        $is_stack = item_get_stack($item_id);
        $product_itms = $is_stack ? (string)$count : (string)$template['itms'];

        $new_item = [
            'itm'     => '',
            'itmk'    => $template['itmk'],
            'itme'    => (int)$template['itme'],
            'itms'    => $product_itms,
            'itmsk'   => $template['itmsk'],
            'itmpara' => isset($template['itmpara']) && is_array($template['itmpara']) ? $template['itmpara'] : [],
```

### 11.5 命令门控与异常错误码

| 错误码 | 触发条件 | 前端处理（通过 log 事件感知） |
|--------|---------|---------|
| `system.itm0_pending` | itm0 不为空时提交非整理/丢弃命令 | 弹出"请先整理背包"提示，高亮 itm0 区域 |
| `organize.fail` | 自动/手动整理失败，道具卡在 itm0（合成/拾取/手动整理共用） | 提示"背包已满，XX暂存到待整理区"，门控锁定 |

| `pickup.empty_item` | 拾取地图实例 itms='0' 或空 | 提示"道具无效"，拒绝拾取 |

**事件解耦原则**：拾取成功（`pickup.success`）与整理失败（`organize.fail`）是独立事件——拾取成功表示道具已从地图删除并存入 itm0 或背包，整理失败表示道具卡在 itm0 需要玩家手动处理。前端可同时收到两个事件（拾取成功+整理失败），分别处理。合成系统同理：`craft.success`（仅传 `recipe_id`）与 `organize.fail` 解耦。

**前端感知原则**：所有命令执行结果（成功/失败/堵塞）统一通过 log/error_log 系统传递到前端，前端根据事件类型展示对应 UI。不依赖专门的 API 字段或轮询机制。

## 十二、边界规则与数据校验

### 12.1 数据编写约定

编写 `item_table.php` 和 `recipe_table.php` 时应遵循以下约定（**不**做运行时校验——当前数据手工符合规则，未来有多产物需求时再按需扩展校验逻辑，不做过度防御）：

| 约定 | 说明 |
|------|------|
| 配方 `results` 中 `stack=false` 的产物 → `count=1` | 不可堆叠产物每次只产出1个 |
| 配方 `results` 中 `stack=false` 的产物总数 → ≤ 1 | 一次合成最多1个不可堆叠道具 |
| 可堆叠产物的 `count <= stack_limit` | 否则 itm0 装不下 |
| 可堆叠道具的 `stack_limit >= 1` | 数据编写时确保 |
| 可堆叠道具的模板 `itms <= stack_limit` | 初始拾取不超限（警告级） |

**注意**：
- `use_effect` 的存在**不**决定 `stack`——数量模型（面包）有 use_effect 且 stack=true，耐久模型（磨刀石）有 use_effect 且 stack=false。判断模型是设计阶段的语义判断，无法自动校验。
- `consume='durability'` **可匹配任意 stack 类型的道具**（§2.3 统一语义：数量模型扣1个数量，耐久模型扣1点耐久）。无需校验 consume='durability' 素材的 stack 类型——这正是 craft_blade_wrapped 配方用1个 blade_shard（可堆叠刀片碎片）或1个 scrap_blade（不可堆叠废铁刀）都能合成的灵活性来源。

### 12.2 itms 边缘状态处理（'0' / 空 / 负数）

itms 在运行时可能出现 `'0'`、空字符串、甚至负数等边缘状态，需明确处理规则避免数据污染：

| 场景 | 处理方式 | 实现位置 |
|------|---------|---------|
| 拾取地图实例 itms='0' 或空 | 拒绝拾取，emit `pickup.empty_item` | `obl_pickup_item` 步骤1之后新增检查 |
| 数量模型扣减后 itms=0 | unset 整槽（§8.3 已规定） | `item_consume_materials` consume='all' 分支 |
| 使用消耗后 itms=0（数量模型） | unset 整槽 | `item_use` 步骤4.5（已实现，无需修改） |
| 使用消耗后 itms=0（耐久模型） | unset 整槽（耐久归零即损坏） | `item_use` 步骤4.5（已实现，无需修改） |
| `_item_build_placed_items` 中 $s='0' | actual_count = min($count, 0) = 0，展开 0 个 placed_item（等价不投入） | §9.2 已隐含处理 |
| `obl_find_mergeable_slot` 遇到 itms='0' | (int)'0' = 0 < stack_limit，会返回该槽位作为可合并 | **需防御**：itms='0' 的槽位应已被 unset，不应存在；若存在则跳过 |

**`item_consume_durability` 与 `item_use` 的职责分离**：
- `item_consume_durability`（[item.use.func.php:126-143](file:///d:/wamp64/www/phpdts/oblivions/include/game/item/item.use.func.php#L126-L143)）只负责扣减 itms 和 emit `durability.broken` 事件，**不**操作槽位
- 槽位 unset 由调用方 `item_use` 步骤4.5 处理（[item.use.func.php:68-71](file:///d:/wamp64/www/phpdts/oblivions/include/game/item/item.use.func.php#L68-L71)）：
```php
if (isset($item['itms']) && (string)$item['itms'] === '0') {
    unset($pdata['itempara'][$slot]);
}
```
- §10.1 "item_use 不变" 正确——已处理 itms=0 unset，无需修改

**防御性建议**：`obl_find_mergeable_slot` 和 `obl_add_item_to_inventory` 预检查中，遇到 `itms='0'` 的槽位应视为"无效数据"跳过（不作为可合并目标，也不计入可用空间），避免污染状态扩散。可在两处函数的循环体内加：

```php
$s = (string)$slot_item['itms'];
if ($s === '0' || $s === '') continue;  // 无效数据，跳过（理论不应存在）
```

**数据来源约束**：
- 地图实例表 `oblmapitem.itms` 不应有 '0' 或空值（数据生成时保证）
- 道具表 `item_table.itms` 模板值应为正整数或 '∞'/'999'（§12.1 已校验）
- 玩家数据 `itempara[*].itms` 运行时若出现 '0'，应在产生它的操作中立即 unset
