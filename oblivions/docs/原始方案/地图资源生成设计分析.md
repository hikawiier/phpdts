# Oblivions 地图资源生成 — 设计分析与补充方案

> 基于《地图、移动与探索机制.txt》和《地图、移动与探索机制_v1.md》的审阅
> 版本：1.0 | 2026-06-14

---

## 一、现有设计评审

### 1.1 优点

- **潮汐系统**设计精巧：用 shallow/deep/abyss 三级危险度同时驱动生成权重、视觉渲染和事件点类型，一石三鸟
- **探索记忆**机制有策略深度：6格记忆上限 + 优先级排序 + 近视误判，不是简单的"点亮全部"
- **地板属性**与**潮汐属性**职责分离清晰：floor 影响玩家交互，tide 影响系统生成，互不干扰
- **预留接口**设计合理：exit_links、obl_post_move_hook、obl_get_move_range 都为后续扩展留了空间

### 1.2 问题与批评

#### P0：资源生成没有数据模型

txt 详细描述了生成规则（200件道具、25+5+1个敌人、事件点），但**没有任何数据表设计**。生成配置（敌人表/道具表/事件表）和生成结果（实例化的敌人/道具/事件点）都缺少存储方案。这是整个资源生成系统的地基，必须先定义。

#### P1：探索系统与地图数据脱节

v1.md 完全没有涉及探索机制。迷雾、探索视野、探索记忆这些核心玩法在技术文档中是空白。需要定义：
- 迷雾状态的数据存储
- 探索视野的计算逻辑
- 探索记忆的容量与优先级实现

#### P2："安全区"概念冲突

txt 定义安全区为**动态判定**（格内无敌人/道具/未触发事件点），v1.md 改成了 `preset_safe` 布尔值。两者应该共存：
- `preset_safe = true`：强制永久安全区（如入口格），不受动态清空影响
- 动态安全区：运行时实时计算，`preset_safe` 为 false 时才走动态判定

#### P3：生成时机未定义

"区域地图初始化时随机生成"——什么时候初始化？这直接影响存储方案。已确认：**整局开始时一次性生成所有区域**。

#### P4：敌人数据结构缺失

txt 提到敌人可移动、大体型敌人占多格、敌人有AI行为，但没有任何数据结构定义。

## 二、确认的设计决策

| 决策项 | 结论 |
|--------|------|
| 生成时机 | 整局开始时一次性生成所有区域资源 |
| 生成配置格式 | PHP 文件（与地图数据一致） |
| 敌人AI | 行为模式配置表，预设巡逻路线型和感知追击型 |
| 生成数据存储 | 每个实体类型一张数据库表 |
| 迷雾状态 | 按格记录，持久化到数据库 |
| 探索记忆 | 持久化到数据库 |

### 3.3 数据库表设计

#### obl_enemy — 敌人实例

```sql
CREATE TABLE obl_enemy (
    eid         INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    gid         TINYINT UNSIGNED NOT NULL,       -- 游戏局ID
    pgroup      TINYINT UNSIGNED NOT NULL,       -- 所在区域
    pls         TINYINT UNSIGNED NOT NULL,        -- 所在地图格
    enemy_id    VARCHAR(32) NOT NULL,             -- 敌人模板ID（关联 enemy_table）
    hp          SMALLINT UNSIGNED NOT NULL,       -- 当前HP
    ap          TINYINT UNSIGNED NOT NULL DEFAULT 0,
    behavior    VARCHAR(16) NOT NULL,             -- 当前行为模式
    patrol_route TEXT DEFAULT NULL,               -- 巡逻路线 JSON: [pls1, pls2, ...]
    patrol_idx  TINYINT UNSIGNED DEFAULT 0,       -- 巡逻当前索引
    perception  TINYINT UNSIGNED DEFAULT 0,       -- 感知范围
    size        TINYINT UNSIGNED DEFAULT 1,       -- 占格数
    anchor_pls  TINYINT UNSIGNED DEFAULT NULL,    -- 大体型锚点格（多格敌人的主格）
    discovered  TINYINT UNSIGNED DEFAULT 0,       -- 是否已被玩家发现
    INDEX idx_gid_pgroup (gid, pgroup),
    INDEX idx_gid_pls (gid, pgroup, pls)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

#### obl_item — 道具实例

```sql
CREATE TABLE obl_item (

    item_id     VARCHAR(32) NOT NULL,             -- 道具模板ID（关联 item_table）
```

## 四、生成算法

### 4.1 整体流程

```
obl_generate_all_regions($gid)
  ├── 对每个 pgroup:
  │   ├── obl_generate_region_enemies($gid, $pgroup)
  │   ├── obl_generate_region_items($gid, $pgroup)
  │   └── obl_generate_region_events($gid, $pgroup)
  └── 返回
```

### 4.2 敌人生成算法

```
obl_generate_region_enemies($gid, $pgroup):
  1. 读取 region_spawn[$pgroup]['enemies']
  2. 对每个敌人配置:
     a. 读取 tide_pref 权重
     b. 将该区域所有地图格按 tide 分组
     c. 按 tide_pref 加权随机选择 count 个格
     d. 排除已有敌人的格、不可通行的格
     e. 对大体型敌人(size>1)，检查锚点格周围是否有足够连续空格
     f. 插入 obl_enemy 表
     g. 如果 behavior == patrol，生成巡逻路线（BFS 路径连接若干随机格）
```

### 4.3 道具生成算法

```
obl_generate_region_items($gid, $pgroup):
  1. 读取 region_spawn[$pgroup]
  2. 对每个 tier pool:
     a. 从 item_table 中筛选该 tier 的所有道具
     b. 按 tide_pref 加权随机选择目标格
     c. 每个格可堆叠多件不同道具
     d. 插入 obl_item 表
```

### 4.4 事件点生成算法

```
obl_generate_region_events($gid, $pgroup):
  1. 读取 event_table
  2. 对每个事件类型:
     a. 按 tide 限制筛选候选格
     b. 排除已有事件点的格
     c. 随机选择 per_region 个格
     d. 如果 spawn_enemy == true，在相同格额外生成1个敌人
     e. 插入 obl_event 表
```

## 五、敌人AI — 游戏刻驱动

### 5.1 游戏刻触发

每次玩家执行移动或探索时，`$gamevars['obl_tick']++`，然后执行一次敌人AI更新：

```php
obl_tick_enemies($gid, $player_pgroup, $player_pls):
  1. 查询 obl_enemy WHERE gid=$gid AND pgroup=$player_pgroup
  2. 对每个敌人:
     switch(behavior):
       case 'patrol':
         移动到 patrol_route 的下一个格
       case 'chase':
         计算与玩家的 BFS 距离
         if 距离 <= perception:
           向玩家方向移动1格
         else:
           随机移动到1个相邻可通行格
       case 'ambush':
         不移动
  3. 更新 obl_enemy 的 pls
  4. 清除该区域内所有敌人的 discovered=0（需要重新探索发现）
```

### 5.2 大体型敌人

- `size=2`：占锚点格 + 1个相邻格，移动时整体移动
- 渲染时，锚点格显示敌人本体，附加格显示半透明阴影
- 战斗时，技能作用于任意一个占据格都算命中

## 六、探索系统

### 6.1 探索视野计算

```
obl_explore($pdata):
  1. 获取探索视野等级 vision_lv（默认1）
  2. 以当前格为中心，计算视野范围内的所有格:
     - lv1: 脚下 + 8方向相邻 = 9格
     - lv2: 扩展到2格距离 = 25格
     - lv3: 扩展到3格距离 = 49格
  3. 对视野范围内的格:
     a. 标记为已探索（插入/更新 obl_explored）
     b. 检查格上的敌人 → 标记 discovered=1
     c. 检查格上的道具 → 标记 discovered=1，加入探索记忆
     d. 检查格上的事件点 → 标记 discovered=1
  4. 应用探索记忆容量限制:
     - 查询当前记忆数量
     - 超出容量时，按优先级移除最低优先级的记忆
     - 事件点/固定内容不占记忆容量
     - 敌人不占记忆容量（但每刻可能消失）
     - 道具占记忆容量
```

### 6.2 近视效果

发现道具时，如果道具触发近视判定：
- 显示为 `道具名（？）`
- 实际可能是：同名道具 / 同T级不同道具 / T+1级道具 / 宝箱怪
- 拾取时才揭示真实身份

## 七、安全区判定（修正版）

```php
obl_is_safe_tile($gid, $pgroup, $pls):
  // 1. 预设安全区优先
  $tile = get_tile($pgroup, $pls);
  if ($tile['preset_safe']) return true;

  // 2. 动态判定
  $has_enemy  = count_enemy_at($gid, $pgroup, $pls) > 0;
  $has_item   = count_item_at($gid, $pgroup, $pls) > 0;
  $has_event  = count_untriggered_event_at($gid, $pgroup, $pls) > 0;

  return !$has_enemy && !$has_item && !$has_event;
```

## 九、地图编辑器扩展

当前编辑器只编辑地图结构数据。资源生成系统完成后，编辑器需要扩展：

1. **潮汐属性可视化**：按 tide 值渲染不同边框色（绿/黄/红/灰）
2. **生成预览**：选择区域后，模拟运行生成算法，预览敌人/道具/事件点分布
3. **生成配置编辑**：编辑每个区域的 enemy_spawn / item_spawn / event_spawn 参数

这些是后续迭代内容，不影响当前编辑器的使用。
