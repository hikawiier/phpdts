## 一、设计目标

### 1.1 核心问题

当前前端 battlelog 播放逻辑散落 `if` 判断，且与设计案1 后端新格式完全不兼容（详见 v3 前置分析文档）。需要新增导演层集中编排，同时还原后端真实的 Turn/Round/战斗结束三层结构。

### 1.2 改动目标

1. **新增 `BattleDirector` 模块**：同步纯函数，输入 raw entries → 输出 `PlayScript`
2. **分层编排**：输出 `PlaySegment[]`，每段对应一个演出单元（Phase 0 / Round / Turn / Battle End）
3. **`directedKind` 标记**：演员按 kind 分发渲染，不依赖 phase 字符串
4. **后端补齐**：扩展 `BattleLogCollector`，emit 时携带 `bl_turn_num`/`bl_round_num`/`bl_segment_flag`；补齐缺失的 `ambush_battle_end` emit；`battle_main_end` 改为 `combatant_cleared`
5. **与现有代码隔离**：新文件，设计案3 才接入

### 2.1 `BattleLogCollector` 扩展

**文件**：`oblivions/include/game/battle_log.func.php`

新增属性、方法、映射表，emit 输出三个新字段：

```php
class BattleLogCollector {
    private $entries = [];
    private $phase = '';
    private $turnNum = 0;        // 0 = 未开始，1+ = 第 N turn
    private $roundNum = null;    // null = Phase 0（无队列），int = 已从 DB 缓存

    private static array $phaseDebugDefault = [
        'initiative_roll'          => false,
        'queue_create'             => true,
        'queue_rebuild'            => true,
        'once_execute_pre'         => false,
        'once_execute_post'        => false,
        'execute_verify_failed'    => false,
        'middle_check_target_dead' => false,
        'actor_state_check'        => true,
        'ap_recover'               => false,
        'flee'                     => false,
        'combatant_cleared'        => false,   // 新增（替代 battle_end 的中途清理）
        'battle_end'               => false,
        'ambush_battle_end'        => false,   // 新增（突袭阶段结束，有别于标准 battle_end）
        // 移除：main_end_cleanup（已不再 emit）
    ];

    /** phase → bl_segment_flag 自动映射 */
    private static array $phaseSegmentFlag = [
        'initiative_roll'    => 'round_start',
        'ap_recover'         => 'turn_start',
        'battle_end'         => 'battle_end',
        'ambush_battle_end'  => 'ambush_battle_end',
        // 其余 phase → null
    ];

    public function nextTurn(): void {
        $this->turnNum++;
    }

    /** 由 battle_queue_create_and_init / battle_queue_rebuild 调用 */
    public function setRoundNum(int $num): void {
        $this->roundNum = $num;
    }

    public function emit(array $params, ?bool $debug = null) {
        $debug = $debug ?? (self::$phaseDebugDefault[$this->phase] ?? true);
        $this->entries[] = [
            // ── 原有字段保持不变 ──
            'phase'        => $this->phase,
            'action_id'    => $params['action_id']    ?? null,
            'actor_pid'    => $params['actor_pid']    ?? null,
            'actor_type'   => $params['actor_type']   ?? null,
            'actor_name'   => $params['actor_name']   ?? null,
            'actor_hp'     => $params['actor_hp']     ?? null,
            'actor_max_hp' => $params['actor_max_hp'] ?? null,
            'actor_ap'     => $params['actor_ap']     ?? null,
            'actor_max_ap' => $params['actor_max_ap'] ?? null,
            'target_pid'    => $params['target_pid']    ?? null,
            'target_type'   => $params['target_type']   ?? null,
            'target_name'   => $params['target_name']   ?? null,
            'target_hp'     => $params['target_hp']     ?? null,
            'target_max_hp' => $params['target_max_hp'] ?? null,
            'effect_value' => $params['effect_value'] ?? null,
            'success'      => $params['success']      ?? null,
            'qid'          => $params['qid']          ?? null,
            'rolls'        => $params['rolls']        ?? null,
            'ambush_pid'   => $params['ambush_pid']   ?? null,
            'combatants'   => $params['combatants']   ?? null,
            'reason'       => $params['reason']       ?? null,
            'winner_pid'   => $params['winner_pid']   ?? null,
            'cleared_pid'  => $params['cleared_pid']  ?? null,    // 新增（combatant_cleared 用）
            'ambusher_pid' => $params['ambusher_pid'] ?? null,    // 新增（ambush_battle_end 用）
            'debug'        => $debug,
            'ts'           => time(),

            // ── 新增：边界标记 ──
            'bl_turn_num'    => $this->turnNum > 0 ? $this->turnNum : null,
            'bl_round_num'   => $this->roundNum,                    // null if Phase 0
            'bl_segment_flag'=> self::$phaseSegmentFlag[$this->phase] ?? null,
        ];
    }
}
```

**字段语义**：

| 字段 | 类型 | 值域 | 含义 |
|------|------|------|------|
| `bl_turn_num` | int \| null | null=Phase 0/尚未开始，1+=第 N turn | Turn 计数，由 `battle_hook_turn_start` 递增 |
| `bl_round_num` | int \| null | null=Phase 0（无队列），0+=第 N round（0-indexed） | Round 计数，从 DB `oblbattle_state.round_num` 读 |
| `bl_segment_flag` | string \| null | `'round_start'` / `'turn_start'` / `'battle_end'` / `'ambush_battle_end'` / null | phase 自动映射的段边界标记 |

### 2.2 设值调用点

| 位置 | 调用 | 说明 |
|------|------|------|
| `battle.func.php` `battle_hook_turn_start()` | `$obl_battle_log->nextTurn()` | Turn start hook 内递增 |
| `battle.queue.func.php` `battle_queue_create_and_init` emit initiative_roll 前 | `$obl_battle_log->setRoundNum(0)` | 队列新建 = Round 1（0-indexed） |
| `battle.queue.main.php` `battle_queue_rebuild` round_num++ + setRoundNum 后、emit initiative_roll 前 | `$obl_battle_log->setRoundNum(obl_battle_state_get_round_num($qid))` | 先递增 DB、同步 collector，再 emit initiative_roll，确保 `bl_round_num` 为新轮次编号 |

`battle_hook_turn_start` 现为空 placeholder，改为：

```php
function battle_hook_turn_start(&$actor_data, &$obl_battle_log, &$battle_cache): void {
    if ($obl_battle_log) {
        $obl_battle_log->nextTurn();
    }
}
```

`battle_hook_turn_end` 不操作计数器（Turn end 不递增，Turn start 才递增——因为 turn_num 标识"当前回合"）。

### 2.3 `battle_main_end` 改为 `combatant_cleared`

**文件**：`oblivions/include/game/battle/battle.main.php:302-308`

```php
// 改造前
$obl_battle_log->setPhase('battle_end');
$obl_battle_log->emit([
    'winner_pid' => (int)$pid,
    'reason'     => $reason === 'escaped' ? 'target_escaped' : ($reason === 'death' ? 'target_dead' : 'forced_cleanup'),

$obl_battle_log->emit([

```

**语义**：`combatant_cleared` = 某人离开战场，战斗可能继续；`battle_end` = 战斗真正终结。两者分离后，导演不再需要区分 mid vs final。

### 2.4 ambush 退出路径补 `ambush_battle_end` emit

**文件**：`oblivions/include/game/battle/battle.entry.php:73-82`

突袭阶段结束是一种有别于标准 `battle_end` 的特殊战斗结束方式：不是"有人赢了"，而是"突袭者退出/杀光所有敌人，突袭阶段终止"。使用独立 phase `ambush_battle_end`，不传 `winner_pid`，只传突袭者 pid + 退出原因。

```php
// step 5a：突袭者死了/逃了 → 突袭阶段结束
if ($ambusher_quit_flag) {
    if ($obl_battle_log) {
        $obl_battle_log->setPhase('ambush_battle_end');
        $obl_battle_log->emit([
            'ambusher_pid' => (int)$actor['pid'],
            'reason'       => 'ambush_' . $ambusher_quit_flag,  // 'ambush_dead' / 'ambush_escaped'
        ]);
    }
    battle_state_clear($actor, $obl_battle_log, $battle_cache, 'ambush_' . $ambusher_quit_flag);
    return;
}

// step 5b：突袭者杀光所有敌人 → 突袭阶段结束
if ($pids === false) {
    if ($obl_battle_log) {
        $obl_battle_log->setPhase('ambush_battle_end');
        $obl_battle_log->emit([
            'ambusher_pid' => (int)$actor['pid'],
            'reason'       => 'ambush_killed_all',
        ]);
    }
    battle_state_clear($actor, $obl_battle_log, $battle_cache, 'ambush_killed_all');
    return;
}
```

**语义对比**：

| phase | 含义 | 谁赢 | 字段 |
|-------|------|------|------|
| `battle_end` | 标准战斗（Phase 1）终结，有赢家 | `winner_pid` | `winner_pid`, `reason` |
| `ambush_battle_end` | 突袭阶段（Phase 0）结束，无赢家概念 | 无 | `ambusher_pid`, `reason` |

### 2.5 新增 `obl_battle_state_get_round_num`

**文件**：`oblivions/include/game/battle_state_machine.func.php`

```php
/**
 * 读取战场的 round_num
 * @param int $qid
 * @return int round_num（0-indexed），qid 不存在返回 0
 */
function obl_battle_state_get_round_num($qid) {
    global $db, $tablepre;
    if ($qid <= 0) return 0;
    $result = $db->query("SELECT round_num FROM {$tablepre}oblbattle_state WHERE qid = " . (int)$qid);
    $row = $db->fetch_array($result);
    return $row ? (int)$row['round_num'] : 0;
}
```

### 2.6 说明：Phase 1 最终 battle_end 的现有发射点

Phase 1 战斗真正终结（有赢家）时，`battle_end` emit 并非来自 `battle_main_end`，而是由 `battle_manage_queue` 在以下两条路径**已存在**的代码发出：

| 路径 | 文件行 | reason | winner_pid |
|------|--------|--------|------------|
| 队列空 | `battle.queue.main.php:92-98` | `queue_empty` | 当前 dispatch actor |
| 解散 | `battle.queue.main.php:127-133` | `disband` | 当前 dispatch actor |

改造后这两条路径**不需要修改**，`setPhase('battle_end')` + `emit()` 自动携带 `bl_turn_num`/`bl_round_num`/`bl_segment_flag`。由于 `battle_hook_turn_start` 在 `battle_manage_queue` 末尾执行，`battle_end` emit 时的 `bl_turn_num` 为上一回合的 turnNum（空队列发生在上一回合结束之后），语义正确。

**只需验证** JSON 输出中 `battle_end` 条目的这三个字段正确。

### 3.2 输出：PlayScript

导演编排后的完整输出，**分层结构**：

```typescript
/** 动画类型 */
type AnimationType = 'none' | 'collision';

/** HP 快照（from/to 配对，仅 action kind 有） */
interface HpSnapshot {
  actorHpBefore: number;
  actorHpAfter: number;
  actorMaxHp: number;
  targetHpBefore: number;
  targetHpAfter: number;
  targetMaxHp: number;
}

/** 导演编排后的单条条目 */
interface DirectedEntry extends BattleLogEntry {
  /** 动画类型（导演决定，仅 action kind 有意义） */
  animation: AnimationType;
  /** HP 快照（仅 action kind 且非非伤害动作时有） */
  hpSnapshot: HpSnapshot | null;
  /** 演员渲染分发标记 */
  directedKind: DirectedKind;
}

/** 7 种渲染分发标记 */
type DirectedKind =
  | 'action'              // pre+post 合并动作
  | 'initiative'          // 先攻掷骰（携带 rolls）
  | 'flee'                // 逃跑
  | 'combatant_cleared'   // 某人被清出队列（死亡/逃跑）
  | 'battle_end'          // 标准战斗终结（Phase 1，有赢家）
  | 'ambush_battle_end'   // 突袭阶段结束（Phase 0，无赢家概念）
  | 'display';            // 其他纯展示（ap_recover/verify_failed/middle_check 等）

/** 段类型 */
type SegmentKind =
  | 'phase0'              // Phase 0（ambush 攻击，无 Turn/Round）
  | 'round'               // Phase 1 的一轮
  | 'turn'                // Phase 1 的一回合
  | 'battle_end'          // 标准战斗终结
  | 'ambush_battle_end';  // 突袭阶段结束

/** 演出段 */
interface PlaySegment {
  /** 段类型 */
  kind: SegmentKind;
  /** 本段内的条目（已配对、已标记 directedKind） */
  entries: DirectedEntry[];
  /** 段元数据 */
  meta: SegmentMeta;
}

interface SegmentMeta {
  /** Round 序号（1-based，仅 round/turn 段有） */
  roundNum?: number;
  /** Turn 序号（1-based，仅 turn 段有） */
  turnNum?: number;
  /** 本回合行动者 pid（仅 turn 段有，来自 ap_recover 的 actor_pid） */
  actorPid?: number;
  /** 本回合行动者名称（仅 turn 段有） */
  actorName?: string;
  /** 先攻顺序（仅 round 段有，来自 initiative_roll 的 rolls） */
  initiatorOrder?: RollData[];
  /** 突袭者 pid（仅 round 段有，来自 ambush_pid） */
  ambushPid?: number;
  /** 战斗结束赢家 pid（仅 battle_end 段有） */
  winnerPid?: number;
  /** 战斗结束原因（battle_end / ambush_battle_end 段有） */
  reason?: string;
  /** 突袭者 pid（仅 ambush_battle_end 段有） */
  ambusherPid?: number;
  /** 标识本段是否为 Phase 0（true=突袭攻击段） */
  isPhase0?: boolean;
}

/** 导演编排后的完整输出 */
interface PlayScript {
  /** 按序排列的演出段 */
  segments: PlaySegment[];
}
```

## 四、模块定位

### 4.1 文件位置

```
vex-vue/src/stores/battle-director.ts
```

### 4.2 模块性质

- **同步纯函数**：不涉及异步、不查 API、不修改 store 状态
- **无副作用**：不修改输入 entries
- **一次性处理**：拉取到一批 entries 后一次性编排完

### 4.3 调用时机

在 `fetchAndPlayBattleLog` 中，拉取到 entries 之后、播放之前调用：

```
fetchAndPlayBattleLog()
  → 拉取 entries（played=0，debug=true 已由后端过滤）
  → BattleDirector.direct(entries)              ← 导演：同步纯函数，编排为 PlayScript
  → npcPid = extractNpcPid(script)              ← 替代 groupByEncounter
  → BattlePlayer.play(script, npcPid)           ← 演员：逐段执行（设计案3）
  → markBattleLogPlayed(allLogIds)
```

**注意**：`markBattleLogPlayed` 仍标记**全部原始 entries 的 log_id**（不依赖导演输出）。导演层即使将异常 pre/post 降级为 display 条目，其 `log_id` 仍包含在 `collectAllLogIds` 返回值中，不会重复播放。

## 五、核心函数设计

### 5.1 主函数 `direct()`

```typescript
/**
 * 战斗导演：把后端 raw entries 编排为分层演出脚本
 *
 * 编排顺序：
 * 1. 配对 once_execute_pre/post，合并为 action DirectedEntry
 * 2. 按 bl_segment_flag / bl_turn_num / bl_round_num 构建 PlaySegment[]
 *
 * @param entries 后端 raw battlelog entries（按 log_id 升序，已过滤 debug=true）
 * @returns 分层演出脚本
 */
export function direct(entries: BattleLogEntry[]): PlayScript {
  const paired = pairPrePost(entries);
  return buildSegments(paired);
}
```

### 5.2 配对函数 `pairPrePost()`

**策略**（v2 保留不变）：栈配对 + interleaving 缓冲。pre 到来时压栈；interleaving 条目（flee/middle_check 等）缓冲；post 到来时合并 pre+post，先输出合并条目再刷出缓冲。

```typescript
interface PendingPre {
  pre: BattleLogEntry;
  buffer: BattleLogEntry[];   // pre→post 之间的 interleaving 条目
}

function pairPrePost(entries: BattleLogEntry[]): DirectedEntry[] {
  const result: DirectedEntry[] = [];
  let pending: PendingPre | null = null;

  for (const e of entries) {
    if (e.phase === 'once_execute_pre') {
      // 悬空 pre（异常：连续两个 pre 无 post）
      if (pending) {
        result.push(toDisplay(pending.pre));
        pending.buffer.forEach(b => result.push(toDisplay(b)));
      }
      pending = { pre: e, buffer: [] };

    } else if (e.phase === 'once_execute_post') {
      if (pending) {
        result.push(mergePrePost(pending.pre, e));
        pending.buffer.forEach(b => result.push(toDisplay(b)));
        pending = null;
      } else {
        // 异常：post 无对应 pre
        result.push(toDisplay(e));
      }

    } else {
      if (pending) {
        pending.buffer.push(e);
      } else {
        result.push(toDisplay(e));
      }
    }
  }

  // 尾部未配对的 pre
  if (pending) {
    result.push(toDisplay(pending.pre));
    pending.buffer.forEach(b => result.push(toDisplay(b)));
  }

  return result;
}
```

### 5.3 转换函数

```typescript
/** phase → directedKind 映射 */
function toDirectedKind(e: BattleLogEntry): DirectedKind {
  switch (e.phase) {
    case 'once_execute_pre':     return 'action';             // mergePrePost 已合并
    case 'once_execute_post':    return 'action';             // 异常单 post，仍标 action
    case 'initiative_roll':      return 'initiative';
    case 'flee':                 return 'flee';
    case 'combatant_cleared':    return 'combatant_cleared';
    case 'battle_end':           return 'battle_end';
    case 'ambush_battle_end':    return 'ambush_battle_end';
    default:                     return 'display';
  }
}

/** 把 raw entry 转为纯展示 DirectedEntry */
function toDisplay(e: BattleLogEntry): DirectedEntry {
  return {
    ...e,
    animation: 'none',
    hpSnapshot: null,
    directedKind: toDirectedKind(e),
  };
}

/** 合并 pre/post 为一条完整 action DirectedEntry */
function mergePrePost(pre: BattleLogEntry, post: BattleLogEntry): DirectedEntry {
  const isNonDamage = pre.action_id && nonDamageActions.includes(pre.action_id);
  return {
    ...pre,
    effect_value: post.effect_value,
    success: post.success,
    animation: decideAnimation(pre),
    hpSnapshot: isNonDamage ? null : {
      actorHpBefore: pre.actor_hp ?? 0,
      actorHpAfter: post.actor_hp ?? 0,
      actorMaxHp: pre.actor_max_hp ?? 1,
      targetHpBefore: pre.target_hp ?? 0,
      targetHpAfter: post.target_hp ?? 0,
      targetMaxHp: pre.target_max_hp ?? 1,
    },
    directedKind: 'action',
  };
}

/** 非伤害动作白名单（escape 等不产生 HP 变化的动作） */
const nonDamageActions = ['escape'];

/** 决定动画类型 */
function decideAnimation(e: BattleLogEntry): AnimationType {
  const attackActions = ['unarmed_strike'];
  if (e.action_id && attackActions.includes(e.action_id)) {
    return 'collision';
  }
  return 'none';
}
```

### 5.4 分段函数 `buildSegments()`

**分段规则**（按段边界信号驱动）：

| 输入信号 | 操作 | segment kind |
|---------|------|-------------|
| `bl_segment_flag === 'round_start'` | 关闭当前 turn/round，开始新 round segment | `round` |
| `bl_segment_flag === 'turn_start'` | 关闭当前 turn，开始新 turn segment | `turn` |
| `bl_segment_flag === 'battle_end'` | 关闭当前段，追加 battle_end segment | `battle_end` |
| `bl_segment_flag === 'ambush_battle_end'` | 关闭当前段，追加 ambush_battle_end segment | `ambush_battle_end` |
| `bl_turn_num === null && bl_round_num === null` 且无 open segment | 归入 phase0 segment | `phase0` |
| 其他 | 归入当前段 | (当前段) |

```typescript
function buildSegments(entries: DirectedEntry[]): PlayScript {
  const segments: PlaySegment[] = [];
  let current: PlaySegment | null = null;
  let roundCounter = 0;
  let turnCounter = 0;

  const closeCurrent = () => {
    if (current && current.entries.length > 0) {
      segments.push(current);
    }
    current = null;
  };

  for (const e of entries) {
    // ── 段边界信号 ──
    if (e.bl_segment_flag === 'round_start') {
      closeCurrent();
      roundCounter++;
      turnCounter = 0;   // 新 round 重置 turn 计数
      current = {
        kind: 'round',
        entries: [e],
        meta: {
          roundNum: roundCounter,
          initiatorOrder: e.rolls ?? undefined,
          ambushPid: e.ambush_pid ?? undefined,
        },
      };
      continue;
    }

    if (e.bl_segment_flag === 'turn_start') {
      closeCurrent();
      turnCounter++;
      current = {
        kind: 'turn',
        entries: [e],
        meta: {
          roundNum: roundCounter,
          turnNum: turnCounter,
          actorPid: e.actor_pid ?? undefined,
          actorName: e.actor_name ?? undefined,
        },
      };
      continue;
    }

    if (e.bl_segment_flag === 'battle_end') {
      closeCurrent();
      current = {
        kind: 'battle_end',
        entries: [e],
        meta: {
          winnerPid: e.winner_pid ?? undefined,
          reason: e.reason ?? undefined,
        },
      };
      closeCurrent();   // battle_end 段立即关闭（单条段）
      continue;
    }

    if (e.bl_segment_flag === 'ambush_battle_end') {
      closeCurrent();
      current = {
        kind: 'ambush_battle_end',
        entries: [e],
        meta: {
          ambusherPid: e.ambusher_pid ?? undefined,
          reason: e.reason ?? undefined,
        },
      };
      closeCurrent();   // ambush_battle_end 段立即关闭（单条段）
      continue;
    }

    // ── 非边界条目：归入当前段 ──
    if (!current) {
      // 无 open segment：Phase 0 段（bl_turn_num === null && bl_round_num === null）
      current = {
        kind: 'phase0',
        entries: [e],
        meta: { isPhase0: true },
      };
    } else {
      current.entries.push(e);
    }
  }

  closeCurrent();
  return { segments };
}
```

**关键**：分段依赖 `bl_segment_flag` 字段（后端前置改造提供），不依赖 phase 字符串推断。`roundCounter`/`turnCounter` 由导演本地维护，与后端 `bl_round_num`/`bl_turn_num` 独立（导演计数用于演出显示"第 N 轮"，后端计数用于排序校验）。

/**
 * 从 PlayScript 中提取 NPC PID
 * 替代现有 battle.ts 的 groupByEncounter()

export function extractNpcPid(script: PlayScript): number {
  for (const seg of script.segments) {
    for (const e of seg.entries) {
      if (Number(e.actor_type) > 0) return Number(e.actor_pid);
      if (Number(e.target_type) > 0) return Number(e.target_pid);
    }
  }
  return 0;
}

/**
 * 判断脚本是否包含 combat 动作（有具体目标的 action）
 * 用于决定演出模式（combat vs flow）
 */
export function hasCombatEntries(script: PlayScript): boolean {
  return script.segments.some(seg =>
    seg.entries.some(e =>
      e.directedKind === 'action' &&
      Number(e.actor_pid) > 0 && Number(e.target_pid) > 0
    )
  );
}

 * 基于原始 entries 而非导演输出，确保异常条目的 log_id 也被标记

export function collectAllLogIds(entries: BattleLogEntry[]): number[] {
  return entries.map(e => Number(e.log_id)).filter(id => id > 0);

## 七、边界情况

### 7.1 once_execute_pre 无配对

异常：pre 后无 post。`pairPrePost` 将未配对的 pre 作为 `directedKind: 'action'` + `hpSnapshot: null` 输出。演员降级显示（名称/动作文本正常，HP 条不更新）。

### 7.2 once_execute_post 无配对

异常：post 无对应 pre。`pairPrePost` 将 post 作为 `directedKind: 'action'` + `hpSnapshot: null` 输出。降级显示。

### 7.3 空 entries

`direct([])` 返回 `{ segments: [] }`，不报错。

### 7.4 多 NPC 战斗

单 NPC 约束下，`extractNpcPid()` 从第一条非零 `actor_type`/`target_type` 中提取 NPC pid。

### 7.5 条目跨批次到达

后端请求级批量持久化（`obl_command.php:129`），pre/post 必在同批。即便前端积压多回合未消费，`pairPrePost` 的栈逻辑跨回合也能正确工作（pre_A/post_A/ap_recover/pre_B/post_B 不会错配）。`buildSegments` 按 `bl_segment_flag` 分段，跨回合自然形成多个 round/turn segment。

### 7.6 非渲染条目

后端 `obl_battle_log_load()` 默认已过滤 `debug=true`，导演不会见到 `queue_create`/`actor_state_check`/`queue_rebuild` 等纯调试 phase。

### 7.7 Phase 0 无 segment 边界信号

Phase 0 条目 `bl_turn_num === null && bl_round_num === null && bl_segment_flag === null`。`buildSegments` 在无 open segment 时创建 `phase0` segment。Phase 0 结束的信号是 `round_start`（队列建立，进入 Phase 1）或 `ambush_battle_end`（突袭阶段终止）。`ambush_battle_end` 与标准 `battle_end` 分离，演员据此区分"突袭结束"与"标准战斗终结"。

### 7.8 `main_end_cleanup` 已移除

后端 `battle_main_end` 不再 emit `main_end_cleanup`（设计案4 已落地）。导演无需处理此 phase。`$phaseDebugDefault` 中的 `main_end_cleanup` 条目已移除。

## 八、演员渲染分发规则（供设计案3 参考）

| SegmentKind | 演员行为 |
|-------------|---------|
| `phase0` | 插入"── 突袭 ──"分隔，逐条播放 entries |
| `round` | 插入"── 第 N 轮 ──"分隔，渲染先攻顺序面板（若有 rolls） |
| `turn` | 切换 HP 条目标为 meta.actorPid，逐条播放 entries |
| `battle_end` | 显示战斗结束文字（读 winnerPid + reason），退出战斗模式 |
| `ambush_battle_end` | 显示突袭结束文字（读 ambusherPid + reason，无赢家），退出战斗模式 |

| DirectedKind | 演员行为 |
|-------------|---------|
| `action` | 播放动画（collision/none），更新 HP 条（若有 hpSnapshot） |
| `initiative` | 渲染先攻顺序面板（读 rolls） |
| `flee` | 显示逃跑文字提示 |
| `combatant_cleared` | 显示击杀/逃跑文字（读 cleared_pid + reason） |
| `battle_end` | 退出战斗模式（读 winnerPid + reason） |
| `ambush_battle_end` | 退出战斗模式（读 ambusherPid + reason，特殊突袭结束渲染） |
| `display` | 纯文字或跳过（ap_recover 显示 AP 恢复，verify_failed 显示校验失败等） |
