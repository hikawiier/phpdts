# 战斗演出三层架构设计案（总纲）

> 本文档定义 battlelog 播放系统的三层架构重构：**后端给全原料 → 前端导演集中编排 → 演员纯执行**。
>
> **当前状态**：设计阶段，未实施。
> **关联文档**：[设计案1-重构后端battle_log.md](设计案1-重构后端battle_log.md) | [设计案2-新建前端导演系统.md](设计案2-新建前端导演系统.md) | [设计案3-重构前端播放系统.md](设计案3-重构前端播放系统.md)
> **前置问题**：前端 battlelog 播放逻辑中散落大量"越权判断"，违反前后端职责分离原则；battlelog 单回合 ~50 条，渲染压力大，无调试/渲染区分。

---

## 一、背景与问题

### 1.1 现状

当前 battlelog 播放流程中，前端 store 承担了大量本不属于"播放器"职责的判断逻辑，散落在多处：

| 位置 | 做的判断 | 性质 |
|------|---------|------|
| `playBattleLogGroup` | `phase === 'excute'` 过滤 | 表现逻辑 |
| `playBattleLogGroup` | `action_id === 'unarmed_strike'` → 碰撞动画 | 表现逻辑 |
| `groupByEncounter` | 从 `actor_type`/`target_type` 推导 NPC pid 分组 | 表现逻辑 |
| `rebuildInitialHpFromEntries` | 从 `extra.actor_oldhp` 反推战前 HP | **数据补救** |
| `buildPlayContext` → API 查询 | 查敌人名称/HP/位置 | **数据补救** |
| `isFlowMode`（BattleModal） | 推导显示模式（flow/combat） | 表现逻辑 |

### 1.2 三类问题

1. **数据补救**：后端 emit 时未给全信息（敌人名称、HP 快照），前端被迫查 API 或反推
2. **表现逻辑散落**：怎么演（显示模式、动画类型、播放顺序）的判断散落在 store、modal、各处 `if`
3. **无渲染/调试分离**：battlelog 同时承载"前端渲染原料"和"后端流程追踪"两种职责，单回合 ~50 条 log，前端需要全量解析

### 1.3 根因

- `BattleLogCollector.emit()` 只记录"发生了什么"，不区分"这条是渲染原料还是调试追踪"
- 所有 emit 用统一字段结构，导致占位符（0/-1）和 extra 滥用
- 前端被迫从残缺数据反推演出方式，每加一种动作/动画就要加一个 `if`

## 二、设计原则

> **后端给全原料 + 渲染/调试分离 → 前端集中编排 → 演员纯执行。**

### 2.1 四层职责

| 层 | 模块 | 职责 | 不做的事 |
|----|------|------|---------|
| **后端** | `BattleLogCollector` | 记录战斗事实 + 给全原料 + 标记 debug | 不决定怎么演 |
| **传输** | battlelog JSON | 渲染原料通过 `debug: false` 传递，调试信息通过 `debug: true` 保留 | 不含中间容器 |
| **前端导演** | `BattleDirector`（新增） | 把原料编排为演出脚本 | 不执行渲染 |
| **前端演员** | `BattlePlayer`（简化后） | 纯执行演出脚本 | 不做任何判断 |

### 2.2 核心原则

1. **后端只记录事实**：emit 时写明"当前状态"（HP 快照、名称等），不写"变化语义"（如 before/after）
2. **渲染/调试分离**：每条 emit 有 `debug` 字段，前端默认只消费 `!debug` 条目
3. **导演集中编排**：所有表现逻辑（分组、显示模式、动画类型、配对）集中在 `BattleDirector`
4. **演员纯执行**：只读脚本字段，不做任何业务推断

### 2.3 phase 细分原则

精准划分 phase 后，每个 phase 对应明确的最小参数集：
- 消除占位符（0/-1/''）
- 消除 extra 滥用
- 前端导演按 phase 分发到不同处理函数

## 三、三份子设计案

本总纲拆分为三份子设计案，按依赖顺序实施：

### 设计案1：重构后端 battle_log

- **范围**：12 phase 体系 + emit() 签名改造 + debug/渲染分离 + 两层 setPhase 策略
- **依赖**：无（基础层）
- **文档**：[设计案1-重构后端battle_log.md](设计案1-重构后端battle_log.md)

### 设计案2：新建前端导演系统

- **范围**：新增 `BattleDirector` 模块（同步纯函数），按 phase 分发编排
- **依赖**：设计案1（需要后端提供细分 phase + debug 标记 + 完整字段）
- **文档**：[设计案2-新建前端导演系统.md](设计案2-新建前端导演系统.md)

### 设计案3：重构前端播放系统

- **范围**：简化 `BattlePlayer` 为纯执行器 + 清理死代码
- **依赖**：设计案2（需要导演模块）
- **文档**：[设计案3-重构前端播放系统.md](设计案3-重构前端播放系统.md)

### 依赖关系

```
设计案1（后端）   →   设计案2（导演）   →   设计案3（播放器）
  基础层                编排层                执行层
```

## 四、架构总览

```
┌─────────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│ 后端（原料+分类）    │     │ 前端导演（编排）  │     │ 前端演员（执行）  │
│ BattleLogCollector  │ →   │ BattleDirector   │ →   │ BattlePlayer     │
└─────────────────────┘     └─────────────────┘     └─────────────────┘
        │                            │                        │
   emit:                        编排(debug=false):         执行指令:
     phase（细分）                 - 过滤 debug=true         - 播碰撞动画
     actor_pid/name/hp            - 分组                    - 显示模态框
     target_pid/name/hp           - 配对 pre/post           - 渲染 HP 条
     action_id                    - 显示模式                - 打字机效果
     effect_value                 - 动画类型                - 伤害数字
     debug: true/false            - HP 快照选取
```

## 五、对比分析

| 维度 | 当前（散落判断） | 三层架构后 |
|------|----------------|-----------|
| 表现逻辑位置 | 散落 store/modal/各处 if | 集中在 BattleDirector |
| 新增动画 | 改前端多处 | 改 BattleDirector 一处 |
| 后端职责 | 数据记录（不全） | 数据记录（给全原料 + 分 debug） |
| 前端职责 | 数据补救+散落判断 | 导演编排+演员执行 |
| phase 粒度 | 粗（4 个实际使用） | 细（12 个） |
| 字段完整性 | 占位符+extra 滥用 | 最小参数集+正式字段 |
| 渲染条目数 | ~50 条/回合（全量解析） | ~26 条/回合（过滤 debug） |
| render/debug 区分 | 无 | `debug` 布尔字段 |
| 职责分离 | 模糊 | 清晰 |
