# 搜索建筑物与掉落机制 设计案

## 一、机制概述

在废土中探索是游戏的核心循环之一。本设计描述玩家如何通过"搜索"行为在地图上获取物资，以及系统如何在每次搜索时决定"得到什么、发生什么"。

搜索行为分为两种类型，分别对应不同的玩家意图：

1. **地面拾取**：玩家移动到一格地格上时，地面上可能散落着一些物品，可以直接拾取。
2. **POI兴趣点搜刮**：玩家点击"POI搜刮"按钮，展开模态框，模态框内显示当前图格内所有的POI。从界面上选择一个POI进行深入搜索。

两者互补：地面拾取是低风险的"路过捡破烂"，POI搜刮是高风险高回报的"深入挖掘"。

***

## 二、地面拾取机制

### 2.1 物品从哪里来

地格所属的区域有一份"潜在物品池"，这是地格刷新道具的基础池。此外，地格本身的地板类型、地格所处潮汐等级会额外提供给地格物品池或物品黑名单。

物品不是一开始就铺满地图的，而是按以下规则逐步生成：

- **首次进入**：玩家第一次踏上一格地格时，系统根据该地格类型、物品池生成一次初始物品。
- **时间流逝**：每推进100次游戏刻（临时，该时间未来会改为“天数”），地格会"刷新"一次潜在物品。每次刷新都会从该地格对应的物品池中随机抽取。
- **潮汐等级越高，刷新越频繁**：潮汐等级是图格的危险等级，潮汐等级越高，物品刷新概率越高；等级越低，刷新越稀疏。

### 2.2 容量上限

为了避免玩家在同一格反复刷出大量物品，每格地格同时最多容纳 **5 件**地面物品。达到上限后，新的刷新会被跳过，直到玩家把其中一些拿走。

### 2.3 地面物品怎么被发现

玩家在某图格上点击\[探索]时，会根据玩家的\[搜刮]技能等级决定每次能发现多少件地面道具。

### 2.4 地面道具在游戏界面上的位置

被发现了的地面道具保存在\[探索]按钮下方的\[脚边道具]里。

## 三、POI兴趣点搜刮机制

### 3.1 搜刮按钮在游戏界面上的位置

满足以下条件时，游戏界面上会在\[脚边道具]右侧出现\[POI交互]按钮：

- 当前地格里**至少有一处POI**
- 不是所有的POI都可以搜刮，有的是“交互型POI”，本文档只涉及搜刮型POI

### 3.2 选择POI搜刮点

点击搜刮按钮后，会弹出搜刮模态框。模态框内显示当前图格内所有的POI，为每一个POI生成一个对应的互动选项。例如，如果地格上同时一件可搜刮的"废弃房子"和一件可搜刮的"公寓大厦"，菜单就会列出两个选项：

- "搜刮废弃房子"
- "搜刮公寓大厦"

每个选项对应一个具体的建筑物搜刮遭遇，拥有自己独立的3项核心概率。核心概率会被光照（未实现仅占位）、天气（未实现仅占位）、图格地板属性、图格所处潮汐等级综合影响，概率包括：

| 概率                   | 含义                                |
| -------------------- | --------------------------------- |
| **物资概率**             | 这次搜索能找到东西的可能性                     |
| **良性事件概率（1-恶性事件概率）** | 这次搜索可能会触发的好事件，比如发现了更多东西的可能性       |
| **恶性事件概率**           | 这次搜索可能会触发的坏事件，比如出意外（摔伤、踩到陷阱等）的可能性 |

### 3.3 工具与技能的影响

某些POI搜刮点允许玩家"附带使用"特定工具或技能改变核心概率、或核心概率中具体某个事件的触发概率，简单举几个例子：

- **开锁器**：可以撬开锁住的门，进入更安全的搜刮路径，物资概率++
- **手电筒**：在黑暗中提供照明，降低意外概率，物资概率++，恶性事件概率--
- **撬棍**：可以打开密封的容器，物资概率++，恶性事件概率+
- **寻踪**：可以判断哪里更值得搜刮，恶性事件概率--
- **潜行**：可以降低恶性事件概率，恶性事件概率--

工具的使用方式见4.2。

使用工具后，系统会把玩家路由到一个"改良版"的搜刮分支，那里通常有更高的物资概率、更低的意外概率，或者额外的奖励掉落池。

### 3.4 POI的搜刮

搜刮后，POI会根据自己的道具池、物资概率、事件概率综合生成掉落，然后改变自己的状态，状态可理解为：

- 同一个建筑物不能被反复搜刮——搜过一次就没了
- 有的POI可以被反复搜刮，但是存在自己的冷却时间

这条规则是"搜刮有代价、资源有限"的核心保障。

## 四、界面表现

### 4.1 按钮

被发现了的地面道具保存在\[探索]按钮下方的\[脚边道具]里。

存在可交互POI时，\[脚边道具]右侧出现\[POI交互]按钮

### 4.2 POI互动界面

点击POI交互按钮后，画面中央会弹出**模态框**，模态框中每个POI为一个带操作按钮的独立卡片。

点击操作按钮后，跳入POI的具体交互界面：

- **左侧POI信息区**：显示该POI搜刮点的场景插图和文字介绍
- **中上部交互区**：显示实时物资概率条、事件概率条和可能搜刮出的道具列表/交互结果。
- **中下部反馈区**：列出已放入的交互工具、技能。
- **右侧交互区**：实时显示可用于与POI交互的工具、技能。

### 4.3 掉落物的界面表现

搜刮结果出来后，掉落物品不会直接飞入背包，而是保存在POI自己的已发现道具表里，第一次会主动弹出模态框，之后需要玩家通过点击POI交互按钮→点击该POI卡片内的交互按钮再次呼出模态框：

### 4.4 事件反馈

- **意外事件**：遭遇窗口的图像区会切换为意外场景插图（例如跌落峡谷），描述文字变为对应的良性、恶性叙述，玩家可能立即受伤（伤口图标会出现在身体面板上）、损坏装备、或失去部分行动点
- 无事发生：若本次掷骰没有触发发现道具，也没有触发事件，会显示"这次什么也没找到"。

## 五、搜刮结果的三档判定

当玩家选定一个POI搜刮点（和可选的工具）后，系统按以下优先级依次判定结果：

### 第一档：保底掉落（"长时间没出货"补偿）

如果玩家已经很久没有从搜刮中获得过像样的奖励，系统会强制触发一次掉落，且奖励质量会比平时更好。这是为了避免玩家陷入"连续多次搜刮都空手而归"的挫败感。

保底触发后，计时器重置；其他结果档触发时，计时器会略微回拨一点，让保底稍微延后。

### 第二档：意外事件

如果本次掷骰落在"触发事件"范围内，系统会从该POI搜刮点的意外事件池中随机抽取一个事件触发。

本设计案暂时不设计具体事件，但是需要设计两\~四个测试用事件填充空位。

### 第三档：普通掉落

如果本次掷骰落在"物资概率"范围内，系统会从该POI搜刮点的战利品池中随机生成物品交给玩家。

### 第四档：什么都没找到

如果以上三档都没触发，玩家会得到一句"这次什么也没找到"的反馈。

## 六、战利品池的生成规则

### 8.1 战利品表

每个POI搜刮点都关联一张"战利品表"，表中列出可能出现的物品及其概率。表的结构如下：

- 表由若干**物品组**构成，每组独立掷骰
- 每组内可以列出多个**互斥选项**，根据权重选择其中一个
- 每个选项指定：物品类型、出现概率、数量范围

例如，一张"医疗工具"表可能包含三组：

- 第一组：100% 出一件基础医疗工具
- 第二组：50% 出一件中级药品
- 第三组：100% 出一个空容器（用来装前面的东西）（占位，未来实现，参见 §8.3）

### 8.2 嵌套表（占位，未来实现）

某些战利品表中的"物品"实际上是另一张战利品表的引用。系统会递归展开，模拟出"先抽一个大类，再在类内抽具体物品"的两层结构。例如先抽"弹药类"，再在弹药类内部抽具体口径。

> **当前重构状态**：嵌套表与递归展开机制暂不实现。原型阶段所有战利品表均为扁平结构，多件物品需求通过扩容物品上限与拆分独立条目满足。本节作为未来扩展的占位。

### 8.3 容器装填（占位，未来实现）

某些表开启了"容器装填"模式：生成的物品会被自动塞进先生成的容器类物品里。例如先抽到一个背包，再抽到几瓶水，水会自动装进背包里，玩家拿走的是"一个装着水的背包"而不是散落的两件物品。

> **当前重构状态**：容器装填机制暂不实现。原型阶段不引入容器类型道具，包含多件物品的配置拆解为多个单件道具独立掉落。本节作为未来扩展的占位。

### 8.4 耐久度衰减

通过搜刮获得的物品，其耐久度通常是衰减过的。系统会在物品原有最大耐久度范围内随机取一个值，模拟"这件东西被丢弃前已经用过一段时间"。这对武器、工具、衣物等有耐久度的物品尤其重要——搜刮来的东西通常不如自己保养的好。

## 七、设计目标总结

1. **风险与回报对等**：高价值POI搜刮点（公寓楼、废弃工厂）通常物品概率和恶性事件概率都高，玩家需要权衡是否值得冒险。
2. **环境塑造氛围**：光照、地形、图格属性共同影响收益，鼓励玩家在合适的时间、合适的地点行动。
3. **工具与技能有意义**：携带合适的装备能显著改善搜刮体验，强化"准备好再出发"的废土生存感。
4. **避免连续挫败**：保底机制保证长时间不出货后必有收获，意外和惊动作为代价调节节奏。
5. **生态感**：地面物品按时间自然刷新，越危险的图格物资越丰沛，鼓励玩家向外探索而非固守一地。
6. **界面信息透明**：通过概率条与道具池预览，玩家能在决策前清楚看到每条路径的预期收益与风险，避免盲搜带来的挫败。
