# 视野-探索-移动模块改造设计案

> 状态：机制与视觉基准设计，尚未进入代码实现  
> 日期：2026-07-22  
> 适用范围：Oblivions 后端模式 + Vex-Vue 正式前端  
> 设计来源：以玩家操作路径为起点重新推导，不继承旧 Demo 的页面壳、Mock/Real 双模式或 K-11、L-10～L-19 等失败方案假设

---

## 一、设计结论

### 1.1 一句话目标

把当前依赖玩家反复点图格的移动方式，改造成一种以“前往下一个探索目标”为单位的自动导航：玩家点击一次移动，后端选择一个目标并逐游戏刻移动，抵达目标或遇到重要事件后停止；移动和主动探索都能触发信息获取，但主动探索拥有更强的信息获取效率。

### 1.2 核心玩家体验

玩家的主要决策不是逐格操作，而是选择探索态度：稳健地覆盖低潮汐区域、就近推进、主动深入险境，或者优先提高移动效率。系统替玩家处理重复寻路，但不替玩家决定是否开战、是否互动 POI、是否拾取道具或是否跨区域。

玩家始终能够理解当前发生了什么：

- 主探索界面只显示当前视野范围。
- 点击移动后有明确的移动演出、逐次日志和信息反馈。
- 每次自动导航只前往一个目标，抵达后必定停止。
- 发现敌人、POI、关键道具或强制事件时立即中断。
- 完整地图负责区域总览和指定目标，不承担探索主界面职责。
- 战斗使用独立场景，但战斗移动仍改变区域地图上的真实位置。

### 1.3 设计哲学校准

本案遵循 `DESIGN.md` 第三节：

- 从玩家画面和操作路径反推状态、API和后端模型。
- 优先降低注意力和重复操作成本，不以展示更多信息为目标。
- 不把内部结算边界机械暴露成玩家必须重复点击的按钮流程。
- 不为尚未验证的策划数值写死“移动只能发现什么、探索只能发现什么”。
- 以可配置框架承载后续调参，但首期玩家规则保持简单、可解释。

## 二、现状基准与改造边界

### 2.1 当前正式前端基准

正式前端以 `vex-vue/src/App.vue` 为根工作台：

- 单一 `StatusBar`。
- 左侧 `LeftPanel -> MapContainer -> MapGrid`。
- 右侧正常模式为 `LogPanel + TileActionBar`。
- 右侧战斗模式为现有 `BattleMode`。
- 属性、背包为左右 push 抽屉。
- POI、合成、itm0、Toast 与战斗演出为现有全局能力。

本案以这个正式工作台为宿主，不把现有整套功能迁移进另一个 Demo 页面。

### 2.2 当前后端基准

当前相关框架为：

- `E-3`：基于图的移动系统，代码锚点 `oblivions/include/game/move.func.php`。
- `E-6`：视野与感知系统，代码锚点 `oblivions/include/game/vision.func.php`。
- `E-7`：探索与交互管道，代码锚点 `oblivions/include/game/explore.func.php`。
- `B-1/B-2/B-3`：命令合约、总线与请求校验。
- `E-1`：游戏刻与时间调度。
- `K-1`：战斗导演与演出播放管道。
- `K-3`：前端命令门控。
- `K-6/K-7/K-9/K-10`：地图权威投影、视觉过渡、presentation 批处理和角色动画意图。
- `L-1/L-7`：正式动作区与地图网格。

### 2.3 当前设计冲突

当前 `E-3/E-7` 把移动和探索按信息类型固定拆开：移动后只清除迷雾，道具和敌人发现依赖主动探索。这会把内部结算分工直接变成玩家必须执行的“移动后再探索”，与目标体验冲突。

本案要求未来修订这一基准：

- 移动和探索都触发统一的信息获取行为。
- 两者通过行动规则、概率补正、候选范围和信息预算形成差异。
- 不再按“移动只管迷雾、探索只管道具和敌人”写死职责。

该修订尚未实现，因此本轮不更新 `Dian.md`，也不修改现有 `@framework` 标签。

### 2.4 本阶段不做的事

- 不写生产代码。
- 不定义最终 API 字段名、数据库表或函数签名。
- 不规定时间调度器内部事件的绝对先后顺序。
- 不修改现有战斗预装填、动作瞄准和战斗执行规则。
- 不把普通地面道具变成自动探索目标。
- 不让自动系统执行 POI 互动、拾取、开战或跨区域操作。
- 不把设计草案提前沉淀到 `Dian.md`。

## 三、模块层

### 3.1 模块 E：地图、移动、视野与探索

模块 E 负责权威地图状态、移动合法性、移动方式、观察方式、自动目标选择、信息获取与游戏刻内的领域结果。

需要修订或新增的能力包括：

- 真实 `explored` 状态。
- 动态通行性与地图拓扑分离。
- 移动方式与观察方式。
- 自动探索目标解析。
- 多次移动导航命令。
- 统一信息获取行为。
- 导航中断结果和逐次移动结果。

### 3.2 模块 B：命令合约与一致性

模块 B 负责接收高层导航意图、校验命令状态、调用时间调度与领域处理，并返回结构化结果。

它必须保证：

- 一次高层导航命令可以包含多次独立移动行动。
- 每次移动行动分别推进一个游戏刻。
- 每次移动后重新依据权威状态判断下一步。
- 无目标、无路线等未形成有效行动的失败不推进游戏刻。
- 页面刷新或重复提交不能制造重复导航结算。

具体如何复用现有命令总线、事务与幂等协议，留待代码集成设计阶段研判。

### 3.3 模块 K：正式前端状态与演出编排

模块 K 负责：

- 三场景的前端所有权。
- 导航响应的逐次结果消费。
- 移动演出播放、加速和跳过。
- 演出期间的命令门控。
- 权威地图与可见演出投影的重基准。
- 临时导航目标在当前页面会话中的展示和暂停状态。

移动导演应复用现有战斗导演已经证明有效的“权威结果与演出投影分离”原则，而不是建立前端循环发送单次移动请求的自动点击器。

### 3.4 模块 L：正式前端组件

模块 L 负责：

- 局部视野地图。
- 完整地图全屏模态场景。
- 固定主操作区。
- 当前格情境操作区。
- 发现结果模态框。
- 横屏手机布局和竖屏旋转提示。
- 战斗场景的正式工作区布局。

现有地图、日志、POI、合成、背包、属性、Toast 和战斗组件应优先复用，不能在新场景中重复实现一套简化版本。

## 四、候选基准框架

> 下列名称用于本设计案沟通，不提前占用新的 `Dian.md` 编号。实现完成并验证后，再决定是修订现有 E-3/E-6/E-7，还是提升新的编号框架。

### 4.1 原子移动与多行动导航框架

一次移动行动具有以下稳定语义：

- 消耗一个游戏刻。
- 移动力表示本次行动可以选择的最大落点距离。
- 玩家只提交一个最终落点，不在中间格形成权威位置状态。
- 一次移动只触发一次信息获取行为。
- 中间路径不按格推进时间，也不按格触发普通地图事件。

一次自动导航是多个移动行动的后端编排：

```text
选择一个目标
→ 向时间调度器提交一次移动行动意图
→ 时间调度器按权威顺序完成本游戏刻
→ 返回移动、信息获取、世界变化、拦截等领域结果
→ 导航器根据本刻最终权威状态判断抵达或中断
→ 未结束则重新判断下一次移动
```

一次高层导航请求可以返回多次移动结果，但每次移动仍是独立的领域行动和游戏刻。移动模块只声明行动意图与移动规则，不规定同一游戏刻内移动、信息获取、敌人行动、地图变化和拦截的先后顺序。

高层导航允许正常的部分完成：

- 每次已经完成的原子移动、游戏刻和世界变化都是权威事实，立即保留。
- 后续一次移动若因体力不足、能力失效、路线失效、目标失效或权威状态变化而无法执行，导航停在最后一次已完成移动的位置。
- 无法执行的下一次移动不消耗资源、不推进游戏刻，并作为结构化的导航中断原因返回。
- 游戏规则导致的中断不回滚已经完成的移动；数据库、请求超时或进程异常属于另一类基础设施一致性问题，必须在正式代码集成设计中通过原子行动提交、幂等和结果恢复单独保证，不能伪装成游戏规则中断。

### 4.2 移动方式框架

移动方式定义：

- 最大范围和距离计算方式。
- 是否需要真实可通行路径。
- 哪些图格、墙体和连接能够阻挡。
- 最终落点的合法条件。
- 轨迹是否可以被特定机制拦截。
- 信息获取的空间足迹。
- 前端演出类型。

首期语义：

- 普通移动存在真实路径，路径会被墙体、连接和动态不可通行状态阻挡。
- 飞行、跳跃、传送等特殊移动的路径主要用于距离、方向、演出和拦截参考，不受普通路径阻挡。
- 特殊移动不会被自动导航擅自消耗。被动飞行可以自动采用，主动技能型位移必须由玩家明确授权。

### 4.3 轨迹拦截框架

轨迹存在不等于玩家逐格经过。移动提交前可以存在一次拦截窗口：

```text
计划 A → C
→ 对轨迹执行拦截判定
→ 无拦截：最终落点 C
→ 在 B 被拦截：结果改写为停在 B 或进入对应事件
→ 整体仍只推进一个游戏刻
```

B 上的普通道具、POI、潮汐和陷阱不会因为轨迹经过而逐格触发。只有 B 成为最终落点，才执行落点规则。

拦截事件的先后顺序由时间调度器研判，不由移动模块自行决定。

### 4.4 地图认知状态框架

地图至少区分：

- `currently_visible`：当前是否处于玩家有效观察范围。
- `revealed`：迷雾信息是否已经揭示。
- `explored`：玩家是否曾经实际站上该格。

`explored` 是持久、真实的空间覆盖状态，唯一成立条件是玩家曾经以最终位置站上该格。清除迷雾、从旁经过、路径预览或远程观察都不能把格子标记为已探索。

迷雾首期只启用“未揭示 / 已揭示”两档，但底层允许未来扩展认知等级。首期不设计第三档视觉和玩法。

### 4.5 地图拓扑与动态通行框架

永久背景空间与动态不可通行必须分离：

- 永远不能站立、没有独立游戏内容的位置属于背景墙、空洞或区域边界，不是图格。
- 真实图格拥有动态通行状态，可以被破坏为不可通行，也可以被修复为可通行。
- 两个真实图格之间的墙属于连接状态，不通过插入假图格表达。

因此需要分别表达：

```text
区域拓扑：哪些位置是真实图格
图格状态：该格当前是否可作为落点
连接状态：两个图格之间是否允许普通移动
```

已探索图格被破坏后仍然保持已探索。未探索图格暂时不可通行时退出当前移动候选，但不会被伪造为已探索。

### 4.6 单位占位框架

一个图格最多存在一个单位：

- 玩家与敌人不能重叠。
- 敌人与敌人不能重叠。
- 被单位占据的图格不是合法落点。

隐藏敌人不会因为占位校验被前端提前显示。自动系统寻找隐藏敌人时，目标是敌人附近的合法搜索位置；玩家手动点击了实际被隐藏敌人占据的迷雾格时，该格作为导航锚点处理，系统寻找附近合法落点。

### 4.7 统一信息获取框架

移动和探索都产生一次信息获取行为：

```text
移动 = 位移 + 一个游戏刻 + 一次基础信息获取
探索 = 原地行动 + 一个游戏刻 + 一次强化信息获取
```

信息获取行为统一处理：

- 行动场景与行动类型。
- 观察方式和作用范围。
- 地图、潮汐、玩家属性、技能和状态补正。
- 可获取的信息类别。
- 发现概率、优先级和单次信息预算。
- 注意力等级和导航中断规则。

移动和探索不再按信息种类硬拆分。探索通常拥有更高的发现概率、信息预算或范围补正，但具体数值由策划配置。

### 4.8 观察方式框架

观察方式定义：

- 作用范围和距离计算。
- 是否需要视线路径。
- 哪些地图结构和状态能够遮挡。
- 能够获取哪些信息类别。
- 概率与预算补正。
- 结果是永久认知还是临时感知。

普通视野存在视线路径并受墙体阻挡。X光、听觉或其他特殊感知可以忽略部分路径阻挡，或只发现特定信息。

多个观察方式可以叠加。主动技能必须由玩家明确使用，被动感知可以自动参与信息获取。

### 4.9 信息获取空间足迹

一次移动只进行一次信息获取，但候选范围由移动方式决定：

- 普通移动可以把真实路径沿途的观察范围合并为一次候选集合。
- 飞行可以配置空中观察走廊。
- 传送通常只使用最终落点的观察范围。
- 路径上的格子不会因此变成已探索，也不会逐格重复投骰。

主动探索使用当前位置的观察方式集合，执行一次强化信息获取。

### 4.10 行动规则过滤

不同场景可以过滤信息类别：

| 场景 | 首期允许的信息 |
|---|---|
| 探索场景移动 | 迷雾、地图、道具、POI、敌人等基础候选 |
| 主动探索 | 同类候选，但使用强化配置 |
| 战斗场景移动 | 只允许指定空间信息，例如点亮迷雾 |
| 特殊技能 | 由技能自身规则指定类别和补正 |

战斗中站上新格仍会把该格标记为已探索，但不会因为移动而弹出与战斗无关的 POI、道具或额外敌人发现提示。

### 4.11 信息显著度与保底

首期规则：

- 最终落脚格的基础地图信息和迷雾必定获得。
- POI 是醒目地标，只要进入有效信息获取范围就 100% 被发现。
- 普通道具即使位于脚下也不保证全部发现，继续执行信息概率和预算判定。
- 周围敌人执行发现概率，不享受 POI 的 100%规则。
- 单位不能重叠，因此不存在玩家站在敌人同格却仍未发现的合法状态。
- 陷阱可以作为落脚或探索事件直接触发，不要求先作为信息被发现。

### 4.12 信息注意力等级

信息结果按注意力等级处理：

- 常规信息：迷雾、地形、潮汐和普通地图变化，播放反馈但不中断导航。
- 普通道具：显示具体名称和数量，写入日志并在地图标记，不中断导航。
- 重要发现：POI、关键道具、任务道具和成功发现的敌人，中断导航。
- 强制事件：陷阱、突袭、战斗或其他时间调度事件，立即终止导航并交接场景。

同一次信息获取发现多个重要内容时合并成一个发现批次，不能连续弹出多个模态框。

## 五、自动探索与导航规则

### 5.1 高层目标与单次移动分离

自动探索任务负责“前往一个目标”，底层移动行动负责“在一个游戏刻内移动一次”。

目标位于本次移动范围内时，只执行一次移动。目标较远时，后端在同一个高层命令中提交多次原子移动；每次原子移动都由时间调度器独立结算一个完整游戏刻，并把该刻的权威结果交回导航器决定是否继续。

### 5.2 目标优先级

自动目标解析按当前可执行候选工作：

1. 优先选择当前可达、尚未探索的真实图格。
2. 没有可达未探索格时，可以处理尚未发现的 POI或尚未发现的敌人搜索位置。
3. 当前仍有未探索格但被临时障碍隔绝时，不把空间覆盖标记为完成；只是在可执行候选中暂时使用次级目标。
4. 障碍解除后，可达未探索格重新获得最高优先级。
5. 普通地面道具不进入自动探索目标池。
6. 已发现 POI永久退出自动探索目标池，不论是否已经互动。
7. 已发现敌人不是自动移动目标，需要玩家明确决定是否进入战斗。

### 5.3 空间覆盖完成后的内容搜索

当所有当前可达的未探索格均已处理后，移动按钮继续承担内容搜索入口：

- 后端可以使用隐藏数据寻找尚未发现的 POI或敌人。
- POI进入有效信息范围后必定被发现，随后退出自动目标池。
- 隐藏敌人只用于生成一个搜索位置，不向前端泄露准确位置或原因。
- 玩家抵达搜索位置后必定停止。
- 如果敌人未被发现，玩家可以主动探索，或再次点击移动生成新的搜索位置。

内容搜索不自动追加一次主动探索行动。

### 5.4 隐藏敌人的搜索位置快照

隐藏敌人会在游戏刻中移动，因此本次导航不能持续追踪敌人实体。

点击移动时，后端根据当前敌人状态生成一个固定搜索位置 C。本次任务只前往 C。敌人之后可以移动、离开、靠近或突袭。玩家抵达 C 即结束；下一次点击移动时再按新的世界状态选择新的搜索位置。

围绕隐藏敌人多次移动是可接受的世界行为，不记录额外的搜索尝试或隐藏降权。敌人的 AI、移动和突袭会自然改变结果。

### 5.5 后端可用隐藏数据，前端不提前泄露

迷雾用于提供揭示新信息的正反馈，不用于限制自动系统的决策能力。

后端可以读取迷雾后的潮汐、通行状态、POI、敌人和地图结构，以便选择目标和路线。前端只能展示玩家已经有权知道的信息：

- 未探索图格和玩家指定目标可以明确显示。
- 已知 POI可以显示名称和位置。
- 隐藏敌人搜索只显示“正在搜索可疑区域”等泛化状态。
- 已揭示区域可以显示精确路线预览。
- 迷雾区域只显示方向、虚线趋势或未知路线，不展示隐藏障碍形成的真实绕行。

### 5.6 四种首期移动倾向

移动倾向只改变目标偏好、路线倾向和默认步幅，不改变“最终覆盖所有可探索图格”的收束目标。

#### 稳健探索

- 首局默认策略。
- 默认每次移动一格。
- 只在当前可行候选、下一落点和路线覆盖之间软性偏好较低潮汐。
- 不要求扫描全区域寻找潮汐最低的目标，也不为追求绝对安全进行大范围绕行。
- 安全区域耗尽后继续进入更危险区域，只显示提示，不停止、不自动切换策略。

#### 就近探索

- 默认每次移动一格。
- 以预计移动行动次数作为主要距离指标。
- 同一行动次数内优先实际距离更近的未探索格。

#### 深入险境

- 默认每次移动一格。
- 主动选择高潮汐未探索目标。
- 允许路线包含危险落点，但危险本身不是无条件奖励。

#### 效率优先

- 默认尽量使用满移动力。
- 以减少移动行动次数为首要目标。
- 可以跳过中间未探索图格，因此可能降低连续覆盖和单面积信息获取次数。

首期不建立复杂的全局权重公式。底层保留策略配置能力，但玩家看到的是明确、可解释的预设。

### 5.7 路线风险的计算边界

移动风险只统计每次原子移动的实际落点。玩家从 A 原子移动到 D 时，几何轨迹经过的 B、C 不产生潮汐暴露；只有轨迹拦截规则可以在途中介入。

多次移动路线的风险由每个游戏刻实际落脚的图格组成。

### 5.8 玩家指定目标

玩家在局部地图或完整地图选择图格时创建临时目标：

- 目标在本次移动范围内：直接执行一次精确移动，不受自动策略一格步幅限制。
- 目标超出范围：创建远程导航，途中步幅和路线服从当前移动倾向。
- 迷雾格可以被指定。
- 实际不可落脚的迷雾格作为导航锚点，系统寻找附近合法落点。
- 导航开始后立即回到局部探索场景播放结果。

临时目标只覆盖“去哪里”，不永久覆盖玩家选择的移动倾向。

### 5.9 改路、失效与暂停

- 每次移动后可以针对同一目标重新寻路。
- 存在替代路线时自动换路，不要求玩家确认。
- 原目标失效或不再存在可达路线时中断。
- 不能在目标失效后静默改选另一个目标。
- 事件中断后，可在当前页面会话中保留目标为暂停状态，由玩家明确继续或取消。
- 暂停目标不要求跨页面刷新恢复。
- 不提供正在执行中的显式停止按钮。

### 5.10 无目标与失败是否消耗时间

- 自动目标不存在、目标非法、无路线等未形成有效移动行动的结果不推进游戏刻。
- 主动探索即使没有发现，也是一项有效行动，会推进游戏刻并承担事件风险。
- 探索按钮不能根据隐藏信息自动禁用，否则会成为探测隐藏内容的旁路。
- 前端始终保留稳定的“探索”入口，不把同一个主按钮改名为“等待”，也不要求玩家另选等待命令。
- 当玩家具备正常行动资格、探索命令已被后端接受，但领域规则判定本次探索不可执行时，后端把该命令降级为等待行动，交由时间调度器结算一个游戏刻，并返回“探索失败并等待”的结构化原因与玩家文本。
- “正常执行探索但没有发现”与“探索不可执行而等待”是两种不同结果，前端日志和反馈必须区分。
- 战斗中、角色死亡、命令门控、重复提交等请求级非法状态不能降级为等待，必须拒绝且不消耗游戏刻。

### 5.11 不自动执行的行为

自动导航永远不会：

- 自动进入战斗。
- 自动互动 POI。
- 自动拾取普通地面道具。
- 自动执行跨区域传送或出口互动。
- 自动消耗主动跳跃、传送等技能资源。
- 自动从一个探索目标继续选择下一个目标。

抵达当前目标后必定停止并交还控制。

## 六、敌人发现与战斗边界

### 6.1 敌人发现状态

沿用现有 `discovered` 语义：

- `discovered = 1` 表示敌人当前处于玩家有效认知中。
- 敌人离开视野或进入迷雾后变回 `0`。
- 完整地图上的敌人头像随之消失。
- 后续重新进入信息范围时需要重新发现。

不建立敌人的永久“已发现历史位置”标记。

### 6.2 玩家先发现敌人

信息获取成功发现敌人时：

1. 立即停止自动导航。
2. 保持在探索场景。
3. 显示敌人标记。
4. 合并本次发现的所有敌人。
5. 弹出“发现了 N 个敌对目标，对方尚未发现你”的模态框。
6. 玩家选择进入战斗预装填，或暂不行动。

模态框不要求玩家先选定一个敌人。进入现有战斗预装填后，由现有瞄准系统处理所有 `discovered = 1` 的合法目标。

### 6.3 已发现敌人与自动导航

已发现敌人是明确的战斗决策边界：

- 自动导航不能进入敌人占据的图格。
- 自动导航不能替玩家主动开战。
- 有其他路线时可以避开敌人。
- 敌人阻断唯一方向时停止并提示，由玩家明确点击敌人或进入战斗预装填。
- 深入险境只表示接受危险区域，不表示授权自动开战。

### 6.4 敌人先发现玩家

敌人突袭、拦截或其他强制事件由时间调度与敌人 AI 接管。导航在对应移动结果处终止，前端先播放已经发生的移动，再显示突袭原因并切换战斗场景。

### 6.5 战斗预装填

保留现有战斗系统：

- 玩家可以随时打开战斗预装填场景。
- 打开、装填、调整和退出不推进游戏刻。
- 可以装填任何动作。
- 提交执行时才校验动作序列是否至少有一个动作瞄准合法敌人。
- 校验失败时留在预装填，不进入正式战斗。

### 6.6 战斗移动与区域位置

战斗场景与探索场景共享同一套区域坐标：

- 战斗移动改变玩家和敌人的实际区域位置。
- 战斗中站上从未到达的真实图格，会把该格标记为已探索。
- 战斗移动触发一次信息获取，但由战斗规则过滤可获得的信息类别。
- 战斗结束后，探索场景以战后最终位置重建局部视野。
- 暂停目标若仍保留，必须从战后位置重新寻路，不能自动恢复移动。

## 七、三场景视觉与操作设计

### 7.1 场景所有权

三个玩家场景为：

- 探索场景。
- 完整地图场景。
- 战斗场景。

探索与战斗是中央工作区的互斥场景。完整地图采用全屏模态场景：视觉上像展开一卷大地图，交互上冻结下方探索场景并接管输入。

全应用只有一个顶栏所有者，按场景切换内容，不在各场景内部重复状态栏。

### 7.2 探索场景

#### 地图

- 只渲染当前视野覆盖的局部地图。
- 视野之外的图格不进入当前舞台，不以完整区域迷雾铺满屏幕。
- 玩家保持局部视野的视觉中心。
- 离开视野的历史信息需要进入完整地图查看。
- 继续使用现有角色移动动画、缩放、平移和地图实体表现能力。

#### 桌面布局

- 保留正式前端当前地图左、日志与动作右的工作台关系。
- 左侧以局部视野地图为主体。
- 右侧继续承载现有通用日志和当前格情境操作。
- 移动、探索和移动倾向组成始终可见的主操作区。
- 拾取、POI、合成和区域动作保留为独立情境操作区。
- 属性与背包继续使用现有抽屉，但响应式降级应依据工作区容器宽度，而不是只看浏览器宽度。

#### 手机横屏布局

- 主设计基准为横屏，例如 `844×390`。
- 地图占左侧主要区域。
- 右侧紧凑承载日志和当前格信息，可通过标签切换。
- 主操作区固定在底部安全区，并控制高度。
- 属性与背包使用覆盖式抽屉。
- 竖屏不承载正式游戏操作，只显示简洁的旋转设备提示。

### 7.3 主操作区

主操作区始终显示：

- 移动。
- 探索。
- 当前移动倾向。
- 当前临时目标或暂停目标状态。

玩家属性如视野、移动力继续放在属性面板，不占用场景顶栏。

正在等待后端导航结果时显示处理中状态。移动导演播放期间锁定会改变游戏状态的操作，但始终允许加速或跳过演出。属性、背包和日志等界面可以继续查看；其中任何会改变游戏状态的操作仍受统一命令门控约束。

“探索”按钮保持稳定标签。实际完成探索时播放扫描演出；后端降级为等待时不伪装成成功扫描，只显示简短等待反馈和明确的失败原因。

### 7.4 主动探索占位演出

首期只提供简单扫描演出：

- 玩家标记短暂亮起。
- 一层简洁波纹覆盖本次信息获取空间足迹。
- 动画短、可加速、可跳过。
- 不为普通视野、X光等制作复杂独立特效。
- 未来有角色素材后，可以直接替换为小人搜索动画。

演出与信息结算解耦，不能让占位动画成为业务状态来源。

### 7.5 完整地图全屏模态场景

#### 共通规则

- 显示当前区域内所有真实图格。
- 支持任意区域尺寸和极端长宽比地图，打开时根据可用工作区自动完成初始适配，不依赖固定图格尺寸或固定区域边界。
- 提供缩放、拖动、定位玩家、定位当前临时目标和恢复初始适配等地图工具。
- 迷雾图格显示位置和轮廓，但隐藏潮汐、地形细节、道具、POI和敌人。
- 已揭示但未探索格显示已知地图信息，并明确仍未到达。
- 已探索格显示完整已知信息。
- 玩家位置始终显示。
- 只显示当前 `discovered = 1` 的敌人。
- 显示已经发现的 POI和普通地面道具。
- 不显示正式探索百分比。空间覆盖、迷雾比例、候选目标和策略评分只在 debug 模式显示。

#### 桌面

- 地图接近铺满工作区，保留少量边缘暗示下方探索场景。
- 地图为主区，右侧为图格详情与目标操作。
- 悬停显示已知摘要，点击图格立即执行“前往此处”。

#### 手机横屏

- 延用地图主区 + 右侧详情栏。
- 点击图格先选中并显示详情，再点击详情区的“前往”。
- 不使用竖屏底部详情面板作为主设计。

#### 目标与路线

- 图格在一次移动范围内时执行精确移动。
- 图格较远时创建临时目标并按当前移动倾向导航。
- 选择目标后立即关闭完整地图，回到局部探索场景播放结果。
- 已知地图可显示精确路线；迷雾部分只显示方向或未知路线。
- 提供当前路线显示开关。预览路线在取消选择、目标失效或提交导航后清除，不能残留为仍然有效的路线。
- 导航完成后的实际路线可以作为独立历史图层显示，但必须可单独关闭或清除，且不能与当前目标路线混淆。

### 7.6 战斗场景

- 战斗场景替换整个中央工作区，不只替换右侧动作区。
- 左侧使用现有区域地图的战斗呈现。
- 右侧完整保留现有动作预装填、瞄准、参战者信息和执行反馈。
- 隐藏探索场景的移动、探索、完整地图和当前格操作。
- 战斗横幅、模态框、伤害数字和 AimMode 继续由现有战斗导演负责。
- 桌面与手机横屏都采用地图主区 + 战斗操作区。
- 战斗结束后回到以权威战后位置重建的局部探索地图。

### 7.7 顶栏与日志

#### 单一顶栏

- 探索场景显示位置、玩家基础状态和全局入口。
- 完整地图场景显示区域、返回、地图工具和当前目标。
- 战斗场景显示战斗阶段、行动者、AP和战斗状态。

#### 日志所有权

- 探索场景显示现有通用日志。
- 每次原子移动继续逐条记录“从 XX 移动到 XX”，不合并。
- 战斗场景只显示现有战斗战报与反馈，不复制探索日志。
- 完整地图不复制日志，只显示图格详情。
- 加速或跳过动画不能丢失日志条目。

### 7.8 发现反馈

保留现有迷雾变化和探索钩子文本，新增“发现了什么”的明确反馈：

- 普通道具：短提示或日志显示具体名称和数量，不弹模态框。
- POI：首次发现时进入重要发现模态框。
- 关键、任务或高价值道具：进入重要发现模态框。
- 敌人：批量合并为敌人发现模态框。
- 同一次信息获取发现多个重要内容时合并为一个“本次发现”模态框。
- 已发现内容不会重复弹首次发现模态框。

POI或关键道具模态框可以提供“一键前往”。该操作只创建临时目标，不自动互动或拾取。

## 八、移动导演与演出协议

### 8.1 后端一次返回多次移动结果

前端不循环发送单次移动请求。一次高层导航命令由后端完成目标选择、逐次移动、逐游戏刻判定和中断判断，并返回按顺序排列的移动结果。

示意结果：

```text
移动 1：A → B，游戏刻 +1，普通信息
移动 2：B → C，游戏刻 +1，清除迷雾
移动 3：C → D，发现敌人，导航中断
最终权威位置：D
```

后端发送领域事实和顺序，不发送具体 CSS 动画指令。

### 8.2 前端移动导演

移动导演负责：

- 逐次播放现有玩家移动动画。
- 在每个落点更新局部视野和迷雾表现。
- 按顺序写入现有日志。
- 播放普通发现、重要发现和强制事件反馈。
- 在最后一帧把可见状态收敛到权威最终状态。
- 将强制战斗结果交给战斗导演。

### 8.3 播放速度

玩家可以配置：

- 正常播放。
- 加速播放。
- 跳过普通移动演出。

刷新页面等同于跳过未完成演出，直接读取最终权威状态。重要发现、强制事件和战斗切换不能被静默丢弃；即使跳过移动动画，也必须明确显示最终原因。

### 8.4 输入门控

移动导演播放时，前端显示的地图位置可能落后于后端权威位置，因此必须阻止新的移动、探索和目标命令。玩家可以加速或跳过，使演出立即追上权威状态后恢复输入。

该门控应优先复用现有 `K-3` 命令门控和 `K-7` 视觉状态过渡原则，不建立第二套互相冲突的锁。

### 8.5 移动到战斗的场景交接

后端导航结果中出现突袭或强制战斗时：

1. 前端先播放已经发生的移动。
2. 在实际遭遇位置显示突袭或中断原因。
3. 切换战斗场景。
4. 由战斗导演继续消费战斗演出结果。

玩家选择跳过时，直接同步到遭遇位置，以简短摘要解释途中发生的事件，再进入战斗。

## 九、跨层契约原则

### 9.1 后端权威

后端负责：

- 使用隐藏地图真值选择目标和路线。
- 计算移动方式、观察方式、占位和通行合法性。
- 按时间调度器顺序执行每次移动。
- 执行信息获取和事件判定。
- 判断抵达、中断、无目标和无路线。
- 返回逐次领域结果和最终权威状态。

前端不能根据本地迷雾投影自行决定真正可达目标，也不能自行循环提交动作来模拟后端导航。

### 9.2 时间调度器所有权

移动模块只声明移动意图和执行结果，不能自行规定玩家移动、敌人行动、地图坍塌、拦截和其他事件的绝对顺序。

时间调度器负责研判同一游戏刻内事件顺序，并在轮到移动时提供当时的权威地图状态。

### 9.3 前端渲染权

前端负责：

- 三场景视觉所有权。
- 玩家可见的信息权限。
- 移动和探索演出。
- 日志、Toast、发现模态和战斗交接。
- 加速、跳过和输入门控。
- 桌面与手机横屏布局。

后端只发送结构化领域结果，不决定模态框尺寸、动画样式或文本排版。

### 9.4 刷新与一致性

导航属于一个后端高层命令，不在前端保存可恢复的执行循环。页面刷新后：

- 读取最后已提交的权威位置和世界状态。
- 不恢复未播完的移动动画。
- 不要求恢复临时目标或暂停目标。
- 不补播已经错过的瞬态演出。

高层导航命令在 PHP 请求中如何保证事务、幂等、超时和刷新一致性，属于正式代码集成设计的必查项。

## 十、边界案例矩阵

| 场景 | 预期行为 |
|---|---|
| 点击移动但没有任何可执行目标 | 不推进游戏刻，提示当前没有自动目标 |
| 仍有未探索格但暂时全部不可达 | 不宣告空间完成；可以处理可达次级目标 |
| 探索没有发现 | 推进一个游戏刻，记录没有新的发现 |
| 探索领域规则判定不可执行 | 同一探索命令降级为等待，推进一个游戏刻并返回“探索失败并等待”的原因 |
| 探索请求被命令门控拒绝 | 不降级为等待，不推进游戏刻 |
| 安全区域已覆盖 | 稳健策略继续工作，提示接下来会进入更危险区域 |
| 所有真实图格已站上 | 自动目标转为尚未发现的 POI和敌人搜索位置 |
| POI被发现但未互动 | 永久退出自动探索目标池，留给玩家手动处理 |
| 普通道具被发现但未拾取 | 不进入自动目标池，完整地图保留已知位置 |
| 隐藏敌人移动 | 本次只前往创建命令时的搜索位置，不持续追踪实体 |
| 发现多个敌人 | 合并提示，一次进入战斗预装填 |
| 玩家拒绝进入战斗 | 敌人保持当前 discovered 状态，自动导航停止 |
| 已发现敌人挡路 | 自动导航不主动开战；无替代路线时停止 |
| 目标路线被世界变化阻断 | 对同一目标重新寻路；无替代路线则中断 |
| 目标本身失效 | 中断，不静默改选目标 |
| 多次移动在完成若干次后无法继续 | 保留已完成移动和游戏刻，停在最后权威位置；未执行的下一次移动不计费、不推进时间 |
| 多次移动发生请求或持久化异常 | 不作为普通导航失败处理；按集成设计的一致性和幂等协议恢复可确认的权威结果 |
| 目标是隐藏不可落脚格 | 作为导航锚点，选择附近合法落点 |
| 普通移动路径有障碍 | 目标不可达或改路；中间格不产生事件 |
| 特殊移动越过障碍 | 按移动方式规则允许，但最终落点仍需合法 |
| 轨迹被拦截 | 结果改写为拦截位置或事件，整次仍只推进一个游戏刻 |
| 战斗移动进入新格 | 标记已探索，只获取战斗规则允许的信息 |
| 打开完整地图 | 不推进游戏刻，冻结探索输入 |
| 完整地图选择目标 | 关闭完整地图，回到局部探索播放导航 |
| 玩家刷新页面 | 跳过未播完演出，加载最终权威状态 |
| 手机竖屏 | 显示旋转设备提示，不进入正式游戏布局 |

## 十一、前后端任务拆分

### 11.1 后端任务

- 为真实图格增加持久 `explored` 语义，确保只有最终落脚能够写入。
- 区分区域拓扑、动态通行状态和连接状态。
- 抽象移动方式和观察方式。
- 建立统一信息获取入口，修订 E-3/E-6/E-7 的固定分工。
- 实现首期行动规则过滤、POI显著度、道具概率与敌人发现规则。
- 实现自动目标解析和四种移动倾向配置。
- 实现隐藏 POI、隐藏敌人搜索位置和玩家临时目标。
- 实现后端多移动导航编排与逐游戏刻中断判断。
- 实现探索不可执行时降级等待的领域规则，并与正常探索无发现、请求级拒绝明确区分。
- 输出逐次移动、信息批次、探索或等待结果、中断原因和最终状态。
- 接入现有时间调度、敌人 AI、战斗触发、命令总线与幂等协议。
- 为 debug 模式输出候选目标、策略选择、路线、观察范围和信息判定证据。

### 11.2 前端任务

- 在正式 `App.vue` 工作台内引入探索、完整地图和战斗场景所有权。
- 把正式地图改为局部视野投影，同时保留现有地图实体、动画、缩放和平移能力。
- 新增固定主操作区：移动、探索、移动倾向和临时目标状态。
- 保持“探索”按钮标签和操作语义稳定，分别呈现正常探索、无发现、降级等待与请求拒绝反馈。
- 保留并重新编排 `TileActionBar` 的道具、POI、合成和区域动作。
- 实现完整地图全屏模态场景。
- 实现移动导演、播放速度、跳过和输入门控。
- 扩展日志与发现反馈，不合并原子移动日志。
- 实现 POI、关键道具和敌人的合并发现模态框。
- 将现有战斗模式提升为完整中央工作区场景。
- 实现桌面与手机横屏布局，以及竖屏旋转提示。
- 实现 debug 视觉覆盖层，但不把探索进度放入正式玩家界面。

### 11.3 跨层共同任务

- 高层导航命令的请求与响应契约。
- 每次移动结果、信息结果和中断结果的顺序身份。
- 探索结果、等待降级原因、玩家文本和是否消耗游戏刻的结构化契约。
- 导航结果与现有 presentation 批次的整合方式。
- 权威地图刷新与移动导演演出投影的重基准。
- 战斗触发时移动导演与战斗导演的交接协议。
- 页面刷新、重复提交、PHP 请求超时与事务一致性。
- 命令门控在探索演出和战斗演出中的统一语义。

### 11.4 不应拆给前端的任务

- 根据迷雾后的真值选择目标。
- 计算真正通行路线和移动方式合法性。
- 循环发送单次移动请求来驱动自动导航。
- 根据本地动画状态推断游戏刻或最终位置。
- 根据按钮是否可用推断隐藏信息。

## 十二、推荐执行阶段

### 阶段 1：设计冻结

交付本设计案，确认玩家路径、机制不变量、三场景关系和策略语义。不得接 API、不得修改生产状态。

使用 `oblivions-compass` 重新映射：

- B-1/B-2/B-3 命令管道。

## 十三、验收标准

### 13.1 连续自动移动

1. 玩家选择移动倾向。
2. 点击一次移动。
3. 后端选择一个目标。
4. 目标较远时执行多次移动和多次游戏刻判定。
5. 前端逐次播放移动、迷雾和日志。
6. 抵达目标后停止。
7. 玩家再次点击才选择下一个目标。
8. 后续移动因体力、能力、路线或目标变化无法执行时，保留此前已完成的移动与游戏刻，在最后权威位置停止并显示原因。
9. 未执行的下一次移动不扣资源、不推进游戏刻，整个高层命令不回滚已完成结果。

### 13.2 主动探索

1. 玩家点击探索。
2. 后端向时间调度器提交一次探索行动，由时间调度器按权威顺序完成本游戏刻并返回结果。
3. 正常探索时执行一次强化信息获取并播放简单扫描占位演出。
4. 普通结果进入地图和日志，重要结果进入合并模态框。
5. 正常探索但无发现时明确记录，不弹空模态框。
6. 领域规则判定探索不可执行时，同一命令结算为等待，明确显示“探索失败并等待”的原因，不播放成功扫描演出。
7. 请求级非法状态直接拒绝，不消耗游戏刻。

### 13.3 局部地图与完整地图

1. 探索场景只显示当前视野。
2. 打开完整地图后显示整个区域和迷雾状态。
3. 桌面悬停查看，点击直接前往。
4. 手机横屏点击选中，再确认前往。
5. 选择目标后立即返回局部探索场景。
6. 迷雾路线不泄露隐藏障碍。
7. 任意区域尺寸打开后自动适配，极端长宽比地图仍可完整浏览。
8. 缩放、拖动、定位玩家、定位当前目标和恢复初始适配均可用。
9. 当前路线可以显示和关闭；取消、失效或提交目标后不残留过期预览，历史路线可独立清除。

### 13.4 POI与道具

1. POI进入信息范围后必定发现。
2. 首次发现弹合并模态框。
3. 已发现 POI不再成为自动目标。
4. 普通道具显示具体名称，但不打断、不自动导航、不自动拾取。
5. 关键道具可以打断并提供一键前往。

### 13.5 敌人与战斗

1. 隐藏敌人可以影响后端搜索位置，但不向前端泄露。
2. 发现敌人后停止导航并批量提示。
3. 玩家可以进入现有战斗预装填或暂不行动。
4. 自动移动不会主动开战。
5. 敌人突袭时先播放移动原因，再进入战斗场景。
6. 战斗移动改变区域真实位置。
7. 战后以最终位置返回探索场景。

### 13.6 演出和刷新

1. 移动导演支持正常、加速和跳过。
2. 演出期间行动输入被门控。
3. 跳过不能丢失日志、重要发现或战斗结果。
4. 刷新后直接显示最终权威状态，不恢复旧动画。

### 13.7 视觉质量

- 不出现重复顶栏、重复日志或重复动作入口。
- 地图是探索场景的主要视觉对象。
- 完整地图不是锁在小框中的缩略图。
- 战斗场景不保留探索主操作。
- 桌面 `1440×900`、手机横屏 `844×390` 以及更窄的受支持横屏尺寸均无内容裁切、文字溢出或关键操作不可达。
- 桌面分别覆盖属性抽屉打开、背包抽屉打开和双抽屉同时打开的边界状态；工作区按实际容器宽度正确降级。
- 长位置名、长日志、长失败原因和多个发现结果不会撑破布局或遮挡操作。
- 手机横屏中的地图详情、发现结果和战斗动作区可以完整滚动，关键提交操作始终可触达。
- 竖屏只显示旋转提示。
- 灰阶、细线、形状、纹理和现有终端视觉语言保持统一。

## 十四、风险与正式代码设计必查项

以下问题不由本设计案凭空决定，必须在代码集成设计阶段以源代码和时间调度器为准：

- 高层导航命令如何在 PHP 请求中执行多次游戏刻而不破坏现有命令总线。
- 导航请求在页面刷新、客户端断开、超时和重复提交时的事务与幂等语义。
- 现有 `map.move` 是扩展、保留为精确移动，还是新增独立高层命令。
- 时间调度器如何向导航循环返回“继续 / 中断 / 进入战斗”等领域结果。
- 逐次移动结果如何进入现有 presentation 批次并被 `K-9` 有序消费。
- `K-7` 当前战斗视觉过渡机是否扩展为通用演出场景，还是新增受同一门控管理的移动演出会话。
- 当前地图投影是否能同时支持局部视野投影和完整区域投影。
- 动态通行状态、连接状态、单位占位和移动方式如何进入统一空间决策。
- 战斗移动写入 `explored` 后，地图与视野投影如何原子刷新。
- 大区域、效率优先和远程目标的最坏导航步数是否会造成 PHP 请求超时或过大 presentation 响应。

任何一项若无法在现有框架内安全实现，应先修订正式代码集成设计，不得把循环或权威判断临时推给视觉 Demo。

## 十五、最终原则

本改造的核心不是增加一个自动寻路按钮，而是建立一套以玩家注意力和世界时间为基准的探索框架：

- 自动系统代替重复操作，不代替玩家决策。
- 移动和探索都提供发现反馈，但主动探索更有效率。
- 每个游戏刻只有一次权威移动状态，每次移动只有一个最终落点。
- 后端可以利用隐藏世界引路，前端只展示玩家有权知道的信息。
- 所有策略最终收束到区域覆盖，但首期规则必须简单、可解释。
- 正式前端是生产宿主，Demo只验证视觉，不承载真实功能迁移。
- 后端负责领域事实，前端负责玩家理解这些事实的方式。
