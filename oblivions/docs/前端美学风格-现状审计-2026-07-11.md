# Oblivions 前端美学风格现状审计

> 审计日期：2026-07-11  
> 范围：`oblivions/docs/前端美学风格-设计案.md`、`oblivions/docs/demos/`、当前 `vex-vue` 源码与本地运行态页面。  
> 性质：只读调研，不包含实现修改。

## 一、结论摘要

当前前端已经形成稳定的灰阶 ASCII 终端底盘，地图角色也采用真实 PNG 立绘和 GSAP 位姿动画，基础方向与“剪纸舞台 + ASCII 终端”一致。但最新美学设计案不是仅要求“整体看起来偏黑白”，而是确立了更严格的框架基准：**黑白单色、形状优先、立绘 popUp 作为唯一瞬时反馈机制、全动画 reduced-motion 兜底**。

按这个基准，当前实现存在四类关键偏差：

1. 战斗主视觉仍大量使用红色传统 VFX，包括全屏红光、红色弹丸、红色扩散爆炸和红色瞄准 HUD，直接违反核心禁令。
2. 设计案列入 P0 的地图纹理、信号色清理和天穹层尚未完成，“黑白漫画”和环境剪纸舞台两层基本缺席。
3. 战斗弹窗、HP、伤害数字等仍采用红/蓝/绿/黄语义色，形成与普通终端 UI 不同的第二套视觉语言。
4. 除合成弹窗外，循环动画、GSAP Actor 动画与战斗演出普遍没有 `prefers-reduced-motion` 降级。

因此，现状不能判定为“符合设计案，只差美术资源”；更准确的判断是：**基础 UI 风格已经对齐约六成，但战斗反馈框架和设计案相冲突，环境表现层尚未落地。**

## 二、审计基准

本次以设计案中的以下硬约束作为判定标准：

- 三层语言：剪纸舞台、ASCII 终端、黑白漫画（设计案 §1.1）。
- 禁用彩色粒子、彩色震波、屏幕变色、全屏瞬时 overlay、残影、sprite 帧序列和 CRT 扫描线（§1.2）。
- 所有瞬时反馈统一为黑白单张立绘 popUp（§1.2、§4.3、§4.6）。
- 所有动画必须提供 reduced-motion，循环或闪烁频率不得超过 3Hz（§1.4）。
- 不引入彩色信号色，信息通过灰阶、形状、纹理、位置冗余编码（§6）。
- demo 的融合方案作为控件层次参考：细线 ASCII 骨架、灰阶硬投影、堆叠纸片层次、明确的按钮 hover/active 状态，不使用反色 hover、粗重边框或不规则圆角。

## 三、严重不符合项

### 3.1 P0：远程弹丸与爆炸仍是彩色 DOM VFX

`vex-vue/src/stores/battle-overlay-executor.ts:9-39` 以 DOM 几何体创建红色发光弹丸和红色圆形扩散爆炸；`vex-vue/src/stores/battle-actor-executor.ts:124-138` 在真实 delivery 流程中调用它们。

这同时违反“禁用彩色粒子/震波”“禁用 overlay 扩散”和“瞬时反馈只能使用单张黑白立绘 popUp”三项硬约束。它不是局部配色问题，而是战斗反馈机制仍属于传统网页 VFX，与设计案要求的 illustration popup executor 方向相反。

建议优先删除几何弹丸/扩散圆环。需要保留投射过程时，使用单张黑白弹道或投射物立绘做位移；命中使用 `hit-impact` / `critical-impact` 单图 popUp。

### 3.2 P0：战斗状态使用全屏红光和地图整体滤镜

`vex-vue/src/App.vue:61-62,143-149` 在战斗态挂载 `.battle-active`；`vex-vue/src/assets/styles/battle.css:16-38` 绘制 fixed 全屏红色脉冲边框；同文件 `:429-432` 对地图施加整体色调/饱和度/亮度滤镜。

这使战斗持续态依赖红色编码，并造成全屏视觉状态变化，压过黑白终端和剪纸角色。建议改为灰阶形状编码，例如固定双线、断裂边框或明确的 `[BATTLE]` 状态构件；进入战斗的瞬时强调应交给黑白场景立绘 popUp，而不是持续红光。

### 3.3 P0：战斗瞄准系统仍是红/黄战术 HUD

`vex-vue/src/components/battle/AimMode.vue:556-571` 使用红色路径、端点、目标框和红光；`:579-583` 用黄色表示越界；`:621-624` 用红色表示 focused。`vex-vue/src/assets/styles/battle.css:379-424` 还有一套重复的全局规则。

瞄准本身已有实线、虚线、点线和暗遮罩等形状冗余，这是可保留的正确基础；问题是颜色仍成为最强信号。建议统一为：可选目标白色实线 + 十字准星，越界灰色虚线，阻挡点线 + 暗遮罩，focused 加粗或增加角标。

### 3.4 P0：全局 reduced-motion 策略缺失

全仓 `vex-vue/src` 只有 `components/craft/CraftModal.vue:765` 提供 `prefers-reduced-motion`。Actor 永久 idle 位于 `animations/actorAnimations.ts:25-35`，移动、跳跃、到达、受击、攻击位于 `:73-227`；战斗边框、HP blink、地图 pulse/glitch、伤害数字和抽屉过渡都没有统一降级。

现有循环频率大多没有超过 3Hz，但“低于 3Hz”和“允许用户关闭动画”是两条独立要求。建议建立统一 motion policy：CSS media 关闭 infinite 动画和 dash；JS `matchMedia` 让 GSAP 降级为立即 set 或极短淡入。

## 四、设计案 P0 尚未落地

### 4.1 地图黑白漫画纹理缺失

设计案 §2 和 demo 已定义 water、vegetation、metal、magic、abyss 的纹理规则。当前 `vex-vue/src/assets/styles/terminal.css:299-305` 仅实现 tide-deep glitch 与 metal 边框；仓库不存在 `textures.css`，`vex-vue/src/main.ts:5-7` 也没有纹理样式导入。

结果是“三层叠加”中的黑白漫画层没有进入真实地图，floor/tide 语义主要仍停留在数据层。应按设计案使用低对比 CSS 渐变纹理，不使用位图平铺。

### 4.2 正式界面的信号色清理不完整

- `vex-vue/src/assets/styles/terminal.css:277-280`：blocked 使用红色。
- `terminal.css:307-310`：safe-zone 使用绿色。
- `terminal.css:716-723`：状态效果 chip 使用暗黄。
- `terminal.css:767-773`：NPC pending 使用暗黄。
- `terminal.css:211-214`：NPC/敌人仍使用红色描边。

设计案和融合 demo 已给出替代语法：blocked 用灰阶双线 + `x` 形标记，safe-zone 用白色虚线 + 菱形，pending 用白色脉冲。NPC 红描边属于设计案明确记录的待 demo 决策点，可作为暂时例外；其余三项应视为未完成的 P0 清理。

### 4.3 天穹层完全缺失

`vex-vue/src/App.vue:142-172` 没有 SkyLayer，`src` 内也没有 `sky-layer` / `SkyLayer` 实现。当前剪纸舞台语言只存在于角色立绘，没有扩展到环境和第一幕的日常、异常、揭星叙事阶段。

这属于规划缺口，不是现有功能回归，但它会阻止设计案所描述的完整美术风格成立。实现时应置于地图外的背景层，`pointer-events:none`，并同时提供 reduced-motion。

## 五、中等偏差

### 5.1 战斗弹窗形成独立的彩色 UI 体系

`vex-vue/src/assets/styles/battle.css:67-75` 使用红边红光；`:120-149` 使用敌红、玩家蓝、HP 绿/红；`:204-206` 使用黄/红日志色。

普通日志已经在 `terminal.css:408-424` 正确降级为灰阶、字重和下划线，战斗弹窗却绕开了这套规则。建议角色双方通过左右位置和对齐区分，HP 使用灰阶亮度/纹理，战斗日志复用普通日志语义样式。

### 5.2 伤害数字承担了彩色特效角色

`vex-vue/src/components/battle/DamageNumber.vue:67-110,149-163` 在战斗弹窗关闭后显示 2 秒残留数字；其颜色和动画位于 `battle.css:245-310`，伤害为红、治疗为绿。

数字作为精确数值信息可以保留，但应改为白/灰，并通过 `-` / `+`、字重、边框形状区分伤害和治疗。冲击感应由与 `impactAt` 同步的黑白图标立绘承担，数字不应成为第二套 VFX。

### 5.3 弹层、Toast、Drawer 的剪纸层次不足

融合 demo 为 Modal、Toast、Drawer 定义了灰阶硬投影、堆叠纸片边缘和侧边结构。当前 `terminal.css:831-839,936-949,966-1006` 主要还是细边框、轻发光和 translate，视觉上只有 ASCII 终端层，没有明显的剪纸容器层次。

这不是硬性违规，但会让“剪纸舞台 + 终端”的融合只发生在地图角色，不发生在 UI 层级。建议将 demo 的硬投影和堆叠边缘抽为通用弹层样式，继续保持直角、灰阶和细线框。

### 5.4 按钮主次与按压反馈弱于融合 demo

`terminal.css:372-398` 的 hover 主要改变背景，active 仅降低 opacity；`components/actions/TileActionBar.vue:232-260` 的等待、探索、合成视觉权重接近。

建议补齐 primary 变体、`focus-visible`、active 下压和 inset shadow，并按动作优先级分层。该问题影响操作扫读和手感，但不破坏核心黑白基调。

### 5.5 窄屏布局依赖强制压缩，存在裁切风险

`vex-vue/src/App.vue:143-156` 的根节点和 main 均为固定视口高度 + `overflow-hidden`；`terminal.css:1060-1066` 在窄屏只把主区改成两行，没有打开页面纵向滚动。

运行态在 390x844 下能够显示地图、日志和动作区，但各区高度被明显压缩；较矮视口或内容扩张时，第二行没有页面级滚动兜底。建议明确移动端策略：页面纵向滚动，或为两行使用稳定的 `minmax()` 并保证各面板内部可滚动。

## 六、较低优先级缺口

- `components/actions/TileActionBar.vue:308-313` 使用 Unicode 星形 `✦` 表示机制效果。它通常不是彩色 emoji，但平台字形不可控，也没有遵循图标立绘语言。可改为 ASCII `[FX]` 或真正的黑白图标 popUp。
- `animations/actorAnimations.ts:25-35` 的所有角色共用同一 idle 呼吸，尚未实现设计案 §7.3 的角色动画签名。建议将 signature 放入 actor visual profile，而不是在动画函数中按角色硬编码。
- `src/assets/illustrations/icons/` 下尚无 hit、muzzle、critical 等完整素材/API。它是核心表现缺口，但设计文档仍将部分内容标为规划中，不能简单归类为历史回归。

## 七、符合设计案的部分

- Actor 的移动、攻击、受击、倒地直接作用真实立绘 pose/action 层，没有半透明 clone 残影，也没有 sprite 帧序列：`animations/actorAnimations.ts:73-227`。
- 近战在 impact cue 后触发受击，AOE 可同时触发多目标 hit，演出时序结构清晰：`stores/battle-actor-executor.ts:209-270`。
- 长距离到达使用 alpha + scale 的 `arriveAnim`，符合区域切换语言：`actorAnimations.ts:144-154`。
- 死亡 fall 和逃离 fade 都是立绘本体变化，不依赖彩色特效：`actorAnimations.ts:57-70,157-164`。
- 普通日志已把历史颜色类映射为灰阶、字重和下划线：`assets/styles/terminal.css:408-424`。
- 地图、背包、装备和状态区保持紧凑、直角、等宽字体和灰阶细边框，ASCII 终端底盘稳定。
- CRT 扫描线确已移除，只保留静态暗角：`terminal.css:24-34`。
- 瞄准交互除颜色问题外，已有实线/虚线/点线、cursor、亮度和菜单状态等冗余编码，键盘操作也完整。
- BattleModal 的黑幕是缓慢过渡，不是瞬时闪屏，属于设计案允许的场景过渡边界：`battle.css:44-65`。

## 八、建议整改顺序

1. **先修框架冲突**：移除红色 DOM 弹丸/爆炸、全屏红光和地图滤镜，建立 illustration popup executor。
2. **统一战斗 UI**：瞄准、BattleModal、HP、日志、伤害数字全部回归灰阶 + 形状语义。
3. **建立 motion policy**：CSS 与 GSAP 共用 reduced-motion 决策，覆盖所有 infinite 和主要过渡。
4. **完成设计案 P0**：textures.css、blocked/safe/pending 灰阶化、SkyLayer 骨架。
5. **吸收 demo 的容器与按钮层次**：硬投影、纸片堆叠、primary/active/focus 状态。
6. **再扩展角色性格和叙事素材**：动画签名、状态立绘、天穹消解、关键场景插画。

## 九、最终判断

当前最值得保留的是 ASCII 终端信息架构、真实立绘 Actor 系统和 impact cue 编排；最需要停止继续扩展的是红色 CSS/DOM 战斗 VFX。后续如果继续在现有 `battle.css` 上增加弹丸、爆炸、发光和全屏滤镜，会让实现离设计案越来越远。正确的框架基准应是：**UI 负责灰阶信息，Actor 负责位姿，所有瞬时冲击统一进入黑白立绘 popUp 管线。**
