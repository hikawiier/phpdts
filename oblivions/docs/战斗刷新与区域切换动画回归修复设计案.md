# 战斗刷新与区域切换动画回归修复设计案

## 一、取消命中纸片实验

撤销空手攻击 illustration popup 实验，包括 Actor effects 层、popup executor、hit command 素材参数和战斗执行器接线。素材文件保留在 `public/img/temp`，不参与运行时。

普通 `hitAnim` 保持现状，后续重新设计命中反馈时再建立新方案。

## 二、战斗刷新后玩家不可见

### 根因

Actor 首次 enter 使用 `pose + visibility` world lease；刷新恢复战斗时 `battle-start` 使用更高优先级 battle pose lease。两者时序接近时，battle-start 会抢断 enter 的整个 lease，但自身不恢复 visibility，`.actor-visibility` 因默认 `opacity:0` 永久不可见。

### 修复

战斗形态切换统一申请 `pose + visibility`，并在播放形态翻转的同时执行 `reset-visible`。即使首次 enter 被抢断，战斗恢复也能显式建立“玩家必须可见”的稳定状态。

已处于目标形态时也执行 `reset-visible`，不能只恢复 idle。

## 三、战斗刷新后无法选择空手攻击目标

### 根因

首次主动进入战斗会调用 `loadCombatTargets()`；页面刷新后的 `refreshBattle()` 只刷新 `player_info`、恢复 `combat_context/currentQid`，没有重新加载 `combat_targets`。AimMode 要求 targets.qid 与 currentQid 一致且候选存在，因此所有敌人均不可选。

### 修复

`refreshBattle()` 在 `enterBattleMode()` 完成 qid 恢复后显式 `await loadCombatTargets()`，再开放玩家操作和播放后续演出。目标列表始终以当前 qid 的后端响应重建。

## 四、区域切换错误播放鸭子步

### 根因

实体投影更新只比较新旧 tile 是否相同，随后按新旧屏幕坐标距离选择 duck/jump/long。跨区域后新入口可能在屏幕上离旧出口很近，于是被误判为 duck。

### 修复

实体更新首先比较 `previousEntity.pgroup` 与 `entity.pgroup`：

- pgroup 不同：立即投影到新区域 anchor，播放 `ActorCommand.arrive`。
- pgroup 相同、pls 不同：继续使用 duck/jump/long 距离分级。

区域语义优先于屏幕几何距离，`arriveAnim` 继续使用 alpha 0->1 与 scale 0.3->1 的专属淡入弹起。

## 五、验证

1. 战斗中刷新后玩家 Actor 可见，并显示战斗形态立绘。
2. 刷新后 `combatTargets.qid === currentQid`，空手攻击可进入瞄准并选中敌人。
3. 同区域相邻移动仍为 duck。
4. pgroup 变化无论屏幕距离多近都播放 arrive。
5. 前端类型检查、导演/Actor fixture 与生产构建通过。
