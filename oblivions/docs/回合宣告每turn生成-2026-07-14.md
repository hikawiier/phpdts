# 回合宣告每 turn 生成设计案

> **目标**：让每个 turn 段都有独立的轮次开场宣告（"第 N 轮 - xx 的回合"），第一个 turn 的宣告自然承担战斗开始的视觉仪式。
>
> **关联文档**：
> - [Dian.md K-1 框架](../Dian.md#框架-k-1战斗回合编排--演示播放管道)（轮次开场 → 回合演出的阶段切片模型）
> - [战斗横幅组件设计案-2026-07-14.md](战斗横幅组件设计案-2026-07-14.md)（已实施完成）
> - [战斗横幅样式优化-2026-07-14.md](战斗横幅样式优化-2026-07-14.md) §6（已实施 round_intro 段附加 actor，本方案改其生成逻辑）

## 一、问题

### 1.1 现状

`round_intro` 段当前在 `directV2` 中由 `round_start` 事件生成，每轮 1 个，actor 取自 `payload.rolls[0]`（先攻掷骰第一名 = 第一个行动者）。

播放流程（多角色轮）：

| 顺序 | 段类型 | 视觉组件 | 显示内容 |
|------|--------|---------|---------|
| 1 | `round_intro`（每轮 1 个） | BattleBanner | "第 N 轮" + "xx 的回合"（xx = `rolls[0]` = 第一个行动者） |
| 2 | `turn`（角色 A） | BattleModal | HP + `── 第 N 轮 ──` 分隔符 + 战报 |
| 3 | `turn`（角色 B） | BattleModal | HP + `── 第 N 轮 ──` 分隔符 + 战报 |
| 4 | `turn`（角色 C） | BattleModal | HP + `── 第 N 轮 ──` 分隔符 + 战报 |

### 1.2 核心问题

每个 `turn` 的 actor 才是各自 turn 的主角，但 `round_intro` 段用 `rolls[0]`（先攻第一名）当 actor——先攻第一名只是先攻值最高，**不是轮的主角**。第二个及以后的 `turn` 段没有任何"xx 的回合"宣告，玩家无法从视觉上知道"现在是谁的回合"。

问题本质：`round_intro` 段的生成逻辑用错了数据源。

### 1.3 战斗开始

原流程第一个 `round_intro` 横幅"第 1 轮 - xx 的回合"已经承担了战斗开始的视觉宣告——玩家进入战斗后看到的第一个横幅就是它。修复 `round_intro` 的生成逻辑后，第一个 `turn` 的 `round_intro` 自然继续承担这个角色。不需要独立的"战斗开始"阶段。

## 二、设计

### 2.1 段类型不变

保留 `BattleSegmentKindV2 = 'round_intro' | 'turn' | 'battle_end' | 'system'`，不新增段类型。`round_intro` 段继续承担"轮次开场"职责（Dian.md K-1 阶段切片模型），只是生成逻辑从"每轮 1 个依赖 `round_start` 事件"改为"每 `turn_start` 事件 1 个"。

### 2.2 buildPlayScriptV2 修改

**删除 `round_start` 事件处理**：不再依赖 `round_start` 事件的 `rolls` payload 构造 actor。

**删除 `rollToCombatantView` 函数**：不再需要从 rolls 构造 CombatantView。

**删除 `RollData` import**：仅 `rollToCombatantView` 使用。

**在 `turn_start` 事件处理时生成 `round_intro` 段**（在 `getTurnSegment` 之前 push，保证顺序为 `[round_intro, turn]`）：

```typescript
if (event.event_type === 'turn_start') {
  const actor = toCombatantView(payload.actor);
  const roundNum = event.bl_round_num !== null ? event.bl_round_num + 1 : undefined;
  const turnNum = event.bl_turn_num ?? undefined;
  segments.push({
    kind: 'round_intro',
    roundNum,
    turnNum,
    actor: actor ?? undefined,
    actions: [],
    notices: [],
  });
  getTurnSegment(event, actor ?? undefined);
  continue;
}
```

**为什么用 `turn_start` 事件触发而非 directV2 末尾遍历所有 turn 段**：`directV2` 是无状态纯函数，每个 presentation batch 独立调用。同一敌人回合的事件可能被后端分到两个 batch（第一个含 `turn_start` + 部分 action，第二个只有 `action_start`）。如果末尾遍历，两个 batch 的 turn 段都会生成 round_intro，导致同一回合横幅宣告两次。改用 `turn_start` 事件触发后，只有包含 `turn_start` 的 batch 才生成 round_intro——跨 batch 的第二个 batch（无 `turn_start`）通过 pending actions 创建的 turn 段不生成 round_intro。

`round_intro` 段的 actor = `turn_start` 事件的 `payload.actor`（不是 `rolls[0]`）。

### 2.3 其他文件不变

- `planPlaybackV2` 不变（`round_intro` 段继续生成 `modal_text` step + `alwaysShowHeader`）
- `BattleBanner.vue` 不变（`playSegment` 继续处理 `round_intro`，模板已显示"第 N 轮 - xx 的回合"）
- `battle.ts` 不变（`selectPlayer` 保留 `round_intro` → `bannerPlayer` 路由；`playSegmentText` 保留 `alwaysShowHeader`）
- `battle-playback-runner.ts` 不变（`SegmentPlayOptions` 保留 `alwaysShowHeader`）
- `BattleMode.vue` / `battle.css` 不变

### 2.4 BattleModal turn 段分隔符微调

每个 `turn` 段前现在有 `round_intro` 横幅（显示"第 N 轮 - xx 的回合"），BattleModal 内的 `turn` 段分隔符如果继续显示"── 第 N 轮 ──"会与横幅重复轮次信息。改为显示"── xx 的回合 ──"（行动者标识），与横幅形成层次分工：横幅是瞬态宣告（轮次 + 行动者），模态框分隔符是战报内的回合定位（行动者）。

```typescript
function getSegmentDivider(seg: BattleSegmentV2): { html: string } | null {
  switch (seg.kind) {
    case 'round_intro': return { html: `── 第 ${seg.roundNum ?? 0} 轮 ──` };  // 死代码（round_intro 不走 BattleModal），保留不动
    case 'turn':
      if (!seg.actor) return null;
      return { html: `── ${seg.actor.type === 0 ? '你' : seg.actor.name} 的回合 ──` };
    case 'battle_end':  return { html: '── 战斗结束 ──' };
    default:            return null;
  }
}
```

### 2.5 fixture 修改

删除 fixture 中的 `round_start` 事件——其 `rolls` payload 不再被消费，且 `round_intro` 段现在由 `turn_start` 事件触发生成。

## 四、边界情况

### 4.1 turn_start 事件无 actor

**触发场景**：极端情况下 `turn_start` 事件的 `payload.actor` 缺失。

**处理**：`round_intro` 段的 actor 为 undefined，BattleBanner 模板中 `v-if="currentSeg.actor"` 不满足，仅显示"第 N 轮"标题，不显示"xx 的回合"副标题。降级体验，不崩溃。

### 4.2 连续多个 turn 同一 actor

**触发场景**：罕见，但理论上可能（同一角色连续行动两次，两个 `turn_start` 事件）。

**处理**：每个 `turn_start` 都生成独立的 `round_intro` 段，显示两次"第 N 轮 - xx 的回合"——语义正确，每个 turn 都是独立的行动单位。

### 4.3 第一个 turn 的 roundNum 未定义

**触发场景**：后端 `bl_round_num` 为 null（极端情况）。

**处理**：`round_intro` 段 roundNum 也为 undefined，横幅显示"第 0 轮"（`currentSeg.roundNum ?? 0`）。视觉异常但不崩溃。后端应保证 `bl_round_num` 可靠。

### 4.4 跨 batch 的 turn 事件分割

**触发场景**：同一敌人回合的事件被后端分到两个 presentation batch——第一个含 `turn_start` + 部分 action，第二个只有 `action_start`。

**处理**：`directV2` 是无状态纯函数，每个 batch 独立调用。第一个 batch 的 `turn_start` 事件触发 `round_intro` 生成；第二个 batch 没有 `turn_start` 事件，通过 pending actions 创建的 turn 段不生成 `round_intro`。结果：同一回合只宣告一次，不重复。

### 4.5 后端不发送 turn_start 事件

**触发场景**：后端仅发送 `action_start` 事件，不发送 `turn_start` 事件。

**处理**：无 `round_intro` 段生成，无横幅宣告。降级为无宣告体验，不崩溃。后端应保证 `turn_start` 事件可靠发送。
