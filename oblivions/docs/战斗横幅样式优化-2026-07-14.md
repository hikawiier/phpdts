# 战斗横幅样式优化设计案

> 在 [战斗横幅组件设计案-2026-07-14.md](战斗横幅组件设计案-2026-07-14.md) 基础上的视觉层优化。
> 命令式驱动架构不变，仅调整横幅的视觉呈现与内容渲染逻辑。

---

## 一、问题诊断

当前 `.battle-banner` 完全复用 `.battle-modal` 的视觉语言：

| 属性 | `.battle-modal` | `.battle-banner`（当前） |
|------|-----------------|------------------------|
| background | `#0a0a0a` | `#0a0a0a` |
| border | `1px solid rgba(220,40,40,0.4)` | 同左 |
| box-shadow | `0 0 40px rgba(220,40,40,0.2)` | 同左 |
| width | `420px` | `420px` |

导致两个问题：

1. **视觉同质化**：玩家无法从视觉上区分"瞬态宣告"（横幅）和"战报详情"（模态框）
2. **语义错位**：横幅承载 round_intro（"第 N 轮"）和 battle_end（结果宣告），本质是瞬态阶段标记，应"轻、快、一眼可读"；但继承了模态框的"重、正式"语言——420px 宽度装一行"── 第 1 轮 ──"显得空旷，红色危险感边框让轮次宣告像威胁信号

此外，当前 `playBannerContent` 沿用了模态框的"逐条播放"逻辑（push 一条 → sleep → push 下一条），对于 round_intro（仅一条分隔符）和 battle_end（仅一条 notice）来说过于拖沓。

---

## 二、优化方向

### 核心原则

横幅 ≠ 缩小版模态框。横幅是**瞬态阶段标记**，应具备：

- **视觉差异性**：与模态框的"信息密度卡片"区分，走"仪式感标记"路线
- **内容即时性**：一次性显示完整内容，不逐条播放
- **段类型分化**：round_intro 与 battle_end 承担不同语义，视觉应分化

### round_intro — 章节卡风格

参考电影章节卡 / 格斗游戏 "ROUND 1" 横幅：

- **有遮罩**（用户确认）
- **无背景框**：透明背景，无边框，无阴影
- **大字号标题**：`第 N 轮`，字号显著放大（28px），letter-spacing 拉开
- **上下装饰线**：细线（60px 宽，居中），替代边框的视觉锚定作用
- **text-shadow**：保证文字在遮罩上的可读性
- **瞬态时长**：总时长压缩到 ~1.5s（淡入 250ms → 停留 800ms → 淡出 300ms）

### battle_end — 仪式感结果卡风格

- **有遮罩**（保留 showMask + showContent 两阶段协调）
- **保留卡片样式**：与 round_intro 的无框风格区分，突出"终局"仪式感
- **标题 + 正文分层**：标题"战斗结束"（20px），正文为 notice.reason
- **中性色调**：无胜者色彩区分（用户确认）
- **直接显示完整内容**：不逐条播放

## 三、组件逻辑调整

### 3.1 移除逐条播放机制

当前 `playBannerContent` 流程：

```
横幅淡入 → push 分隔符 → sleep → push 条目1 → sleep → push 条目2 → sleep → 停留 → 横幅淡出
```

新流程：

```
一次性填充内容 → 横幅淡入 → 停留 → 横幅淡出
```

移除：
- `collectPlaybackItems` 函数
- `displayedEntries` 数组与 `shown` 标记逻辑
- `ENTRY_INTERVAL` / `ENTRY_FADE_DELAY` 常量
- 逐条 push + `nextTick` + `scrollToBottom` 循环

改为：直接根据 `currentSeg.kind` 在 template 中渲染对应结构，横幅整体淡入时内容已就位。

### 3.2 移除 displayedEntries，改用 currentSeg 直接渲染

```vue
<div class="battle-banner" :class="bannerClass">
  <!-- round_intro: 装饰线 + 标题 + 装饰线 -->
  <template v-if="currentSeg?.kind === 'round_intro'">
    <div class="banner-line"></div>
    <div class="banner-title">第 {{ currentSeg.roundNum ?? 0 }} 轮</div>
    <div class="banner-line"></div>
  </template>

  <!-- battle_end: 标题 + 正文 -->
  <template v-else-if="currentSeg?.kind === 'battle_end'">
    <div class="banner-title">战斗结束</div>
    <div class="banner-body">
      <div
        v-for="notice in currentSeg?.notices ?? []"
        :key="notice.rawLogId"
        class="banner-notice"
        v-html="notice.reason"
      ></div>
    </div>
  </template>
</div>
```

### 3.3 playSegment 增加 maskOpen 操作（round_intro 需要遮罩）

当前 `playSegment` 仅操作 `bannerOpen`。新增 `maskOpen` 同步操作：

```typescript
async function playSegment(segment, _sessionId, options): Promise<void> {
  if (playing.value) return;
  playing.value = true;
  try {
    currentSeg.value = segment;
    // round_intro 段无 actions/notices，alwaysShowHeader 控制是否仍显示
    // （实际 round_intro 总是显示标题，此检查可简化为直接播放）
    
    // 遮罩 + 内容同时淡入
    const maskEntered = waitForMaskTransition();
    const bannerEntered = waitForBannerTransition();
    maskOpen.value = true;
    maskClosing.value = false;
    bannerOpen.value = true;
    bannerClosing.value = false;
    await Promise.all([maskEntered, bannerEntered]);
    if (cancelRequested) return;

    await sleep(COMPLETE_HOLD);
    if (cancelRequested) return;

    // 内容 + 遮罩同时淡出
    const bannerExited = waitForBannerTransition();
    const maskExited = waitForMaskTransition();
    bannerClosing.value = true;
    maskClosing.value = true;
    bannerOpen.value = false;
    maskOpen.value = false;
    await Promise.all([bannerExited, maskExited]);
    bannerClosing.value = false;
    maskClosing.value = false;
    currentSeg.value = null;
  } finally {
    playing.value = false;
  }
}
```

### 3.4 showContent 简化（不再调用 playBannerContent）

```typescript
async function showContent(segment, _sessionId): Promise<void> {
  currentSeg.value = segment;

  // 内容淡入（遮罩已在 showMask 阶段打开）
  const bannerEntered = waitForBannerTransition();
  bannerOpen.value = true;
  bannerClosing.value = false;
  await bannerEntered;
  if (cancelRequested) return;

  await sleep(COMPLETE_HOLD);
  if (cancelRequested) return;

  // 内容淡出
  const bannerExited = waitForBannerTransition();
  bannerClosing.value = true;
  bannerOpen.value = false;
  await bannerExited;
  bannerClosing.value = false;

  // 遮罩淡出
  const maskExited = waitForMaskTransition();
  maskClosing.value = true;
  maskOpen.value = false;
  await maskExited;
  maskClosing.value = false;
  currentSeg.value = null;
}
```

### 3.5 移除 playBannerContent 共用函数

`playSegment` 和 `showContent` 不再共用 `playBannerContent`——它们的遮罩协调逻辑不同（playSegment 同时开关遮罩，showContent 只关遮罩），各自内联更清晰。

### 3.6 cancelMask 不变

`cancelMask` 逻辑保持不变：仅在 `bannerOpen === false` 时关闭 `maskOpen`。对 round_intro 无影响（round_intro 是单次 playSegment 调用，没有"纯遮罩等待"阶段）。

## 六、round_intro 回合提示（框架基准重构）

### 6.1 需求

在 round_intro 横幅的"第 N 轮"标题下显示附加信息——"你的回合"或"XX的回合"——替代原 toast "你的回合" 提示。

### 6.2 框架基准研判

**问题本质**：在轮次横幅下显示本轮第一行动者，是 round_start 事件**本身就该携带的语义信息**，而非边界补丁。

**理由**：
- 轮次（round）是独立叙事单元，由 round_start 事件宣告开启
- 该事件携带的 `payload.rolls` 是**已排序**的先攻队列（`myorder=1` 排首位）
- 排序结果的第一位就是本轮的开局者——这是先攻计算的直接产物，属于 round_start 事件的核心语义

**当前实现的根本缺陷（信息流断裂）**：

1. 后端 `battle_calc_initiative` 已持有完整 `$player_map`（含 name），但生成 roll 元素时只提取 `type`，**丢弃了 name**
2. 后端 `combat_log_v2_round_start` 把 rolls 作为 payload 发送给前端
3. 前端 `directV2` 收到 round_start 事件时**完全忽略 payload.rolls**，只读取 `bl_round_num` 生成 round_intro 段
4. 信息丢失后，前端事后从 turn 段借 actor 给 round_intro 段打补丁——这是把"源信息丢失"的框架缺陷用"下游修补"来掩盖

**结论**：该需求是**框架基准**。从框架重构角度修复信息流：

- **源头修复**：后端在 roll 元素中保留 name（信息源就有，不该丢）
- **正确接入**：前端 directV2 处理 round_start 事件时直接从 `payload.rolls[0]` 构造 actor，附加到 round_intro 段
- **移除补丁**：删除后置修补逻辑

### 6.3 设计

#### 6.3.1 后端 battle_calc_initiative 保留 name

`battle.queue.func.php` 的 `battle_calc_initiative` 在两个分支（ambush + 普通）生成 roll 元素时附加 `'name' => (string)($data['name'] ?? '')`。

`$data` 来源：`$player_map[$pid]` 或 `obl_fetch_playerdata_by_pid($pid)`，二者均含 name 字段。

#### 6.3.2 前端 RollData 类型补全 name

`api.ts` 的 `RollData` 接口添加 `name: string` 字段。

`BattleLogV2Payload` 显式声明 `rolls?: RollData[]` 和 `ambush_pid?: number | null` 字段，不再依赖 `[key: string]: unknown` 索引签名访问 rolls。

#### 6.3.3 directV2 从 round_start payload.rolls[0] 提取 actor

`battle-director-v2.ts` 处理 round_start 事件时：

- 读取 `payload.rolls`（类型已显式声明为 `RollData[]`）
- 取 `rolls[0]`（myorder=1 的第一行动者，已由后端排序保证）
- 构造 `CombatantView`：pid/type/name 直接来自 roll；hp/mhp 默认 0（横幅只显示 name/type，不显示血量，0 不影响视觉）
- 附加到 round_intro 段的 `actor` 字段

构造逻辑封装为独立函数 `rollToCombatantView`，与 `toCombatantView`（处理 CombatantSnapshot）区分——两者输入语义不同（先攻掷骰结果 vs 战斗快照），不应共用。

#### 6.3.4 移除后置修补逻辑

删除 `battle-director-v2.ts` 中"为 round_intro 段附加 actor"的循环（遍历 segments 从后续 turn 段借 actor）。

#### 6.3.5 BattleBanner.vue template（已完成）

round_intro 横幅在标题下复用 `.banner-subtitle` 样式显示 actor 信息：

```vue
<template v-if="currentSeg?.kind === 'round_intro'">
  <div class="banner-line"></div>
  <div class="banner-title">第 {{ currentSeg.roundNum ?? 0 }} 轮</div>
  <div class="banner-subtitle" v-if="currentSeg.actor">
    {{ currentSeg.actor.type === 0 ? '你的回合' : `${currentSeg.actor.name}的回合` }}
  </div>
  <div class="banner-line"></div>
</template>
```

#### 6.3.6 移除 toast "你的回合"（已完成）

- `battle.ts` 已移除 `YOUR_TURN_TOAST_DURATION` 常量
- `applyVerifiedBattleState` 已移除 toast 调用
- `useToastStore` import 保留（"战斗数据异常" toast 仍在使用）

### 6.4 边界情况

- **rolls 为空数组**：`rollToCombatantView` 返回 null，actor 为 undefined，横幅不显示附加信息
- **rolls[0] 缺失 name**：构造时 fallback 为空字符串，横幅显示"的回合"——视觉异常但不会崩溃。后端已保证附加 name，此为防御性兜底
- **rolls[0] 是突袭者**：后端排序已保证 ambush_pid 排在 rolls[0]，符合"突袭者本轮先行动"的语义
- **round_intro 段已存在（重复 round_start 事件）**：当前逻辑用 `roundNum` 去重，已存在则不重新创建。实际 round_start 每轮只触发一次，无需处理

### 6.5 落地步骤

1. `battle.queue.func.php`：`battle_calc_initiative` 两个分支附加 `name` 字段
2. `api.ts`：`RollData` 添加 `name`；`BattleLogV2Payload` 显式声明 `rolls` 和 `ambush_pid`
3. `battle-director-v2.ts`：
   - 新增 `rollToCombatantView` 函数
   - round_start 事件处理时从 `payload.rolls[0]` 构造 actor 附加到 round_intro 段
   - 移除后置修补逻辑
4. `battle-director-v2.fixture.ts`：fixture 中 round_start 的 rolls 已包含 name 字段（与重构方案一致，无需修改）
5. 类型检查 + 导演测试
