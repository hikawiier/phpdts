# 命令锁与战斗瞄准权威判定重构设计案

> 状态：审查修订、实施与验收完成
> 日期：2026-07-11
> 适用范围：Oblivions 战斗领域、Command API、地图可见性投影、vex-vue 命令门控与战斗瞄准交互

## 0. 最终结论

> 本节与第 1-2 节记录实施前事实；实际完成状态以第 0.1 节为准。

本轮针对三个用户反馈完成代码级复核：

1. 任意操作后“探索周围”可能永久变灰，问题真实存在。根因是 `CommandQueue` 将普通 class 字段 `_locked/_cooldown` 暴露给 Vue computed 使用，解锁和冷却到期都不会主动触发响应式更新。
2. “战斗移动瞄准后点哪里都没反应”不是事件总线整体断裂。普通空白合法格的事件链是完整的，但同时存在三项真实缺陷：
   - 后端技能列表投影把 `move` 的 `action_range` 算成 `0`；
   - 前端再把 `0` 非法兜底成 `1`，使可选范围严重缩小；
   - 角色立绘与地图格是兄弟节点，点击立绘覆盖的合法格时，`closest('[data-pls].aim-targetable')` 无法找到目标格。
   - 距离大于单次 move power 的目标还可能通过 preview/tag，却在真实 effect 中被 `obl_perform_move_core()` 再次按固定 3 格拒绝。
3. 迷雾格被高亮的问题真实存在，但 `fog` 数值描述相反：`fog=0` 才是迷雾，`fog=1` 是已点亮。当前代码虽然不允许点击迷雾格，却给迷雾格统一添加 `aim-out-of-range`，产生明显虚线和遮罩，错误暗示它是一个已知但超距的目标。

后端射程权威函数的结论如下：

> 实施前不存在真正的单一权威射程函数。

项目中已经多次实现射程模式解析，用户的印象是准确的：

- `combat_get_action_range_meta()` 支持完整的五种模式，是目前语义最完整、参数边界最合适的已有候选；
- `combat_tag_compute_range()` 同样支持五种模式，但绑定 `CombatContext`；
- `obl_get_action_range()` 仍被技能列表、旧技能可用性和旧 battle tag 使用，却遗漏 `move_power`；
- `combat_tag_derive_tile_out_of_range()` 又额外内置了“移动力 × 可用 AP”的动态范围计算，而且该逆推公式与真实 AP calculator 在 `apcost>1` 时不等价。

因此不能只在 `obl_get_action_range()` 补一个 `move_power` case 后宣布问题解决。需要先把“图距离、技能基础射程、目标 AP 报价、资源可负担性、观察规则、最终目标合法性”拆成独立概念，再建立单一领域服务。

### 0.1 实施结果

已完成：

1. 新增 `combat.range.php`，五种 range mode 只保留一套解析；旧 range API 降为薄包装。

## 1. 已确认的代码事实

### 1.1 命令锁不是响应式真值

当前结构：

```text
ExploreButton computed
  -> commandQueue.canExecute('map.explore')
     -> _blockDecision()
        -> 读取普通字段 _locked / _cooldown
```

相关位置：

- `vex-vue/src/stores/command-queue.ts`
  - `_locked`、`_cooldown`：63-64
  - 请求开始加锁：161
  - `finally` 解锁：181-183
  - `remainingCooldown` 直接读取 `Date.now()`：236-238
- `vex-vue/src/components/actions/ExploreButton.vue`
  - `computed(() => !commandQueue.canExecute('map.explore'))`：17

请求期间 player、battle、inventory 或 presentation store 发生响应式变化时，按钮 computed 可能在 `_locked=true` 的瞬间重新计算并缓存为 disabled。随后 `_locked=false` 不是响应式写入，按钮不会恢复。冷却截止时间到达也没有 timer 或响应式时钟唤醒 UI。

### 1.2 tile 瞄准事件链本身完整

正常链路：

```text
PreloadArea 点击 tile 技能
  -> battle:aim-mode
  -> AimMode.applyAimTargetable()
  -> #mapGrid 原生 click listener
  -> battle:aim-target-selected { pls }
  -> PreloadArea.addToQueue()
```

已确认：

- `MapGrid` 在 aim mode 只 return，不调用 `stopPropagation()`；
- `AimMode` 注册和解除的是同一组 listener 引用；
- `DataManager.broadcast()` 是同步 `Set.forEach()`；
- `AimMode` 与 `PreloadArea` 同属 `BattleMode` 常驻子组件；
- SVG 瞄准线 `pointer-events:none`，不会拦截点击。

所以“所有合法空格都因事件总线断裂而无响应”不符合当前源码事实。

### 1.3 立绘覆盖格存在独立命中缺陷

地图 DOM 结构是：

```text
#mapGrid
  .map-cell[data-pls]
  .map-cell[data-pls]
  .entity[data-character-pid]
```

`.entity` 与 `.map-cell` 是兄弟节点，不是格子的子节点。tile 瞄准点击使用：

```ts
target.closest('[data-pls].aim-targetable')
```

点击落到 `.entity` 时，DOM 向上只能找到 `.entity -> #mapGrid`，无法找到其视觉下方的 sibling cell。因此玩家、NPC 或其他 actor 立绘覆盖的合法 tile 会无响应。

### 1.4 迷雾格被错误归类为超距

`AimMode.applyAimTargetable()` 当前只有两个结果：

```text
revealed && passable && inRange -> aim-targetable
其他全部                         -> aim-out-of-range
```

这把以下状态错误压成同一类：

- 迷雾；
- 不可通行；
- 不可达；
- 超距；
- 无效 pls。

`.aim-out-of-range` 使用橙色虚线、深色覆盖和 `not-allowed` 光标。迷雾格因此被明显标记，既产生视觉噪声，也向玩家暗示迷雾下存在可枚举的图格目标。

### 1.5 战斗移动 preview 与 execute 已经分叉

当前链路：

```text
tile_out_of_range tag
  -> move_power * floor(actor_ap / apcost)
  -> 距离 6 / AP 2 可以通过

combat_ap_calc_move_distance
  -> max(apcost, ceil(distance / move_power))
  -> 计算消耗 2 AP

combat_effect_move
  -> obl_perform_move_core(..., max_distance=null)
  -> 默认 max_distance = move_power = 3
  -> 距离 6 最终失败 too_far
```

相关位置：

- `combat.tag.php`：206-228
- `combat.ap.php`：62-98
- `combat.effect.php`：194-200
- `move.func.php`：130-168

这不是 UI 误差，而是领域执行一致性错误。preview、AP reservation、planned state projector 可以认为移动成功，真实 effect 却拒绝，后续动作会基于错误位置继续投影。

此外，真实 execute 当前在 `combat_pipeline_run()` 前调用 `combat_action_reserve_resources()`，会先把 `actor.ap` 改成扣款后余额。随后 aim rules 再运行 `tile_out_of_range`；如果该 tag 继续读取当前 `actor.ap` 反推范围，同一 action 会用扣款后的 wallet 二次判定，可能在进入 effect 前就被错误拒绝。

因此报价时序必须明确：

1. verify/preview 使用动作开始前的 planned wallet 生成 AP quote 与 spatial decision；
2. quote 随 verified action 冻结并传入 execute；
3. execute 可以重验目标、路径、通行和占用等易变空间事实；
4. execute 不得使用预扣后的 `actor.ap` 重新推导本 action 的可负担范围；
5. 资源恢复/提交只消费冻结 quote，不重新报价。

## 2. 后端射程实现全量盘点

### 2.1 空间距离权威

`oblivions/include/game/move.func.php`

| 函数 | 语义 | 当前状态 |
|---|---|---|
| `obl_get_distance(pgroup, from, to)` | 按 neighbors BFS 计算最短可通行路径距离；目标格允许不可通行；不可达返回 `-1` | 当前唯一通用图距离实现，可保留为基础拓扑权威 |
| `obl_get_move_range()` | 无 actor 参数，固定返回 `3` | 旧接口，与新领域概念重复 |
| `obl_get_move_power(actor)` | actor 单次移动力，当前固定返回 `3` | 新战斗配置 `range.mode=move_power` 的数据源 |
| `obl_perform_move_core()` | 真实移动合法性与执行，检查存在、通行、占用、距离 | execute 阶段权威，但不是 preview/投影接口 |

`obl_get_distance()` 只表达地图拓扑与通行性，不表达：

- 技能射程；
- AP；
- 冷却；
- 占用；
- 迷雾；
- 战斗规则。

因此它是“距离权威”，不是“目标合法性权威”。

### 2.2 动作基础射程解析重复三次

| 实现 | 文件 | 支持模式 | 主要调用方 | 问题 |
|---|---|---|---|---|
| `obl_get_action_range()` | `game/battle/battle.calc.php` | fixed/inherit/additive/capped_additive；缺少 move_power | 技能列表 API、`skill_is_usable()`、旧 battle tag | 当前 move 投影为 0 的直接根因 |
| `combat_tag_compute_range()` | `game/combat/combat.tag.php` | 完整五种 | 新 pipeline 的 pid/tile range tag | 绑定 `CombatContext`，不适合作为通用投影 API |
| `combat_get_action_range_meta()` | `game/combat/combat.preview.php` | 完整五种 | `combat_can_engage()` | 语义最完整，但位于 preview 文件且没有被其他模块复用 |

三者都读取同一份 `combat_skill_config.php['range']`，却复制 switch。当前已经发生实际分叉：两套认识 `move_power`，技能列表所用的一套不认识。

### 2.3 动态移动范围是第四套逻辑

`combat_tag_derive_tile_out_of_range()` 对 `ap_calc=move_distance` 有额外公式：

```text
effective_range = move_power * floor(actor_ap / base_apcost)
```

前端 `PreloadArea.getTileAimRange()` 又复制了同一公式，并将 `predictedAp` 代入。

这说明当前名为 `action_range` 的值实际上混合了两种不同概念：

1. `base_range`：技能空间尺度，例如 move power=3；
2. `target_ap_cost`：选择具体目标后，由真实 AP calculator 给出的报价；
3. `affordable`：planned wallet 是否支付得起该报价；
4. `effective_range`：仅供 UI 摘要展示的当前预算最大可负担距离。

当前 tag 使用的逆公式并不等价于 AP calculator。若未来 `apcost=2`、AP=3、move power=3：

- tag 公式给出最大距离 `3 * floor(3/2) = 3`；
- AP calculator 对距离 9 的报价是 `max(2, ceil(9/3)) = 3`，实际可负担。

因此不能再由 range、tag 或前端反推 AP 价格。具体目标必须先调用唯一 AP calculator 报价，再比较 planned AP。`effective_range` 如需投影，也必须由该 calculator 配套提供预算函数。

### 2.4 最终合法性已有正确方向，但缺少批量投影

`combat_preview_single()` 已经通过 `combat_chain_project()` 运行真实的：

- aim resolve；
- aim rules；
- target capture；
- AP 计算；
- planned state；
- effect projection。

这条链与真实执行共享规则，是当前最接近“最终合法性权威”的入口。

但它只接收单个目标。前端进入 tile aim 时需要一次得到整张当前地图的候选状态；逐格发请求会产生延迟和 N 次重复 projection。当前还缺少“基于计划动作前缀，批量投影候选目标”的领域接口。

### 2.5 `combat.can_engage()` 只是近似包络

`combat_get_max_attack_range()` 当前遍历所有非 hidden pid 技能，但没有完整过滤 actor 是否拥有技能、装备要求、CD、当前 AP，以及 move 后是否还支付得起攻击。

`combat_can_engage()` 再使用：

```text
distance <= max_attack_range + move_power
```

这会因未拥有的远程技能而高估，也会在 actor 有足够 AP 多段移动时低估。它不是实际 pipeline 的可执行性证明，不能继续作为权威战斗入口预判。

### 2.6 world move 与 combat move 存在双真值风险

- `obl_get_move_range()`：无 actor 参数，固定 3，供 world move 和 game_map API 使用；
- `obl_get_move_power(actor)`：actor-aware，当前也固定 3，供 combat 使用。

当前数值相同只是偶然。未来装备、状态或角色属性改变移动力后，两者会分叉。world SP 与 combat AP 可以是不同预算，但基础 actor move power 不应维护两份。

## 3. 必须建立的五层概念

### 3.1 Graph Distance

定义：两个 tile 在指定 traversal policy 下的最短路径边数。

输入：

- pgroup；
- from/to pls；
- traversal policy。

输出：

- distance；
- reachable；
- 可选 path/reason。

它不读取技能、AP 或战斗状态。

### 3.2 Base Action Range

定义：技能配置与 actor 固有属性解析出的基础射程。

支持模式：

- `fixed`
- `inherit`
- `additive`
- `capped_additive`
- `move_power`

它不读取目标，不判断是否可达，也不消耗 AP。

### 3.3 Target AP Quote And Affordability

定义：在当前 planned actor state 下，为具体目标计算 AP 报价，并判断当前 wallet 是否可负担。

输入：planned actor state、skill config、resolved target、graph distance。

输出：quoted AP cost、available AP、affordable，以及可选的 effective range 摘要。

这里必须调用与 execute 相同的 AP calculator。禁止 tag、preview 或前端根据 calculator 名称自行反推公式。

### 3.4 Observation Decision

定义：目标是否满足技能声明的观察/获取策略。

建议策略：

- `none`：不要求地图知识；
- `revealed`：tile 必须 `fog=1`；
- `controller_known`：按 actor/controller 类型选择知识 provider；玩家使用房间 fog，NPC 使用自身 perception policy；
- `detected`：character 必须已被发现，或已经是同一 qid 的有效 member；
- `visible`：保留给未来基于当前视野范围的技能。

观察规则与 range 分离，不能把“看不见”伪装成“超距”。

### 3.5 Target Eligibility

定义：具体 aim intent 在 planned state 下是否可提交。

它组合：

- aim resolver；
- tile/character 是否存在；
- 可见性；
- 通行性；
- 占用；
- graph distance；
- base range；
- observation decision；
- target AP quote 与 affordability；
- 技能 aim/rules；
- 战斗参与和 capability 等其他领域规则。

最终 execute 与 preview 必须共享这一层，UI 不应自行复制最终合法性。

## 4. 后端目标结构

### 4.1 新建射程与空间判定领域模块

新增：

`oblivions/include/game/combat/combat.range.php`

建议公共 API：

```php
combat_range_resolve_base(array $actor_data, string $act_id): array
combat_spatial_decide(CombatContext $ctx, array $resolved_target): array
```

返回结构：

```php
[
    'mode' => 'move_power',
    'base_range' => 3,
    'distance' => 6,
    'target_ap_cost' => 2,
    'affordable' => true,
    'effective_range' => 9,
    'base_apcost' => 1,
    'available_ap' => 3,
]
```

约束：

1. 只能从 `combat_skill_get_config()` 读取主动技能配置；
2. 五种 range mode 只允许在该模块出现一次 switch；
3. `combat_spatial_decide()` 必须调用真实 AP calculator，不得按 `ap_calc` 名称复制逆公式；
4. unknown mode fail closed，并写结构化错误日志，不能静默退回 fixed；
5. 缺技能返回明确失败结构，不能同时存在 `0`、`1` 两种兜底语义。

### 4.2 迁移所有调用方

以下实现改为薄包装或直接删除：

- `obl_get_action_range()`
- `obl_get_action_range_meta()`
- `combat_tag_compute_range()`
- `combat_get_action_range_meta()`
- `PreloadArea.getTileAimRange()` 中的权威公式

迁移目标：

- skill available list 使用 `combat_range_resolve_base()` 投影 `base_range`；
- combat tag、preview、projector 和 execute 使用 `combat_spatial_decide()`；
- `combat_can_engage()` 不再自行组合 range 与 move power；
- `skill_is_usable()` 若继续保留目标射程判断，也必须使用同一 resolver；
- 旧 `battle_target_distance_check()` 若无新 pipeline 调用方，应删除，不再维护第二套 legacy tag。

为避免继续混淆，前端 API 字段不再使用含义不清的 `action_range`：

```text
range.base
range.effective
range.mode
range.available_ap
range.base_apcost
```

其中 `range.effective` 只能来自 AP calculator 配套的 budget projection；若 calculator 不提供可靠预算投影，则省略该字段，前端依赖逐目标 eligibility，不能猜测。

### 4.3 修正 move effect 执行边界

`combat_effect_move()` 不得再调用“默认只允许一个 move power”的 core 路径。

推荐结构：

1. aim/rule 阶段基于 planned actor wallet 生成 `spatial_decision`；
2. decision 包含 distance、quoted AP、affordable、origin 和 target；
3. verified action 保存冻结 decision 或足以稳定重建 decision 的不可变 facts；
4. AP reservation 使用 decision 的同源报价，并记录 `ap_before/ap_after`；
5. effect 阶段重新检查易变事实：目标存在、passable、occupied、当前 topology distance；
6. effect 使用冻结 decision 的预算边界，不在 AP 已预扣后用剩余 AP 重算另一套范围；
7. projector 与真实 effect 消费同一 decision，成功/失败必须一致。

`obl_perform_move_core()` 应拆成纯空间执行原语，或要求调用方显式传入由 decision 确定的 max distance，禁止 `null -> move_power` 的隐式战斗语义。

### 4.4 新增批量目标投影命令

新增只读命令：

`combat.preview_targets`

请求：

```json
{
  "act_id": "move",
  "prefix_actions": [],
  "candidate_ids": [1, 2, 3]
}
```

流程：

1. 只投影一次 `prefix_actions`，得到 planned actor position/AP/tag state；
2. 解析当前动作的 base/effective range；
3. 对 candidate 批量运行与 `combat_preview_single()` 相同的 aim/rule 判定；
4. 不执行真实 effect，不写 DB，不消耗 RNG，不产生 presentation；
5. 返回每个目标的结构化 eligibility。

响应：

```json
{
  "origin_pls": 12,
  "range": {
    "mode": "move_power",
    "base": 3,
    "effective": 9,
    "available_ap": 3,
    "base_apcost": 1
  },
  "targets": {
    "13": { "selectable": true, "distance": 1, "reason": null },
    "14": { "selectable": false, "distance": 2, "reason": "tile_occupied" },
    "15": { "selectable": false, "distance": null, "reason": "tile_unrevealed" }
  }
}
```

`candidate_ids` 由前端当前地图投影提供，后端仍必须验证每个 ID。响应只返回请求候选，避免接口无条件枚举隐藏地图信息。

### 4.5 迷雾与目标观察作为后端规则

当前 `oblmapstates` 主键是 `(pgroup, pls)`，没有 pid/uid，因此 fog 是房间地图级状态，不是每个 actor 独立视野。当前设计必须忠于实际数据模型，使用术语 `tile_revealed`，不能伪称“actor 私有可见性”。

新增批量读取函数：

```php
obl_get_revealed_tile_set(int $pgroup): array
```

技能配置增加：

```text
aim.observation = none | revealed | controller_known | detected | visible
```

默认规则：

- 玩家显式 tile aim 不允许选择 `fog=0` 目标；
- `move` 使用 actor-aware 的 `observation=controller_known`：玩家显式瞄准要求 `fog=1`，NPC 继续遵守“可在雾中自由移动”的现有 AI 规则；
- 其他 tile 技能是否允许盲投由配置显式声明，禁止前端自行决定；
- pid 技能的初始目标通常使用 `detected`；同一 qid 的有效 member 由 roster 授权，不因世界 discovered 暂时变化而丢失战斗目标资格；
- 对未知 PID 的 API 请求返回通用 `TARGET_NOT_VISIBLE`，不得泄漏位置、距离或存在性；
- 当前阶段只禁止 hidden target，不顺手改变 `obl_get_distance()` 的 traversal 语义。

“路径是否允许穿越未揭示格”是独立玩法规则。若后续决定禁止，应为 graph distance 引入 traversal policy，而不是修改全局 `obl_get_distance()`，否则会同时改变 AI、攻击距离、视野和世界移动。

### 4.6 重写 engagement preview

将 `combat_can_engage()` 的“最大攻击射程 + 一次移动力”近似替换为 `combat_engagement_plan()`：

1. 只枚举 actor 实际拥有且当前可用的 hostile action；
2. 枚举合法 approach tile；
3. 使用统一 observation/path/spatial/AP decision；
4. 校验 move 报价 + attack 报价不超过 planned wallet；
5. 返回最优 plan 或结构化拒绝原因；
6. `battle.start` 仍通过同一 planner/pipeline 强校验，L0 预判不能单独授权。

### 4.7 收敛 world/combat move power

删除无 actor 的 `obl_get_move_range()` 真值。world move 和 game_map 的 `move_range` 投影改为读取 `obl_get_move_power(actor)`，但 world move 继续使用 SP 预算，combat move 使用 AP quote。共享的是移动力与 path 原语，不共享资源预算。

### 5.4 消除 DOM ancestry 命中依赖

- 点击 cell：`selectTile(cell.pls)`；
- 点击 entity：`selectTile(entity.pls)`；
- enemy aim：继续使用 `entity.characterPid`。

不得再用 `event.target.closest()` 猜测视觉下方的 sibling tile。

如需浏览器层兜底，可在 tile aim 模式临时为 actor entity 设置 `pointer-events:none`，但这只能作为命中保护，不应替代数据驱动选择逻辑。

### 5.5 统一 fog 解析

`vex-vue/src/utils/map-visibility.ts`

只把 `1`、`'1'`、`true` 解释为 revealed；`0`、`'0'`、`false`、缺键均为 hidden；当前格始终 revealed。

以下位置必须复用：

- `useMapRender.ts`
- `useMapReachability.ts`
- aim targeting candidate 构造

这能避免字符串 `'0'` 被 JavaScript truthy 误判为已点亮。

## 8. 明确不采用的方案

1. 只给 `obl_get_action_range()` 增加 `move_power`：只能修复一个投影点，继续保留三套 switch 和 base/effective 混淆。
2. 继续用 `move_power * floor(AP/apcost)` 反推范围：与实际 AP calculator 在 `apcost>1` 时不等价。
3. 前端继续自己计算最终合法格：会再次与后端 occupied、fog、planned state、AP 和未来状态效果规则分叉。
4. 给所有无效格统一加 `aim-out-of-range`：原因错误且泄漏隐藏地图结构。
5. 永久关闭 entity pointer events：会破坏 enemy aim 和正常实体点击。
6. 通过定时轮询按钮状态修复 command lock：额外制造全局时钟和无效渲染，正确做法是让状态变化本身响应式。
7. 修改全局 `obl_get_distance()` 让它忽略迷雾：会无意改变 AI、攻击、视野等其他领域；如需限制穿越迷雾，应新增显式 traversal policy。
