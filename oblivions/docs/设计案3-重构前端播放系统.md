# 设计案3：重构前端播放系统

> 本文档定义前端 `BattlePlayer` 的简化方案：从散落判断重构为纯执行器，并清理死代码。
>
> **所属总纲**：[战斗演出三层架构设计案.md](战斗演出三层架构设计案.md)
> **依赖**：[设计案2-新建前端导演系统.md](设计案2-新建前端导演系统.md)（需要导演模块）

---

## 一、设计目标

### 1.1 核心问题

当前 `battle.ts` 的 `playBattleLogGroup` 承担了多重职责：
- 分组（`groupByEncounter`）
- 过滤（`phase === 'excute'`）
- HP 重建（`rebuildInitialHpFromEntries`）
- API 查询（`buildPlayContext` → `refreshContextFromApi`）
- 动画判断（`action_id === 'unarmed_strike'`）
- 播放执行

此外还存在多处死代码（前端状态机轮询分支，因后端同步执行模型永远不会触发）。

### 1.2 改动目标

1. **简化播放器**：`playBattleLogGroup` 重写为 `playBattleLog`，只调用导演 + 执行脚本
2. **删除旧逻辑**：分组/过滤/HP重建/API查询等函数全部删除
3. **BattleModal 改造**：删除 `isFlowMode` 计算属性，改读导演输出的 `displayMode`
4. **清理死代码**：`startNpcTurnRefresh`/`isNpcActing`/`NPC_ACTING` 状态锁等

### 2.2 改造后 playBattleLog

```typescript
import { direct, type PlayScript } from './battle-director';

/**
 * 战斗播放器：纯执行导演脚本
 *
 * 不做任何判断，只读脚本字段执行。
 * 导演编排逻辑见 battle-director.ts
 */
async function playBattleLog(entries: BattleLogEntry[]): Promise<void> {
  // 1. 导演编排（同步纯函数）
  const scripts = direct(entries);
  if (scripts.length === 0) return;

  // 2. 逐场景执行
  for (const script of scripts) {
    if (script.displayMode === 'flow') {
      await playFlowModal(script);
    } else {
      await playCombatModal(script);
    }
  }
}

/** flow 场景：无 HP 条，纯文本播放 */
async function playFlowModal(script: PlayScript): Promise<void> {
  const rendered = script.entries
    .map(e => ({ entry: e, html: renderBattleLogEntryHtml(e) }))
    .filter(r => r.html);
  if (rendered.length === 0) return;

  battleLogEntries.value = rendered.map(r => r.entry);
  battleModalOpen.value = true;
  await waitForModalClose();
}

/** combat 场景：HP 条 + 碰撞动画 + 模态框 + 伤害数字 */
async function playCombatModal(script: PlayScript): Promise<void> {
  // 1. 更新战斗 header（名称/位置直接从 entry 读，不查 API）
  const firstEntry = script.entries[0];
  if (firstEntry) {
    enemyName.value = firstEntry.target_name ?? '';
    // enemyLocation 从其他途径获取（如 battleQueue），或后端补全
  }

  // 2. 碰撞动画（读 animation 字段，不判断 action_id）
  for (const e of script.entries) {
    if (e.animation === 'collision') {
      dataManager.broadcast('battle:play-collision', { entry: e, npcPid: script.npcPid });
      await sleep(COLLISION_ANIM_DURATION);
    }
  }

  // 3. 模态框（HP/名称直接从 entry 读，不查 API、不 rebuild）
  battleLogEntries.value = script.entries;
  battleModalOpen.value = true;
  await waitForModalClose();

  // 4. 伤害数字
  dataManager.broadcast('battle:play-damage-numbers', {
    entries: script.entries,
    npcPid: script.npcPid,
  });
}

/** 等待模态框关闭 */
async function waitForModalClose(): Promise<void> {
  await new Promise<void>((resolve) => {
    const timeout = setTimeout(() => {
      _modalResolve = null;
      resolve();
    }, MODAL_TIMEOUT);
    _modalResolve = () => {
      clearTimeout(timeout);
      resolve();
    };
  });
}
```

## 四、清理死代码

### 4.1 前端状态机轮询死分支

**背景**：由于后端 PHP 同步执行模型，前端通过 `api_v2.php` 获取状态时，`PLAYER_ACTING` 和 `NPC_ACTING` 都已经过去，前端只能看到 `IDLE` 和 `WAITING_PLAYER`。

**死代码清单**：

| 文件 | 位置 | 死代码 | 原因 |
|------|------|--------|------|
| `battle.ts` | 134-142 | `startNpcTurnRefresh()` | `NPC_ACTING`/`PLAYER_ACTING` 永远不会出现 |
| `battle.ts` | 145-150 | `stopNpcTurnRefresh()` | 同上 |
| `battle.ts` | 152-155 | `hasNpcTurnRefreshTimer()` | 同上 |
| `battle.ts` | 325-326 | `if (battleState === 'NPC_ACTING' \|\| battleState === 'PLAYER_ACTING')` | 永远为 false |
| `battle.ts` | 76 | `npcTurnRefreshTimer` | 无调用点 |
| `command-queue.ts` | 57 | `if (advancesTick && usePlayerStore().oblBattleState === 'NPC_ACTING')` | 永远为 false |
| `command-queue.ts` | 104 | `isLocked` 中的 `NPC_ACTING` 判断 | 永远为 false |
| `command-queue.ts` | 107-109 | `isNpcPending` getter | 永远为 false |
| `player.ts` | 56-58 | `isNpcActing` 计算属性 | 永远为 false |

## 六、边界情况

### 6.1 enemyLocation 获取

当前 `buildPlayContext` 通过 API 查询敌人位置（`enemy.pls`）。改造后后端未提供 `target_pls` 字段（设计案1 未包含）。

**处理方案**：
- 方案A：后端 emit 时补全 `target_pls`（推荐，符合"给全原料"原则）
- 方案B：前端从 `battleQueue` 中提取位置（临时方案）

建议在设计案1 实施时补全 `target_pls` 字段。

### 6.2 BattlePlayContext 类型

`BattlePlayContext` 类型（`battle-templates.ts` 中定义）在改造后不再需要。但 `renderBattleLogEntryHtml` 函数可能仍依赖它。

**处理方案**：
- 检查 `renderBattleLogEntryHtml` 的参数
- 如果它依赖 `BattlePlayContext`，改为直接从 entry 读取 name/hp 等字段
- 删除 `BattlePlayContext` 类型

### 6.3 模态框"战斗开始"分隔符

当前 `BattleModal.vue` 在首条 entry 前显示"── 战斗开始 ──"分隔符，flow 模式下跳过。

**改造后**：
- 改读 `displayMode` 判断是否显示
- combat 模式显示，flow 模式跳过
