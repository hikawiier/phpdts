## 二、详细设计

### 2.0 旧技能框架清理

**背景**：旧的 verify/calc 目录框架已被 modules 框架取代。throw 已用 modules，idle 也将用 modules。escape 仍留在 `calc/escape.calc.php`，是旧框架唯一的实际使用者。`verify/` 目录根本不存在，`skill_act_verify` 中的 verify 文件回退是死代码。

**清理步骤**：

1. **迁移 escape**：`calc/escape.calc.php` → `modules/escape.skill.php`

   把 `escape_calc` 函数原样搬到 `modules/escape.skill.php`，文件结构与 `throw.skill.php` 一致：

   ```php
   <?php
   if (!defined('IN_GAME')) exit('Access Denied');

   function escape_calc(&$actor_data, &$target_data, &$obl_battle_log, &$battle_cache) {
       # 1. emit flee battlelog
       if ($obl_battle_log) {
           $obl_battle_log->setPhase('flee');
           $obl_battle_log->emit([
               'actor_pid'  => (int)$actor_data['pid'],
               'actor_name' => $actor_data['name'],
               'success'    => true,
           ]);
       }
       # 2. combatants 标记为 0 + 写入 escaped mutation
       $pid = (int)$actor_data['pid'];
       $battle_cache['combatants'][$pid] = 0;
       if (!isset($battle_cache['tag_mutations'][$pid])) {
           $battle_cache['tag_mutations'][$pid] = ['dead' => false, 'escaped' => false, 'hidden' => false];
       }
       $battle_cache['tag_mutations'][$pid]['escaped'] = true;
   }
   ```

2. **删除 `calc/escape.calc.php`**，`calc/` 目录空了可以删除

3. **简化 `skill_act_verify`**：删除 verify 文件回退逻辑（死代码）

   ```php
   # 修改前
   $verify_func = $act_id . '_verify_check';
   if (!function_exists($verify_func)) {
       $verify_file = GAME_ROOT . './oblivions/include/game/skill/verify/' . $act_id . '.verify.php';
       if (file_exists($verify_file)) {
           include_once $verify_file;
       }
   }
   if (function_exists($verify_func)) { ... }

   # 修改后
   $verify_func = $act_id . '_verify_check';
   if (function_exists($verify_func)) { ... }
   ```

4. **简化 `skill_execute`**：不再回退 calc 目录，只查 `function_exists`

   ```php
   function skill_execute(&$actor_data, $act_id, &$target_data, &$obl_battle_log, &$battle_cache) {
       $calc_func = $act_id . '_calc';
       if (function_exists($calc_func)) {
           $calc_func($actor_data, $target_data, $obl_battle_log, $battle_cache);
       }
   }
   ```

   `skill_load_modules()` 在 bootstrap 时已加载所有 `modules/*.skill.php`，`function_exists` 一定能找到已注册的 calc 函数。无 calc 函数的技能（如 `unarmed_strike`）直接跳过，伤害由 `obl_calc_damage` + `battle_apply_damage` 处理。

### 2.1 `obl_save_player` 去引用

**问题**：当前 `obl_save_player(&$pdata)` 引用传参，`skill_strip_temporary` 原地剥离 equipment 技能后污染了内存中的 `$pdata['skillpara']`。虽然当前战斗流程不致命，但属于脆弱设计。

**方案**：

1. 函数签名 `obl_save_player(&$pdata)` → `obl_save_player($pdata)`
2. 删除 `$json_backup` 数组和末尾的恢复循环（`foreach ($json_backup as $key => $val) $pdata[$key] = $val;`）
3. `skill_strip_temporary` 仍调用，但只影响值拷贝，外部 `$actor_data` 不受影响

**改造后流程**：
```
$pdata（值拷贝）
  → skill_strip_temporary（剥离拷贝中的 equipment 技能）
  → json_encode 各 JSON 字段
  → 构建 $ndata → UPDATE DB
  → 函数返回，拷贝丢弃
```

**docstring 更新**：去掉"引用传递"说明，改为"值传递，不修改外部数据"。

### 2.3 `obl_get_action_range` 配置缺失报错

**问题**：当前 `$config` 为 null 时静默返回 `base`，掩盖了"技能被执行但配置不存在"的 bug。

**方案**：在 `obl_get_action_range` 中，`$config` 为 null 时 emit `obl_error_log`，兜底返回 1。

```php
function obl_get_action_range(&$actor_data, $act_id) {
    include_once GAME_ROOT . './oblivions/include/game/skill/skill.main.php';
    $config = skill_get_config($act_id);
    $base   = obl_get_range($actor_data);

    if (!$config) {
        global $obl_error_log;
        if (isset($obl_error_log) && $obl_error_log) {
            $obl_error_log->emit('skill.config_missing', array(
                'skill_id'  => $act_id,
                'actor_pid' => isset($actor_data['pid']) ? (int)$actor_data['pid'] : 0,
            ), 'command');
        }
        return 1;  # 兜底，让战斗不中断
    }
    ...
}
```

### 2.4 `battle_build_target_tags` 打标流程内联前置条件

**问题**：当前 Cat A 打标（`self`、`out_of_range`）无条件执行，self 目标技能也走 out_of_range 计算，靠"distance=0, range_max=0, 0<=0"巧合通过。

**方案**：在 `battle_build_target_tags` 中为 `out_of_range` 加内联前置条件——actor 与 target 是同一人时跳过计算，直接设为 false。

```php
// ── Cat A：始终重算（依赖当前 actor，不可缓存）──
$tags['self'] = battle_tag_self($actor_data, $target_data);

// out_of_range 前置条件：self 目标永不在射程外（复用 self 判断，避免重复 pid 比较）
$tags['out_of_range'] = !$tags['self']
    ? battle_tag_out_of_range($actor_data, $target_data, $act_id, $battle_cache)
    : false;
```

`self` tag 保持无条件（始终计算），因为它的计算量极小且被 `require:self` 规则使用。

### 2.5 `idle` 技能与 `hidden` 配置项

#### 2.5.1 `hidden` 的语义

`hidden` 不是"后端不暴露给玩家"，而是"前端界面上不显示"。区别在于：

- 后端 `skill_get_available_list` **正常返回** hidden 技能，只是在返回数据中带上 `hidden` 字段
- 前端技能列表组件根据 `hidden` 字段**跳过渲染**
- `skill_act_verify` 和 `skill_is_usable` **不需要特殊放行**——hidden 技能仍然在 skillpara 中
- `idle` 通过 `skill_ensure_npc_defaults` 仅注入 NPC（type>0）skillpara，玩家 skillpara 中不包含 idle

#### 2.5.2 `skill_config.php` 新增 `idle` 配置

```php
'idle' => [
    'apcost'       => 0,
    'cd'           => 0,
    'target'       => 'self',
    'target_rules' => ['require' => ['self']],
    'lifetime'     => 'permanent',
    'category'     => 'unattack', // 与 escape 同类，不进入伤害流程（见 §2.10）
    'finisher'     => 0,
    'range_mode'   => 'fixed',
    'range_max'    => 0,
    'hidden'       => true,   // 前端不显示，但后端正常处理
],
```

#### 2.5.3 NPC 专属默认技能注入

`idle` 是 NPC 专属技能，不应注入玩家 skillpara。通过 `$pdata['type']` 区分：type=0 为玩家，type>0 为敌人类型 ID。

`skill_ensure_defaults` 保持不变（只管通用默认 `unarmed_strike`、`escape`），新增 `skill_ensure_npc_defaults` 处理 NPC 专属默认技能，由 `obl_format_playerdata` 在 type>0 时调用：

```php
// skill.main.php 新增
function skill_ensure_npc_defaults(&$skillpara) {
    $npc_defaults = array('idle');
    foreach ($npc_defaults as $skill_id) {
        if (!isset($skillpara[$skill_id]) || !is_array($skillpara[$skill_id])) {
            $skillpara[$skill_id] = array('lstact' => 0);
        }
        if (!isset($skillpara[$skill_id]['lstact'])) {
            $skillpara[$skill_id]['lstact'] = 0;
        }
    }
}
```

```php
// obl_format_playerdata 中编排
skill_format_skillpara($skillpara);
if (function_exists('skill_inject_equipment')) {
    skill_inject_equipment($skillpara, $pdata);
}
if ((int)$pdata['type'] > 0) {
    skill_ensure_npc_defaults($skillpara);
}
$pdata['skillpara'] = $skillpara;
```

职责分层：
- `skill_ensure_defaults`：通用默认技能（所有人都有）
- `skill_ensure_npc_defaults`：NPC 专属默认技能（仅 type>0）
- `skill_inject_equipment`：装备临时技能（按装备状态动态注入/剥离）

玩家 skillpara 中永远不会有 `idle`，前端不需要过滤——它根本不在列表里。`hidden` 字段仍然保留在配置和 `skill_get_available_list` 返回中，作为通用的"前端不显示"标记，未来可能有其他 hidden 技能（如隐藏被动技能）需要注入玩家但前端不显示。

#### 2.5.4 `skill_get_available_list` 返回 `hidden` 字段

```php
$skills[] = array(
    ...
    'hidden'      => !empty($config['hidden']),
```

不过滤，正常返回。前端根据此字段决定是否渲染。

#### 2.5.5 `modules/idle.skill.php`（新建）

### 2.6 `skill_is_usable` 增加射程预判

**问题**：当前 `skill_is_usable` 只检查配置/拥有/CD/AP，不检查射程。NPC AI 用它选技能时无法预判射程，导致选了技能却被 `out_of_range` 拦截。玩家侧也需要一个通用的"技能对某目标是否可用"判断。

**方案**：增加可选参数 `$target_data = null`（非引用，避免"调用方不能传 null 字面量"的陷阱），传入时检查射程。

```php
function skill_is_usable(&$actor_data, $skill_id, $target_data = null) {
    // 1. 查配置
    $config = skill_get_config($skill_id);
    if (!$config) return false;

    // 2. 检查拥有
    if (!isset($actor_data['skillpara'][$skill_id])) return false;

    // 3. 检查 CD
    ...

    // 4. 检查 AP
    ...

    // 5. 射程预判（仅当 target_data 提供且目标非 self 时）
    //    注意：pgroup 无效或跨区域时 return false 是保守策略——
    //    当前唯一调用方 NPC AI 只在同区域战斗时决策，pgroup 必然 >0。
    //    未来玩家侧复用时需重新评估此边界（战前 pgroup=0 会被误判不可用）。
    if ($target_data !== null && (int)$actor_data['pid'] !== (int)$target_data['pid']) {
        include_once GAME_ROOT . './oblivions/include/game/battle/battle.calc.php';
        include_once GAME_ROOT . './oblivions/include/game/move.func.php';
        $action_range = obl_get_action_range($actor_data, $skill_id);
        $actor_pgroup = isset($actor_data['pgroup']) ? (int)$actor_data['pgroup'] : 0;
        $target_pgroup = isset($target_data['pgroup']) ? (int)$target_data['pgroup'] : 0;
        $actor_pls = isset($actor_data['pls']) ? (int)$actor_data['pls'] : 0;
        $target_pls = isset($target_data['pls']) ? (int)$target_data['pls'] : 0;
        if ($actor_pgroup > 0 && $actor_pgroup === $target_pgroup && $actor_pls > 0 && $target_pls > 0) {
            $distance = obl_get_distance($actor_pgroup, $actor_pls, $target_pls);
            if ($distance < 0 || $distance > $action_range) return false;
        } else {
            return false;  // 不同区域或无效位置
        }
    }

    return true;
}
```

**不传 target_data 时行为不变**，现有调用方（不传 target）不受影响。新参数为非引用，调用方传 `null` 字面量也安全。

### 2.7 `obl_ai_select_combat_action` 决策逻辑重构

**当前逻辑**：
```
遍历 combat_skills → 选第一个 skill_is_usable 的 → 回退 unarmed_strike
```

**新逻辑**：
```
1. fetch target_data
2. 遍历 combat_skills → 用 skill_is_usable(npc, skill, target) 选第一个可用攻击技能
3. 有可用攻击技能 → 返回该技能
4. 无可用攻击技能（射程不足或全 CD）→ 检查 NPC 是否有 escape：
   a. skill_is_usable(npc, 'escape') → 返回 escape（逃跑兜底）
   b. escape 不可用 → 返回 idle（发呆）
```

```php
function obl_ai_select_combat_action(&$npc_data, $target_pid) {
    $combat_skills = isset($npc_data['oblpara']['combat_skills'])
        ? $npc_data['oblpara']['combat_skills']
        : array('unarmed_strike');
    if (!is_array($combat_skills) || empty($combat_skills)) {
        $combat_skills = array('unarmed_strike');
    }

    # fetch target data（射程预判需要）
    $target_data = obl_fetch_playerdata_by_pid($target_pid);
    if (!$target_data) {
        # target 不存在，发呆
        return array(array('act_id' => 'idle', 'target' => (int)$npc_data['pid']));
    }

    # 1. 尝试攻击技能
    foreach ($combat_skills as $skill_id) {
        if (skill_is_usable($npc_data, $skill_id, $target_data)) {
            return array(array('act_id' => $skill_id, 'target' => (int)$target_pid));
        }
    }

    # 2. 无可用攻击技能 → 逃跑兜底
    if (skill_is_usable($npc_data, 'escape')) {
        return array(array('act_id' => 'escape', 'target' => (int)$npc_data['pid']));
    }

    # 3. escape 也不可用 → 发呆
    return array(array('act_id' => 'idle', 'target' => (int)$npc_data['pid']));
}
```

**注意**：`obl_fetch_playerdata_by_pid` 会触发 `obl_format_playerdata`（含 skillpara 格式化），开销可控（单次查询）。

### 2.8 前端 `idle` 动作渲染

[battle-templates.ts](file:///d:/wamp64/www/phpdts/vex-vue/src/data/battle-templates.ts) 按 **`directedKind`** 分发（`action`/`initiative`/`flee`/...），不是按 `action_id` 分发。`idle` 动作的 directedKind 是 `action`，因此应在 [`renderAction`](file:///d:/wamp64/www/phpdts/vex-vue/src/data/battle-templates.ts#L45-L68) 内部加 `if (actionName === 'idle')` 分支，与 `unarmed_strike`/`throw` 并列。模板函数签名统一为 `(e: DirectedEntry, playerPid: number) => string`。

```typescript
function renderAction(e: DirectedEntry, _playerPid: number): string {

  }

  if (actionName === 'unarmed_strike') { /* 现有逻辑 */ }
  if (actionName === 'throw') { /* 现有逻辑 */ }
  // default 分支
}
```

### 2.10 伤害流程 `unattack` 类别

**问题**：[battle_once_execute](file:///d:/wamp64/www/phpdts/oblivions/include/game/battle/battle.main.php#L80-L134) 无条件调用 `obl_calc_damage` + `battle_apply_damage`，`escape`/`idle` 这类无伤害技能也进入伤害流程，靠 [obl_calc_damage 内部 `damage_type === 'none'` 兜底返回 0](file:///d:/wamp64/www/phpdts/oblivions/include/game/battle/battle.calc.php#L134)。这是缺陷设计：

1. `escape` 现有配置未写 `damage_type`，`$config['damage_type'] === 'none'` 对未定义 key 触发 E_NOTICE
2. 语义不清——逃跑/发呆技能本就不应进入伤害流程，靠内部兜底是"靠巧合工作"

**方案**：新增 `unattack` 类别作为"不进入伤害流程"的统一标记。`escape` 的 `category` 从 `'escape'` 改为 `'unattack'`，`idle` 的 `category` 设为 `'unattack'`。`battle_once_execute` 在调用伤害流程前判断 `category === 'unattack'` 跳过。`$damage` 初始化为 0，保证 `once_execute_post` 快照字段完整。

**配置变更**（[skill_config.php](file:///d:/wamp64/www/phpdts/oblivions/gamedata/skill_config.php)）：

```php
'escape' => [
    ...
    'category' => 'unattack',  // 原为 'escape'，改为统一的不进入伤害流程类别
    ...
],
'idle' => [
    ...
    'category' => 'unattack',
    ...
],
```

**battle_once_execute 修改**：

```php
// battle_once_execute 中，skill_execute 之后：
skill_execute($actor_data, $act_id, $target_data, $obl_battle_log, $battle_cache);

// 伤害流程：unattack 类别技能跳过
$damage = 0;
$config = skill_get_config($act_id);
$category = $config && isset($config['category']) ? $config['category'] : '';
if ($category !== 'unattack') {
    $damage = obl_calc_damage($actor_data, $target_data, $act_id, $battle_cache);
    battle_apply_damage($actor_data, $target_data, $damage, $obl_battle_log, $battle_cache);
}
```

**收益**：
- 修复 escape 进入伤害流程的遗留缺陷
- idle 天然不进入伤害流程，无需靠 `damage_type` 兜底
- 语义清晰：`unattack` 是"非战斗动作"的统一标记，未来新增同类技能（如防御、装填等）直接归此类即可，无需改伤害流程代码

**obl_calc_damage 内部检查保留**：作为防御性兜底，不删除。`damage_type` 字段缺失的 E_NOTICE 问题不在本设计案范围（escape 归 `unattack` 后不再进入伤害流程，不会再触发）。

**影响面确认**：全代码库搜索 `category === 'escape'` 仅命中 skill_config.php 的配置定义本身，无任何逻辑依赖 `category='escape'` 这个值。前端 `skill_get_available_list` 透传 category 但不根据值做逻辑判断。改动安全。
