# 战斗横幅组件设计案

> **目标**：将轮次宣告（round_intro）和终局战报（battle_end）的视觉呈现从模态框改为横幅，并借此次组件替换重构段文本播放流程——从"响应式共享状态 + watch"驱动模式改为"命令式直接调用 + await"驱动模式。
>
> **关联文档**：
> - [Dian.md K-1 框架](../Dian.md#框架-k-1战斗回合编排--演示播放管道)
> - [DESIGN.md 1.16 瞬态战斗与常态战斗](../DESIGN.md)
> - [CODEBASE.md §8 前端播放系统](../../vex-vue/CODEBASE.md)

---

## 一、问题

当前 BattleModal 同时承担三类段的视觉呈现：

| 段类型 | 渲染内容 | 信息量 | 模态框合理性 |
|--------|---------|--------|-------------|
| round_intro（轮次宣告） | 1 行段分隔符"── 第 N 轮 ──"，无 HP 条、通常无正文 | 极低 | 冗余 |
| turn（战报回放） | HP 条 + 段分隔符 + 多条正文 + HP 实时同步 | 高 | 合理 |
| battle_end（终局战报） | 段分隔符"── 战斗结束 ──" + 0~N 条 notices | 低 | 冗余 |

低信息量段承受模态框视觉负担，容易审美疲劳。但引入横幅组件替代模态组件时，发现当前播放流程存在 4 个框架基准问题（详见 §二），不能通过"打补丁"方式解决——必须重构播放流程。

---

## 二、框架基准问题

### 2.1 驱动模式：响应式共享状态 + watch → 命令式直接调用

**当前**：store 设置 `battleModalOpen=true` + 共享状态 → 组件 watch 并响应 → 组件读取 store 获取参数 → 组件完成后调 `notifyModalClosed` 通知 store

**问题**：
- 多组件 watch 同一信号需要互斥守卫
- onUnmounted 兜底需要 `playing` 守卫（否则会干扰其他组件）
- 组件承担了路由职责（判断"这个段是不是我的"）
- 本质是"发布-订阅"模式硬塞"命令-响应"语义

**重构方向**：store 通过组件 ref 直接调用播放函数，await 组件返回。组件不 watch store，不判断段类型，不读取共享状态。

### 2.2 状态归属：共享读写 → 参数传递 + 组件内部状态

**当前**：`currentSegment` / `battleModalSessionId` / `battleModalIsBattleEnd` / `battleModalContentReady` 被 store 和组件共享读写。状态重置分散在 `notifyModalClosed` / `exitBattleMode` / `reset` 三处。

**问题**：共享状态导致组件间耦合，引入第二组件后状态归属不清。

**重构方向**：store 通过函数参数传递播放参数，组件内部维护自己的播放状态。store 不持有"当前播放会话"相关的共享 ref——staleness 检查由 `presentationSession`（battle_end 流程）或组件内部 sessionId 参数（普通段流程）承担。

### 2.3 两阶段协调：共享状态 watch + 通知 → 命令式调用链

**当前**：`enterBattleEndOverlay` → openBattleModal(isBattleEnd=true) → 等 `notifyBattleEndOverlayCovered` → handoff → `contentReady=true` → 组件 watch `contentReady` → 继续播放 → `notifyModalClosed`

**问题**：通过 4 个共享状态 + 2 对 wait/notify 函数传递信号，组件需要 watch `battleModalContentReady` 变化。

**重构方向**：`enterBattleEndMask()` 命令式调用组件显示遮罩 → 返回；handoff 完成；`playBattleEndContent()` 命令式调用组件显示正文 → 返回。组件内部管理遮罩状态，不需要 watch。

### 2.4 命名语义：Modal 前缀 → 中性命名

**当前**：`playSegmentInModal` / `openBattleModal` / `battleModalOpen` / `waitForModalClose` / `notifyModalClosed` / `enterBattleEndOverlay` / `playBattleEndModalContent`

**问题**：命名反映"实现方式"（模态框）而非"语义"（段文本播放）。横幅取代后命名失真。

**重构方向**：中性命名——`playSegmentText` / `enterBattleEndMask` / `playBattleEndContent` 等。

## 三、设计原则

1. **横幅组件取代模态框组件承担流程职能**：BattleBanner 接管 round_intro / battle_end 段，BattleModal 保留 turn / system 段
2. **重构播放流程为命令式驱动**：store 通过组件 ref 直接调用播放函数，await 组件返回
3. **消除共享状态耦合**：store 通过参数传递播放参数，组件内部维护自己的播放状态
4. **命名中性化**：函数/状态命名反映语义（段文本播放）而非实现（模态框）

## 四、当前实现回顾

### 4.1 step → runtime callback 映射（来自 [battle-playback-runner.ts](../../vex-vue/src/stores/battle-playback-runner.ts)）

### 4.2 当前共享状态（待消除）

[battle.ts L135-140](file:///d:/wamp64/www/phpdts/vex-vue/src/stores/battle.ts#L135) 定义了 5 个共享状态：

- `battleModalOpen`：触发组件播放的开关
- `currentSegment`：当前段
- `battleModalSessionId`：会话 ID（**注**：在 battle_end 流程中被复用为 `presentationSession.id`，这是历史耦合）
- `battleModalIsBattleEnd`：是否 battle_end 段
- `battleModalContentReady`：handoff 是否完成

### 4.3 当前等待/通知机制（待消除）

- `closedWait` / `waitForModalClose` / `notifyModalClosed`：组件播放完成通知
- `coveredWait` / `waitForBattleEndOverlayCovered` / `notifyBattleEndOverlayCovered`：遮罩已覆盖通知
- 组件内部 `waitForBattleEndContent`：等 `contentReady=true`

### 4.4 终幕遮罩与终局战报的当前协调关系

`enterBattleEndOverlay`（终幕遮罩）和 `playBattleEndModalContent`（终局战报）操作同一个 BattleModal 实例，用同一个 `sessionId`（= `presentationSession.id`）：

- 终幕遮罩阶段：`openBattleModal(_, sessionId, true, false)` → 设置 `battleModalSessionId.value = sessionId` → overlay 淡入 → `notifyBattleEndOverlayCovered` → `waitForBattleEndContent` 等 handoff
- 终局战报阶段：handoff 完成 → `contentReady=true` → BattleModal 继续显示正文 → `notifyModalClosed`

> **关键耦合**：当前 `handoffPresentationScene`（[L875, L889](file:///d:/wamp64/www/phpdts/vex-vue/src/stores/battle.ts#L875)）和 `playBattleEndModalContent`（[L940](file:///d:/wamp64/www/phpdts/vex-vue/src/stores/battle.ts#L940)）的 staleness 检查都依赖 `battleModalSessionId.value === sessionId`——这条链路由 `openBattleModal` 在终幕遮罩阶段建立。重构后 `enterBattleEndMask` 不再设置任何共享 sessionId，这条链路断裂，staleness 检查必须改基于 `presentationSession`（详见 §6.6）。

| 段类型 | 视觉组件 | 触发路径 |

## 六、重构后的 store 层

### 6.1 组件注册

store 持有 BattleBanner 和 BattleModal 的 ref，由 BattleMode.vue 挂载时通过 `ref` 绑定（详见 §11.5）：

```typescript
// 组件接口类型
interface SegmentPlayer {
  /** 播放一个段（round_intro / turn / system） */
  playSegment(segment: BattleSegmentV2, sessionId: string, options: SegmentPlayOptions): Promise<void>;
}

interface BattleEndPlayer {
  /** 显示终幕遮罩（仅遮罩层淡入，保持遮罩状态） */
  showMask(segment: BattleSegmentV2, sessionId: string): Promise<void>;
  /** 在已显示的遮罩上显示终局战报正文（正文淡入 → 播放 → 淡出 → 遮罩淡出） */
  showContent(segment: BattleSegmentV2, sessionId: string): Promise<void>;
  /** 关闭持续显示的遮罩（仅纯遮罩阶段生效；正文播放中为 no-op） */
  cancelMask(): void;
}

type BannerPlayer = SegmentPlayer & BattleEndPlayer;

// store 内部
let bannerPlayer: BannerPlayer | null = null;
let modalPlayer: SegmentPlayer | null = null;

function registerBannerPlayer(player: BannerPlayer): void { bannerPlayer = player; }
function registerModalPlayer(player: SegmentPlayer): void { modalPlayer = player; }
function unregisterBannerPlayer(): void { bannerPlayer = null; }
function unregisterModalPlayer(): void { modalPlayer = null; }
```

组件在 `onMounted` 时注册，`onUnmounted` 时注销。

### 6.2 组件播放接口

接口定义见 §6.1。`SegmentPlayOptions` 简化为：

### 6.3 store runtime callback（重构后）

```typescript
async function playSegmentText(
  segment: BattleSegmentV2,
  options: SegmentPlayOptions,
): Promise<void> {
  if (!segmentHasRenderableText(segment) && !options.alwaysShowHeader) return;
  const sessionId = `playback-${nextSessionId++}`;
  const player = selectPlayer(segment);
  if (!player) throw new Error(`no player registered for segment kind: ${segment.kind}`);
  await player.playSegment(segment, sessionId, options);
}

function selectPlayer(segment: BattleSegmentV2): SegmentPlayer | null {
  switch (segment.kind) {
    case 'round_intro':
      return bannerPlayer;
    case 'turn':
    case 'system':
      return modalPlayer;
    default:
      return null;
  }
}

async function enterBattleEndMask(segment: BattleSegmentV2, sessionId: string): Promise<void> {
  if (presentationSession?.id !== sessionId) throw new Error('stale battle-end presentation session');
  if (!bannerPlayer) throw new Error('banner player not registered');
  await bannerPlayer.showMask(segment, sessionId);
}

async function playBattleEndContent(segment: BattleSegmentV2, sessionId: string): Promise<void> {
  try {
    const pending = pendingBattleEndHandoff;
    if (!pending || pending.sessionId !== sessionId) throw new Error('battle-end handoff run is missing');
    if (!bannerPlayer) throw new Error('banner player not registered');
    const [contentResult, handoffResult] = await Promise.allSettled([
      bannerPlayer.showContent(segment, sessionId),
      pending.finished,
    ]);
    if (pendingBattleEndHandoff === pending) pendingBattleEndHandoff = null;
    if (contentResult.status === 'rejected') throw contentResult.reason;
    if (handoffResult.status === 'rejected') throw handoffResult.reason;
  } finally {
    // 兜底关闭遮罩：正常流程下 showContent 已关闭遮罩，cancelMask 为 no-op；
    // 异常分支（pending 缺失 / bannerPlayer 缺失 / handoff 失败导致 showContent 未被调用）下关闭持续显示的遮罩
    // 注意：finally 中 bannerPlayer 可能为 null（如组件未注册），需 null 检查
    if (bannerPlayer) bannerPlayer.cancelMask();
  }
}
```

> **关键变更**：
> - `playSegmentText` 不再设置任何共享 sessionId ref——sessionId 仅作为参数传给组件（用于日志/调试）。组件不需要 staleness 检查：runner 串行执行保证不会重入，`onUnmounted` 兜底保证 unmount 时 Promise reject
> - `selectPlayer` 删除 `battle_end` 分支（死代码——battle_end 段不走 `modal_text` step）
> - `playBattleEndContent` 删除 `playbackSessionId.value !== sessionId` 检查——staleness 由 `pending.sessionId !== sessionId` 承担
> - `playBattleEndContent` 的 `try/finally` 包裹整个函数体，确保异常分支（`!pending` / `!bannerPlayer`）也能触发 `finally` 中的 `cancelMask()` 兜底关闭遮罩（见 §10.5）

## 七、重构后的组件层

### 7.1 BattleBanner.vue

**接口**：实现 `BannerPlayer`（= `SegmentPlayer & BattleEndPlayer`）

```typescript
defineExpose({
  async playSegment(segment, sessionId, options) {
    // 播放 round_intro 段
    // 横幅淡入 → 段分隔符 →（如有）逐条正文 → COMPLETE_HOLD → 横幅淡出
  },
  async showMask(segment, sessionId) {
    // 显示终幕遮罩（仅遮罩层淡入），保持遮罩状态
    // 返回后遮罩持续显示，等待 showContent 调用
  },
  async showContent(segment, sessionId) {
    // 在已显示的遮罩上显示终局战报正文
    // 横幅淡入 → 段分隔符 → 逐条正文 → COMPLETE_HOLD → 横幅淡出 → 遮罩淡出
  },
  cancelMask() {
    // 关闭持续显示的遮罩（仅纯遮罩阶段生效）
    if (bannerOpen.value) return;  // 正文正在播放，不干扰
    maskOpen.value = false;
    maskClosing.value = false;
  },
});
```

**内部结构**：两层（遮罩层 + 内容层），两套独立状态机（`maskOpen`/`maskClosing` + `bannerOpen`/`bannerClosing`）

**内部函数**：
- `sleep(ms)` / `cancelRequested` / `rejectSleep`：可取消的 sleep
- `waitForBannerTransition()` / `waitForMaskTransition()`：过渡等待（`TRANSITION_FALLBACK=1000` 兜底）
- `collectPlaybackItems(segment)`：收集段内 text cues
- `getSegmentDivider(seg)`：生成段分隔符（接收 segment 参数，不读 store）

**播放流程**：

1. `playSegment`（round_intro 段）：
   - `bannerOpen=true` → `waitForBannerTransition()`
   - 段分隔符 →（如有）逐条正文 → COMPLETE_HOLD
   - `bannerOpen=false` + `bannerClosing=true` → `waitForBannerTransition()` → `bannerClosing=false`

2. `showMask`（battle_end 第一阶段）：
   - `maskOpen=true` → `waitForMaskTransition()`
   - 返回（遮罩持续显示）

3. `showContent`（battle_end 第二阶段）：
   - `bannerOpen=true` → `waitForBannerTransition()`
   - 段分隔符 → 逐条正文 → COMPLETE_HOLD
   - `bannerOpen=false` + `bannerClosing=true` → `waitForBannerTransition()` → `bannerClosing=false`
   - `maskOpen=false` + `maskClosing=true` → `waitForMaskTransition()` → `maskClosing=false`

4. `cancelMask`（异常兜底）：
   - 仅在 `bannerOpen === false` 时生效（纯遮罩阶段）
   - 关闭 `maskOpen`（CSS 过渡会触发淡出，与正常关闭视觉一致）
   - 若 `bannerOpen === true`（正文播放中），为 no-op——正文流程会自行关闭遮罩

**`onUnmounted` 兜底**：
```typescript
onUnmounted(() => {

  if (currentTimer) {
```

## 十、边界案例

### 10.1 组件未注册（未 mounted）

store 命令式调用时 `bannerPlayer` / `modalPlayer` 为 null → 抛错。runner 的 `withTimeout` 会在 step timeout 后兜底推进。

与当前"无组件响应 `battleModalOpen` → 30s 超时"等价，但更快失败（立即抛错 vs 等待超时）。

> **注**：实际上 BattleMode.vue 在 `currentMode === 'battle'` 时挂载（[RightPanel.vue L65 v-else](file:///d:/wamp64/www/phpdts/vex-vue/src/components/layout/RightPanel.vue#L65)），BattleBanner + BattleModal 在 BattleMode 内部无条件挂载。所以进入战斗模式后组件必然已注册。此边界案例主要发生于"组件挂载时序竞争"（极罕见）。

### 10.2 组件播放中 unmounted

**触发场景**：用户主动退出战斗（[StatusBar.vue L138](file:///d:/wamp64/www/phpdts/vex-vue/src/components/layout/StatusBar.vue#L138) 调 `exitBattleMode`）→ `currentMode.value = 'normal'` → RightPanel.vue `v-if` 切换 → BattleMode.vue 卸载 → BattleBanner / BattleModal 卸载 → 组件 `onUnmounted` 触发。

**链路**：
1. `exitBattleMode` 设置 `currentMode.value = 'normal'`
2. Vue 响应式触发 RightPanel 重新渲染，BattleMode 卸载
3. BattleBanner / BattleModal 的 `onUnmounted` 触发
4. `cancelRequested = true` + reject `rejectSleep` → 当前播放 Promise reject
5. store 的 `await player.playSegment(...)` 接到 reject
6. runner 的 `withTimeout` catch 错误，继续推进（或 `guardScene` 兜底）
7. `exitBattleMode` 的 `cancelPendingBattleEndHandoff` 清理 handoff

不再需要 `playing` 守卫——命令式调用下，只有正在播放的组件才会被调用，unmounted 必然导致 Promise reject。

### 10.3 重入保护

组件内部 `playing` 标志位。若同一组件播放中再次被调用：
- 选项 A：第二次调用 await 第一次完成后再播放
- 选项 B：第二次调用直接返回（函数立即 resolve，不抛错）

推荐选项 B（与当前 BattleModal 重入保护语义一致：重入时直接推进）。命令式模式下"返回"即"推进"，不需要调 `notifyModalClosed`。

> **注**：命令式 + runner 串行执行下，重入保护实际上是防御性编程——runner 串行执行 step，前一个 step 完成后才执行下一个，不会同时调用同一组件两次。重入保护只防止"组件 unmount 后立即重新 mount 并调用"等极端时序竞争。

**`playSegment` 与 `showMask` 的冲突**：实际不会发生——round_intro 和 battle_end 不会在同一 playback plan 中交替（[planPlaybackV2](file:///d:/wamp64/www/phpdts/vex-vue/src/stores/battle-director-v2.ts#L482) 按 segment 顺序生成 step，round_intro 在前，battle_end 在后，且 battle_end 是最后一个 segment）。`showMask` 与 `showContent` 之间也不会有 `playSegment` 调用。

### 10.4 battle_end 段 handoff 失败

`playBattleEndContent` 的 `Promise.allSettled([showContent, pending.finished])` 等两个 promise 都 settle。

**情况一：handoff 在 L893-921 之间失败**（`pendingBattleEndHandoff` 已设置）：
- `pending.finished` reject
- `showContent` 仍会执行（关闭遮罩）
- `Promise.allSettled` 后检查 `handoffResult.status === 'rejected'` → throw
- 遮罩由 `showContent` 关闭，不会卡住

**情况二：handoff 在 L873-891 之间失败**（`pendingBattleEndHandoff` 未设置）：
- `playBattleEndContent` 检查 `!pending` → throw，**不调 `showContent`**
- 遮罩会卡住——此时 `playBattleEndContent` 的 `finally` 调 `bannerPlayer.cancelMask()` 关闭遮罩

> **注**：组件不需要 staleness 检查——命令式调用下，组件被调用就播放，组件 unmount 就 reject Promise。handoff 失败的兜底完全由 store 层的 `finally { cancelMask() }` 承担。

> **关键**：runner 的 `withTimeout` 在 task.finished reject 时 catch 错误并 resolve（[runner.ts L169-172](file:///d:/wamp64/www/phpdts/vex-vue/src/stores/battle-playback-runner.ts#L169)），不会中断后续 step。所以 `playBattleEndContent` 总会被调用，`finally` 中的 `cancelMask()` 总会执行。

### 10.5 showMask 与 showContent 之间的状态保持

`showMask` 返回后，遮罩层保持显示状态。`showContent` 调用时，在已显示的遮罩上叠加横幅内容。两个函数调用之间，组件内部 `maskOpen` 状态持续为 true。

**异常兜底**：若 `showMask` 后 `showContent` 未被调用（如情况二的 handoff 失败），`playBattleEndContent` 的 `finally` 调 `cancelMask()` 关闭遮罩。

`cancelMask()` 的守卫逻辑：仅在 `bannerOpen === false` 时生效（纯遮罩阶段）。若 `showContent` 正在执行（`bannerOpen === true`），`cancelMask()` 为 no-op——正文流程会自行关闭遮罩。

### 10.6 exitBattleMode / reset 的清理

当前 [exitBattleMode L498-499](file:///d:/wamp64/www/phpdts/vex-vue/src/stores/battle.ts#L498) 重置 `battleModalOpen` / `currentSegment`；[reset L1078-1082](file:///d:/wamp64/www/phpdts/vex-vue/src/stores/battle.ts#L1078) 重置 5 个共享状态 + [L1093-1096](file:///d:/wamp64/www/phpdts/vex-vue/src/stores/battle.ts#L1093) resolve `coveredWait` / `closedWait`。重构后这些状态/变量已消除，清理逻辑改为：

**exitBattleMode**：
- 删除 L498-499（`battleModalOpen.value = false` / `currentSegment.value = null`）
- 保留 `cancelPendingBattleEndHandoff('battle_exited')`
- 组件中断由 `currentMode='normal'` → BattleMode 卸载 → `onUnmounted` 兜底（见 §10.2）

**reset**：
- 删除 L1078-1082（5 个共享状态重置）
- 删除 L1093-1096（`coveredWait?.resolve()` / `closedWait = null` / `closedWait?.resolve()` / `closedWait = null`）
- 保留 `cancelPendingBattleEndHandoff('battle_reset')`
- 组件中断由 `currentMode='normal'` → BattleMode 卸载 → `onUnmounted` 兜底

> **注**：`exitBattleMode` / `reset` 都设置 `currentMode.value = 'normal'`，必然触发 BattleMode 卸载，组件 `onUnmounted` reject Promise。不需要额外的 `cancel()` 方法。
