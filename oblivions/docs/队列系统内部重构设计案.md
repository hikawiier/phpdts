# 队列系统内部重构设计案

> 对 `battle.queue.func.php` 进行内部流水线拆分 + SQL 统一封装 + 函数重命名。
>
> **状态**：设计阶段，未实施
> **前置**：battle_main解耦设计案v3（已实施），战斗入口设计案（已实施）
>
> 本设计案不涉及跨模块接口变化，`battle_manage_queue()` 对外签名保持不变。

---

## 一、问题

| # | 问题 | 表现 |
|---|------|------|
| 1 | 流程不清晰 | `battle_queue_check` 同时做 "ensure + mark done + update" 三件事 |
| 2 | SQL 操作不统一 | 读用函数，写用裸 SQL 拼接。散落在 4 个函数中 |
| 3 | 命名歧义 | `battle_finish_check` / `battle_new_turn` 听起来像战斗级函数，实际只操作队列内部 |

---

## 二、方案

### 2.1 队列生命周期拆为 4 步流水线

当前 `battle_manage_queue()` 内部：

```
battle_queue_check()
  └── ensure(没队列→创建) + mark_done + update(解散/重建/qorder)

battle_finish_check()
  └── (队列空了?) → 终了清理 / 下一轮准备
```

改为：

```
battle_queue_ensure()                     ← 只做：没队列就创建
battle_queue_advance()                    ← 三步不拆：mark_done + disband + rebuild
battle_queue_try_end()                    ← 只做：(队列空了?) → 清理 / 下一轮准备
battle_queue_prepare_next_round()         ← 只做：AP 恢复 + save
```

`battle_manage_queue` 调用时变成一条清晰的四步流水线：

```php
function battle_manage_queue(&$actor_data, &$obl_battle_log, &$battle_cache) {
    $obl_battle_log->setPhase('queue_check');
    battle_queue_ensure($actor_data, $obl_battle_log, $battle_cache);
    battle_queue_advance($actor_data, $obl_battle_log, $battle_cache);

    $obl_battle_log->setPhase('finish_check');
    battle_queue_try_end($actor_data, $obl_battle_log, $battle_cache);
}
```

### 2.2 SQL 零裸 SQL：补全写操作函数到 sql.func.php

当前 `sql.func.php` 只有读函数 + `obl_update_queue_done()`。补全以下写操作：

```php
// ── 队列写操作 ──
obl_queue_insert_entry($pid, $qid, $type, $myorder)      // INSERT
obl_queue_delete_entry($pid, $qid)                        // DELETE 单行
obl_queue_delete_by_qid($qid)                             // DELETE 整个队列
obl_queue_delete_by_pid($pid)                             // DELETE 旧记录
obl_player_set_bid($pid, $qid)                            // UPDATE bid
obl_queue_update_qorder($pid, $qid, $qorder)              // UPDATE qorder

// ── 辅助 ──
obl_queue_next_qid()                                      // SELECT MAX(qid)+1
obl_queue_next_myorder($qid)                              // SELECT MAX(myorder)+1
```

所有写操作的函数签名统一为 `(参战者标识, 队列标识, 其他参数)`。

### 2.3 函数重命名

| 当前名 | 新名 | 理由 |
|--------|------|------|
| `battle_queue_check` | 拆为 `battle_queue_ensure` + `battle_queue_advance` | 单一职责 |
| `battle_finish_check` | `battle_queue_try_end` | 前缀 queue，作用域明确 |
| `battle_new_turn` | `battle_queue_prepare_next_round` | 命名描述行为而非假设 |
| `battle_queue_update` | 保留不动 | 但内部三步改为调用 2.2 的函数 |

调整后 `battle_manage_queue` 的 4 步 + 底层 CRUD 的命名全部以 `battle_queue_` 开头，作用域一目了然。

## 三、battle_queue_advance 内部结构

当前 `battle_queue_update` 内部有三步（注释标记 C/D/E）：

```
C: disband_check   → 队列 ≤1 人 → 解散
D: rebuild_check   → 全部 done → 重投先攻
E: qorder_update   → 更新当前顺位
```

保持三步合一，但内部改为调用 `sql.func.php` 的写函数：

```php
function battle_queue_advance(&$actor_data, &$obl_battle_log, &$battle_cache) {
    $qid = (int)$actor_data['bid'];
    if ($qid <= 0) return;

    // C. 解散检查
    $count = obl_fetch_queue_count_by_qid($qid);
    if ($count <= 1) {
        $battle_cache['last_qid'] = $qid;
        obl_queue_delete_by_qid($qid);
        $actor_data['bid'] = 0;
        obl_save_player($actor_data);
        return;
    }

    // D. 重建检查
    $undone = obl_fetch_queue_undone_by_qid($qid);
    if (empty($undone)) {
        if (isset($actor_data['oblpara']['ambush_flag'])) {
            unset($actor_data['oblpara']['ambush_flag']);
        }
        $combatants = obl_fetch_queue_pids_by_qid($qid);
        battle_queue_create($actor_data, $combatants, $obl_battle_log, $qid);
    }

    // E. qorder 更新
    if ($qid > 0) {
        $my_queue = obl_fetch_queue_by_pid($actor_data['pid']);
        if ($my_queue) {
            obl_queue_update_qorder($actor_data['pid'], $qid, (int)$my_queue['myorder']);
        }
    }
}
```

| 替换 `$db->query("UPDATE ... SET qorder=...")` → `obl_queue_update_qorder()` | 1 处替换 |

| 替换 `SELECT MAX(myorder)..." → `obl_queue_next_myorder()`` | 1 处替换 |

| `battle_finish_check` → `battle_queue_try_end` | 改名 |
