# Oblivions 地图、移动与探索 — 完整设定案

> 版本：1.0 | 基于草案分析与答疑完善

---

## 一、核心概念

### 1.1 层级结构

```
区域 (Region)           pgroup  tinyint   多个区域线性连接（预留网状接口）
  └── 地图格 (Tile)      pls     tinyint   区域内局部索引，手工设计的不规则形状
```

- **区域**：一个独立的子地图，由多个地图格拼接而成。玩家通过出入口在不同区域间移动。
- **地图格**：最小的移动单元，使用 `(pgroup, pls)` 组合键唯一确定。`pls` 是区域内的局部索引（0-254），跨区域时 pls 可重用。数据库字段无需修改（`pls tinyint unsigned` 和 `pgroup tinyint unsigned` 均保持不变）。

### 1.2 属性体系

每个地图格拥有两类属性，职责分离：

| 属性类型 | 对谁有影响 | 用途 |
|----------|-----------|------|
| **地板属性** (floor) | 玩家 | 影响玩家互动：移动消耗修正、技能效果、可破坏性 |
| **潮汐属性** (tide) | 系统逻辑 | 影响资源生成倾向：稀有度权重、敌人生成偏向、事件点类型 |

地板属性枚举：
- `standard` — 标准地板
- `water` — 含水地板
- `vegetation` — 覆植地板
- `metal` — 金属地板
- `magic` — 富魔力地板

潮汐属性枚举：
- `shallow` — 浅滩区（T-1 级，低危险，边缘绿色渲染）
- `deep` — 深水区（T 级，中危险，边缘黄色渲染）
- `abyss` — 深海区（T+1 级，高危险，边缘红色渲染）
- `safe` — 安全区（边缘灰色，动态判定：该格无敌人/道具/未触发事件点）

安全区判定逻辑：模板预设优先，无预设时动态检查。模板可明确标记某格为永久安全区，不受动态清空影响。

### 1.3 区域连接

- **当前阶段**：线性连接，每个区域有 1 个入口格和 1 个出口格，到达出口格后自动切换到下一区域的入口格。
- **预留接口**：`exit_links` 字段支持多出口，未来可扩展为网状（到达出口格时弹出选择）。

## 二、数据模型

### 2.1 存储文件

```
oblivions/gamedata/
  └── map.php     — 完整地图数据（区域 + 地图格）
```

### 2.2 数据格式

```php
// oblivions/gamedata/map.php
return [
    'regions' => [
        $pgroup => [
            'name'          => '区域名称',
            'desc'          => '区域描述',
            'entrance_pls'  => 1,        // 入口格 pls（区域内局部索引）
            'exit_pls'      => 6,        // 出口格 pls（到达后切换 next_region）
            'next_region'   => 2,        // 下一区域 pgroup（null = 终点）
            'exit_links'    => [2],      // [预留] 多出口，覆盖 next_region
        ],
    ],
    'tiles' => [
        $pgroup => [                     // 按区域分组
            $pls => [                    // 区域内局部索引 1-254
                'name'      => '地图格名称',
                'desc'      => '地图格描述（移动到达时显示）',
                'floor'     => 'standard',   // 地板属性
                'tide'      => 'shallow',    // 潮汐属性
                'height'    => 0,            // 高度（预留：影响移动消耗/战斗修正）
                'passable'  => true,         // 是否可通行
                'destructible' => false,     // 是否可破坏（预留）
                'neighbors' => [2, 3],       // 相邻格 pls 列表（区域内局部索引）
                'x'         => 2,            // 前端渲染坐标 X（列）
                'y'         => 3,            // 前端渲染坐标 Y（行）
                'preset_safe' => false,      // 是否预设为永久安全区
            ],
        ],
    ],
    'grids' => [
        $pgroup => [
            'cols' => 10,                // 该区域渲染列数
            'rows' => 8,                 // 该区域渲染行数
        ],
    ],
    // [可选] 预计算距离矩阵，加速跨格移动判定
    'distances' => [
        $pgroup => [
            $from_pls => [
                $to_pls => $distance,    // 最短路径长度（边数）
            ],
        ],
    ],
];
```

### 2.3 组合键定位

使用 `(pgroup, pls)` 组合键唯一确定一个地图格，无需修改数据库字段：

- `pls` 保持 `tinyint unsigned`（1-254），作为区域内局部索引。`pls=0` 保留不使用
- `pgroup` 保持 `tinyint unsigned`（0-255），最多 255 个区域
- 每个区域最多 254 个地图格，对手工不规则形状足够
- 跨区域时 pls 可重用，如区域 1 的 pls=5 和区域 2 的 pls=5 是不同的格

## 三、移动逻辑

### 3.1 基本规则

| 项目 | 值 | 说明 |
|------|-----|------|
| 保底移动距离 | 1 格 | 技能系统未开发时的默认值 |
| 移动消耗 | 25 SP | 每次移动动作（无论跨多少格） |
| 移动冷却 | 无 | 先不设冷却，后续加入 |
| 跨格移动 | 预留 | 由技能系统控制，保底 1 格 |

### 3.2 移动判定流程

```
obl_move($moveto)
  ├── 1. pls == moveto?              → 跳过（已在原地）
  ├── 2. moveto 在 tiles 中?         → 拒绝（无效目标）
  ├── 3. tile['passable'] == false?  → 拒绝（不可通行）
  ├── 4. sp < 25?                    → 拒绝（体力不足）
  ├── 5. moveto 在当前格 neighbors?  → 拒绝（不相邻）
  │     └── [预留] 技能跨格：检查距离 <= 技能范围
  ├── 6. sp -= 25
  ├── 7. pls = moveto
  ├── 8. 如果是出口格 → 切换区域
  │     └── pgroup = next_region
  │     └── pls = next_region.entrance_tile
  ├── 9. 写日志（区域名 + 格名 + 格描述）
  └── 10. [预留] obs_post_move_hook($pdata)
```

### 3.3 区域切换

当玩家到达当前区域的出口格（`tile[$pls] == region['exit_tile']`）时：
1. 读取 `region['next_region']`
2. 若 `next_region` 为 null → 到达终点，日志提示（暂不设结束条件）
3. 否则：`pgroup = next_region`，`pls = next_region.entrance_tile`
4. 日志输出区域切换信息

### 3.4 游戏刻

- 每次移动（无论是否跨区域）→ 更新 1 游戏刻
- `$gamevars['obl_tick']` 存储当前游戏刻
- 游戏刻仅记录，暂不驱动任何系统（战斗/NPC AI 未实现）

## 五、前端渲染

### 5.1 核心改变

旧版：10×10 固定网格 + `XY_COORDS` 硬编码坐标 → 35 个区域散布在固定格中。

新版：每个区域自定义网格大小（`grids[pgroup].cols × rows`），地图格按 `tile[x][y]` 坐标放置。空白格标为灰色不可通行，隐藏地图格（passable=false 且未探索）标为暗色。

### 5.2 渲染规则

| 条件 | 样式 |
|------|------|
| 当前位置 | 黄色高亮 + ★ |
| 相邻可到达 | 绿色可点击 |
| 不相邻（passable） | 暗灰色不可点击 |
| 不可通行 | 黑色不可点击 |
| 空白格（无 tile） | 深灰色 |
| 出口格 | 蓝色边框 |
| 入口格 | 绿色边框 |

### 5.3 区域切换时的前端行为

1. `currentRegion` 变化时，重新取 `grids[newRegion]` 的尺寸渲染
2. 地图格坐标从 `tiles` 中读取 `x` `y`
3. 相邻格判定从 `tiles[pls].neighbors` 读取

### 5.4 实现方案

修改 `map.js`：
- `mapData.links` 中取 `regions`、`tiles`、`grids`
- `renderMapGrid()` 按 `grids[currentRegion]` 尺寸动态生成网格
- `isReachable()` 从 `tiles[pls].neighbors` 判定
- 出口格高亮 + 点击时正常移动（后端自动切换区域）

## 九、编码约束

### 9.1 禁止 extract($pdata)

Oblivions 代码中**禁止**使用 `extract($pdata, EXTR_REFS)` 将 `$pdata` 展开为全局变量。直接通过 `$pdata['pls']`、`$pdata['pgroup']` 等方式访问。

旧版 `move()` 对 `$pls`、`$sp` 等全局变量的依赖是通过 `init_playerdata()` 中的 `extract` 实现的，Oblivions 不走此路径，直接操作 `$pdata` 数组。

### 9.2 与旧系统的兼容

- `oblivions_is_active()` 为 false 时，所有逻辑走旧版，不受影响。
- `data.js` 的 `XY_COORDS` 和 `PLACE_NAMES` 保留，仅在 `mapData.links` 为空时使用。
- 旧版 `move()` 不做任何修改。
