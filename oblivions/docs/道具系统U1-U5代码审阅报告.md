# 第一部分：U1-U3 审阅发现

## 一、错误

### U3-E1【严重】`item_use` 未拦截耐久为 0 的道具，玩家可无限使用已损坏道具

**位置**：`oblivions/include/game/item/item.use.func.php` 行 30-64

**问题**：`item_use` 流程只检查槽位是否为空（步骤 1）和 `tag_usable`（步骤 2），不检查耐久是否为 0。`item_consume_durability` 注释明确说"本函数只负责扣减耐久和 emit 事件，**不从背包移除道具**"。

后果链：
1. 道具耐久扣到 0 → `item_consume_durability` emit `durability.broken`，但道具仍在背包
2. 玩家再次使用该道具 → `item_use` 步骤 1 槽位非空 ✓ / 步骤 2 有 `tag_usable` ✓
3. 步骤 3 应用使用效果（效果函数若已注册，**会再次生效**）
4. 步骤 4 `item_consume_durability` 检测 `itms='0'` → 直接 return（不再扣减，也不重复 emit `durability.broken`）
5. 步骤 5 emit `use_item.success`

**影响**：玩家可对已损坏道具无限使用，效果无限触发。破坏消耗品的经济模型。

**根因分析**：主设计案 §5.4.3 **自身存在内部矛盾**——

| 位置 | 内容 | emit broken | 从背包移除 |
|------|------|:---:|:---:|
| §5.4.3 文字描述（行 783） | "耐久扣到 0 → 道具破坏（从背包移除，emit durability.broken 日志）" | ✓ | ✓ |
| §5.4.3 伪代码（行 786-793） | 只做 `$item['itms'] = (string)$cur;` | ✗ | ✗ |
| 实际代码 `item_consume_durability` | emit broken（行 128）+ 注释说"不从背包移除" | ✓ | ✗ |

代码是**混合实现**：emit 遵循文字描述，不移除遵循伪代码。

**权威决策**：以 §5.4.3 **文字描述**为准（文字描述表达设计意图，伪代码是实现细节）。耐久归零应**既 emit 又从背包移除**。

**修复方案**（两层）：
1. **入口拦截**（防止使用已损坏道具）：在 `item_use` 步骤 2 后检查 `itms='0'`，emit `use_item.broken` 并 return
2. **耐久归零移除**（遵循 §5.4.3 文字）：在 `item_use` 步骤 4 后检查耐久是否归零，归零则 `unset($pdata['itempara'][$slot])`

`item_consume_durability` 保持现状（只扣耐久 + emit），移除逻辑由调用方 `item_use` 负责（符合代码注释"从背包移除的逻辑由调用方按需处理"）。

**同步**：反向更新主设计案 §5.4.3 伪代码，补充 emit 和"调用方负责移除"的说明。

# 第二部分：U4-U5 审阅发现（原报告内容）

## 六、错误（U4-U5）

### E1【中】重复槽位导致素材被重复计数

**位置**：`item.craft.func.php` 多处（`item_match_recipes_by_slots` 行 380-392、`item_consume_materials` 行 286-300、`item_craft` 步骤 6 行 586-599）

**现象**：若前端传入 `slots=[1,1,3]`（同一槽位出现两次），代码会从 `$pdata['itempara'][1]` 读两次到 `$placed_items`，导致同一道具被当作两个独立素材参与匹配。

**影响**：
- 匹配阶段：可能错误地匹配需要 2 个该道具的配方
- 消耗阶段：`item_consume_materials` 内部 `unset($pdata['itempara'][$slot])` 会执行两次，第二次因 `isset` 返回 false 而跳过，实际只消耗 1 个；但 mapping 标记了两个 placed_index，导致耐久扣减模式可能错位

**修复**：在读 placed_items 前对 `slots` 去重：
```php
$slots = array_values(array_unique(array_map('intval', $slots)));
```
同理对 `workbench_materials` 也应去重。

### E2【中】`item_craft` 步骤 9 触发 `Undefined index` Notice

**位置**：`item.craft.func.php` 行 676

```php
'itmpara' => is_array($template['itmpara']) ? $template['itmpara'] : [],
```

**问题**：若 `$template['itmpara']` 键不存在，`is_array()` 会先触发 `Notice: Undefined index: itmpara`，再返回 false。

**修复**：
```php
'itmpara' => isset($template['itmpara']) && is_array($template['itmpara']) ? $template['itmpara'] : [],
```

### E3【中】`craft.success` 日志直接用 `item_id` 渲染，违反文案分离原则

**位置**：`vex-vue/src/data/log-templates.ts` 行 319-326

**问题**：日志渲染为"合成成功，获得 bandage×1"，玩家看到的是英文 item_id 而非中文名"绷带"。违反项目硬约束"前端通过 locale 查询文案"。

**修复**：在日志模板中查询 locale：
```typescript
import { ITEM_LOCALE } from '@/data/item-locale';

'craft.success': {
    render: (params) => {
      const results = params.results as Array<{ item_id: string; count: number }> | undefined;
      if (!results || !results.length) return `合成成功。`;
      const parts = results.map((r) => {
        const name = ITEM_LOCALE[r.item_id]?.name ?? r.item_id;
        return `${name}×${r.count}`;
      });
      return `合成成功，获得 ${parts.join('、')}。`;
    },
},
```

**注**：此问题与 U3-E2/U3-E3 同类，应统一修复方案。

## 八、冲突（U4-U5）

### C1【需决策】`item_consume_materials` 中 `consume='all'` 的清空方式与主设计案不一致

**位置**：`item.craft.func.php` 行 340

**主设计案 §5.5.8**：用空数组清空槽位
**代码**：用 `unset($pdata['itempara'][$slot])`

**冲突原因**：主设计案的空数组写法不被 `obl_find_empty_slot` 识别为空槽位（`obl_find_empty_slot` 检查 `!isset(...) || === null`，空数组既已 set 又非 null，返回 false）。导致合成后产物无法放入被消耗的槽位。

**代码修复**：改为 `unset()`，与 `obl_discard_item` 的 `obl_set_item($pdata, $slot, null)` 保持一致。

**权威决策**：以代码为准，反向更新主设计案 §5.5.8 的伪代码为 `unset()`。

**原则**：主设计案文字描述 > 代码 > 伪代码。当伪代码有 bug（空数组不被 `obl_find_empty_slot` 识别为空槽位）但代码已修复时，以代码为准并反向更新伪代码。这与 U3-E1 的方向一致——U3-E1 中代码未遵循文字描述，需修复代码；此处代码已正确实现文字描述的意图（"从背包移除"），仅需更新伪代码。
