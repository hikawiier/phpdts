# 战斗执行阶段重构设计案

> 配套设计：`终结技（Finisher）队列排序设计案.md`

---

## 一、设计目标

- 用 **Tag 系统** 统一描述目标状态
- 用 **白名单+黑名单** 配置驱动动作-目标规则
- 去掉命令层 A2 的 `state !== 0` 硬拒绝，下沉到执行预检
- Actor 状态检查独立，不再依赖调用方
- 错误信息通过 `$obl_battle_log` emit，前端可见
- 跨 action 标签变更通过 `$battle_cache['tag_mutations']` 累积，不依赖 DB 拉取
- **重构 `$battle_cache['combatants']`**：代表一次 `battle_main` 生命周期后还能**继续战斗**的目标合集
- **引入 `battle_state_middle_check`**：接手 execute 内的存活检测，只写缓存不写 DB
- **引入 `battle_main_end`**：集中处理 cleanup（`state=1`、`queue_exit`、`obl_save_player`）
- **队列流程不动**：`current_initiator` 继续查 DB，combatants 重构后不改队列逻辑

## 二、Tag 系统

### 2.1 定义

Tag 是目标的状态标记，每个标签 `{tag_name: bool}`。

### 2.2 基础标签集

**Category A（主视角相关）**：始终从当前 actor/target 重算，不缓存。

| Tag | 条件 | 含义 |
|-----|------|------|
| `self` | `target.pid === actor.pid` | 目标是自己 |
| `out_of_range` | 不在当前 actor 射程内 | 目标超出射程 |

**Category B（绝对状态）**：通过 `tag_mutations[pid]` 缓存跨 action 可见。

| Tag | 来源 | 含义 |
|-----|------|------|
| `dead` | `target.state === 1` / middle_check 写入 | 目标已死 |
| `escaped` | calc 写入 | 目标已逃跑 |
| `hidden` | calc 写入 | 目标隐身/潜伏 |

Category A 的 tag 基于 DB/actor 状态构建，Category B 通过 mutation 机制叠加。

### 2.3 实现（统一入口 + 内部委派）

**A/B 分类**：Category A tag（self/out_of_range）始终从当前 actor/target 重算；Category B tag（dead/escaped/hidden）通过 `tag_mutations[pid]` 缓存。

```php
function battle_build_target_tags(&$actor, &$target, $act_id, &$battle_cache): array {
    $tags = [];
    $pid = (int)$target['pid'];

    // ── Cat A：始终重算（依赖当前 actor，不可缓存）──
    $tags['self']         = battle_tag_self($actor, $target);
    $tags['out_of_range'] = battle_tag_out_of_range($actor, $target, $battle_cache);

    // ── Cat B：从缓存读取可变状态 tag ──
    $cached = $battle_cache['tag_mutations'][$pid] ?? null;
    if ($cached !== null) {
        $tags['dead']    = !empty($cached['dead']);
        $tags['escaped'] = !empty($cached['escaped']);
        $tags['hidden']  = !empty($cached['hidden']);
    } else {
        // 首次构建：从 DB 派生
        $tags['dead']    = battle_tag_dead($target);
        $tags['escaped'] = false;
        $tags['hidden']  = false;
    }

    // 只写 Cat B 到 tag_mutations（Cat A 每次重算）
    $battle_cache['tag_mutations'][$pid] = [
        'dead'    => $tags['dead'],
        'escaped' => $tags['escaped'],
        'hidden'  => $tags['hidden'],
    ];

    return $tags;
}
```

内部委派的单 tag 函数，只做派生不做写入：

```php
function battle_tag_dead(&$target): bool  { return (int)$target['state'] === 1; }
function battle_tag_self(&$actor, &$target): bool { return (int)$target['pid'] === (int)$actor['pid']; }
function battle_tag_out_of_range(&$actor, &$target, &$battle_cache): bool {
    return !battle_target_distance_check($actor, $target, $battle_cache);
}
```

## 三、Config 层：白名单 + 黑名单

### 3.1 格式

```php
'unarmed_strike' => [
    'apcost'        => 1,
    'target_rules'  => [
        'forbid'  => ['self', 'dead'],
    ],
],
'escape' => [
    'apcost'        => 0,
    'finisher'      => 1,
    'target_rules'  => [
        'require' => ['self'],
        'forbid'  => ['dead'],
    ],
],
'resurrect' => [
    'target_rules' => [
        'require' => ['dead'],
        'forbid'  => [],
    ],
],
```

无 `target_rules` 的旧技能 = 不限制（向后兼容）。

### 3.2 匹配算法

```php
function battle_check_target_rules($config, array $tags): array {
    $rules = $config['target_rules'] ?? null;
    if (!$rules) return ['pass' => true, 'reason' => null];

    if (!empty($rules['require'])) {
        foreach ($rules['require'] as $tag) {
            if (empty($tags[$tag])) {
                return ['pass' => false, 'reason' => "require:{$tag}"];
            }
        }
    }

    if (!empty($rules['forbid'])) {
        foreach ($rules['forbid'] as $tag) {
            if (!empty($tags[$tag])) {
                return ['pass' => false, 'reason' => "forbid:{$tag}"];
            }
        }
    }

    return ['pass' => true, 'reason' => null];
}
```

## 四、Tag Mutations 机制

### 4.1 存储位置

`$battle_cache['tag_mutations']` 存 Category B tag（全量写入/读取，非 overlay）：

```php
$battle_cache['tag_mutations'] = [
    int $target_pid => [
        'dead'    => false,   // 死亡标记
        'escaped' => false,   // 逃跑标记
        'hidden'  => false,   // 隐身标记
    ],
];
```

### 4.2 生命周期

```
battle_execute()
  ├─ 循环开始：tag_mutations 为空
  │
  ├─ act 1:
  │    verify → build_tags（首次构建：从 DB 派生全量 tag → 写入 tag_mutations[pid]）
  │    once_execute:
  │      ├─ calc/execute 写入 escaped/hidden 等 transient tag 到 tag_mutations[pid]
  │      └─ middle_check 更新 tag_mutations[pid]（dead→true）
  │
  ├─ act 2:
  │    verify → build_tags（直接从 tag_mutations 读取缓存，跳过 DB 派生）
  │    once_execute 同上
  │
  └─ 循环结束：
       tag_mutations → 被 battle_main_end 消费（读 dead/escaped 分流 cleanup）
       → 随 cache 销毁
```

### 4.3 初始化

由 `battle_cache_create` 初始化为空数组，详见 5.2。

### 4.4 写入

```php
// 逃跑 calc 中：
$battle_cache['tag_mutations'][(int)$target_data['pid']]['escaped'] = true;
```

### 4.5 读取

`battle_build_target_tags` 内从 `tag_mutations[pid]` 读取 Category B tag（`dead`/`escaped`/`hidden`），详见 2.3。

## 五、`$battle_cache['combatants']` 重构

### 5.1 新语义

```
$battle_cache['combatants'][pid] = 1  → 能继续战斗（存活且未逃跑）
$battle_cache['combatants'][pid] = 0  → 不能继续战斗（死亡/逃跑）
```

代表经历一次 `battle_main()` 生命周期后，还能继续战斗的目标合集。

**不参与队列后续流程**——`battle_queue_advance` / `update` / `try_end` 继续查 DB，不动。

### 5.2 初始化

`battle_cache_create` 参数由 `$initiator_pid` 改为 `$initiator_data`（完整数据），同时初始化 `tag_mutations`：

```php
function battle_cache_create(&$initiator_data, $is_ambush = false, $combatants = null) {
    if ($combatants === null) {
        // 发起者有战斗队列 → 载入队列内其他人
        $qid = (int)$initiator_data['bid'];
        if ($qid > 0) {
            $all_pids = obl_fetch_queue_pids_by_qid($qid);
            $combatants = [];
            foreach ($all_pids as $pid) {
                $combatants[(int)$pid] = 1;
            }
        } else {
            // 无队列 → 仅自己
            $combatants = [(int)$initiator_data['pid'] => 1];
        }
    }
    return [
        'combatants'    => $combatants,
        'last_qid'      => 0,
        'is_ambush'     => $is_ambush,
        'tag_mutations' => [],
    ];
}
```

五个入口的调用更新：

```php
// 入口 1：玩家突袭
$battle_cache = battle_cache_create($pdata, true);   // 之前传 $pdata['pid']

// 入口 2：NPC 突袭
$battle_cache = battle_cache_create($npc, true);      // 之前传 $npc['pid']

// 入口 3：遭遇战
$battle_cache = battle_cache_create($actor, false, $explicit_combatants); // 不变

// 入口 4：NPC 回合准备
$battle_cache = battle_cache_create($npc, false);     // 之前传 $npc['pid']

// 入口 5：玩家回合动作（cmd_handle_obl_battle_action → battle_main）
$battle_cache = battle_cache_create($pdata, false);   // 之前传 $pdata['pid']
```

### 5.3 写入时机

| 位置 | 操作 | 条件 |
|------|------|------|
| `battle_state_middle_check` | `combatants[target_pid] = 0` | 目标无法继续战斗 |
| `battle_state_middle_check` | `combatants[target_pid] = 1` | 目标可继续战斗 |
| `escape.calc` | `combatants[actor_pid] = 0` | 逃跑者退出战斗（9.2 用 `escaped` mutation 跳过 cleanup） |

### 5.4 读取时机

| 位置 | 用途 | 是否保留 |
|------|------|---------|
| `battle_queue_ensure` → `battle_get_alive_pids` | 初始建队 | **保留**（新初始化为载入队列成员后，逻辑不变） |
| `battle_main_end` | 遍历 status=0 的 pid 执行 cleanup | **新增** |

function battle_actor_can_act(&$actor_data, &$obl_battle_log): bool {

## 八、`battle_state_middle_check`

替换 `battle_target_alive_check`，在 `battle_once_execute` 内的伤害结算之后调用。

### 8.1 职责

```
写入缓存（combatants + tag_mutations），不修改 DB（state/hp 以外的字段）。
```

### 8.2 检测规则

用 hp/state 判定目标是否能继续战斗。三者互斥：
- `hp > 0` 且 `state == 0` → 能继续战斗 → `combatants[pid] = 1`（保留已有 mutation）
- `escaped` mutation 已存在 → 不能继续战斗 → `combatants[pid] = 0`，**不改 `dead`**
- 其他（hp<=0 或 state=1）→ 不能继续战斗 → `combatants[pid] = 0` + `tag_mutations[pid]['dead'] = true`

### 8.3 实现

```php
function battle_state_middle_check(
    &$actor_data, &$target_data, $act_id, &$obl_battle_log, &$battle_cache
): void {
    $pid = (int)$target_data['pid'];
    $hp  = (int)$target_data['hp'];

    // 读取当前缓存标签
    $mutations = $battle_cache['tag_mutations'][$pid] ?? [];
    $escaped = !empty($mutations['escaped']);
    $isDead = $hp <= 0 || (int)$target_data['state'] === 1;

    if (!$isDead && !$escaped) {
        $battle_cache['combatants'][$pid] = 1;
    } elseif ($escaped) {
        // 已逃跑：只标记 combatants，不改 dead
        $battle_cache['combatants'][$pid] = 0;
    } else {
        // 死亡：标记 combatants + 更新 mutation
        $battle_cache['combatants'][$pid] = 0;
        $battle_cache['tag_mutations'][$pid]['dead'] = true;

        $obl_battle_log?->emit([
            'actor_pid'    => (int)$actor_data['pid'],
            'target_pid'   => $pid,
            'action_id'    => 'state.middle_check',
            'extra'        => [
                'result' => 'died',
                'hp'     => $hp,
                'state'  => (int)$target_data['state'],
                'tags'   => $mutations,
            ],
        ]);
    }
}
```

## 九、`battle_main_end`

放在 `battle_main` 末尾、`battle_manage_queue` 调用之前。遍历 `combatants`，对 status=0 的目标执行 cleanup。

### 9.1 执行流程

```
battle_main_end(actor, atk_act, log, cache)
├─ 读取 cache['combatants']
├─ 遍历 status === 0 的 pid
│   ├─ 读 cache['tag_mutations'][pid]
│   ├─ 判定：
│   │   ├─ tag dead → state=1 + battle_state_clear
│   │   ├─ tag escaped → battle_state_clear（不改 state）
│   │   └─ 兜底 → battle_state_clear
└─ 结束
```

### 9.2 实现

```php
function battle_main_end(&$actor_data, &$atk_act, &$obl_battle_log, &$battle_cache): void {
    if (empty($battle_cache['combatants'])) return;

    foreach ($battle_cache['combatants'] as $pid => $status) {
        if ($status !== 0) continue;

        $mutations = $battle_cache['tag_mutations'][(int)$pid] ?? [];

        // 用 actor_data 避免重复 fetch（actor 可能也在 combatants 中）
        $target_data = $actor_data['pid'] == $pid ? $actor_data : obl_fetch_playerdata_by_pid((int)$pid);
        if (!$target_data) continue;

        // 标记死亡 state（escaped 不变）
        if (!empty($mutations['dead'])) {
            $target_data['state'] = $target_data['state'] ?: 1;
        }

        // dead / escaped 都走 state_clear（escaped 清 action/bid/ap，不改 state）
        if (!empty($mutations['escaped']) || !empty($mutations['dead'])) {
            battle_state_clear($target_data, $obl_battle_log, $battle_cache);
            continue;
        }

        // 兜底：combatants=0 但无 dead/escaped tag
        $obl_battle_log?->emit([
            'actor_pid'  => (int)$actor_data['pid'],
            'target_pid' => (int)$pid,
            'action_id'  => 'main_end.fallback',
            'extra'      => ['reason' => 'combatants_zero_no_tag'],
        ]);
        battle_state_clear($target_data, $obl_battle_log, $battle_cache);
    }
}
```

### 9.3 调用位置

```php
function battle_main(&$actor_data, &$atk_act, &$obl_battle_log, &$battle_cache) {
    $obl_battle_log->setPhase('verify');
    battle_verify($actor_data, $atk_act, $obl_battle_log, $battle_cache);

    if (!empty($atk_act)) {
        battle_sort_actions($atk_act);
        $obl_battle_log->setPhase('excute');
        battle_execute($actor_data, $atk_act, $obl_battle_log, $battle_cache);
    }

    // ── 集中 cleanup ──
    battle_main_end($actor_data, $atk_act, $obl_battle_log, $battle_cache);
}
```

### 9.4 与入口的关系

| 入口 | 调 `battle_main`? | 有 execute? | 需 `main_end`? |
|------|-------------------|-------------|----------------|
| 1. 玩家突袭（`battle_entry_player_ambush`） | 是 | 是 | 是 |
| 2. NPC 突袭（`battle_entry_npc_ambush`） | 是 | 是 | 是 |
| 3. 遭遇战（`battle_entry_encounter`） | **否**（直接 `battle_manage_queue`） | 否 | 不涉及 |
| 4. NPC 回合（`battle_entry_npc_prepare_actions`） | 是 | 是（可能空动作） | 是 |
| **5. 玩家回合动作（`cmd_handle_obl_battle_action`）** | 是 | 是 | 是 |

入口 3 不走 `battle_main`，也无 execute，不产生 cleanup 需求。入口 5 在已有队列中提交玩家回合动作，走完整 execute + main_end。

## 十、改动后的 `battle_once_execute`

```php
function battle_once_execute(&$actor_data, $act_id, &$target_data, &$obl_battle_log, &$battle_cache)
{
    battle_state_init($target_data);

    include_once GAME_ROOT . './oblivions/include/game/skill/skill.main.php';
    skill_execute($actor_data, $act_id, $target_data, $obl_battle_log, $battle_cache);

    $actor_oldhp  = (int)$actor_data['hp'];
    $target_oldhp = (int)$target_data['hp'];

    $damage = obl_calc_damage($actor_data, $target_data, $act_id, $battle_cache);
    battle_apply_damage($actor_data, $target_data, $damage, $obl_battle_log, $battle_cache);

    $obl_battle_log?->emit([
        'actor_pid'    => (int)$actor_data['pid'],
        'actor_type'   => (int)$actor_data['type'],
        'target_pid'   => (int)$target_data['pid'],
        'target_type'  => (int)$target_data['type'],
        'action_id'    => $act_id,
        'effect_value' => $damage,
        'extra'        => [
            'actor_oldhp'   => $actor_oldhp,
            'target_oldhp'  => $target_oldhp,
            'actor_newhp'   => (int)$actor_data['hp'],
            'target_newhp'  => (int)$target_data['hp'],
        ],
    ]);

    // ── 后检：用 tag 判定能否继续战斗，只写缓存 ──
    // 内部已更新 combatants[pid] + tag_mutations[pid]
    battle_state_middle_check($actor_data, $target_data, $act_id, $obl_battle_log, $battle_cache);

    obl_save_player($actor_data);
    obl_save_player($target_data);
}
```

## 十一、改动后的 `battle_execute` 循环

```php
function battle_execute(&$actor_data, &$atk_act, &$obl_battle_log, &$battle_cache) {
    foreach ($atk_act as $act) {
        $act_id = $act['act_id'];

        // A. 动作者能不能行动（per act 一次）
        if (!battle_actor_can_act($actor_data, $obl_battle_log)) continue;

        $targets_array = is_array($act['target']) ? $act['target'] : array($act['target']);

        foreach ($targets_array as $target_id) {
            $verify_result = battle_execute_verify(
                $actor_data,
                ['act_id' => $act_id, 'target' => $target_id],
                $obl_battle_log,
                $battle_cache
            );
            if (!$verify_result) continue;

            $target_data = &$verify_result['target_data'];

            battle_once_execute($actor_data, $act_id, $target_data, $obl_battle_log, $battle_cache);
        }
    }
}
```

## 十二、变更后的完整流程

```
battle_main(actor, atk_act, log, cache)
  │
  ├─ [verify] battle_verify
  │    └─ 校验 + 扣除 AP，无效 action 从 atk_act 删除
  │
  ├─ [sort]   battle_sort_actions          ← finisher 排序
  │
  ├─ [execute] battle_execute
  │    └─ foreach act
  │         ├─ A. battle_actor_can_act     ← actor 能否行动（emit 失败）
  │         ├─ foreach target
  │         │    ├─ battle_execute_verify  ← tag 构建 + 规则匹配（emit 失败）
  │         │    │    ├─ B. fetch target
  │         │    │    ├─ C. build_tags（含 mutations 合并）
  │         │    │    └─ D. check_target_rules
  │         │    │
  │         │    └─ battle_once_execute
  │         │         ├─ skill_execute     ← 非伤害效果（可写 mutations）
  │         │         ├─ calc_damage + apply_damage
  │         │         ├─ battle_state_middle_check  ← 写 combatants + mutations
  │         │         └─ obl_save_player(both)     ← HP 即时落库
  │         │
  │         └─ (next act...)
  │
  ├─ [end] battle_main_end                  ← 集中 cleanup
  │    └─ foreach combatants[pid] === 0
  │         ├─ dead tag → state=1 + battle_state_clear
  │         ├─ escaped tag → battle_state_clear（不改 state）
  │         └─ 兜底 → battle_state_clear
  │
  └─ return → battle_manage_queue 按现有逻辑
```

## 十四、安全边界

| 场景 | 原行为 | 新行为 |
|------|--------|--------|
| 攻击已死敌人 | 命令层 `state !== 0` 拒绝 | 命令层放行；`execute_verify` 检测 `dead` tag + forbid 规则拒绝 |
| 死人再逃跑 | `state !== 0` 拒绝 | 命令层放行；`target_rules.forbid: [dead]` 拒绝 |
| 攻击自己 | 放行（`target_check` 不拦） | `forbid: [self]` 拒绝（除非技能未设该规则） |
| Actor 死亡后继续执行队列 | 无检查 | `battle_actor_can_act` 拦截 |
| 未来：复活对活人放 | — | `require: [dead]` 拒绝 |
| 同一回合内逃跑→再攻击 | — | mutation `escaped` → 后续 verify 感知 |
| 执行中途崩溃 | 未保存的 state 丢失 | HP 已即时落库；state 未写入，恢复后仍为 state=0，HP=0 → HP 检查兜底 |
| 队列读到未 cleanup 的死人 | 可能（state 与 queue 未同步） | `battle_main_end` 在队列前执行，cleanup 完成后再交给队列，时序安全 |
