# 战报事件字段本地化契约

> 日期：2026-07-16
> 范围：`oblivions/include/game/combat/`（后端 emit）↔ `vex-vue/src/data/battle-templates.ts`（前端字典）
> 性质：跨层文本契约，后端 snake_case 字段作为索引锚点，前端字典 key 必须 1:1 对齐
> 关联设计案：[战报回放文本本地化与排版重构-2026-07-16.md](战报回放文本本地化与排版重构-2026-07-16.md)
> 关联框架基准：`OBL_EVENT_LOG_DESIGN.md` §7.2 out-of-scope 约束已解除，battle_log 通道进入本地化框架

## 一、字段契约

### 1.1 字段映射表

| 字段 | 类型 | 后端来源 | 前端字典 key | 解析策略 |
|---|---|---|---|---|
| `action_id` | snake_case string | `combat.log.php` emit / `enemy_ai.func.php`（`idle`） | `BATTLE_ACTION_TEMPLATES` | 直接匹配 |
| `effect_type` | enum string（`damage`/`heal`/`move`/`escape`/`ap_change`/`status`/`custom`） | `combat.log.php` emit | `BATTLE_EFFECT_TEMPLATES` | 直接匹配；未枚举值归为 `custom` |
| `reason` | snake_case string（可能含 `:` 分隔参数） | `combat.skill.php` / `combat.target_unit.php` / `combat.chain.php` / `combat.target_capture.php` / `combat.pipeline.php` / `combat.effect*.php` / `skill_*.php` | `BATTLE_REASON_TEMPLATES` | 前缀匹配（`prefix:剩余`）；剩余支持 `key=val,key=val` 键值对解析 |
| `combatant_cleared.reason` | enum string（`death` / `escaped`） | `combat.log.php`（由 `dead` 转换为 `death`）/ `combat.core.php` / `combat.target_unit.php` | `BATTLE_REASON_TEMPLATES` | 无前缀，直接匹配 |
| `battle_end.reason` | enum string（`queue_empty` / `disband` / `no_candidate`） | `battle_turn.func.php` | `BATTLE_REASON_TEMPLATES` | 无前缀，直接匹配 |
| `event_type` | enum string | `combat.log.php` emit | `BATTLE_NOTICE_TEMPLATES` | 直接匹配 |
| `channel` | enum string（`render` / `debug` / `diagnostic`） | `combat.log.php` emit | 路由信号 | `diagnostic` → debug-only 渲染（仅 `?debug=ai` 模式可见） |
| `winner_pid` | number / null | `combat.log.php` emit（来自 `battle_turn.func.php`） | `NoticeTextContext.winnerPid` | 用于 `battle_end` 胜负分支判定 |
| `payload.message_type` | enum string（`zh` / `key` / `debug`） | notice 事件 emit（待后端实现） | `BATTLE_NOTICE_TEMPLATES.notice` 路由 | 见 §1.3 |

### 1.2 reason 前缀清单

前端 `BATTLE_REASON_TEMPLATES` 必须覆盖以下全部前缀（含无前缀 enum 值）：

**action_failed reason 前缀**（`prefix:剩余` 格式）：

| 前缀 | 后端来源 |
|---|---|
| `damage_target_missing` | `combat.effect_projector.php` / `combat.effect.php` |
| `heal_target_missing` | `combat.effect_projector.php` / `combat.effect.php` |
| `move_target_missing` | `combat.effect_projector.php` |
| `ap_insufficient` | `combat.skill.php`（参数格式 `need=N,have=M`） |
| `rule_forbid` | `combat.skill.php` |
| `skill_not_found` | `combat.skill.php` / `combat.chain.php` |
| `move_spatial_rejected` | `skill_move.php` |
| `move_ap_quote_changed` | `skill_move.php` |
| `target_resolve_failed` | `combat.preview.php`（preview 通道已剥离，BattleLog 通道未剥离） |
| `AIM_RULE_FAILED` | `combat.preview.php`（preview 通道已剥离，BattleLog 通道未剥离） |
| `execute_hook_missing` | `combat.chain.php` / `combat.target_unit.php` |
| `CAPABILITY_BLOCKED` | `combat.pipeline.php` |
| `CAPTURE_RESOLVER_NOT_FOUND` | `combat.target_capture.php` |
| `CAPTURE_INVALID_OUTPUT` | `combat.target_capture.php` |
| `NO_VALID_TARGET` | `combat.target_unit.php` |
| `EFFECT_FAILED` | `combat.target_unit.php` |
| `NO_EXECUTABLE_EFFECT` | `combat.target_unit.php` |

**combatant_cleared reason enum**（无前缀）：

| 值 | 后端来源 |
|---|---|
| `death` | `combat.log.php`（由 `dead` 转换） |
| `escaped` | `combat.core.php` / `combat.target_unit.php` |

**battle_end reason enum**（无前缀）：

| 值 | 后端来源 |
|---|---|
| `queue_empty` | `battle_turn.func.php` |
| `disband` | `battle_turn.func.php` |
| `no_candidate` | `battle_turn.func.php` |

### 1.3 notice 事件 `payload.message_type` 路由

notice 事件的 `payload.message` 字段语义多样，后端应通过 `payload.message_type` 显式标记：

| message_type | 含义 | 前端处理 |
|---|---|---|
| `zh` | 后端硬编码中文 | 直接使用 `payload.message` |
| `key` | 字典 key | 查询 `BATTLE_NOTICE_TEMPLATES[message]`，未匹配走兜底 + `console.warn` |
| `debug` | 调试字符串 | 仅 `?debug=ai` 模式显示 |
| 未标记 | 后端暂未实现 | 回退为"按 `event.channel === 'diagnostic'` 判定 debug" |

### 1.4 action_id 清单

| act_id | 来源 | SKILL_TEMPLATES 注册 |
|---|---|---|
| `unarmed_strike` / `move` / `escape` / `heal` / `throw` / `whirlwind` / `execute` / `vampiric_bite` / `grenade` | `combat.log.php` emit | 是（`action_desc` 作为动词短语注入） |
| `idle` | `enemy_ai.func.php` | 否（NPC 专属，BATTLE_ACTION_TEMPLATES 独立条目） |

## 二、后端新增字段约束

1. 后端新增 `action_id` / `effect_type` / `reason` 枚举值时，**必须同步更新前端字典**与本文档清单
2. 后端 `reason` 字段保持"前缀:参数"格式，避免无前缀的裸字符串（`combatant_cleared.reason` 与 `battle_end.reason` 是无前缀 enum，单独管理）
3. 后端不应在 `reason` 中嵌入中文文案（保持跨层职责边界）
4. 后端 `combat_preview_reason_public` 的前缀剥离逻辑仅用于 preview 通道；**BattleLog 通道不应依赖该剥离**，前端字典必须覆盖原始 reason 全部前缀
5. 后端新增 `event_type` 时，必须同步扩展前端 `BattleLogV3EventType` 类型枚举与 `DirectedNotice.type` 联合类型
6. 后端实现 `notice` 事件时，应显式标记 `payload.message_type`（`zh` / `key` / `debug`），避免前端"中文字符检测"不可靠

## 三、前端校验

`battle-templates.ts` 导出 `validateBattleTemplates()` 函数，在 `main.ts` 的 `import.meta.env.DEV` 分支自动运行：

- 检查 `BATTLE_ACTION_TEMPLATES` 覆盖 `SKILL_TEMPLATES` 全部 key + `idle`（`idle` 是 SKILL_TEMPLATES 例外）
- 检查 `BATTLE_EFFECT_TEMPLATES` 覆盖生成文本的 4 个 type（`damage` / `heal` / `escape` / `status`）
- 检查 `BATTLE_REASON_TEMPLATES` 覆盖 §1.2 全部前缀清单（含 `*_target_missing` 三个具体展开、`target_resolve_failed` / `AIM_RULE_FAILED` 补遗、`death` / `escaped` combatant_cleared reason、`queue_empty` / `disband` / `no_candidate` battle_end reason）
- 检查 `BATTLE_NOTICE_TEMPLATES` 覆盖 `BattleLogV3EventType` 中需文本生成的 5 个 event_type（`action_failed` / `combatant_cleared` / `battle_end` / `combatant_joined` / `notice`）
- 输出未覆盖项 `console.warn`

## 四、模板匹配失败策略

按 `DESIGN.md` §4.1 跨层命名契约的"硬错误 + 兜底文案"策略：

- 未匹配的 `act_id`：`console.warn` + 兜底文案 `{actor}使用了{act_id}`（act_id 用 grey 高亮，提示开发者）
- 未匹配的 `effect_type`：`console.warn` + 返回 `undefined`（不显示文本）
- 未匹配的 `reason` 前缀：`console.warn` + 兜底文案 `原因：{raw_reason}`（raw_reason 用 grey 高亮）
- 未匹配的 `event_type`：`console.warn` + 兜底文案 `[未识别事件] {event_type}`（grey 高亮）
- `event.channel === 'diagnostic'`：仅 `?debug=ai` 模式显示 `[诊断] {detail}`
