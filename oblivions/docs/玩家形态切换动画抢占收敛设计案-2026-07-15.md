# 玩家形态切换动画抢占收敛设计案

> 日期：2026-07-15  
> 范围：Vex-Vue 玩家小人形态意图、地图角色运行时与 Header 战斗入口

## 1. 问题

Header 的 `[战斗]` / `[取消]` 会连续发布 `battle-start`、`battle-end` 形态意图。快速切换时，旧动画可能被新动画抢占后停在翻转中间态，表现为小人卡死、压扁或侧翻。

问题不应通过按钮冷却解决。按钮表达真实 UI 模式切换，最终小人必须收敛到最后一次意图指定的形态；输入频率不能改变动画正确性。

## 2. 根因

### 2.1 意图快照丢失

`useMapEntities` 的 watcher 先等待 `nextTick()`，再读取全局最新 `intent` 与 `intentSeq`。多个尚未完成的回调可能读到同一个最新序号，生成相同 `sessionId`，从而复用同一租约。任一旧回调释放该租约时，会取消仍在运行的新动画。

### 2.2 抢占后姿态没有收敛

形态翻转在动画中点提交图片切换。若动画在中点后被取消，`currentAppearance` 可能已经等于最后目标，但 DOM 姿态仍保留中间的 `rotationY`、`scale` 或 `y`。现有“外观已一致”分支只执行 `reset-visible`，没有重置 pose，因此中间态会永久保留。

## 3. 基准设计

### 3.1 不可变意图运行

watcher 回调进入时立即捕获 `intentSeq` 和 `intent`，后续异步阶段只消费该快照。`sessionId` 必须包含捕获的序号和角色运行时 generation，使每次非防抖意图获得独立租约身份。

### 3.2 最新意图抢占

形态切换继续使用 `owner='battle'` 和 `replaceEqualOwner=true`。较新的独立 session 抢占旧 session，ActorRuntime 负责取消旧 handle；旧回调只能释放自己的租约，不能影响新 session。

### 3.3 终态收敛

形态意图完成时必须同时满足：

- `currentAppearance` 与最后一次 `desiredAppearance` 一致；
- pose 回到中性变换；
- visibility 回到可见状态；
- 租约无论完成、取消或异常都被释放。

当图片已经是目标形态时不重复播放翻转，只执行即时 `reset-pose` 和 `reset-visible`。这既修复被取消动画留下的半途中间态，也不会让重复的战斗进入通知产生第二次翻转。

## 4. 边界案例

- `[战斗] → [取消] → [战斗]` 在一次翻转时长内完成：最终显示战斗形态且姿态中性。
- 翻转中点前取消：旧图片不提交，新意图从当前 DOM 状态抢占并收敛。
- 翻转中点后取消：即使图片已经提交，反向意图仍重置被取消的 pose。
- 同一形态重复通知：不重新翻转，只恢复中性 pose 与可见性。
- 角色运行时 generation 已变化：旧回调的 session 不能操作替换后的运行实例。

## 5. 实现边界

- `vex-vue/src/composables/useMapEntities.ts`：捕获意图快照、编排抢占和最终释放。
- `vex-vue/src/composables/useActorRuntime.ts`：提供 `reset-pose` 命令并维持通道租赁约束。
- `vex-vue/src/animations/actorAnimations.ts`：实现姿态中性化动画。
- `vex-vue/src/types/actor-runtime.ts`：声明新的运行时命令。
- `vex-vue/src/stores/player-avatar.ts`：仍只发布意图与目标形态，不接管动画执行。

## 6. 完成标准

- 快速交替点击不会留下中间姿态或不可见状态。
- 每次形态意图使用捕获的唯一序号。
- 旧回调释放不会取消新回调的租约。
- 类型检查、角色运行时针对性测试、设计锚点校验通过。
