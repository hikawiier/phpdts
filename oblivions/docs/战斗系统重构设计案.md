# 战斗系统重构设计案（先攻轮机制）

> 本文档记录 2026-06-19 完成的战斗系统重构，供后续调试参考。
> 原始设计案见 `oblivions/docs/原始方案/战斗设定.txt`。

---

## 一、重构概述

### 核心问题
旧 `obl_battle_execute()` 一次调用结算双方先攻轮（玩家+敌人），违背了"先攻轮是单方的"核心概念。旧"突袭"机制是名称谬误，实际是 NPC 移动到玩家格的"遭遇战"。

### 重构方案
1. **先攻轮是单方的**：一个先攻轮只属于一个"先攻者"，被攻击方只能反击
2. **先攻率机制**：动态属性函数 `obl_get_initiative_rate()`，默认 50，双方摇 `mt_rand(0, 先攻率)`，大者先攻
3. **先攻队列**：保存在所有人 `oblpara['battle']['queue']` 中
4. **NPC 先攻轮自动执行**，玩家先攻轮等前端提交
5. **只有玩家先攻轮推进 tick**（`obl_battle_action` 加入白名单），NPC 先攻轮不推进
6. **遭遇战走正常战斗载入流程**（取消"突袭"特殊逻辑）
7. **指令与核心函数分离**：`obl_battle_action` 指令 → `obl_battle_resolve_round()` 核心函数

## 二、核心概念

### 先攻轮（Initiative Round）
单方行动单位，一个先攻轮只属于一个先攻者，包含：
1. 加载攻击队列
2. foreach 执行攻击动作
3. 检查反击（留接口）
4. 队列清空 → 先攻轮结束

### 先攻率（Initiative Rate）
- 动态属性函数 `obl_get_initiative_rate(&$pdata)`，阶段一固定返回 50
- 双方摇 `mt_rand(0, 先攻率)`，大者先攻

### 先攻队列
结构保存在双方 `oblpara['battle']['queue']`：
```php
[
    0 => ['pid' => 先攻者pid, 'done' => 0],  // 顺位 0 = 第一先攻者
    1 => ['pid' => 另一方pid, 'done' => 0],
]
```
- `done=0` 未执行，`done=1` 已执行
- 所有人都 `done=1` 时重新先攻判定

### 先攻补正（设计案 L30）
- 玩家不是第一顺位时，玩家随机数 += 第一顺位者随机数 × 25%
- 但最高只能成为第二顺位（1v1 中无实际效果，为 1vN 预留）

### 平局规则
随机数相同 → 先攻率大者先攻 → 先攻率也相同 → 玩家优先（type=0）

### 遭遇战
- 原"突袭"的正名，NPC 移动到玩家格触发
- 走正常战斗载入流程（状态检测 + 先攻判定 + NPC 自动执行）
- 取消 `obl_battle_ambush()`，新增 `obl_battle_encounter()`

## 三、完整战斗生命周期

### 玩家主动攻击流程
```
1. 玩家点击地图敌人 → startBattle(enemyPid) → obl_battle_start 命令
   → obl_battle_enter_prebattle() → action='prebattle', bid=enemy_pid

2. 前端显示 prebattle 模式（动作面板 + 可取消）

3. 玩家选择动作 → obl_battle_action 命令（带 action_id）
   → cmd_handle_obl_battle_action() → obl_battle_resolve_round($action_id, $pdata)

4. obl_battle_resolve_round() 内部：
   4a. 若 action='prebattle'（首次）：
       - obl_battle_enter_battle()  → 双方 action='battle', 初始化战斗状态
       - emit battle.start 日志
       - obl_battle_roll_initiative()  → 先攻判定，生成队列
   4b. 获取当前顺位 obl_battle_get_current_initiator()
       - 若所有人都 done → 重新先攻判定
       - 若当前顺位不是玩家 → 走 obl_battle_auto_npc()
   4c. 执行玩家先攻轮 obl_battle_execute($pdata, $enemy, $action_id)
   4d. 标记玩家 done=1（双方同步）
   4e. 检查战斗结束（escape/victory/defeat）→ 若结束 obl_battle_end()
   4f. NPC 自动执行 obl_battle_auto_npc()
       - 循环：获取当前顺位 → 若是玩家则 break → 否则 NPC 执行先攻轮
       - 所有人都 done → 重新先攻判定
       - 检查战斗结束

5. 命令返回 → command [F] 段白名单判定 → obl_battle_action 推进 tick
   → 下次加载 common.inc.php 时结算 tick 事件（NPC AI 等）
```

### 遭遇战流程（NPC 移动到玩家格）
```
1. tick 结算 → obl_resolve_all_enemy_ai() → obl_enemy_tick() → obl_enemy_chase_player()
   → obl_enemy_move() → 目标格是玩家格 → obl_resolve_collision_battle()

2. obl_resolve_collision_battle() → obl_battle_encounter($player, $enemy)
   - obl_battle_enter_battle()  → 双方 action='battle'
   - 互相 discovered=1
   - emit battle.start 日志（initiator='enemy'）
   - obl_battle_roll_initiative()  → 先攻判定
   - obl_battle_auto_npc()  → NPC 自动执行直到玩家顺位或战斗结束
   - 立即持久化战斗日志（遭遇战可能在非当前请求玩家的 tick 中发生）

3. 玩家下次拉取 player_info → action='battle' → 前端进入战斗模式
```

### tick 推进机制
- **白名单机制**：只有白名单内的命令才推进 tick
- 当前白名单：`{ move, obl_explore, obl_search, obl_battle_action }`
- **只有玩家先攻轮推进 tick**，NPC 先攻轮在 `obl_battle_resolve_round()` 内部自动执行，不单独推进
- tick 推进位置：`obl_command.php` [F] 段
- tick 结算位置：`common.inc.php` 检测 `obl_pretick < obl_tick` 时调用 `obl_resolve_tick_events()`

### 核心原则
- 玩家已处在战斗状态（action=battle）→ NPC AI 跳过战斗状态玩家（`obl_resolve_all_enemy_ai` 中 `if ($pdata['action'] == 'battle') break`）
- 不存在玩家提交指令被 NPC 行为覆盖的情况

**checkPlayerTurn 逻辑：**
```javascript
function checkPlayerTurn(battleState, enemyPid) {
    if (!battleState || !Array.isArray(battleState.queue)) return true;
    for (let i = 0; i < battleState.queue.length; i++) {
        if (battleState.queue[i].done == 0) {
            return parseInt(battleState.queue[i].pid) !== parseInt(enemyPid);
        }
    }
    return true;
}
```

## 五、BattleLogEntry 结构与 emit 签名

### BattleLogEntry 结构
```json
{
    "id": "battle.action",
    "turn": 0,
    "actor": "player" | "enemy_{pid}" | "system",
    "action_id": "unarmed_strike" | "escape" | "battle.start" | "initiative.roll" | ...,
    "action_name": "空手攻击" | "逃跑" | "开战" | "遭遇" | "先攻判定" | ...,
    "target": "player" | "enemy_{pid}" | "第一顺位者名字",
    "effect_value": 0,
    "extra": {},
    "position": null,
    "ts": "..."
}
```

### BattleLogCollector::emit 签名
```php
$obl_battle_log->emit(
    $turn,           // 先攻轮序号（用于日志排序）
    $actor,          // 'player' | 'enemy_{pid}' | 'system'
    $action_id,      // 动作 ID
    $action_name,    // 动作显示名称
    $target,         // 'player' | 'enemy_{pid}' | 名字字符串

    $extra,          // 额外数据数组，默认 null
```

## 六、前端事件驱动架构

- **无定时轮询**，命令完成后广播 `game:action-completed` 事件触发面板刷新
- `api_v2.php` 加载 `common.inc.php` 天然触发 tick 结算
- `api_v2.php` 的 `player_info` 返回 `oblpara` 字段（第 159 行），前端可获取先攻队列

### 前端战斗状态机
```
action='prebattle' → prebattle 模式（显示动作按钮，可取消）
action='battle'    → battle 模式
  - 检查 oblpara.battle.queue
  - 玩家是当前顺位 → 显示动作按钮
  - 玩家不是顺位   → 显示"敌人正在行动..."
action=''          → 退出战斗模式，恢复 normalMode
```
