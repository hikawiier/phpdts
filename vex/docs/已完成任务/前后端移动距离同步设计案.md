# 前后端移动距离同步设计案

## 背景

后端 `obl_get_move_range()` 返回 3，支持跨格移动（BFS 距离 ≤3）。前端 `isReachable()` 只检查 `neighbors` 直连，未做 BFS 距离判定，导致跨格可达格被标记为不可达。

## 改动清单

### 一、后端：API 返回 move_range

**文件**：`oblivions/include/api/api_v2.php`（game_map action）

在 `game_map` 响应中增加 `move_range` 字段：
```php
'move_range' => obl_get_move_range(),
```

前端从 `mapData.links.move_range` 或顶层字段读取（取决于 API 结构，实施时确认）。

### 二、前端：isReachable 改为 BFS 距离判定

**文件**：`vex/js/map.js`

#### 2.1 缓存可达性 Map

新增模块级变量 `reachableMap`（Map<pls, distance>），每次 `renderMapGrid()` 时从当前格做一次 BFS，计算所有距离 ≤ move_range 的格子。

```
reachableMap = new Map()
BFS 从 curLoc 出发：
  - 遍历 neighbors，跳过 passable=false 的中转格
  - 记录每个可达格的 distance
  - distance > move_range 时停止扩展
  - 目标格本身不检查 passable（与后端一致，passable 在 move 时单独检查）
```

#### 2.2 isReachable 改写

```js
function isReachable(areaId) {
    // 入口格特殊处理（保留现有逻辑）
    ...
    // BFS 距离判定
    return reachableMap.has(areaId);
}
```

移除原有的 `neighbors.indexOf` 判定，改为查 `reachableMap`。

#### 2.3 move_range 来源

从 `mapData.links.move_range` 读取，默认值 1（兼容旧数据）。

### 三、前端：findPath 修正

**文件**：`vex/js/map.js`

移除之前错误添加的"只走空间相邻格（切比雪夫距离≤1）"限制。改为纯 neighbors BFS，跳过 `passable=false` 中转格，与后端 `obl_get_distance()` 逻辑一致。

### 四、前端：路径预览不高亮迷雾中间格

**文件**：`vex/js/map.js` — `showPathPreview()`

路径中间格高亮前，检查该格是否迷雾。迷雾格跳过高亮（不加 `.cell-path`，不加方向箭头）。

### 五、前端：键盘移动同步

**文件**：`vex/js/map.js` — `handleKeyMove()`

键盘移动目前只检查 `neighbors` 直连。改为检查 `reachableMap.has(targetPls)`，支持跨格键盘移动。

注意：键盘方向键是上下左右四方向，跨格移动时目标格可能不在四方向相邻坐标上。键盘移动仍只移动到四方向相邻格（距离1），跨格移动通过鼠标点击触发。这样保持键盘移动的直觉性。

## 涉及文件

| 文件 | 改动 |
|------|------|
| `oblivions/include/api/api_v2.php` | game_map 返回 move_range |
| `vex/js/map.js` | reachableMap 缓存 + isReachable BFS + findPath 修正 + 路径预览迷雾过滤 + move_range 读取 |

## 验证点

1. 跨格可达格（距离2-3）显示为 reachable，可点击移动
2. 距离 >3 的格不可达
3. 路径预览显示已探索中间格 + 方向箭头，迷雾中间格不高亮
4. 不可通行格不作为中转
5. 入口格回退逻辑正常
6. 键盘移动仍只走四方向相邻格
