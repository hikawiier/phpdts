## 问题 1：`loadItemFind()` 残留

### 现状

`inventory.js` 仍导出 `loadItemFind` 函数，`app.js` 仍 import 并在 `refreshAll()` 中调用。该函数实际只做两件事：从 `player_info` 缓存中读取 `club` 和 `items[0].name`，设置 `playerClub` 和 `hasFoundItem` 两个导出变量。但这两个变量没有任何模块引用——"发现物品"面板和 `map.js` 中的引用已在之前的清理中删除。

### 影响

- `refreshAll()` 中 `loadItemFind()` 白跑一次 `dataManager.fetch('player_info')`（有缓存，开销极小但无意义）
- 代码误导：新介入的 AI 或开发者会以为 `loadItemFind` 有实际功能
- `playerClub` 和 `hasFoundItem` 导出变量是死代码

### 修复方案

**删除 `loadItemFind` 函数及其导出变量**：

1. `inventory.js`：删除 `export let playerClub = 0;`、`export let hasFoundItem = false;`、整个 `loadItemFind()` 函数
2. `app.js`：import 行从 `import { loadItemFind, loadInventory } from './inventory.js'` 改为 `import { loadInventory } from './inventory.js'`
3. `app.js`：`refreshAll()` 中删除 `loadItemFind()` 调用

### 验证

- 浏览器访问页面，确认无 `ReferenceError` 或 `import` 报错
- 背包/装备/丢弃功能正常

## 问题 3：地图格名称溢出

### 现状

`map.js` 中地图格内容通过 `cell.innerHTML = '<span class="cell-name">名称</span>'` 渲染。当前 CSS：

```css
.map-cell .cell-name {
    font-size: 9px;
    text-align: center;
    line-height: 1.3;
    max-width: 100%;
    padding: 0 2px;
    overflow: hidden;
}
```

`overflow: hidden` 只隐藏溢出文字，但文字仍会撑大 `.cell-name` 的固有宽度，导致 grid 格子被撑宽。根本原因：`.cell-name` 是 inline 元素，`max-width: 100%` 对 inline 元素无效。

### 影响

- 有名字的格子（如"散落的零件堆"）文字过长时撑破格子宽度
- 地图网格不再对齐，视觉混乱

### 修复方案

**给 `.cell-name` 加 `display: block` + `overflow: hidden` + `text-overflow: ellipsis` + `white-space: nowrap`**：

```css
.map-cell .cell-name {
    display: block;              /* 关键：让 max-width 生效 */
    font-size: 9px;
    text-align: center;
    line-height: 1.3;
    max-width: 100%;
    padding: 0 2px;
    overflow: hidden;
    text-overflow: ellipsis;     /* 溢出显示省略号 */
    white-space: nowrap;         /* 禁止换行 */
}
```

同时确保 `.map-cell` 本身有 `overflow: hidden`（已有），防止内容撑大格子。

### 补充：当前格多行内容

当前格渲染 `[我]` + 名称，`[我]` 用 `.cell-me { display: block }` 换行。修复后名称行也会被截断，这是可接受的——当前格信息在 ACTIONS 面板和状态栏都有完整显示。

### 验证

- 在地图数据中设置一个长名字的格子（如"废弃的金属零件堆积处"），确认文字被截断且格子宽度正常
- 确认短名字格子显示完整

## 问题 4：`handleSwitchRegion` 逻辑

### 现状

`tile-action.js` 中 `handleSwitchRegion()` 的实现：

```javascript
const targetPls = isOnExit ? regionInfo.exit_pls : regionInfo.entrance_pls;
const result = await commandQueue.execute({ command: 'move', moveto: targetPls });
```

当玩家站在出口格时，`targetPls === mapData.curLoc`，即 move 到自己位置。

**后端已支持此场景**：`obl_move()` 第 150-161 行明确处理了同位置移动——如果当前格是出入口，执行 `obl_switch_region()` 并返回。

### 结论

**这不是 bug，代码逻辑正确。** 后端已实现"站在出入口格原地 move 触发区域切换"。

### 需清理的内容

代码注释有误导性（"后端 move 到当前位置不会触发切换"），应更新注释：

```javascript
// 站在出入口格 → move 到当前位置 → 后端 obl_move() 检测到出入口同位置移动 → 触发区域切换
const targetPls = isOnExit ? regionInfo.exit_pls : regionInfo.entrance_pls;
```

### 验证

- 站在出口格点击"前往下一区域"按钮，确认区域切换成功
- 站在入口格点击"返回上一区域"按钮，确认区域切换成功
- 站在非出入口格，确认按钮不出现

## 问题 5：响应式布局

### 现状

`terminal.css` 中仅有一个断点：

```css
@media (max-width: 900px) {
    .grid-cols-\[55\%_1fr\] {
        grid-template-columns: 1fr !important;
        grid-template-rows: auto auto;
    }
}
```

这仅将双栏改为单栏堆叠，但存在以下问题：

1. **地图格尺寸**：桌面端自适应 48-80px，但移动端屏幕宽度 375px / 10 列 = 37.5px，格子过小
2. **Bottom Sheet**：移动端 `max-h-[50vh]` 可能遮挡大部分内容
3. **抽屉**：280px 宽在 375px 屏幕上占 75%，比例过大
4. **动作条**：`max-height: 180px` 在单栏布局下可能不够
5. **字体**：9-11px 在移动端偏小

### 修复方案

**分阶段实施，优先保证可玩性**：

#### 阶段 1：移动端基础可用（必须）

| 改动 | 说明 |
|------|------|
| 地图格缩放 | 移动端 `cellSize` 最小降至 32px，`cellHeight` 降至 22px，字号降至 7px |
| 单栏布局 | 900px 断点下左右栏堆叠，左栏（地图+动作条）在上，右栏（日志+背包）在下 |
| 滚动 | `main` 在移动端允许纵向滚动（`overflow-y: auto`），而非 `overflow-hidden` |
| Bottom Sheet | 移动端 `max-height: 70vh`，留更多空间 |
| 抽屉 | 移动端宽度改为 `85vw`，最大 320px |

#### 阶段 2：交互优化（建议）

| 改动 | 说明 |
|------|------|
| 地图格点击区域 | 移动端增大 touch target，`min-height: 44px`（Apple HIG 推荐） |
| 手势 | 地图支持双指缩放 / 拖拽平移（需引入 touch 事件处理） |
| 动作条 | 移动端改为固定底部栏，取代 Bottom Sheet |
| 日志 | 移动端折叠为单行，点击展开 |

#### 阶段 3：平板适配（可选）

| 改动 | 说明 |
|------|------|
| 768-1024px | 双栏比例调整为 50%/50% |
| 横屏 | 利用 `orientation: landscape` 优化布局 |

### CSS 改动示例（阶段 1）

```css
/* 移动端基础适配 */
@media (max-width: 900px) {
    /* 单栏堆叠 + 允许滚动 */
    main {
        grid-template-columns: 1fr !important;
        grid-template-rows: auto auto;
        overflow-y: auto !important;
    }
    /* 地图格缩小 */
    .map-cell .cell-name { font-size: 7px; }
    .map-cell .cell-me { font-size: 6px; }
    /* 抽屉适配 */
    .player-drawer { width: 85vw; max-width: 320px; }
    .drawer-toggle.shifted { left: 85vw; max-left: 320px; }
    /* Bottom Sheet 更多空间 */
    .bottom-sheet { max-height: 70vh; }
}
```

### JS 改动示例（阶段 1）

`map.js` 中 `renderMapGrid()` 的格子尺寸计算：

```javascript
// 移动端：最小 32px，桌面端：最小 48px
const isMobile = window.innerWidth <= 900;
const minSize = isMobile ? 32 : 48;
const maxSize = isMobile ? 48 : 80;
const cellSize = Math.max(minSize, Math.min(maxSize, Math.floor(containerWidth / cols)));
const cellHeight = Math.max(isMobile ? 22 : 32, Math.floor(cellSize * 0.6));
```

### 验证

- Chrome DevTools 设备模拟：iPhone SE (375px)、iPhone 14 (390px)、iPad (768px)
- 确认地图格可点击、动作条可操作、日志可滚动
- 确认桌面端（>900px）布局不受影响
